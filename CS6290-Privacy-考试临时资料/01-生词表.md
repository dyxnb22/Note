# CS6290 Lecture + Tutorial 生词表

> 本词表根据 Lecture 0–8、Tutorial 1–10、教材和题目答案整理。词条已经去重，按英文词头的字母序排列。这里的“生词”以课程中的技术术语、缩写和关键表达为主，不收录 Alice、Bob 等示例人名以及普通日常英语。

## 使用说明

- **Term**：英文术语或缩写。
- **中文释义**：适合考试和阅读讲义的中文意思。
- **课程语境**：说明它在本课程中具体指什么。
- 同一个概念可能有缩写和全称两个入口，例如 PoS 和 Proof of Stake；为方便检索，关键缩写会单独列出。
- 单词、短语和缩写均按英文首字母排序；大小写不影响排序。

## A

| Term | 中文释义 | 课程语境 |
|---|---|---|
| ABI | 应用二进制接口 | Ethereum 合约调用的数据编码规范；函数选择器和参数 calldata 按 ABI 编码。 |
| acceptance criteria | 验收标准 | 用可观察、可测试的条件判断功能是否完成，例如 p95 延迟小于某个阈值。 |
| account model | 账户模型 | 直接维护账户余额、nonce、代码和 storage 的区块链状态模型。 |
| accumulator | 累加器 | 用一个较小的摘要承诺一组状态或 UTXO，并通过证明验证成员关系；Utreexo 是例子。 |
| actor-critic | 执行者—批评者循环 | agent 先执行，再由独立角色检查结果、更新计划并决定是否重试。 |
| address | 地址 | 代表收款条件、账户或一次性支付目标的标识。 |
| adversarial model | 对手模型 | 明确攻击者的计算、网络、身份和资源能力的形式化假设。 |
| adversary | 对手/攻击者 | 安全模型中试图破坏协议、可以偏离协议的参与者。 |
| aggregation | 聚合 | 将多个签名、证明、流动性来源或交易请求合并，降低数据或验证成本。 |
| aggregator | 聚合器 | 同时搜索多个 DEX 或流动性池，选择或拆分出更优交易路径的协议。 |
| agreement | 协议一致性 | 共识或 RBC 要求诚实节点不对同一对象作出不同决定。 |
| air-gapped wallet | 物理隔离钱包 | 与网络隔离、通常用于冷存储和高价值资产审批的钱包。 |
| allowance | 授权额度 | ERC-20 中 owner 允许 spender 代为花费的最大 token 数量。 |
| AMM | 自动做市商 | Automated Market Maker，用数学曲线而不是订单簿自动报价和交易。 |
| anonymity | 匿名性 | 观察者无法把行为关联到真实身份；Bitcoin 地址通常是伪名而非真正匿名。 |
| anonymity set | 匿名集合 | 某个真实对象可能属于的候选对象集合；集合越大，单个对象越难被识别。 |
| application layer | 应用层 | 区块链系统中直接面向用户的合约、钱包、DeFi、隐私应用等部分。 |
| APR | 年化百分比率 | Annual Percentage Rate，通常是不计复利的简单年化收益率。 |
| APY | 年化收益率 | Annual Percentage Yield，包含复利效果的年化收益指标。 |
| arbitrage | 套利 | 利用不同市场或 AMM 与外部价格之间的差异获利。 |
| arbitrageur | 套利者 | 执行套利交易、把池子价格拉回外部市场价格的参与者。 |
| arithmetic circuit | 算术电路 | 用加法门、乘法门和约束表示计算，常作为 ZKP 的证明对象。 |
| artifact budget | 工件预算 | 限制规格、计划和任务文档的数量与大小，防止文档膨胀和过时。 |
| assertion | 运行时断言 | 在运行时检查测试、schema、不变量、性能或错误条件，验证现实是否符合预期。 |
| atomicity | 原子性 | 一组操作要么全部生效，要么全部回滚；Flash loan 和跨合约交易依赖它。 |
| attestation | 证明性投票 | PoS 验证者对区块、链头或 checkpoint 的签名投票。 |
| authenticated channel | 认证信道 | 接收者能确认消息来自指定发送者，但消息仍可能延迟或重排的信道。 |
| availability | 可用性 | 系统能持续响应请求或提供数据的性质；也是 CAP 中的 A。 |
| availability sampling | 可用性抽样 | 节点随机抽查部分数据，以高概率发现整批数据是否不可用。 |
| Avalanche consensus | Avalanche 共识 | 通过反复随机抽样少量节点并累积偏好实现收敛的共识系列。 |
| avalanche effect | 雪崩效应 | 哈希输入改变少量比特后，输出应呈现完全不同、近似随机的变化。 |

## B

| Term | 中文释义 | 课程语境 |
|---|---|---|
| back-running | 后置套利 | 在一笔大交易之后立即交易，利用价格变化或套利机会获利。 |
| base fee | 基础费 | EIP-1559 中按网络需求调整并被销毁的费用部分。 |
| batch | 批次 | Rollup 一次提交到 L1 的一组 L2 交易、状态更新或相关数据。 |
| BBS+ | BBS+ 签名 | 支持选择性披露属性的签名方案，可用于隐私身份凭证。 |
| BFT | 拜占庭容错 | Byzantine Fault Tolerance，在部分节点恶意时仍保证共识性质。 |
| bisection | 二分定位 | Optimistic Rollup 用二分协议逐步定位状态执行中第一个错误步骤。 |
| Bitcoin | 比特币 | 使用 UTXO、数字签名、PoW 和 Nakamoto 共识的开放式加密货币系统。 |
| blob | 临时大数据对象 | EIP-4844 等方案为 Rollup 提供的临时数据空间；通常不作为永久 storage 保存。 |
| block | 区块 | 按顺序组织交易并链接到前一区块的数据单元。 |
| block header | 区块头 | 包含前块哈希、Merkle root、时间、难度和 nonce 等字段的区块摘要部分。 |
| block reward | 区块奖励 | 矿工或验证者因产生有效区块获得的补贴和/或交易费。 |
| blockchain | 区块链 | 通过哈希指针链接、由共识选择的有序区块历史。 |
| bootstrapping | 引导启动 | 节点获得初始对等节点、区块头或网络状态的过程。 |
| bridge | 跨链桥 | 在不同区块链之间锁定、证明、铸造或释放资产与消息的系统。 |
| builder | 区块构建者 | 搜索交易排列和 MEV 后组装候选区块，再向 proposer 出价的角色。 |
| Bulletproofs | Bulletproofs 范围证明 | 不需要 trusted setup、证明大小对数级的零知识范围证明系统。 |
| Byzantine | 拜占庭式的 | 节点可以任意恶意，包括停止、说谎、双签以及向不同节点发送矛盾消息。 |
| Byzantine broadcast | 拜占庭广播 | 让一个 leader 的提案在恶意节点存在时被诚实节点一致交付的协议。 |
| Byzantine fault | 拜占庭故障 | 最强故障模型；节点行为不受协议约束且可针对不同对象发送不同消息。 |
| Byzantine Generals Problem | 拜占庭将军问题 | 用叛徒将军和忠诚将军的故事形式化分布式一致性问题。 |

## C

| Term | 中文释义 | 课程语境 |
|---|---|---|
| calldata | 调用数据 | Ethereum 外部调用提供的只读字节输入，包含函数 selector 和 ABI 编码参数。 |
| CAP theorem | CAP 定理 | 网络分区时，系统难以同时保证强一致性、可用性和分区容错。 |
| Casper FFG | Casper 最终性组件 | Ethereum Gasper 中通过 checkpoint 投票提供 BFT 风格最终性的部分。 |
| CEI | Checks-Effects-Interactions | 智能合约安全模式：先检查、再更新状态、最后进行外部交互，以减少重入风险。 |
| censorship resistance | 抗审查性 | 某个运营者、sequencer 或验证者不能永久阻止合法交易或提款。 |
| CFT | Crash Fault Tolerance，崩溃容错 | 只考虑节点停止或崩溃、不考虑任意恶意行为的容错模型。 |
| chain growth | 链增长 | 一段时间内诚实链至少增长一定区块数的性质，支撑活性。 |
| chain quality | 链质量 | 链的任意足够长片段中，攻击者区块不能占据过高比例的性质。 |
| chain velocity | 链速度 | 衡量一定时间或轮次中链增长多少区块的指标。 |
| challenge period | 挑战期 | Optimistic Rollup 提交状态后，watcher 可以提交 fraud proof 的时间窗口。 |
| change detection | 找零识别 | 根据金额、地址格式和脚本特征推测某个输出是否为付款者找零。 |
| Chernoff bound | Chernoff 界 | 用于界定独立随机变量偏离期望值概率的集中不等式。 |
| circuit breaker | 熔断器 | 发现异常流出或系统风险时自动暂停交易、提现或关键操作的控制。 |
| coinbase transaction | Coinbase 交易 | 区块中产生矿工补贴和手续费收入的特殊交易，不是普通 UTXO 输入交易。 |
| CoinJoin | CoinJoin 混币 | 多个用户共同签署一笔交易，打乱输入和输出之间的对应关系。 |
| cold wallet | 冷钱包 | 离线或隔离保存私钥、暴露面较小但不适合高频支付的钱包。 |
| collateral | 抵押品 | 借贷或稳定币系统中锁定、用于支持债务或 token 价值的资产。 |
| collision resistance | 抗碰撞性 | 难以找到两个不同输入却有相同哈希输出。 |
| commitment | 承诺 | 先隐藏一个值，之后再打开并证明没有改变的密码学对象。 |
| commitment scheme | 承诺方案 | 通常要求 hiding（隐藏性）和 binding（绑定性）。 |
| committee | 委员会 | 被随机或按规则选出的验证者子集，负责某个 slot、epoch 或协议步骤。 |
| common prefix | 共同前缀 | 去掉链尾若干区块后，诚实节点的链视图互为前缀的性质。 |
| common-input ownership | 共同输入所有权启发式 | 推测同一交易中的多个输入通常由同一控制者拥有的链上分析方法。 |
| completeness | 完备性 | ZKP 中诚实 prover 持有正确 witness 时，诚实 verifier 应接受。 |
| computational soundness | 计算健全性 | 计算能力受限的恶意证明者不能以非忽略概率证明错误命题。 |
| confidential transaction | 保密交易 | 用承诺和范围证明隐藏金额，同时验证输入输出金额守恒。 |
| confirmation | 确认数 | 某笔交易所在区块后面又追加的区块数量；PoW 中确认越多通常越难回滚。 |
| consensus | 共识 | 分布式节点对值、交易顺序或账本状态形成一致决定的过程。 |
| consistency | 一致性 | 诚实节点不能对同一决定得到互相冲突的结果。 |
| constant product formula | 恒定乘积公式 | AMM 使用的 x·y=k 定价关系。 |
| context engineering | 上下文工程 | 通过磁盘持久化、渐进加载和任务状态管理，使 agent 在有限上下文中保持稳定。 |
| contract account | 合约账户 | Ethereum 中由 bytecode 控制、拥有 storage、不能主动发起交易的账户。 |
| convergence opportunity | 收敛机会 | 诚实网络有机会看到并延长同一个区块、重新统一链视图的时机。 |
| CP/CG/CQ | Common Prefix / Chain Growth / Chain Quality | 教材用来分别刻画安全性、活性和诚实区块密度的三种链性质。 |
| critic | 批评者/审查者 | 独立检查 agent 输出、寻找反例并要求证据的角色。 |
| cryptographic agility | 密码系统敏捷性 | 系统可以在底层算法被削弱或过时后迁移到新的密码算法。 |
| cryptographic primitive | 密码学原语 | 哈希、签名、承诺、伪随机函数等可组合的基础密码工具。 |
| Cypherpunk | 密码朋克 | 主张用密码学保护数字时代个人隐私和自由的运动与思想群体。 |

## D

| Term | 中文释义 | 课程语境 |
|---|---|---|
| DA layer | 数据可用性层 | 专门为 Rollup 或应用保存并提供批量数据的外部层。 |
| DAG | 有向无环图 | Directed Acyclic Graph；多个区块可并行引用多个父节点的结构。 |
| DAO | 去中心化自治组织 | 由智能合约、token 投票和治理规则共同管理的组织。 |
| data availability | 数据可用性 | 其他节点能否取得足够交易数据以重建状态、验证或退出。 |

| DeFi | 去中心化金融 | Decentralized Finance，用智能合约实现交易、借贷、稳定币、质押等金融功能。 |
| delegatecall | 委托调用 | Ethereum 中执行另一个合约的代码，但使用当前合约的 storage 和调用上下文。 |
| deterministic finality | 确定性最终性 | 达到共识条件后，除非突破协议假设，否则结果不可逆。 |
| DEX | 去中心化交易所 | Decentralized Exchange，用户直接与智能合约或流动性池交易的交易所。 |

| difficulty | 难度 | PoW 中衡量找到有效哈希所需计算工作的参数；目标越低通常越难。 |
| digital signature | 数字签名 | 用私钥证明消息由控制者授权，并允许他人用公钥验证。 |
| Dolev-Strong | Dolev-Strong 协议 | 在同步网络中通过多轮签名链实现拜占庭广播的协议。 |
| double spending | 双重支付/双花 | 同一个 UTXO 或价值被两笔冲突交易同时花费。 |
| dynamic availability | 动态可用性 | 参与者和网络状态变化时，系统仍尝试持续提供服务。 |

## E

| Term | 中文释义 | 课程语境 |
|---|---|---|
| ECDH | 椭圆曲线 Diffie–Hellman | 用双方密钥计算共享秘密；隐身地址常用它派生一次性支付地址。 |
| ECDSA | 椭圆曲线数字签名算法 | Bitcoin 等系统使用的数字签名方案之一。 |
| eclipse attack | 日蚀攻击 | 攻击者控制节点的邻居，使它看不到诚实网络和真实链视图。 |
| EIP | Ethereum 改进提案 | Ethereum Improvement Proposal，描述协议、标准或应用接口变化。 |
| EIP-1559 | Ethereum 费用机制升级 | 将费用分为 base fee 与 priority fee，并销毁 base fee。 |
| EIP-4844 | Ethereum blob 交易提案 | 为 Rollup 提供临时 blob 数据空间，降低 L2 数据发布成本。 |
| EOA | 外部拥有账户 | Externally Owned Account，由私钥控制、可以主动发起 Ethereum 交易的账户。 |
| epoch | 纪元 | 区块链协议中的一段固定轮次；Ethereum 一个 epoch 包含多个 slot。 |
| equivocation | 模棱两可/双重投票 | 同一节点对互相冲突的值或区块同时签名、投票或发送不同说法。 |
| ERC | Ethereum 请求评论 | Ethereum Request for Comments，偏应用层接口和 token 标准。 |
| ERC-20 | 同质化 token 标准 | 定义 totalSupply、balanceOf、transfer、approve、allowance 等接口。 |
| escape hatch | 逃生口 | Rollup 或桥在协调者故障、审查时允许用户直接通过 L1 退出或强制执行。 |
| evidence-first execution | 证据优先执行 | 每个实现步骤都同时产出 diff、测试、日志或可复核结果。 |
| EVM | Ethereum Virtual Machine，以太坊虚拟机 | 所有 Ethereum 节点按确定性规则执行智能合约代码的虚拟机。 |
| execution layer | 执行层 | Ethereum 中按交易执行 EVM 代码、更新状态的部分。 |
| existential unforgeability | 存在性不可伪造 | EUF；即使可请求任意消息签名，攻击者也不能伪造未请求消息的有效签名。 |
| external call | 外部调用 | 一个合约向另一个合约发送消息；调用时 msg.sender 等上下文会发生变化。 |
| externally verified bridge | 外部验证桥 | 由外部委员会、多签或专门验证者观察源链并向目标链证明事件的桥。 |

## F

| Term | 中文释义 | 课程语境 |
|---|---|---|
| fair ordering | 公平排序 | 试图限制区块生产者任意利用交易顺序获利的排序规则。 |
| fallback | 回退函数 | Solidity 中无法匹配 selector 或没有 data 时可能进入的函数。 |
| fee market | 手续费市场 | 区块空间稀缺时，用户通过手续费竞争被打包优先级的市场。 |
| Fiat–Shamir | Fiat–Shamir 变换 | 用承诺的哈希替代 verifier 的随机 challenge，把交互式证明变成非交互式证明。 |
| finality | 最终性 | 某个交易、区块或状态不再被合法历史替代的程度。 |
| flash loan | 闪电贷 | 在一笔原子交易内借款并必须在交易结束前归还的无抵押贷款。 |
| Flashbots | MEV 基础设施 | 连接 searcher、builder 和 proposer，帮助构建和提交 MEV 区块的生态。 |
| flooding | 泛洪传播 | 节点把消息转发给多个邻居，使消息在 P2P 网络扩散。 |
| FLP | FLP 不可能性结果 | 纯异步系统中即使只有一个 crash fault，也无法同时保证确定性共识的安全和活性。 |
| forced inclusion | 强制包含 | 用户把交易放入 L1 queue，迫使 sequencer 或系统在期限内处理。 |
| fork | 分叉 | 节点暂时或永久采用不同区块历史或协议规则的情况。 |
| fork choice | 分叉选择规则 | 节点在多个有效链或分支之间选择当前链头的方法。 |
| fraud proof | 欺诈证明 | Optimistic Rollup 中证明某个已提交状态转移无效的证据。 |
| FRI | Fast Reed–Solomon IOPP | STARK 使用的多项式低次数测试协议。 |
| front-running | 抢跑 | 攻击者观察到待处理交易后，先提交自己的交易以利用价格或状态变化。 |
| FROST | 阈值 Schnorr 签名协议 | 通过分布式密钥生成实现多方共同签名，避免单一 dealer。 |
| full node | 全节点 | 保存并验证区块链完整规则和当前状态的节点。 |
| function selector | 函数选择器 | Ethereum calldata 开头的 4 字节，用于指示要调用的合约函数。 |
| fungibility | 可互换性 | 同种资产的每个单位在价值和使用上尽量等价，不因历史来源不同而被区别对待。 |

| Term | 中文释义 | 课程语境 |

## 易混词对照

| 容易混淆 | 区别 |
|---|---|
| address / account | address 是标识或收款目标；account 是链上账户状态对象。 |
| anonymity / pseudonymity | anonymity 难以知道真实身份；pseudonymity 只是用地址或公钥代替姓名，仍可能被关联。 |
| APY / APR | APY 包含复利；APR 通常是简单年化。 |
| availability / data availability | availability 是系统能否响应；data availability 是交易或状态数据能否被他人取得和重建。 |
| block reward / transaction fee | block reward 是区块奖励；transaction fee 是用户为交易支付的费用。 |
| commitment / proof | commitment 先隐藏并绑定一个值；proof 证明某个命题成立。 |
| consensus / execution | consensus 决定顺序或结果；execution 按该顺序执行状态机。 |
| gas limit / gas used | gas limit 是允许的上限；gas used 是实际使用量。 |
| hash / encryption | hash 通常不可逆且无密钥解密；encryption 依靠密钥加密并可解密。 |
| light client / pruned node | light client 不验证或保存完整历史；pruned node 通常验证过完整链，只裁剪历史存储。 |
| Merkle root / Merkle proof | root 是整体承诺；proof 是证明某个叶子属于该承诺的路径。 |
| nonce in PoW / nonce in account | PoW nonce 用来反复试哈希；账户 nonce 用来防重放并保证交易顺序。 |
| optimistic rollup / validity rollup | Optimistic 默认正确、靠 fraud proof；validity rollup 先生成 validity proof。 |
| PoW / PoS | PoW 以算力和电力获得出块权；PoS 以质押资本获得投票权。 |
| privacy / security | privacy 关注信息泄露；security 关注伪造、盗取、篡改和不可用。 |
| prover / verifier | prover 生成证明；verifier 检查证明。 |
| safety / liveness | safety 要求坏事不发生；liveness 要求好事最终发生。 |
| stake / slashing | stake 是被锁定的资本；slashing 是对恶意行为罚没 stake。 |
| state root / transaction root | state root 承诺全局账户/存储状态；transaction root 承诺区块中的交易集合。 |
| stealth address / ring signature | stealth address 隐藏收款者关联；ring signature 隐藏发送者。 |
| token / coin | token 通常由合约表示；coin 在 Bitcoin 数据模型中通常对应可花费 UTXO。 |
| trusted setup / transparent setup | trusted setup 需要可信仪式和秘密销毁；transparent setup 不依赖秘密设置。 |
| UTXO / balance | UTXO 是可花费的具体输出；balance 是所有可花费 UTXO 的金额总和。 |
| validity proof / fraud proof | validity proof 在接受前证明正确；fraud proof 在接受后挑战错误。 |
| watchtower / watcher | watchtower 特指支付通道监控服务；watcher 更广泛，也可监控 Rollup 和共识。 |
| ZKP / ZK-SNARK | ZKP 是总类；ZK-SNARK 是其中一种短、非交互、快速验证的具体系统。 |

## 词汇学习建议

1. 先背每个词的中文释义，再用“课程语境”把它放回机制中。
2. 优先掌握易混词：UTXO/account、PoW/PoS、safety/liveness、validity/fraud proof、privacy/security。
3. 对缩写至少记住英文全称：BFT、SMR、MPC、NIZK、R1CS、QAP、HTLC、MEV、TVL。
4. 复习时用一条因果链串词：

~~~text
UTXO → double spending → consensus → block → PoW/PoS
→ Merkle proof → light client → privacy commitment → ZKP
→ payment channel / bridge / Rollup
~~~

5. Tutorial 3 的词汇要和工程动作一起记：

~~~text
spec → plan → tasks → implement → critic → evidence
~~~

这份词表覆盖了 Lecture 和 Tutorial 讲义中的主要技术生词，后续遇到新术语时可以继续按对应首字母补充。
