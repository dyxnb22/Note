# Lecture 1A：加密货币基础、账本革命与 Bitcoin 运行机制

## 1A.1 Cypherpunk 与 Bitcoin 的出发点

早期 Cypherpunk 运动由密码学家、程序员和活动人士组成，核心观点是：数字时代的隐私应由个人通过密码学保护，而不是依赖政府或公司“承诺”不滥用权力。其常见原则包括：

- **隐私是选择性披露**：个人可以决定向谁披露哪些信息；
- **密码学赋能个人**：强密码工具使个人无需请求许可即可保护通信和资产；
- **去中心化减少单点控制**：分布式系统挑战单一机构的审查和监控。

PGP、Tor 和 Bitcoin 都受这一愿景影响。Bitcoin 的目标不是把银行网页搬到网上，而是创建一种无需可信中央机构的数字现金。

## 1A.2 数字现金的核心难题：双重支付

纸币具有物理稀缺性：Alice 把一张 100 美元纸币交给 Bob 后，Alice 手里不再有同一张纸币。数字文件却可以完美复制。若“100 coins”只是一个文件，Alice 可以把同一份文件同时发给 Bob 和 Carol。

这就是 **double spending（双重支付）**：同一份数字价值被花费两次。传统方案让银行维护唯一真账本；银行检查余额、顺序处理转账，并决定是否接受交易。Bitcoin 的问题是：

> 能否在没有银行的情况下，让互不信任的节点对“哪一笔交易先发生”形成共同判断？

历史上的 DigiCash 依赖中央机构，b-money 停留在理论层面，Bit Gold 没有解决完整的共识机制。Bitcoin 在 2008 年把已有的哈希、数字签名、P2P 网络、工作量证明和最长链规则组合成了第一个实用的无许可数字货币系统。

## 1A.3 从单式、复式到三式记账

可以用三种记账方式理解 Bitcoin 的思想：

| 记账方式 | 典型场景 | 谁验证 | 主要信任对象 |
|---|---|---|---|
| 单式记账 | 个人记自己的账 | 自己 | 自己 |
| 复式记账 | 银行或机构 | 机构内部系统 | 银行和制度 |
| 三式记账 | Bitcoin 式公开账本 | 网络中的每个节点 | 密码学、共识和公开证据 |

在复式记账中，Alice 的账减少 1 BTC，Bob 的账增加 1 BTC，银行作为账本管理员保证两边一致。三式记账增加了第三份记录：一张带签名、公开可验证、按顺序写入区块链的密码学收据。这样，Alice 的记录、Bob 的记录和公共链上的记录相互对应。

优点是任何人都能验证，且没有一个机构可以悄悄修改账本或任意冻结交易；代价是每个节点重复保存和验证，带来吞吐量、存储、能源和隐私成本。

## 1A.4 哈希函数

哈希函数把任意长度的数据映射成固定长度输出：

```text
h = H(m)
```

Bitcoin 大量使用 SHA-256；输出通常表示为 256 位。哈希不是加密：加密可以用密钥解密，哈希通常只有从输入到输出的单向计算。

重要性质：

1. **Preimage resistance（原像抗性）**：给定 h，很难找到任意 m 使 `H(m)=h`。
2. **Second-preimage resistance（第二原像抗性）**：给定 m1，很难找到不同的 m2 使 `H(m2)=H(m1)`。
3. **Collision resistance（抗碰撞性）**：很难主动找到任意不同的 m1、m2 使两者哈希相同。
4. **Avalanche effect（雪崩效应）**：输入改动一位，输出应看起来完全不同。
5. **可快速计算、易验证**：大家可以快速重算，但没有捷径反推输入。

三个抗性不要混淆：第二原像是“给定一个已有消息，找另一个匹配它”；碰撞是“随便找一对匹配的消息”。

哈希在 Bitcoin 中的用途：交易 ID、区块连接、Merkle root、地址生成和挖矿工作量证明。

## 1A.5 Merkle 树：少量数据证明大集合成员资格

如果一个区块有成千上万笔交易，轻客户端不应下载全部交易才能验证某一笔交易是否在区块中。Merkle 树把交易哈希两两合并，层层计算到一个根：

```text
H1 = H(T1), H2 = H(T2), ...
H12 = H(H1 || H2)
H34 = H(H3 || H4)
MerkleRoot = H(H12 || H34)
```

要证明 T2 在树中，服务器只需提供 T2、它在各层的兄弟节点以及区块头中的 root。客户端沿路径重新计算，若结果等于 root，便相信该交易被该区块承诺。证明大小是 `O(log n)`，而不是 `O(n)`。

Merkle root 只证明“这笔交易属于这个承诺的集合”，不自动证明交易有效；交易是否有效仍需按协议规则验证。

## 1A.6 区块链：Merkle 树加哈希指针

每个区块头主要承诺：

- 前一个区块的哈希；
- 本区块交易的 Merkle root；
- 时间戳、难度、nonce 等字段。

```text
Block 1 --hash--> Block 2 --hash--> Block 3 --hash--> Block 4
```

如果攻击者修改 Block 2，Block 3 中记录的前块哈希就不再匹配，后续所有链接都断裂。因此区块链提供的是**篡改可检测性**，不是“任何篡改在物理上不可能”。攻击者仍可以尝试重算后续工作量证明，但成本通常极高。

## 1A.7 公钥密码学与数字签名

Bitcoin 使用椭圆曲线密码学（课件使用 secp256k1 作为示例）：

```text
随机生成私钥 sk
公钥 pk = sk · G
地址 A = Encode(Hash160(pk))
```

从私钥计算公钥容易，从公钥反推出私钥在经典计算机上应当不可行。私钥是控制权；公钥可以公开。

数字签名流程：

1. `KeyGen()` 生成 `(sk, pk)`；
2. `σ = Sign(sk, message)`；
3. `Verify(pk, message, σ)` 返回真或假。

签名提供认证、授权和不可否认性：只有私钥持有者能授权花费，任何人都能验证交易未被修改。签名本身不提供隐私；地址和交易图仍然可以公开。

课件比较了 ECDSA 与 Schnorr：Schnorr 签名固定大小且具有线性结构，适合 MuSig 等多签聚合，Taproot 采用了 Schnorr 体系。量子计算方向上，Shor 算法理论上会破坏 ECDSA/Schnorr 的离散对数假设，因此密码系统需要具备 crypto-agility，并关注后量子签名迁移。

## 1A.8 Bitcoin 交易的生命周期

一笔交易大致经历：

1. 钱包选择可花费的 UTXO；
2. 组装输入、输出、找零和手续费；
3. 用对应私钥签名；
4. 通过 P2P gossip 广播；
5. 各节点检查签名、UTXO 是否存在且未花费、输入是否足以覆盖输出；
6. 合法交易进入各节点自己的 mempool；
7. 矿工选择交易，打包成区块并解决 PoW；
8. 其他节点验证区块并继续传播；
9. 后续区块增加确认深度。

Bitcoin 交易大致包含版本、输入、输出和 locktime。手续费近似为：

```text
fee = sum(inputs) - sum(outputs)
```

## 1A.9 P2P 网络、mempool 和手续费市场

Bitcoin 没有中心服务器，节点组成类似 BitTorrent 的去中心化网状网络。交易被节点验证后向邻居转发，形成受控 flooding/gossip。

每个节点有自己的 mempool，它是“已看到但尚未进入区块链”的交易集合，而不是共识状态的一部分。不同节点的 mempool 可以暂时不同。区块空间稀缺，所以手续费形成类似网络 QoS 的优先级：

```text
fee = transaction_size × fee_rate
```

Bitcoin 常用 sat/vByte 表示 fee rate。拥堵时，交易提高 fee rate 才更可能被矿工选中。RBF（Replace-By-Fee）允许使用相同输入、提高手续费的替代交易替换原来卡住的交易，前提是原交易表明允许替换并满足相关规则。

## 1A.10 Nakamoto consensus 与 Proof-of-Work

核心问题是：谁决定 mempool 中哪些交易先进入账本？Nakamoto consensus 由三部分组成：

1. **PoW 提供 Sybil resistance**：成为区块提议者需要消耗真实算力，而不是创建大量免费身份；
2. **最长链/最重链规则**：节点选择累计工作量最多的有效链；
3. **经济激励**：区块奖励和手续费使诚实挖矿有利可图。

PoW 要求找到 nonce，使：

```text
H(block_header) < target
```

寻找很难，只能反复尝试；验证很容易，只需一次哈希。难度每 2016 个区块调整，使平均出块时间保持在约 10 分钟附近。挖矿的“随机性”意味着下一位矿工不可预测，获得区块的概率大致与其算力占全网算力的比例相关。

### 1A.10.1 区块、coinbase 与分叉

矿工找到有效 nonce 后广播区块。区块第一笔交易是 coinbase transaction，用于支付区块补贴和手续费；它是新 BTC 进入流通的方式。Bitcoin 的供应上限设计为 2100 万枚，区块补贴按大约四年周期减半。

两个矿工可能同时发现区块，导致短暂分叉。节点继续在累计工作量更高的分支上挖矿，另一分支被抛弃，其中交易回到 mempool。因而 Bitcoin 的最终性是**概率性的**：确认越深，被反转的概率越低，但协议层面通常不说绝对不可逆。

### 1A.10.2 安全性、活性与 51% 攻击

- **Safety/persistence**：已确认的交易不会出现两份相互冲突的“最终历史”；
- **Liveness**：合法交易最终有机会被打包，链不会永久停止。

若攻击者控制超过约一半的有效挖矿能力，可以尝试私下挖更长的链并进行双花。但 51% 攻击不能凭空窃取别人私钥、不能直接创造超出规则的 BTC，也不能单方面修改所有节点都不接受的新规则。攻击通常只能重排相对近期的区块，而且会损害攻击者持有资产的价值。

### 1A.10.3 矿池与节点

单个小矿工可能很久才独立挖到一个区块，因此矿工加入矿池，按贡献的算力分享收益。矿池降低收益方差，却造成算力集中风险；Stratum V2 等设计尝试让个人矿工而不是矿池运营者选择交易。

节点类型包括：

- Full node：保存并验证完整规则；
- Mining node：在完整验证基础上寻找 PoW；
- SPV/light client：主要保存区块头，依赖 Merkle proof；
- Pruned node：验证全链但只保留部分历史数据。

### 1A.10.4 课件中的 2026 网络快照

课件用约 1 ZH/s 的哈希率、约 745 GB 链大小、约 2.45 万公共可达节点、区块奖励 3.125 BTC 等数量级帮助建立直觉。这些数字的作用是说明系统规模：每一个节点都在重复执行验证，PoW 需要大量真实资源，账本会持续增长。

## 1A.11 本讲核心总结

```text
Hash      -> 防篡改、PoW、ID、Merkle
Signature -> 证明授权，但不等于隐私
Merkle    -> 用 O(log n) 证明集合成员资格
P2P       -> 无中心传播
PoW       -> 把“谁有投票权”绑定到真实算力
Longest chain -> 让网络在分叉后收敛
Economics -> 让诚实行为比攻击更理性
```
