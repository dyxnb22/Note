## J251｜Redis Pipeline 解决什么问题？

> 题类：Redis · 来源：[[Learning/Backend/Data/Redis#Redis Pipeline 解决什么问题？|原题与完整答案]]

**30 秒口述答案**

## J253｜Redis 如何保证原子性？事务、Lua 和 WATCH 有什么区别？

> 题类：Redis · 来源：[[Learning/Backend/Data/Redis#Redis 如何保证原子性？事务、Lua 和 WATCH 有什么区别？|原题与完整答案]]

## J256｜过期删除和内存淘汰有什么区别？

## J257｜Redis 的过期 key 会立即删除吗？

> 题类：Redis · 来源：[[Learning/Backend/Data/Redis#Redis 的过期 key 会立即删除吗？|原题与完整答案]]

**30 秒口述答案**

不会。Redis 采用两种方式：惰性删除：访问 key 时检查 TTL，发现过期后再删除。定期删除：周期性抽样过期字典，清理过期 key，并限制单次清理时间。这样可以避免大量 key 同时过期时集中消耗 CPU，但冷数据过期后可能暂时占用内存。

## J261｜Redis Cluster 是怎么分片和路由的？

> 题类：Redis · 来源：[[Learning/Backend/Data/Redis#Redis Cluster 是怎么分片和路由的？|原题与完整答案]]

## J262｜Redis 主从和 Cluster 能保证强一致性吗？

> 题类：Redis · 来源：[[Learning/Backend/Data/Redis#Redis 主从和 Cluster 能保证强一致性吗？|原题与完整答案]]

## J299｜大文件上传如何支持断点续传和秒传？

> 题类：系统设计 · 来源：[[Learning/Backend/Architecture/01_系统设计#大文件上传如何支持断点续传和秒传？|原题与完整答案]]

**30 秒口述答案**

不要让一次 HTTP 请求承载整个文件，采用“文件标识 + 分片 + 合并”的流程：客户端按固定大小切片，生成文件 hash 和分片序号。服务端先查询文件 hash；全部分片已存在则直接秒传，否则返回未完成分片列表。客户端只补传缺失分片，可并发上传；服务端按文件标识和分片号幂等保存。所有分片上传完成后合并，并校验最终 hash、大小和格式，再更新文件状态。
