## J003｜Java 是编译型语言还是解释型语言？

> 题类：Java 语言与运行时 · 来源：[[Learning/Backend/Java/面试题库/01_语言与运行时#Java 是编译型语言还是解释型语言？|原题与完整答案]]

## J005｜为什么金额计算使用 BigDecimal，而不是 double？

> 题类：Java 语言与运行时 · 来源：[[Learning/Backend/Java/面试题库/01_语言与运行时#为什么金额计算使用 BigDecimal，而不是 double？|原题与完整答案]]

`double` 是二进制浮点数，无法精确表示很多十进制小数，例如 `0.1`，可能产生精度误差。`BigDecimal` 使用任意精度的十进制表示，适合金额等精确计算。创建 `BigDecimal` 时优先使用字符串或 `BigDecimal.valueOf()`。

## J020｜Java 对象什么时候会被回收？

> 题类：Java 语言与运行时 · 来源：[[Learning/Backend/Java/面试题库/01_语言与运行时#Java 对象什么时候会被回收？|原题与完整答案]]

**30 秒口述答案**

主流 JVM 通过可达性分析判断对象是否仍然存活，而不是简单依赖引用计数。从 GC Roots 沿引用链查找对象。不可达对象具备被回收的条件，但不保证立即回收。强引用通常不会被回收；软引用内存不足时可能回收；弱引用在下一次 GC 时通常回收；虚引用用于跟踪回收。常见 GC Roots 包括虚拟机栈局部变量、类静态字段、常量引用和 JNI 引用。`finalize()` 不推荐使用，资源应通过显式关闭或 `try-with-resources` 管理。

## J046｜虚拟线程改善什么，不能解决什么？

**30 秒口述答案**

Java 21 虚拟线程降低大量阻塞式 I/O 任务的线程创建和调度成本，使“一个请求一个线程”的代码更容易扩展。它不提升 CPU 密集计算，也不会消除数据库连接、下游并发和内存等资源上限。使用虚拟线程仍要限制外部并发，并检查 `synchronized`、本地调用等可能导致载体线程固定的问题。

## J049｜Collection 和 Collections 有什么区别？

## J050｜集合使用有哪些常见陷阱？

> 题类：集合与容器 · 来源：[[Learning/Backend/Java/面试题库/03_集合与容器#集合使用有哪些常见陷阱？|原题与完整答案]]

**30 秒口述答案**

`Arrays.asList(array)` 返回的是数组的定长视图：可以 `set()`，但不能 `add()`/`remove()`；需要可变列表时使用 `new ArrayList<>(Arrays.asList(array))`。遍历时删除元素使用 `Iterator.remove()` 或 `removeIf()`，不要直接调用集合的 `remove()`；否则可能触发 `ConcurrentModificationException` 或跳过元素。
