## A001｜什么是 Agent？与普通 LLM Chat、Workflow、RPA 和传统后端服务有什么区别？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#1. 什么是 Agent？与普通 LLM Chat、Workflow、RPA 和传统后端服务有什么区别？|原题与完整答案]]

**30 秒口述答案**

Agent 是围绕目标运行的有限循环：读取状态，让模型提出下一步，校验并执行动作，再根据结果继续或结束。普通 Chat 主要生成一次回复，Workflow 的路径预先确定，RPA (**机器人流程自动化**)按固定规则操作；Agent 的部分路径由模型根据中间结果动态决定，但权限、事实和成功判定仍应由代码控制。

## A002｜Agent 的最小闭环是什么？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#2. Agent 的最小闭环是什么？|原题与完整答案]]

**30 秒口述答案**

目标 → 读取当前状态 → 模型决定下一步 → 校验/授权 → 执行工具 → 回填结果 → 判断继续或结束。**最小闭环必须有预算上限和明确停止原因**，否则只是一个可能无限循环的模型调用。

## A004｜Agent 如何理解任务、制定计划、调用工具、观察结果并结束任务？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#4. Agent 如何理解任务、制定计划、调用工具、观察结果并结束任务？|原题与完整答案]]

**30 秒口述答案**

## A005｜Agent 的自主性体现在哪里？自主性越强一定越好吗？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#5. Agent 的自主性体现在哪里？自主性越强一定越好吗？|原题与完整答案]]

## A006｜什么场景适合 Agent，什么场景应该使用确定性的 Workflow？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#6. 什么场景适合 Agent，什么场景应该使用确定性的 Workflow？|原题与完整答案]]

**30 秒口述答案**

步骤固定、输入输出稳定、合规要求高的流程优先 Workflow；目标明确但路径取决于检索、工具结果或环境反馈的任务才适合 Agent。通常先做 Workflow 基线，只有动态性带来可测量的成功率或覆盖率收益时才引入 Agent。

**深挖追问**

- 这个场景判断成立的前提和不适用边界分别是什么？

## A007｜Agent 系统中哪些部分应该由模型决定，哪些部分应该由代码决定？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#7. Agent 系统中哪些部分应该由模型决定，哪些部分应该由代码决定？|原题与完整答案]]

**30 秒口述答案**

模型适合做意图理解、候选计划、工具选择和自然语言生成；代码应负责权限、参数校验、状态持久化、预算、幂等、沙箱、成功判定和审计。凡是不可逆副作用和安全边界，都不能只依赖 Prompt。

## A011｜ReAct 是什么？Reasoning、Action、Observation 如何循环？

## A012｜Agent Loop 在什么条件下继续执行、什么条件下结束？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#12. Agent Loop 在什么条件下继续执行、什么条件下结束？|原题与完整答案]]

## A013｜Plan-and-Execute 与 ReAct 有什么区别？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#13. Plan-and-Execute 与 ReAct 有什么区别？|原题与完整答案]]

**30 秒口述答案**

## A016｜Planner、Executor、Critic 分别负责什么？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#16. Planner、Executor、Critic 分别负责什么？|原题与完整答案]]

## A021｜长任务应该一次性规划还是边执行边规划？为什么？

> 题类：Agent 基础与架构 · 来源：[[Learning/Agent面试题库/01_基础架构/Agent基础与架构#21. 长任务应该一次性规划还是边执行边规划？为什么？|原题与完整答案]]

**30 秒口述答案**

通常采用分阶段规划：先得到粗粒度计划，执行到检查点后根据事实细化。一次性计划容易被环境变化打破，完全逐步规划又会增加调用和震荡；分阶段方式更容易控制成本、恢复和审计。

**深挖追问**

- 这个结论背后的关键机制是什么？
- 这个结论依赖哪些前提，什么情况下不再成立？
- 如何用可观察证据证明原因，而不是只凭经验判断？

## A045｜如何设计上下文的优先级？哪些内容必须保留，哪些内容可以丢弃？

> 题类：Prompt 与 Context Engineering · 来源：[[Learning/Agent面试题库/02_Prompt与上下文/Prompt与Context Engineering#15. 如何设计上下文的优先级？哪些内容必须保留，哪些内容可以丢弃？|原题与完整答案]]

**30 秒口述答案**

安全规则、当前目标、未完成任务、关键状态和成功标准优先；重复对话、已验证且可重新查询的中间结果、低相关检索块可以压缩或丢弃。优先级应由任务和风险决定，而不是简单按时间截断。

**深挖追问**

- 这套设计的核心组件、状态和完整执行链路是什么？
- 流量、数据量或失败率上升时，哪个边界最先成为瓶颈？
- 上线前如何验证正确性、可靠性和降级路径？

## A046｜如何避免上下文污染？

> 题类：Prompt 与 Context Engineering · 来源：[[Learning/Agent面试题库/02_Prompt与上下文/Prompt与Context Engineering#16. 如何避免上下文污染？|原题与完整答案]]

**30 秒口述答案**

把系统规则、用户请求、外部数据和工具结果分区并标注来源，检索内容默认视为不可信数据；进入 Context 前做权限过滤、长度限制和敏感信息处理。不要让外部文本获得系统指令地位，关键约束在执行层重复检查。

## A047｜如何让模型只读取当前任务相关的历史信息？

> 题类：Prompt 与 Context Engineering · 来源：[[Learning/Agent面试题库/02_Prompt与上下文/Prompt与Context Engineering#17. 如何让模型只读取当前任务相关的历史信息？|原题与完整答案]]

## A050｜两个 Skill 内容不同但 Description 相似，Agent 经常选错，如何解决？

> 题类：Prompt 与 Context Engineering · 来源：[[Learning/Agent面试题库/02_Prompt与上下文/Prompt与Context Engineering#20. 两个 Skill 内容不同但 Description 相似，Agent 经常选错，如何解决？|原题与完整答案]]

**30 秒口述答案**

让 Description 增加互斥的适用条件、输入类型、输出和明确的“不适用”例子，并在路由阶段先分类再给模型小候选集。对高风险或易混淆工具加确定性前置校验和回归题，必要时合并为一个带分支的 Skill。
