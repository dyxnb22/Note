## A101｜SSE 与 Streamable HTTP 有什么区别？

> 题类：Tool Calling 与 MCP · 来源：[[Learning/Agent面试题库/04_Tool与协议/Tool Calling与MCP#26. SSE 与 Streamable HTTP 有什么区别？|原题与完整答案]]

**30 秒口述答案**

SSE 是服务端向客户端推送事件的流式通道，适合单向进度/结果传递；Streamable HTTP 是面向远程协议交互的 HTTP 流式传输形态，可承载更完整的请求响应和会话语义。实际选型要以协议版本和客户端能力为准，不能只看“能不能流式”。

## A102｜MCP 返回结果如何流式传递？

> 题类：Tool Calling 与 MCP · 来源：[[Learning/Agent面试题库/04_Tool与协议/Tool Calling与MCP#27. MCP 返回结果如何流式传递？|原题与完整答案]]

**30 秒口述答案**

Transport 传递进度或增量事件，Client 负责关联调用 ID、处理取消、限速、结果拼接和最终状态；模型 Context 不应每个 token 都无条件回填。对用户推送的进度和用于模型决策的最终结构化结果应分开。

## A103｜没有 MCP 时，大模型调用工具的完整流程是什么？

> 题类：Tool Calling 与 MCP · 来源：[[Learning/Agent面试题库/04_Tool与协议/Tool Calling与MCP#28. 没有 MCP 时，大模型调用工具的完整流程是什么？|原题与完整答案]]

**30 秒口述答案**

应用本地注册工具并把 Schema 传给模型，模型返回 ToolCall，应用校验/授权/执行后回填 ToolResult，再继续 Loop。MCP 主要把发现和调用的能力合同抽到可复用的 Server/Client 边界，并没有改变这条执行逻辑。

## A105｜MCP 工具如何做超时、重试和取消？

> 题类：Tool Calling 与 MCP · 来源：[[Learning/Agent面试题库/04_Tool与协议/Tool Calling与MCP#30. MCP 工具如何做超时、重试和取消？|原题与完整答案]]

**30 秒口述答案**

## A106｜A2A 解决了什么问题？什么时候应该用 A2A？

**30 秒口述答案**

A2A 主要用于 Agent 之间发现能力、委派任务、传递状态和结果，适合跨团队/跨系统的 Agent 协作；同一应用内部的函数或工具不必先引入 A2A。使用前要明确任务合同、身份、权限、进度、超时、回退和结果可信度。
