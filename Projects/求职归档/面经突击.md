## 面向对象有哪些设计原则？

- 单一职责原则：一个类尽量只负责一类职责。
- 开放封闭原则：对扩展开放，对修改封闭。
- 里氏替换原则：子类应能替换父类而不破坏程序正确性。
- 接口隔离原则：**接口应该小而专**，客户端不依赖不需要的方法。
- 依赖倒置原则：高层和低层都**依赖抽象**，细节依赖抽象。
- 最少知识原则：对象**只与必要的直接对象交互**。

## Comparable 和 Comparator 有什么区别？如何定义多字段排序？

| | `Comparable` | `Comparator` |
| --- | --- | --- |
| 定义位置 | **类内部**，实现接口 | **类外部**，独立比较器 |
| 方法 | `compareTo(T o)` | `compare(T o1, T o2)` |
| 排序含义 | **自然排序**（类天生的排序能力） | **定制排序**（外部指定规则） |
| 典型场景 | `Student implements Comparable<Student>` | `Collections.sort(list, comparator)` |

**笔试结论：** 如果希望一个类天然具有排序能力（比如放进 `TreeSet` / `TreeMap` 自动有序），就让它实现 **`Comparable`**；需要其他排序规则时，用 `Comparator` 在类外定义。

```java
import java.util.Comparator;

class Student implements Comparable<Student> {
    private int id;
    private int score;
    private String name;

    @Override
    public int compareTo(Student other) {
        int byScore = Integer.compare(other.score, score); // 分数降序
        return byScore != 0 ? byScore : Integer.compare(id, other.id); // 学号升序
    }

    public String getName() { return name; }
}

class StudentSortExample {
    static final Comparator<Student> byName = Comparator.comparing(Student::getName);
}
```

这里 `Comparable` 定义了分数降序、学号升序的自然顺序；按姓名等其他规则排序时，可以使用外部 `Comparator`，不必把所有规则都写进 `compareTo()`。

## ArrayList 如何扩容？
现代 JDK 中无参构造通常**先使用空数组**，第一次添加元素时再分配默认容量；容量不足时创建更大的数组并复制旧元素，常见实现是扩容为原容量的**约 1.5 倍**。

## ConcurrentSkipListMap 和 ConcurrentSkipListSet 适合什么场景？

- `ConcurrentSkipListMap`：基于**跳表**的线程安全有序 Map。
- `ConcurrentSkipListSet`：基于 `ConcurrentSkipListMap` 的线程安全有序 Set。

如果既需要**并发安全又需要按 key 或元素排序**，可以考虑它们；如果只需要高并发无序 Map，通常优先 `ConcurrentHashMap`。

## Queue 的 poll/peek 和 remove/element 有什么区别？

Queue 为同一操作提供两套方法：

| 方法          | 作用     | 队列为空时                      | 队列已满时（仅限有界队列）             |
| ----------- | ------ | -------------------------- | ------------------------- |
| `poll()`    | 出队     | 返回 `null`                  | 返回 `null`                 |
| `remove()`  | 出队     | 抛 `NoSuchElementException` | 抛 `IllegalStateException` |
| `peek()`    | 查看队头元素 | 返回 `null`                  | —                         |
| `element()` | 查看队头元素 | 抛 `NoSuchElementException` | —                         |
| `offer()`   | 入队     | 入队，返回 `true`               | 返回 `false`（不抛异常）          |
| `add()`     | 入队     | 入队，返回 `true`               | 抛 `IllegalStateException` |


## 方法区和元空间是什么关系？

方法区是 JVM 规范中的**逻辑区域**，元空间是 HotSpot 对它的一种**实现**：

- JDK 7 及以前主要**使用永久代实现**。
- JDK 8 移除永久代，**改用本地内存中的元空间**。

## 对象创建过程是什么？

1. **类加载检查**：检查类是否已加载、解析和初始化，必要时先触发类加载。
2. **分配内存**：在堆中分配空间，多线程下用 TLAB 或 CAS 保证安全。
3. **初始化零值**：将字段设为**类型默认值**（0、null、false）。
4. **设置对象头**：写入 Mark Word、类型指针、GC 年龄等。
5. **执行 `<init>`**：执行构造方法，完成 Java 层面的初始化。

## 对象的内存布局是什么？

HotSpot 普通对象通常包括：

| 部分   | 内容                             |
| ---- | ------------------------------ |
| 对象头  | Mark Word、类型指针；数组对象还包含**数组长度** |
| 实例数据 | 对象自身及父类的字段                     |
| 对齐填充 | 按对象对齐要求补齐的空间                   |

Mark Word 会根据对象状态保存**哈希码、GC 年龄和锁状态**等信息。压缩类指针和压缩普通对象指针也会影响对象头大小。


## 常见 GC Roots：

- 虚拟机栈中的**局部变量和方法参数引用**。
- 本地方法栈中的 **JNI 引用**。
- 类**静态字段**和运行时**常量引用**。
- **被同步锁持有的对象**。
- JVM **内部引用**，例如**系统类加载器和基本类型 Class 对象**。

## 垃圾回收算法有哪些？

| 算法    | 思路            | 优点         | 缺点                | 常见区域    |
| ----- | ------------- | ---------- | ----------------- | ------- |
| 标记-清除 | 标记可回收对象后清除    | 实现简单、不移动对象 | **产生碎片**          | CMS 老年代 |
| 复制    | 将存活对象复制到另一块区域 | 无碎片，适合存活率低 | 需要额外空间，存活率高时复制成本大 | 新生代     |
| 标记-整理 | 标记后将存活对象向一端移动 | 减少碎片       | 移动成本高，通常需要 STW    | 老年代     |
| 分代收集  | 不同生命周期使用不同算法  | 符合对象朝生夕死规律 | 需要处理**跨代引用**      | 传统分代 GC |

## 常见垃圾收集器有哪些？

| 收集器                   | 范围      | 特点                        | 定位       |
| --------------------- | ------- | ------------------------- | -------- |
| Serial / Serial Old   | 新生代/老年代 | **单线程**、STW、实现简单          | 小堆或兜底    |
| ParNew                | 新生代     | **Serial 的多线程版本**，可配合 CMS | 历史组合     |
| Parallel Scavenge/Old | 新生代/老年代 | **吞吐量优先**、自适应调节           | 批处理、后台计算 |
| CMS                   | 主要老年代   | **并发标记**清除、**低停顿**但有碎片    | 老版本低延迟服务 |
| G1                    | 整堆      | **Region 化、可预测停顿、局部复制**   | 现代服务端常用  |
| ZGC / Shenandoah      | 整堆      | 大量并发阶段、超低停顿               | 大堆和低延迟场景 |

## CMS 和 G1 有什么区别？

| 对比  | CMS                             | G1                     |
| --- | ------------------------------- | ---------------------- |
| 范围  | 主要老年代，通常搭配新生代收集器                | 面向整堆，按 Region 管理       |
| 算法  | 标记-清除                           | **Region 间复制**，整体减少碎片  |
| 目标  | 尽量缩短老年代停顿                       | 在吞吐和可预测停顿之间平衡          |
| 问题  | 碎片、浮动垃圾、Concurrent Mode Failure | 转移失败或空间不足时可能退化         |
| 阶段  | **初始标记、并发标记、重新标记、并发清除**         | 初始标记、并发标记、最终标记、筛选回收/转移 |

## G1 有哪些主要特性？

- Region 化：堆被划分为多个大小相等的 Region。
- 分代逻辑：Region 可以**动态扮演** Eden、Survivor、Old 或 Humongous。
- **可预测停顿**：通过 `-XX:MaxGCPauseMillis` 设置期望目标，**优先回收收益高的 Region**。
- **局部复制、整体整理**：降低碎片。
- **并行与并发**结合：标记可以并发，转移阶段通常需要 STW。

Humongous 对象通常是超过 Region 一半大小的对象，会占用一个或多个连续 Humongous Region。


## 哪些 GC 阶段会 Stop The World？

STW 表示暂停用户线程，让 GC 在一致性视图下完成工作。

- 新生代复制存活对象通常需要 STW。
- Serial、Parallel 的主要回收阶段基本是 STW。
- CMS 的**初始标记和重新标记需要 STW**，**并发标记和清除**不暂停用户线程。
- G1 的初始标记、最终标记和筛选回收/对象转移需要 STW，**并发标记不需要全程 STW**。
- 标记-整理中的对象移动和引用更新通常需要 STW。

## 类加载过程有哪些阶段？

类加载过程通常概括为：加载 → 验证 → 准备 → 解析 → 初始化 → 使用 → 卸载。其中验证、准备、解析合称连接。

| 阶段  | 主要工作                                      |
| --- | ----------------------------------------- |
| 加载  | 获取 class 字节流，转为**方法区运行时结构并生成 `Class` 对象** |
| 验证  | 校验文件格式、元数据、字节码和符号引用                       |
| 准备  | 为类**变量分配内存并设置零值**                         |
| 解析  | 将**符号引用替换为直接引用**                          |
| 初始化 | 执行 `<clinit>`，即**静态赋值和静态代码块**合并后的逻辑       |
| 卸载  | 满足条件后回收类元数据                               |

## 双亲委派模型为什么可能被打破
典型打破场景：
- SPI：**父加载器加载接口**，具体实现由子加载器提供。
- **Web 容器：不同应用之间需要类隔离**（ 优先自己加载，找不到才委托父加载器）。
- 插件化和热部署：需要动态加载、替换和卸载类（新建一个类加载器，直接加载新版本的类）。


## 守护线程

守护线程只适合执行随进**程生命周期结束即可丢弃的后台辅助工作**。所有非守护线程结束后，JVM 可以退出，**不会等待守护线程完成**

## happens-before 是什么

Java 内存模型给出了 happens-before 这个承诺：**前一个操作 happens-before 后一个操作 = 前者的写对后者一定可见**，同时 JVM 不会对两者之间的指令做违规重排序。

常见规则：

- **程序次序**：同一线程内，代码从上往下执行，**前面的对后面的可见**。（这是基本保证，不然线程自己都看不懂自己。）
- **volatile 写读**：写一个 volatile 变量后，后续任何线程读它都能拿到最新值。（常用于停止标志、状态开关。）
- **锁的释放→获取**：释放一把锁之前的写入，**对另一个线程获取这把锁后的读取可见**。（synchronized/ReentrantLock 都靠这个。）
- **线程启动**：**`start()` 之前的写入，对新线程内的操作可见**。
- **线程终止**：线程内的**所有写入，对另一个线程 `join()` 返回后的操作可见**。（join 返回 = 我能看到你跑完。）
- **中断**：`interrupt()` 调用，对被中断线程后续检测到中断的代码可见。
- **传递性**：A→B、B→C，则 A→C。（可以串联。）



# DNS

域名解析是网络排障的第一环，实际顺序是**浏览器缓存 → 系统 hosts 文件（`/etc/hosts`）→ 本地 DNS 服务器**。查询方式的术语区分是常考点：客户端到本地 DNS 是**递归查询**（只要最终结果），本地 DNS 到根、顶级域、权威服务器是**迭代查询**
