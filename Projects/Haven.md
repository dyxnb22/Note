在本地 Git 仓库里给它一个编码任务，流程是：Agent 搜索和阅读代码 → 提出精确的修改（diff）→ 等你审批 → 原子化地应用修改 → 运行注册好的验证命令 → 在有界预算内修复失败 → 最终展示 diff、测试证据、成本和停止原因。全程可检查点、可恢复、可回放、可评分。

支撑这条流程的几个关键机制：

- **唯一执行通道**：模型提出的每个动作都要穿过同一条流水线——工具注册表 → 严格 schema 校验 → 路径/预镜像检查 → 确定性策略 → 摘要绑定的单次审批 → TOCTOU 复核 → 执行器。模型永远碰不到真正的副作用。
- **证据门禁（Evidence Gate）**：一次改了文件的运行，不能靠模型自己说“我改好了”就算成功——必须有 diff、有最后一次写入之后通过的检查、有确定性审查（无密钥泄漏、无冲突标记等）。
- **持久化执行**：SQLite 检查点 + 追加式事件日志；中断恢复时对模糊的副作用**绝不自动重放**。
- **离线评估套件**：39 个用例（安全、任务、鲁棒性、注入、预算、恢复），用 ScriptedModel 全离线跑，不需要 API key，有硬性安全门禁。
