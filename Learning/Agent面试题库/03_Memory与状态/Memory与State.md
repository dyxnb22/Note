# Memory 与 State

> 递进路径：先区分记忆和状态，再设计读写策略，最后解决并发、恢复和隐私。

## Level 1｜基础认知：记忆、上下文和状态的边界

1. 短期记忆、长期记忆、任务记忆、工作记忆分别是什么？
2. 对话历史、Summary、结构化状态和向量 Memory 如何配合？
3. 什么信息应该写入长期记忆？什么信息不应该写？
4. 用户偏好、事实、任务进度和工具结果应该分别如何保存？
5. 跨 Session 应该保留哪些信息？
6. Memory 与 RAG 的边界是什么？
7. Memory 与普通数据库、缓存和日志的边界是什么？

## Level 2｜原理机制：Memory 如何读写和检索

8. Memory 的写回时机如何设计？实时写、任务结束写还是异步写？
9. Memory 的读取时机如何设计？
10. Memory 如何分层、过滤、召回、重排和衰减？
11. 为什么可以用 RAG 检索 Memory？向量方式有什么优缺点？
12. 结构化记忆与文本记忆如何避免重复？
13. 如何判断一条 Memory 是否有用？
14. 如何防止错误信息被长期记忆放大？
15. 用户明确纠正旧信息时，如何更新和删除旧记忆？
16. 记忆冲突怎么解决？
17. 记忆的时间衰减如何设计？
18. 如何处理不同来源、不同可信度的记忆？
19. 如何做 Memory 的离线评测和线上监控？

## Level 3｜设计取舍：State、Checkpoint 与并发一致性

20. State 与 Checkpoint 有什么区别？
21. State 全局管理如何做？
22. 多 Agent 并行更新共享 State 时，如何避免覆盖？
23. 如何设计 State Schema 和状态版本？
24. 如何用乐观锁、事件溯源或事务保证状态一致性？
25. 进程崩溃后如何从 Checkpoint 恢复？
26. 如何暂停、恢复、取消和重放一个 Agent 任务？
27. State 中哪些字段应该对模型可见，哪些字段只能由系统维护？
28. 如何避免把内部状态和敏感信息泄露给模型？
29. 多租户场景下如何隔离 Memory、State 和 Checkpoint？
30. State 过大时如何压缩和归档？
31. 如何处理并发任务对同一份 State 的读写？

## Level 4｜场景追问：把 Memory 放进真实产品

32. 设计一个多角色对话系统，用户和多个 AI 角色的记忆如何隔离和共享？
33. 用户先说“我住在上海”，后来改成“我住在深圳”，旧记忆如何处理？
34. 长任务运行到一半进程崩溃，如何判断哪些工具副作用已经发生，再从 Checkpoint 恢复？
35. 记忆召回明显提升了回答相关性，但隐私风险增加，如何设计权限、删除和审计？
