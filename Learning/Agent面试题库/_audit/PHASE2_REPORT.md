## 资产

- `atom_registry.json`：原子数组，包含 ID、规范名称、定义、domain、aliases、status，以及 canonical_owner 和 source_question_ids。
- `atomization_log.json`：每批阅读的完整题目范围、创建前注册表哈希、已有数量、新增及复用 ID 和边界核对说明。
- `atom_review.json`：17 组原子边界复核，包括 4 对词面候选和跨领域人工核对；它不是题目去重裁决表。
- `atom_validation.json`：可复跑的结构检查、来源统计和未决条目。
- `atoms.py`：读取、追加与校验工具，只写 `_audit` 资产；源 Markdown 变化时拒绝继续使用旧基线。

`domain` 是稳定命名空间代码，例如 `mem`、`state`、`tool`、`eval`；同一代码可跨主线与深化文件复用，不按文件建立独立 namespace。canonical_owner 的 `01` 或 `12/03` 指题库主题归属；`external:` 后的路径相对 `Learning/`，可指已有目录或省略 `.md` 的文件。原子出处不等于 canonical question，后者仍需结合 intent 与 answer contract 裁决。

通用模型机制的 26 个原子归 AI；通用后端和交付机制、算法及语言原子归现有 Backend、CS 或 Python 路径。这里只登记当前题库涉及的知识，并未修改或补写外部知识库，也未做技术版本正确性审计。

## 粒度与归属处理

- 任务累计预算、上下文窗口配额和模型推理投入分别建档。
- 业务幂等、Loop 无进展检测和消息投递语义分别建档。
- State 快照、Context 摘要、恢复前核验与操作日志分工分别建档。
- 工具调用、MCP 能力协议、A2A 任务协议与委托身份治理保持不同边界。
- RAG 的 Recall、Precision、MRR、NDCG 独立；课程深化复用召回排序原子，补充摄取、版本与图关系治理。
- 综合题默认作为跨领域知识组合处理，本轮不因高 overlap 判重复，也不为每个综合场景生成一个无法复用的大原子。

### 未决条目

`PROMPT-006`（提示版本的分桶回归）为 `needs_review`，候选已有原子是 `EVAL-001`、`DATA-001`、`EVAL-022`。其定义可能是已有实验、切片与门禁知识的场景组合。下一阶段对照来源题 9、10、32 的完整答案合同，判断应改为组合引用，还是收窄为提示规则之间的冲突。当前不擅自合并或丢弃知识。

这一未决状态符合第一版原子注册的挂起规则，不表示正文修改获准。词面检查不能证明所有语义原子唯一，后续逐题映射仍可暴露遗漏或粒度问题。

## 验证

- `inventory.py --check` 通过，原 29 个 Markdown 文件集合及字节哈希与 Phase 1 基线一致。
- `atoms.py check` 通过，包括原子 ID、规范名与别名、定义、出处、归属路径、待审引用以及 20 批创建历史的哈希链和顺序校验。
- 6 个负向校验用例通过：跨原子别名碰撞、不存在题目出处、无效 owner、不存在候选原子、空定义、缺少说明的待审状态，均被拒绝。
- 词面相似仅生成候选。Recall/Precision、编辑距离/LCS 等相似对经定义核对后保留，不由阈值自动合并。

在仓库根目录复核：

```bash
python3 'Learning/Agent面试题库/_audit/inventory.py' --check
python3 'Learning/Agent面试题库/_audit/atoms.py' check
```

创建历史记录的是逐域完成时的原子定义；本轮末尾只附加待审状态和理由，校验器还原当时的 active 状态核对历史哈希。后续若修改原子定义或迁移 ID，需要新增显式迁移记录与相应校验，不能覆盖历史后假装仍是同一基线。

下一阶段为 Phase 3：每批 20–40 题，根据完整答案建立 atoms、primary_atom、intent、layer 和答案范围记录；先处理 `PROMPT-006` 边界，再检查未知引用、遗漏映射与活跃原子覆盖。题目去重判断要等 Atom Map、候选和裁决完成后进行。
