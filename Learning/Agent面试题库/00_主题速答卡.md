# Agent 主题速答卡

这份卡片迁移自原有 Agent 面试目录中的主题速答。每个主题都按“先给结论 → 再讲机制 → 最后补边界和工程”的顺序准备 60 秒回答。

| 主题 | 先给结论 | 接着讲机制 | 最后补边界 |
|---|---|---|---|
| LLM 调用 | LLM 服务应该被封装成统一、可观测、可取消的边界 | 流式、结构化输出、超时、重试、Provider 差异 | SSE 断线、取消、Schema 校验不等于业务可信 |
| Tool Calling | 模型只产出结构化意图，宿主系统负责真正执行代码 | Schema、参数校验、授权、执行、结果回填 | 超时、错误、幂等、权限和副作用确认 |
| Agent 架构 | 固定路径优先 Workflow，存在动态决策才引入 Agent | Loop、State、Tool、终止条件和预算 | 多 Agent 协调成本、错误传播和人工接管 |
| Context | Context 是运行时组装的工作集，不等于完整聊天历史 | 来源分层、裁剪、摘要、检索和优先级 | 上下文污染、Prompt Injection 和权限兜底 |
| Memory | Memory 是跨回合或跨任务保存的可检索信息，不是无脑保存全部历史 | 写回、读取、召回、重排、衰减和冲突消解 | 隐私、权限、错误记忆和删除机制 |
| RAG | RAG 的核心不是接向量库，而是让知识可召回、可引用、可更新 | 解析、切分、混合检索、Rerank、引用和评测 | 权限前置、过期文档、表格和注入内容 |
| Multi-Agent | 先证明单 Agent 不够，再按职责和权限拆 Agent | Supervisor、handoff、共享状态、消息和结果聚合 | 拆分收益、通信成本、并发和故障传播 |
| Harness | Harness 用确定性代码给模型提供边界、验证和恢复能力 | 工具封装、状态机、校验、重试、审批和回放 | 不要把所有约束都塞进 Prompt；权限必须在系统层兜底 |
| 安全 | 外部内容默认是不可信数据，不是系统指令 | 信任边界、最小权限、参数校验、沙箱、审计 | 间接注入、数据外泄、越权和人工确认 |
| Durable | 长任务必须把状态和副作用从进程内存中分离出来 | Checkpoint、队列、租约、恢复、取消和幂等 | 重试前核实事实，避免重复执行不可逆动作 |
| Eval | Agent 不能只看最终答案，要同时看任务结果、轨迹和工具行为 | 数据集、执行器、评分器、Trace、回归和线上指标 | 随机性、长尾、LLM Judge 偏差和成本 |
| 可观测性 | 通过 Trace 还原一次运行，才能定位 Agent 的真正失败点 | Token、成本、延迟、工具轨迹、检索质量和输出质量 | Replay、关联 ID、脱敏和跨服务链路 |
| LangGraph | 它是状态图和控制流的实现，不是 Agent 原理本身 | State、Node、Edge、Checkpoint、interrupt、stream | 框架 API 要翻译回通用 Loop、状态和编排机制 |
| MCP | MCP 是跨进程的能力协议，不自动解决安全和业务治理 | Server、Tool、Resource、Transport 和版本 | 认证、权限、供应链、兼容性和部署边界 |
| 成本与性能 | 先测量 Token、命中率、TTFT、TPOT、工具耗时和任务成功率 | 缓存、路由、压缩、并行、批处理和降级 | 不要用降低质量换来的低成本冒充优化 |

## 60 秒通用口述结构

1. **一句话定义**：说明主题解决什么问题。
2. **三步机制**：用 3 个动作讲清楚数据如何流动。
3. **一个取舍**：说明为什么选择当前方案，而不是替代方案。
4. **一个失败处理**：至少说超时、错误、权限或恢复中的一个。
5. **一个验证指标**：说明怎样证明它有效。

## 示例：Tool Calling

> Tool Calling 的本质是让模型输出结构化的动作意图，由宿主系统完成校验、授权和执行，而不是让模型直接拥有外部系统权限。运行时先把工具名称、参数 Schema 和约束提供给模型，模型返回工具调用后，服务端校验参数和权限，再执行工具并把结构化结果回填到上下文，最后由模型决定继续还是结束。生产环境还要补充超时、错误归一化、幂等、重试、审计和高风险动作审批；验证时不能只看最终回答，还要看工具选择准确率、参数错误率、重复副作用和任务成功率。
