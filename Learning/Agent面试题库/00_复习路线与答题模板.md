# Agent 面试复习路线与答题模板

这份笔记把原有 Agent 面试目录中的“学习范围、题型矩阵、复习顺序和答题模板”迁移到新题库。题目统一按由浅入深的路径准备：先说清楚是什么，再解释为什么，最后落到设计、工程和场景取舍。

## 一、整体复习路线

### Level 0：先建立共同语言

目标：能用自己的话解释概念，不依赖框架名词。

- 什么是 Agent？与普通 LLM Chat、Chain、Workflow、RPA 有什么区别？
- Agent Loop 的输入、决策、工具执行、结果回填和结束条件是什么？
- Context、State、Memory 分别解决什么问题？
- Tool、Function Calling、MCP、Skill、Workflow 分别处在哪一层？
- 为什么有些任务不需要 Agent？

对应题库：[[01_基础架构/Agent基础与架构]]、[[02_Prompt与上下文/Prompt与Context Engineering]]、[[03_Memory与状态/Memory与State]]、[[04_Tool与协议/Tool Calling与MCP]]。

### Level 1：掌握单 Agent 的可控闭环

目标：能画出一个最小但可终止、可恢复、可观测的 Agent。

- 如何构建最小 Agent Loop？
- 如何设计工具 Schema、参数校验和错误回填？
- 如何设置步数、Token、时间和成本上限？
- 如何处理工具超时、重试、幂等和副作用？
- 如何保存 State 和 Checkpoint？
- 如何用 Trace 定位模型决策、工具执行和最终答案的问题？

对应题库：Tool Calling 与 MCP、[[07_可靠性与安全/可靠性与安全]]、[[08_评测与可观测/评测与可观测性]]。

### Level 2：掌握一个完整业务场景

目标：选择一个和自己项目接近的场景，从需求一直讲到上线。

- 企业知识 Agent：摄取、切分、混合检索、重排、引用、权限、更新和删除。
- Coding Agent：仓库导航、补丁、命令沙箱、测试、写后验证和任务恢复。
- Workflow / 业务 Agent：路由、分支、审批、重试、人工接管和 SLA。
- 数据分析 Agent：取数、执行 Python/SQL、结果验证和防止模型假分析。
- 工具生态 Agent：工具发现、动态加载、权限、版本和调用回放。

对应题库：[[05_Multi-Agent与Workflow/Multi-Agent与Workflow]]、[[06_RAG与知识库/RAG与检索]]、[[09_工程化与系统设计/生产工程与系统设计]]。

### Level 3：深入多 Agent、生产化和模型优化

目标：能回答为什么拆分、如何扩展、如何控制代价，以及怎么证明系统变好了。

- 什么情况下拆成多 Agent？什么时候应该退回单 Agent？
- Supervisor、handoff、Pipeline、Blackboard 如何选？
- 如何控制多 Agent 协调成本、错误传播和并发？
- 如何做多租户、限流、队列、流式、模型路由和故障转移？
- 如何建立评测集、Badcase 回流、灰度发布和回滚？
- 何时应该换模型、调参数、加 Harness 还是做 SFT？

对应题库：Multi-Agent 与 Workflow、评测与可观测性、生产工程与系统设计、[[10_模型与推理/模型与推理基础]]。

## 二、题型矩阵

| 题型 | 递进路径 | 最终要讲清楚什么 |
|---|---|---|
| 基础与边界 | 定义 → 对比 → 适用边界 → 取舍 | 为什么用 Agent，以及为什么有时不用 Agent |
| Agent 运行时 | Loop → 状态 → 工具 → 终止 → 恢复 | 模型决策如何变成可控执行 |
| 工具与动作 | Schema → 校验 → 授权 → 执行 → 失败 | 工具调用如何安全地产生副作用 |
| Context / Memory | 分类 → 读写 → 检索 → 压缩 → 冲突 | 当前上下文与持久化记忆如何分工 |
| RAG / 搜索 | 数据 → 召回 → 重排 → 引用 → 更新 | 知识如何可靠进入 Agent |
| 多 Agent / 编排 | 单 Agent 基线 → 拆分 → 通信 → 聚合 → 回退 | 拆分带来的收益是否超过协调成本 |
| 安全与治理 | 威胁 → 信任边界 → 权限 → 沙箱 → 审计 | Agent 能做什么、不能做什么、谁来批准 |
| Eval / 观测 | 指标 → 数据集 → Trace → Badcase → 回归 | 如何证明系统变好了、错在哪里 |
| 系统设计 | 约束 → 基线 → 数据路径 → 可靠性 → 上线 | 如何在质量、延迟、成本和复杂度之间取舍 |

## 三、统一答题模板

系统设计题和项目深挖题都按下面顺序回答：

1. **问题与约束**：用户是谁，任务成功标准是什么，数据是否敏感，延迟/QPS/SLA 和副作用要求是什么。
2. **最小基线**：先判断是否需要 Agent；能用确定性函数链或 Workflow 解决，就说明为什么不默认动态循环。
3. **核心机制**：说明 Loop、State、Context、Tool、Memory、RAG 或多 Agent 的职责边界。
4. **数据路径**：输入 → 上下文/检索 → 模型决策 → 工具执行 → 状态/Trace → 输出、审批或人工接管。
5. **失败路径**：超时、重试、幂等、checkpoint、取消、降级、部分成功和不可逆动作怎么处理。
6. **安全边界**：信任边界、最小权限、参数校验、沙箱、敏感数据、Prompt Injection 和审计。
7. **评测与上线**：离线样本、任务/轨迹/工具指标、线上监控、灰度、回滚和事故闭环。
8. **取舍与验证**：明确质量、延迟、成本、复杂度和可维护性的取舍，并说如何用实验验证。

## 四、同一专题的递进答法

遇到任何一个主题，至少准备下面五层：

1. **概念层**：它是什么，解决什么问题？
2. **原理层**：核心数据结构、流程和状态变化是什么？
3. **设计层**：如何选型、拆模块、定接口？替代方案是什么？
4. **工程层**：异常、并发、权限、成本、观测和恢复怎么落地？
5. **场景层**：结合项目或业务，为什么这样做？数据和指标如何证明有效？

如果只能回答概念层，不算掌握；如果只能背工程名词但讲不出边界和取舍，也不算掌握。

## 五、面试前最小 Checklist

- [ ] 能在 2 分钟讲清一个真实项目的目标、Loop、State、工具、权限、指标和一次失败。
- [ ] 能解释 Agent 与 Workflow 的边界，并给出为什么不需要更复杂方案的理由。
- [ ] 能说清工具 Schema、授权、超时、重试、幂等和人工审批。
- [ ] 能区分 Context、State、Memory，说明长任务如何 checkpoint、恢复和取消。
- [ ] 能从任务结果、轨迹、工具行为、延迟、成本和安全解释 Agent 质量。
- [ ] 能完成一个企业知识、客服、数据分析或 Coding Agent 的系统设计。
- [ ] 能把一个专题从概念层讲到场景层，而不是只背一句定义。

## 六、准备深度

- **P0**：完成 01～04、07～09 的 Level 1～3，覆盖所有 Agent 岗位共同要求。
- **P1**：从 05、06、09、11 中选择一个和项目最接近的场景，完成五层递进回答。
- **P2**：GraphRAG、A2A、Computer Use、语音实时对话、模型训练/RLHF、推理内核和具体厂商 API，只有岗位明确要求时再深入。

面试准备的完成标准不是看完所有文件，而是：能实现一个最小可终止 Agent，能讲通一个完整业务场景，能用指标和 Trace 解释一次成功与一次失败。
