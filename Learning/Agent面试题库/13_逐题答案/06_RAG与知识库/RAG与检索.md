# RAG 与知识库｜逐题答案

> 回答顺序：先保证数据可用，再讲召回与排序，最后补权限、更新、评测和复杂场景。编号与题目版一致。

## Level 1｜基础认知

### 1. RAG 的完整流程是什么？

答：离线侧解析、清洗、切分、生成索引；在线侧理解查询、按权限召回候选、重排、组装 Context，模型基于证据生成并返回引用。真正的 RAG 还要处理文档更新、删除、权限、评测和失败，而不是只接一个向量库。

### 2. 文档解析、清洗、切分、Embedding、索引、召回、Rerank、生成如何串联？

答：先保留结构和来源做规范化，再按语义/结构切块并附文档、页码、权限、版本元数据；生成倒排和向量索引，查询时混合召回、Rerank，最后按预算组装证据并生成。每一步都要记录版本，便于解释和回滚。

### 3. 固定长度切分、按段落切分、语义切分和父子块有什么区别？

答：固定长度简单但可能切断语义，段落切分保留结构但长度不稳定，语义切分按主题边界更自然但成本和稳定性更高；父子块用小块召回、较大的父块提供上下文。选择取决于文档结构、召回粒度和上下文预算，应通过检索评测验证。

### 4. Chunk Size 和 Overlap 如何确定？

答：以一个问题所需的最小完整语义单元为起点，观察召回是否缺上下文、重复率和 Token 成本；Overlap 只补跨边界信息，过大会制造重复。不同文档类型可用不同策略，并用 Recall、MRR、答案正确率和延迟联合调参。

### 5. 如何处理 PDF、扫描件、OCR、表格、图片和复杂版式？

答：先区分文本型和扫描型 PDF，保留页码、坐标、标题层级和表格关系；扫描件用 OCR 并记录置信度，表格转成结构化数据加可读摘要，图片必要时走视觉模型。低置信度内容不能当作高可信事实，解析结果要用样本和端到端问答评测。

### 6. OCR 准确率和端到端问答准确率如何评估？

答：OCR 层看字符/词错误率、表格单元格准确率、布局和关键字段召回；端到端看检索命中、引用正确、答案正确和拒答质量。两层要分开定位，否则答案错时不知道是识别、检索还是生成的问题。

### 7. 如何让 RAG 支持结构化数据库和非结构化文档？

答：结构化问题优先生成受限 SQL/API 并由权限和结果校验控制，非结构化问题走文档检索；需要联合时由 Workflow 规划数据源，再用统一证据 Schema 合并。不要把业务数据库全量转成文本来规避权限和一致性问题。

### 8. 如何处理文档中的标题、表格、脚注、页码和引用关系？

答：在解析阶段保存文档树、表格结构、页码/坐标、父子节点和原始片段 ID，切块时继承这些元数据。生成引用时从元数据反查原文位置，避免只返回没有出处的向量片段。

## Level 2｜原理机制

### 9. BM25、向量检索和混合检索各自适合什么场景？

答：BM25 擅长专有名词、编号、精确词面和稀有关键词，向量检索擅长语义相近、表达不同的查询；混合检索适合企业知识中两类需求并存的场景。权重和召回数不能凭经验固定，要按题型分桶评测。

### 10. 多阶段 RAG 中 BM25 和向量结果如何合并？

答：先分别召回候选并做去重，再用归一化分数、Reciprocal Rank Fusion 或学习排序合并，最后交给 Reranker；要保留各来源得分，便于调参和排障。融合前先做权限过滤，不能把无权文档引入候选集。

### 11. 混合检索的比例如何确定？实际收益如何验证？

答：按数据集中的精确词面题、语义题、长查询和实体题分桶，网格或离线实验比较 Recall、MRR/NDCG、答案正确率、延迟和成本。比例不是越平均越好，线上还要观察文档类型变化和查询分布漂移。

### 12. Rerank 为什么有效？放在什么位置？

答：初检索追求高召回，候选排序可能只使用词面或向量相似度；Reranker 用查询和候选的联合语义关系重新排序，适合放在混合召回之后、Context 组装之前。候选太多会增加延迟和成本，需要限制 TopK 并做缓存/分级。

### 13. Rerank 后返回多少个块？如何验证？

答：从满足答案所需的最小证据集合开始，用不同 K 评估答案正确、引用覆盖、重复、Token、延迟和长尾召回；K 不是越大越好。对多跳问题可按子问题分别召回，再合并去重。

### 14. Rerank TopK 截断怎么做？为什么？还有哪些替代方案？

答：按排序保留预算内的高相关、互补证据，结合相似度阈值、MMR 去重和每文档上限，避免同一文档占满 Context。替代方案包括动态 K、按问题类型路由、分层检索和让模型选择候选，但都要用评测验证。

### 15. TopK 如何选择？

答：先测检索 Recall 随 K 的曲线，再把生成答案、引用正确、延迟和 Token 纳入联合目标；不同查询类型可使用动态 K。最终 K 要能解释为预算和收益的取舍，而不是一个脱离模型和文档的常数。

### 16. 如何避免召回重复内容？

答：在索引和在线阶段都保留文档/段落 ID，先精确去重，再按相似度或 MMR 去掉高度重叠块，并限制同一来源数量。摘要只能减少展示重复，不能掩盖底层切分和索引重复问题。

### 17. 如何处理查询改写、Multi-Query 和 HyDE？

答：查询改写扩展实体、约束和缺省上下文，Multi-Query 用多个视角提高召回，HyDE 用假设答案的语义表示帮助召回；它们会增加调用和噪声。只在原查询 Recall 明显不足的题型启用，并保留原查询、改写和证据链用于评估。

### 18. 如何区分检索失败、阅读失败、推理失败和表达失败？

答：检查金标准证据是否进入候选和最终 Context，若没有是检索/权限问题；有证据但模型未使用是 Context/阅读问题；证据足够仍推断错误是推理问题；内容正确但格式/引用不对是表达/校验问题。Trace 要记录每层输入输出，不能统称“RAG 不准”。

## Level 3｜工程设计

### 19. 文档更新、删除和权限变更如何同步到索引？

答：文档有不可变版本和状态，摄取、索引、权限同步通过事件驱动并记录进度；在线召回先按当前权限/版本过滤，删除要让主库、倒排、向量、缓存和引用一起失效。更新未完成时宁可返回旧版本明确标记，也不能混合新旧内容而不说明。

### 20. 如何做增量索引和热更新？

答：按文档版本计算变更块，只重建受影响的解析、Embedding 和索引分片，用双版本索引或原子切换发布；失败时回退旧版本。查询结果记录索引版本，方便发现热更新造成的质量变化。

### 21. 如何处理知识库中的冲突事实和过期事实？

答：保存来源、时间、版本和权威等级，召回/重排时优先当前有效和权威来源；冲突无法自动解决时展示不确定性或请求人工确认。业务事实应回查权威系统，RAG 文档不能无条件覆盖实时数据。

### 22. 如何做分租户、分用户、分文档的权限过滤？

答：权限元数据随文档和索引存储，查询时使用真实身份构造强制过滤条件，不能让模型在结果返回后自行筛掉；应用层和存储层双重校验，缓存键也包含权限 Scope。权限变更需要及时失效索引和缓存。

### 23. 如何防止已删除或无权限文档被召回？

答：召回前做权限和有效版本过滤，删除/权限事件触发索引、缓存和引用撤销；输出前再次检查来源权限。定期用“已删除/无权文档”对抗集测试，不能只依赖向量库的最终删除。

### 24. 如何单独评估 Retriever、Reranker 和 Generator？

答：Retriever 看金标准证据 Recall/候选覆盖，Reranker 看相关文档排序和 NDCG/MRR，Generator 看有证据时答案正确、引用和拒答质量。分层评估能避免生成模型偶然猜对掩盖召回问题。

### 25. 如何评估 Recall、Precision、MRR、NDCG 和上下文利用率？

答：先建立查询—金标准文档/段落标注；Recall 衡量找全，Precision 衡量噪声少，MRR 关注首个正确结果，NDCG 兼顾多级相关性，上下文利用率看模型是否使用了召回证据。指标要按查询类型分桶，不要只报一个平均数。

### 26. RAG 和 Memory 的边界是什么？

答：RAG 面向外部知识和业务文档，强调版本、权限、引用和新鲜度；Memory 面向用户/任务个性化事实，强调写回、遗忘、冲突和隐私。两者可以共用检索基础设施，但索引命名空间和授权策略不能混为一谈。

### 27. 如何让 Agent 在需要时自主决定是否检索？

答：先用任务类型、是否需要实时/外部事实、置信度和知识缺口做路由，模型可以提出检索，但执行器限制可用数据源、次数和预算。检索后还要验证证据是否真的覆盖问题，不能把“调用过搜索”当成回答有依据。

### 28. 如何防止检索内容中的 Prompt Injection？

答：检索内容明确标记为不可信数据，不能改变系统规则、工具权限或输出策略；对高风险文档做内容检测、字段隔离和最小化，执行器再次授权。必要时让模型只提取事实，不把原文指令直接拼入高优先级 Prompt。

### 29. 如何把检索结果、引用和最终回答建立可追溯关系？

答：每个 Chunk 带稳定文档/版本/页码/片段 ID，Context 和生成结果记录引用映射，输出只允许引用已进入 Context 且权限有效的证据。评测检查引用是否支持具体结论，不能只在末尾列一堆未使用链接。

### 30. 文档库很大时如何控制延迟和成本？

答：离线做分层索引和增量更新，在线先用轻量过滤/关键词/向量召回，再对小候选集 Rerank；缓存 Embedding、热门查询和稳定上下文，按复杂度路由模型。优化前先测解析、检索、Rerank、模型和网络各段耗时，避免盲目压缩 K 伤害质量。

## Level 4｜场景追问

### 31. 设计一个支持扫描 PDF、表格、权限和增量更新的企业知识 Agent。

答：摄取层区分文本/OCR，保留页码、坐标、表格结构和权限元数据；索引层按租户/文档版本构建倒排+向量，查询时先权限过滤、混合召回、Rerank，再以带引用的 Context 生成。更新/删除通过版本事件原子切换，评测分解析、检索、引用、答案和越权率。

### 32. 如果 BM25 召回了关键词正确但语义不相关的文档，向量检索和 Rerank 如何配合修复？

答：保留 BM25 的精确词优势，同时增加向量候选扩大语义覆盖，合并去重后由 Reranker 用查询—文档联合关系排序；再按题型调权和 K。修复要用相关性标注比较候选覆盖、排序和最终答案，不应只看一个查询。

### 33. 文档被删除或权限变更后，如何保证旧索引不会继续返回它？

答：删除/权限事件先更新权威状态，再让倒排、向量、缓存和引用索引失效；在线查询强制附带当前 Scope/有效版本过滤，输出前再校验。删除传播期间可短暂降级为只查权威存储，不能把旧缓存当安全边界。

### 34. 检索结果正确但最终回答仍然幻觉，如何区分是上下文组织、模型推理还是输出校验问题？

答：先检查正确证据是否真的进入模型 Context、是否被摘要/截断破坏；证据完整但结论错，属于模型推理/Prompt问题；结论正确但格式或引用错，属于输出校验问题。用固定证据回放和分层评测分别验证，避免重新调整个 RAG。
