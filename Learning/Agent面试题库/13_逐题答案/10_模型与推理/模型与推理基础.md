# 模型与推理基础｜逐题答案

> 回答顺序：先讲模型结构，再讲推理成本，最后联系 Agent 的模型选择、路由和训练。编号与题目版一致。

## Level 1｜基础认知

### 1. Transformer 的整体结构是什么？

答：输入 Token 先经过嵌入和位置信息，进入多层 Attention、前馈网络、残差连接和归一化，最后由输出头产生下一个 Token 的分布。Encoder 更偏理解，Decoder/causal Transformer 逐 token 生成，LLM Agent 通常围绕 decoder 生成文本或工具调用。

### 2. Self-Attention 和 Multi-Head Attention 的原理是什么？

答：Self-Attention 用每个位置的 Query 与所有位置的 Key 计算相关性，再对 Value 加权求和；Multi-Head 用多个投影空间并行关注不同关系，拼接后再映射。它让 Token 能根据上下文动态聚合信息。

### 3. 为什么 Attention 使用 Q、K、V？

答：Q 表示“当前要找什么”，K 表示“每个位置提供什么索引特征”，V 表示真正被聚合的内容；Q/K 点积得到权重，权重作用在 V 上。分离三者让匹配和内容表示可以有不同投影。

### 4. 为什么 KV Cache 不缓存 Q？

答：自回归生成时新 Token 的 Query 只在当前步使用，而历史 Token 的 Key/Value 会在后续每一步重复参与注意力，因此缓存历史 K/V 能避免重复计算。Q 对每个新 Token 都不同且不需要被未来步骤反复读取，所以通常不缓存。

### 5. Attention 的时间和空间复杂度是什么？

答：对序列长度 n，标准全注意力的计算和注意力矩阵空间通常是 O(n²)，这也是长上下文成本高的主要原因；生成阶段 KV Cache 可避免重复计算历史投影，但仍受序列长度和 KV 内存影响。不同稀疏/线性注意力会改变复杂度，但要结合质量和实现成本。

### 6. Causal Mask 和 Padding Mask 有什么区别？

答：Causal Mask 防止当前位置看到未来 Token，保证自回归生成；Padding Mask 忽略批次中用于对齐长度的填充位置。两者可同时使用，目的分别是防信息泄露和忽略无效输入。

### 7. FFN、残差连接和 LayerNorm 的作用是什么？

答：FFN 对每个位置做非线性特征变换，残差连接保留原信息并改善深层训练，LayerNorm 稳定激活尺度和优化过程。它们与 Attention 共同组成 Transformer block。

### 8. 同一个 Token 在不同位置的向量是否相同？

答：词嵌入部分可以相同，但位置编码/位置表示不同，经过 Attention 后还会因上下文不同而不同。因此相同词在不同位置和句子中的最终隐藏状态通常不相同。

### 9. 位置编码有哪些方式？

答：常见有绝对位置嵌入、正弦位置编码、相对位置编码和 RoPE 等；它们把顺序信息注入注意力。面试时重点说它们解决“模型本身对排列不敏感”的问题，以及长上下文外推/实现成本的取舍。

### 10. Softmax 在 Attention 中起什么作用？

答：Softmax 把 QK 相似度转成归一化权重，使每个 Query 对 Value 做加权聚合；温度会影响分布尖锐程度。数值实现通常先减最大值避免溢出，Mask 位置在 Softmax 前设为极小值。

## Level 2｜推理机制

### 11. Temperature、Top-K、Top-P 如何影响输出？

答：Temperature 调整分布平滑程度，越高越随机；Top-K 只保留概率最高的 K 个 Token，Top-P 保留累计概率达到阈值的动态集合。Agent 工具调用和结构化输出通常偏低随机性，并用 Schema/验证器兜底。

### 12. Context Window 和 Token Budget 有什么区别？

答：Context Window 是模型一次可接收的输入/历史/输出总容量上限，Token Budget 是某次任务愿意或允许消耗的额度。预算通常小于窗口，并要同时约束输入、输出、工具结果和循环累计成本。

### 13. Prefix Caching 如何工作？

答：对相同前缀的系统 Prompt、工具目录或固定上下文复用已计算的推理状态，减少重复 Prefill；只有前缀字节/Token、模型和相关配置匹配时才安全。用户/租户敏感内容和动态权限不能被不加 Scope 地共享缓存。

### 14. continuous batching 解决什么问题？

答：它允许不同请求在生成过程中动态加入/退出批次，提高 GPU 利用率和吞吐，适合长度差异大的在线生成；调度复杂度和尾部延迟控制也随之增加。Agent 场景还要处理取消、优先级、流式和每任务预算。

### 15. vLLM、PagedAttention 和 KV Cache 的关系是什么？

答：KV Cache 保存历史 Token 的注意力键和值，PagedAttention 用类似分页的方式管理不同请求的 KV 内存，vLLM 是提供高吞吐推理服务的实现之一。它们优化的是推理执行和内存管理，不会自动提升 Agent 规划正确率或工具安全。

### 16. LLM 推理优化有哪些常见方法？

答：模型/量化、KV/Prefix Cache、连续批处理、投机解码、请求合并、上下文压缩、模型路由和输出长度控制都可能有效。先用 Trace 区分 Prefill、Decode、排队、网络和工具耗时，再决定优化，否则可能把瓶颈判断错。

### 17. 如何估算模型服务的吞吐、并发和显存？

答：根据模型参数/精度、权重和 KV Cache 占用估算显存，再用输入/输出 Token、并发、batch 和目标 P95 压测实际吞吐；长上下文和生成长度会显著增加 KV 内存。容量还要加多副本、峰值、重试和流式连接开销。

### 18. 如何在模型质量、延迟和成本之间做选择？

答：按任务复杂度和风险分层路由，简单/低风险使用小模型或 Workflow，复杂/关键任务使用更强模型和验证；用任务成功、长尾、安全、P95 和单任务成本综合评估。不要只比较单次 API 价格，Agent 的多轮调用和失败重试才是总成本。

### 19. 如何处理模型上下文窗口溢出？

答：在进入模型前计算 Token 预算，按优先级裁剪重复历史、摘要已完成步骤、检索必要证据和压缩工具结果；必要时拆成子任务或暂停请求用户缩小范围。系统应在溢出前停止并给出原因，不能依赖 Provider 截断掉关键约束。

### 20. 如何做多模型路由和 Fallback？

答：根据任务能力、工具支持、隐私、延迟、成本和预算选择模型，适配器统一消息/工具/错误合同；Fallback 只切换兼容模型并记录原因，重试要考虑副作用。上线前对每个模型跑同一套工具选择、结构化、安全和长尾评测。

## Level 3｜训练机制

### 21. 预训练、SFT、LoRA、QLoRA、RLHF、PPO、GRPO 分别是什么？

答：预训练学习通用语言/知识，SFT 用示范数据学习任务行为；LoRA/QLoRA 以低秩/量化方式降低微调成本；RLHF 用偏好/奖励优化行为，PPO 是一种策略优化方法，GRPO 通常用同组样本相对奖励减少对 Value Model 的依赖。面试时说明它们解决的数据、能力和成本问题，不要把名称当成 Agent 必需组件。

### 22. RL 之前是否需要 SFT？什么时候不需要？

答：若模型尚未学会任务格式、工具协议或基本行为，SFT 通常先提供可学习的初始策略；若基础模型已有能力、奖励可直接衡量且数据/训练目标稳定，可以少量或不做 SFT。判断依据是基线行为、奖励稀疏程度、稳定性和成本实验。

### 23. Reward 如何设计？如何避免 Reward 过于稀疏？

答：Reward 应对应业务目标和安全边界，区分最终任务成功、步骤进展、工具正确性、成本/延迟和违规惩罚；中间奖励只能鼓励可验证进展，不能奖励表面格式。用多任务/困难样本检查奖励是否与真实价值一致，避免模型钻空子。

### 24. 什么是 Reward Hacking？如何发现？

答：模型找到提高评分但没有完成真实目标的捷径，例如伪造引用、缩短任务、迎合 Judge 或绕过工具。通过独立验证器、对抗样本、隐藏评测、工具事实和人工抽检比较奖励与真实成功的相关性，发现后修正奖励、增加约束和回归。

### 25. 什么是熵坍塌？如何识别？

答：策略分布过度集中，模型几乎总选同一动作/输出，探索和泛化下降；可看 Token/动作分布熵、候选多样性、不同输入的重复率和长尾成功率。修复要结合训练目标、采样温度、数据覆盖和策略约束，不能只看训练 loss。

### 26. PPO 中 Value Model 和 Reward Model 如何训练？

答：Reward Model 从偏好/评分数据学习评价轨迹或答案，Value Model 估计当前状态的未来回报，用于计算优势；PPO 再用裁剪目标更新策略并限制偏离。工程上要防止奖励模型偏差、价值估计不稳和 KL/安全约束失控。

### 27. GRPO 的 Reward 体系能否迁移到 PPO？

答：不能直接照搬，因为两者对优势估计、基线和样本分组的假设不同；可以复用奖励定义和验证器，但要重新检查尺度、稀疏性、方差、归一化和训练稳定性。最终以同一隐藏评测和安全指标验证，而不是按算法名迁移。

### 28. 什么时候应该换模型，什么时候应该做微调？

答：模型缺少广泛推理/工具/语言能力时先换模型；行为已经接近目标但在稳定格式、领域术语或固定任务分布上反复失败，且有高质量数据时再微调。若根因是工具、Context、权限或验收缺失，微调通常不是正确修复。

### 29. 如何选择训练数据和构造 Hard Negative？

答：数据应覆盖真实任务、长尾、错误工具、冲突上下文、安全边界和不同难度，并保留可验证标签；Hard Negative 可以是相似但错误的工具/文档/计划，重点训练区分边界。数据要去重、脱敏、版本化，并防止把评测集泄漏进训练。

### 30. Badcase 如何回流到训练集或评测集？

答：先标注根因和正确行为，保留原 Trace、上下文和工具事实；可泛化的代表案例进入训练，关键回归/安全案例保留在评测集，不能同一条未经处理地同时调参和验收。回流后要检查是否修一类坏另一类。

## Level 4｜场景追问

### 31. 一个任务需要复杂工具调用，但成本和延迟都很高，你会换模型、做路由还是增加确定性约束？

答：先用 Trace 拆出模型、工具、排队和 Context 的耗时/Token，确认瓶颈；工具参数/流程稳定就用 Workflow/Harness 减少循环，任务复杂度差异大就做路由，模型能力确实不足才换模型。每种方案都以任务成功、P95、费用和安全回归验证。

### 32. 如何判断问题来自模型能力不足，还是 Context、Tool、RAG 或 Harness 设计不足？

答：用固定输入和证据做分层实验：给模型完整正确 Context 的基线、禁用/替换工具的基线、绕过 RAG 的基线，再比较错误是否消失；Trace 看第一次偏离。只有在输入、工具和约束都正确仍稳定失败时，才更像模型能力问题。

### 33. 如何为高质量模型、低成本模型和专用模型设计路由与 Fallback？

答：定义能力标签、最大 Context/工具支持、延迟/成本和安全等级，先按任务风险和复杂度路由；Fallback 只能去到合同兼容且预算允许的模型，并在结果上做同样验证。记录路由命中、失败原因和效果差异，避免低成本模型被迫承担不适合的任务。

### 34. 如何用实验分别验证量化、缓存、批处理和 Prompt 压缩的收益？

答：固定任务、模型版本、工具和并发，单变量对照测质量、P95/TTFT、Token、显存、吞吐和费用；量化要看能力退化，缓存要看命中和越权，批处理要看尾部延迟，压缩要看长任务成功率。通过线上灰度确认离线收益可复现。
