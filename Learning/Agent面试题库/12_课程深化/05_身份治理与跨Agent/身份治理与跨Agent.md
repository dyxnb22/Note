# 身份治理、多 Agent 与跨 Agent 协议

> 递进路径：先区分身份、权限和数据治理，再讲能力授权与委托合同，最后判断多 Agent/A2A 是否真的有必要。

## Level 1｜身份与数据治理

1. Agent 系统中 Actor、Agent、Service 和 Resource 分别是什么？
2. 一个授权判断至少应包含哪些维度？
3. 为什么数据分类不能只分“公开/私密”两类？
4. 数据最小化在 Agent 系统里如何落地？
5. Secret 的生命周期应如何管理？
6. 多租户隔离为什么要覆盖数据库、向量库、缓存、工作区、队列和 Trace？
7. 数据删除请求为什么不能只删除主数据库中的记录？
8. 为什么模型输出和其他 Agent 输出都应被当作不可信数据？

## Level 2｜能力授权与委托

9. 面向 Agent 的能力授权凭证应绑定哪些条件？
10. 人工审批合同至少要展示什么？
11. 为什么审批不能只是一个布尔值？
12. 跨 Agent 委托的最小任务合同应包含哪些字段？
13. Tool、MCP 和 A2A/Task API 的边界分别是什么？
14. 跨 Agent 的 Capability Card 或发现信息应该声明什么？
15. 委托任务如何传播身份、预算、截止时间、取消和证据要求？
16. 为什么跨 Agent 返回值不能直接作为高权限执行依据？

## Level 3｜多 Agent 设计与评估

17. 什么证据能证明多 Agent 比单 Agent 或 Workflow 更值得？
18. Manager-Worker、Planner-Executor、Executor-Reviewer、Router-Specialist 分别适合什么场景？
19. 子任务合同应如何定义输入、输出、权限和终止条件？
20. 多 Agent 共享 State 时如何处理并发写和冲突？
21. 多 Agent 如何处理部分成功、超时、失败和过期结果？
22. 多 Agent 之间出现结论冲突时如何仲裁？
23. 如何避免委托循环、语义漂移和错误传播？
24. 多 Agent 评测至少要和单 Agent 基线比较哪些指标？
25. 什么情况下应该用进程内节点或普通 API，而不是 A2A？

## Level 4｜场景追问

26. 设计一个跨租户、多 Agent 的研究系统，如何防止子 Agent 越权读取和回传敏感资料？
27. 一个 Reviewer Agent 认为 Executor 的结论错误，但两者都没有完整证据，你会如何处理？
28. 一个委托 Agent 超时后上游想重新派发任务，如何避免重复副作用？
29. 如果多 Agent 比单 Agent 多花三倍 Token 但成功率只提高一点，你会如何决定是否保留？
