# Prompt 与 Context Engineering

> 递进路径：先会写稳定指令，再理解上下文组装，最后处理多轮交互和污染风险。

## Level 1｜基础认知：Prompt 如何表达任务

1. 如何构建稳定的 Prompt 模板？
2. System Prompt、User Prompt、Tool Description、Retrieved Context 如何分层？
3. Prompt 中如何描述角色、目标、约束、工具、输出格式和终止条件？
4. 为什么 Skill 常常放在 System Prompt，而不是 User Query？
5. 如何写出清晰、可判别、少歧义的 Skill Description？
6. Prompt 中应该放示例吗？Few-shot 什么时候有效？
7. 如何控制模型的语气、格式、长度和拒答边界？
8. 如何用 Schema、Grammar、校验和重试保证 JSON 输出稳定？
9. Prompt 调优有哪些常见误区？
10. Prompt 调优中“修好一类问题、坏了另一类问题”怎么解决？
11. Prompt 调优到极限后，如何判断换模型、调参数、加约束还是做 SFT？
12. 如何为不同模型维护同一套 Prompt？

## Level 2｜原理机制：上下文如何组装和压缩

13. 什么是 Context Engineering？它和 Prompt Engineering 有什么区别？
14. 一个 Agent 的上下文应该包含哪些内容？
15. 如何设计上下文的优先级？哪些内容必须保留，哪些内容可以丢弃？
16. 如何避免上下文污染？
17. 如何让模型只读取当前任务相关的历史信息？
18. 工具描述、用户历史、检索结果、计划和中间结果如何组织？
19. Skill 太多导致上下文变大，如何动态发现和加载？
20. 两个 Skill 内容不同但 Description 相似，Agent 经常选错，如何解决？
21. Todo List 为什么能让模型更聚焦？如何生成、更新和校验 Todo List？
22. 多轮对话中如何区分新任务、补充信息和纠正信息？
23. 如何设计上下文窗口的 Token 预算？
24. 上下文窗口不够时，如何做摘要、压缩、裁剪、分层和检索？
25. Summary 如何保留关键事实、约束、未完成任务和工具结果？
26. 长上下文中的旧信息与新信息冲突时，如何处理？

## Level 3｜设计取舍：查询改写与交互控制

28. 多维度查询改写如何做？
29. 如何判断信息不足并让用户补充？
30. 如何设计澄清问题，避免一次问太多？
31. 用户中途修改目标时，如何更新计划和上下文？
32. 如何把自然语言需求拆成可执行的结构化任务？
33. 如何防止用户输入直接覆盖系统约束？
34. 如何处理过长、重复、矛盾或恶意的用户输入？

## Level 4｜场景追问：从 Prompt 走到系统

36. 上下文窗口只剩一半预算，但任务还需要历史、工具结果和检索文档，如何排序和裁剪？
37. 用户输入要求覆盖系统约束时，Prompt 层和执行层分别如何防守？
38. 如何通过评测集证明一次 Prompt 改动没有只修好短样本而伤害长尾任务？
