# AMM 协议研究与安全审计

这个案例把 AMM 的数学机制、流动性提供者收益、交易者价格、合约状态和安全风险连起来。它不是对某个具体协议的安全结论，而是一套可复用的研究骨架。

## 1. 先写协议合同

- 交易者希望按给定输入或输出完成兑换。
- 流动性提供者向池子提供资产并获得份额或费用。
- 协议通过储备、曲线和费用规则决定可执行价格。
- 管理者、升级者、预言机和外部 Token 可能改变信任边界。

必须写清：支持哪些 Token、是否允许转账税/回调、费用在哪里扣除、份额如何铸造/销毁、异常时谁能暂停。

## 2. 核心不变量

对恒定乘积型池子，可以用：

~~~text
x × y = k
~~~

作为直觉起点，但真实实现还要考虑手续费、整数舍入、Token 精度、最小输出、储备更新顺序和流动性份额。

每笔交易研究：

- 输入前后储备。
- 用户实际收到的输出。
- 费用归属。
- 曲线不变量是否在允许误差内成立。
- 事件、receipt 和链上存储是否一致。

公式成立不等于经济安全，也不等于实现没有重入、权限或精度问题。

## 3. 状态与权限

画出：

~~~text
池初始化
→ 添加流动性
→ 兑换
→ 移除流动性
→ 手续费/协议费结算
→ 暂停/升级/治理
~~~

对每个状态列出调用者、输入、前置条件、状态变化、事件和失败路径。区分 LP 份额、储备余额、实际 Token 余额和协议内部记账。

## 4. 安全审计清单

- 重入和外部调用顺序。
- Token 返回值、转账税、回调和非标准实现。
- 价格操纵、闪电贷和低流动性。
- 精度、舍入、边界输入和极端储备。
- 最小输出、滑点和截止时间。
- 管理员、暂停、升级和多签权限。
- 事件、储备和实际余额不一致。
- 费用或份额计算导致的价值泄漏。
- 初始化、迁移和孤立资产。

## 5. 证据分层

| 证据 | 能证明什么 | 不能证明什么 |
|---|---|---|
| 白皮书/文档 | 设计意图 | 实现正确 |
| 源码 | 逻辑路径存在 | 已部署版本一致 |
| 单元测试 | 覆盖样例行为 | 未覆盖攻击面 |
| 模拟/模糊测试 | 某类输入下的不变量 | 所有经济攻击 |
| 链上读取和事件 | 实际状态与历史动作 | 未来安全 |
| 审计报告 | 审计范围内的发现 | 无风险保证 |

## 6. 最小实验

实现一个小型本地池：

1. 添加和移除流动性。
2. 兑换和手续费。
3. 最小输出与滑点保护。
4. 故意制造舍入、重入和余额不一致测试。
5. 比较公式、内部状态、事件和实际余额。

## 结论边界

不要把本地模型、单一审计或前端显示当作链上协议安全证明。具体协议必须锁定合约地址、部署网络、源码版本、依赖、权限和核验区块。
