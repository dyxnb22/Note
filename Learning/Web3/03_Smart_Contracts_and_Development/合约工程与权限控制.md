# 合约工程与权限控制

智能合约把状态和可执行规则放到链上。阅读合约时，先弄清楚它维护什么状态、谁能改变状态、失败时会发生什么，再看管理权限和升级路径。

## 合约如何工作

- **状态**：合约存储的数据，例如余额、配置或当前所有者。
- **函数**：定义调用者可以请求的操作。`view` 函数只读取状态；状态变更调用由交易执行并消耗 Gas。
- **权限检查**：限制哪些地址可以执行敏感操作。检查遗漏或权限主体设置错误，可能让任意调用者改变关键状态。
- **事件**：把状态变化写入交易日志，供客户端和索引器观察；事件不是合约状态，也不能代替链上读取。
- **回滚**：未被捕获的 `revert` 等失败会回滚该调用中的状态变更；调用者仍可能支付已消耗的 Gas。

链上代码与状态公开可检查，外部调用者可以反复尝试边界条件。部署后如何修复，取决于合约是否设计了升级机制以及谁掌握升级权限，因此升级能力本身也是信任与风险边界。

## 一个最小的权限示例

下面用 OpenZeppelin Contracts 5.x 的 `Ownable` 展示单一所有者如何控制写操作。示例只保存一个整数，不托管用户资产。

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {Ownable} from "@openzeppelin/contracts/access/Ownable.sol";

contract Box is Ownable {
    uint256 private _value;

    event ValueChanged(uint256 newValue);

    constructor(uint256 initialValue) Ownable(msg.sender) {
        _value = initialValue;
    }

    function store(uint256 newValue) external onlyOwner {
        _value = newValue;
        emit ValueChanged(newValue);
    }

    function retrieve() external view returns (uint256) {
        return _value;
    }
}
```

- 部署者成为初始 `owner`；之后只有该地址能调用 `store`。
- `retrieve` 不受所有者限制，任何人都能读取当前值。
- `onlyOwner` 是访问控制检查；事件方便外部系统跟踪更新，但真正的当前值仍以合约状态为准。
- 如果 `store` 中的检查失败，状态不会被部分更新。

运行此示例需要安装 OpenZeppelin Contracts 5.x。它用于理解权限边界，不是可直接用于管理资金的生产合约。

## 所有权、角色、多签与时间锁

| 机制 | 适用情形 | 主要检查点 |
|---|---|---|
| `Ownable` | 一类敏感操作由一个管理主体控制 | 所有者地址是谁；是否能转移或放弃所有权；失去所有者后哪些功能无法使用 |
| `AccessControl` | 不同职责需要不同权限 | 每个角色能做什么；谁能授予/撤销角色；默认管理员权限如何保护 |
| 多签钱包 | 关键操作需要多个签名者共同批准 | 签名门槛、成员独立性、密钥恢复与成员变更流程 |
| 时间锁 | 高影响操作需要公告和等待期 | 延迟是否足以让相关方审查或退出；紧急操作是否绕过等待期 |

多签是由多个授权者共同控制账户的机制，不是 Solidity 语言关键字。它可以作为合约的 owner 或管理员地址，和合约自身的角色控制配合使用。时间锁提供审查窗口，但不保证待执行操作本身正确。

权限越集中，操作越快，单点失误或密钥泄露的影响也越大；权限拆分和审批流程会增加协作成本。不要只确认代码里有 `onlyOwner`，还要沿地址关系查明 owner 最终由谁控制。尤其要检查升级、暂停、铸币、资金转移、角色授予等高影响权限是否过度集中。

## 审查与测试顺序

1. 列出资产、状态变量和外部可调用函数，明确哪些操作会改变状态。
2. 对每个敏感函数追踪调用者限制，并沿 owner、角色管理员、多签成员等关系查到实际控制人。
3. 检查成功路径、拒绝路径和异常路径：权限不足时是否回滚，外部调用失败时状态是否一致。
4. 验证升级权、暂停权和资金权的边界；检查所有权转移、角色增删和密钥轮换流程。
5. 写测试覆盖未授权调用、授权调用、权限变更和关键业务不变量；对涉及资产和外部调用的合约，还要单独分析重入、数值边界和极端状态。
