# 钱包、私钥、签名和地址

私钥控制签名能力，地址用于公开识别与接收资产，钱包提供密钥管理、签名和交互。钱包软件不等于交易所账户，也不等于业务后端。在非托管钱包中，私钥由本地或硬件等受控方式保存，不能暴露给应用服务器或第三方应用。

## 签名登录的调用顺序

在一个常见的签名登录流程中，服务端发出 nonce，钱包让用户签署相应消息，服务端验签后建立 Session 或 JWT 会话。应用需要的是对这条消息的签名，不应要求用户把私钥交给服务器或第三方应用。

验签还要核对消息用途、上下文、时间范围与重放保护。证明某地址的控制能力后，后端仍需判断它对业务资源拥有哪些权限。

## 签名、授权与转账分开看

签名可以用于消息，也可以用于交易。签署登录消息、批准协议使用代币和直接转账，会产生不同的权限或状态变化。不能只看到钱包弹窗就把它们当成同一件事。

例如，批准代币额度与实际扣走代币是不同操作。检查时先看消息或交易内容，再看批准对象与用途；既要防止私钥泄露，也要防止用正确密钥签署了错误内容。

## 核对控制权和展示内容

读钱包流程时，确认密钥由用户、本地设备、硬件或托管方中的谁持有；再查看用户看到的内容是否足以理解签名范围。授权还应有明确额度、用途与可撤销方式。

地址是公开标识，不能当密码。钱包可以提供签名入口，业务权限和会话管理仍由应用按实际规则实现。
