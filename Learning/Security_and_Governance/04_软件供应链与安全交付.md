# 软件供应链与安全交付

安全交付要证明“运行中的制品来自可追溯的源代码、依赖和构建过程”，而不只是扫描一次代码。

## 1. 供应链对象

至少盘点：

- 源代码、分支和 Review。
- 第三方依赖、基础镜像和构建工具。
- CI Runner、密钥和缓存。
- 二进制、容器、模型、Prompt、工具和配置制品。
- 发布渠道、包仓库、部署账号和回滚版本。

## 2. 最小控制

- 依赖版本和来源可锁定。
- 构建过程尽量可重复。
- CI 使用短期、最小权限凭证。
- 测试、扫描和人工 Review 有明确门槛。
- 制品包含版本、来源、构建时间和依赖清单。
- 生产只能部署已验证制品。
- 紧急修复有审计和事后补齐流程。

扫描结果不是风险判断的终点。要按可利用性、暴露面、权限、补丁可用性和业务影响排序。

## 3. AI 制品

模型权重、数据集、Embedding、Prompt、工具 Schema 和 Eval 集合同样是供应链对象。要记录：

- 来源与许可。
- Hash 和版本。
- 训练/构建代码。
- 评估结果和已知限制。
- 发布审批和回滚对象。

## 4. 演练

模拟：

- 依赖出现高危漏洞。
- 构建缓存被篡改。
- 镜像与源码版本不一致。
- 发布后发现模型或 Prompt 回归。
- 生产密钥出现在 CI 日志。

验收标准：能定位受影响制品、暂停发布、撤销凭证、回滚并保存证据。
