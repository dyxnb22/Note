# 身份、权限与秘密生命周期

认证回答“你是谁”，授权回答“你能对哪个资源做什么”，审计回答“事后能否证明谁在什么条件下做了什么”。

## 1. 身份分类

不要把下列身份混成一个用户 ID：

- 真实用户和组织成员。
- 租户、组织和资源所有者。
- 服务账号、任务和部署身份。
- Agent Run、工具和审批人。
- 外部 Provider、Webhook 和回调来源。

每种身份的生命周期、凭证、权限和撤销方式都不同。

## 2. 授权检查

一次敏感操作至少检查：

~~~text
主体身份 + 租户/组织
资源归属 + 资源状态
动作 + 作用域
当前认证强度
时间/地域/设备/审批条件
审计与幂等要求
~~~

前端隐藏按钮不是授权。只在 API 入口做粗粒度检查，也不能替代资源级和字段级边界。

## 3. 秘密生命周期

秘密需要：

1. 生成：使用合适的随机性和最小范围。
2. 存储：进入秘密系统，不进入代码、镜像和普通日志。
3. 使用：短时获取、最小权限和明确受众。
4. 轮换：支持新旧凭证短暂并存和回滚。
5. 撤销：发现泄露后能快速失效。
6. 复盘：追踪访问、泄露面和补救范围。

## 4. Agent 特有边界

模型输出、工具结果、网页内容和上传文件都不是权限授予者。Agent 可以提出动作，但权限必须由确定性策略、工具执行器和审批流程决定。

## 5. 评审真实系统时检查

为一个多租户服务建立身份和权限矩阵，测试：

- 同租户不同用户。
- 跨租户资源访问。
- 被撤销用户的旧 Token。
- Agent 代表用户执行高风险操作。
- 秘密出现在错误、Trace、备份和导出中的情况。
