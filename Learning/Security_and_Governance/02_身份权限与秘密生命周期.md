# 身份、权限与秘密生命周期

认证建立调用者的身份，授权判断这个身份能对某个资源执行什么动作，审计保存当时的决定与结果。三者沿一次请求协作，不能由“已经登录”替代全部判断。

## 从身份到具体资源

用户、租户、服务账号、部署进程与 Agent 任务具有不同的生命周期。用户所属租户不等于资源必然归属同一租户，服务持有的系统凭证也不代表它能替任意用户访问任意数据。

设用户 U 属于租户 A，并能编辑自己的导出任务；请求却传入租户 B 的任务 ID。服务需要读取可信的资源归属并校验动作，不能因为 U 已认证或前端显示了按钮就直接返回文件。

| 调用情况 | 判断依据 |
|---|---|
| 用户读取本租户自己的任务 | 身份、资源归属与读权限 |
| 同租户用户修改他人任务 | 是否存在明确的共享或管理授权 |
| 用户请求另一租户任务 | 租户边界与额外授权，默认不能沿用本租户权限 |
| 后台任务或 Agent 代用户操作 | 服务身份与被委托权限的有效范围 |

资源状态、字段范围、有效期和审批条件还会进一步收窄允许的操作。客户端提供的租户 ID、角色或审批结果都需要与服务端可信信息核对。

## 权限怎样结束

用户离职、移出租户、资源转移或授权到期，都可能让先前允许的请求变为不允许。令牌是否仍未过期与权限是否仍有效，是不同的判断。

撤销可以依赖会话状态、令牌吊销或受限的有效期等机制，具体方案要说明传播延迟与检查失败时的行为。异步任务恢复时也应按其授权约定重新判断，避免旧任务无限保留已经撤回的能力。

## 秘密从生成走向撤销

密钥与令牌按用途和受众生成，存入秘密管理系统，在执行时以最小范围使用；代码、镜像、普通日志和错误信息不应成为它们的分发渠道。

轮换需要让调用方有机会取得新凭证，并在计划窗口结束后撤销旧凭证。泄露处置还要追踪副本、缓存、部署环境与使用记录，确认旧秘密是否仍能被某条路径继续使用。

## Agent 提案怎样进入执行边界

模型输出、工具结果和网页内容可以提供信息，不能授予权限。执行器根据已认证主体、资源、动作、范围与审批状态决定是否执行，并记录决定与实际结果。

同一原则也适用于普通服务的回调与后台任务。授权范围要在每次跨越信任边界时保持明确，具体代理场景可对照[身份治理与委托](../Agent/07_可靠性与安全/身份治理与跨Agent.md)。
