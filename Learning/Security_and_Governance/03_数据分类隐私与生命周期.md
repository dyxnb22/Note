# 数据分类、隐私与生命周期

数据风险取决于内容、用途、可关联性和访问范围。把一列移出日志只能改变其中一条暴露路径，原文、缓存、导出和派生制品仍可能继续保存同样的信息。

## 分类连接用途与访问范围

公开资料、内部业务记录、个人标识、凭证和关键业务事实具有不同后果。同一个字段放进不同组合后，也可能改变识别能力：换成随机用户 ID 不会自动切断它与其他记录的关联。

收集一个字段前，先说明它服务什么功能、谁需要使用、需要多高精度以及保存多久。聚合、降低精度或减少字段可以降低暴露，但仍需结合具体用途判断；无限保留会同时扩大访问、错误传播和维护范围。

## 沿一份文档跟踪数据副本

设用户上传一份内部文档供知识库问答。原文进入对象存储，解析生成文本，文本再变为切片、向量、关键词索引和引用；请求日志、缓存与外部模型输入可能形成额外副本。

这些副本需要共同保留来源、版本、租户、权限和处理状态。检索取得一段内容时，既要确认用户仍有访问权，也要能够追溯它来自哪个原始版本。数据进入训练、评测或第三方服务时，还要记录用途、许可与原文接触范围。

## 删除如何传播到派生数据

源文档删除后，处理流程先记录删除事实，停止新的摄取与检索，再清理文本、切片、索引和缓存。每一步分别记录完成与失败，使重试能继续清理同一来源，而不重新产生副本。

只查询主库发现记录不存在，不足以证明向量索引或旧缓存已经不可返回内容。验证应沿来源 ID 和版本检查实际检索与引用；备份的保留窗口、恢复后的删除记录重放也需要有对应规则。

模型制品与训练数据、外部 Provider 与本地存储具有不同处理路径。原文删除是否意味着某个派生制品也应停止使用，需要根据其用途与记录单独处理，不能由主库的一次删除推定全部完成。

## 把生命周期变为可恢复过程

收集、校验、使用、共享、归档与删除分别具有负责人、权限和审计记录。导出和恢复尤其容易重新扩大访问范围，需要沿原有归属与限制继续检查。

故障发生时，能够回答哪些副本已经处理、哪些仍在等待，才能解释当前风险并继续恢复。生命周期管理由此成为跨存储的状态过程，相关状态与删除传播也见[知识摄取与版本管理](../Agent/06_RAG与知识库/知识摄取与GraphRAG.md)。
