# 数据分类、隐私与生命周期

隐私治理不是在日志里删除几个字段，而是从收集目的、访问范围、使用方式、保留期限和删除证据开始。

## 1. 数据分类

可以按风险而不是按文件格式分类：

- 公开数据。
- 内部业务数据。
- 个人数据和可关联标识。
- 敏感个人数据、凭证和财务信息。
- 关键业务事实、模型制品和安全证据。

同一字段在不同上下文中的风险可能不同。匿名 ID、组合字段和低敏字段也可能重新识别个人。

## 2. 数据最小化

对每个字段回答：

- 为什么收集？
- 谁需要访问？
- 什么时候使用？
- 是否可以降低精度、脱敏或聚合？
- 何时删除或匿名化？
- 用户能否查看、导出、更正或撤回？

为了“以后可能有用”无限保存，会扩大泄露、合规、成本和错误传播的范围。

## 3. 生命周期

~~~text
收集 → 校验 → 使用 → 共享/导出 → 归档 → 删除/匿名化
~~~

每个阶段都要有所有者、权限、版本、审计和失败处理。备份、缓存、向量索引、日志、模型训练集和第三方 Provider 不能因为不在主数据库中就被忽略。

## 4. 引用和训练数据

进入 RAG、训练或评测的数据需要记录：

- 来源、许可和用途。
- 版本、时间和删除传播方式。
- 权限、租户和引用范围。
- 脱敏规则和误删风险。
- Provider 是否接触原文。

删除源数据后，缓存、索引、备份和衍生制品是否仍包含它，需要单独设计。

## 5. 评审真实系统时检查

为一个知识库或订单系统建立数据清单，至少覆盖主库、日志、缓存、备份、搜索索引和模型输入，写出保留、删除、导出和审计路径。
