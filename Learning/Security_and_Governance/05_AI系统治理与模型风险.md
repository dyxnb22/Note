# AI 系统治理与模型风险

AI 系统的风险来自模型、数据、工具、权限、反馈和组织流程的组合，不能只用一次准确率或安全测试概括。

## 1. 分层看风险

- 模型：幻觉、偏差、越权指令跟随、能力不稳定。
- 数据：来源、许可、敏感信息、污染、代表性和删除传播。
- Context：检索权限、提示注入、过时信息和引用缺失。
- 工具：参数、权限、网络、文件、外部副作用和可撤销性。
- 运行：预算、延迟、Provider、版本、状态恢复和审计。
- 组织：责任人、审批、用户告知、事故响应和停用权。

## 3. 评测不只看答案

高风险 Agent 要评估：

- 任务成功和用户价值。
- 工具选择、参数和调用顺序。
- 权限违反、数据外传和提示注入。
- 失败后是否停止、澄清或接管。
- 步数、Token、费用和延迟。
- 重复执行和外部副作用。

评测集应包含正常、边界、恶意、权限、故障和恢复样本，并与版本绑定。

## 4. 人机协同

人工审批不是“把所有请求弹窗确认”，而是按动作风险、可逆性、金额、影响范围和用户期待分级。低风险可自动执行，高风险先展示计划、Diff、目标、权限和副作用。

## 5. 评审真实系统时检查

为一个 Agent 工具建立风险登记表，覆盖模型、数据、Context、工具、运行和组织层；每项风险至少有预防、检测、缓解、审计和回滚动作。
