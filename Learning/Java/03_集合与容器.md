# 03 集合与容器

先确定数据需要保存什么关系，再选择容器：List 保留位置和重复值，Set 根据相等或比较规则去重，Map 将键映射到值，Queue/Deque 表达待处理顺序。接口的语义、实现的成本与并发协议需要一起考虑。本章完整程序使用 JDK 17，可用 java -ea 运行断言。

## 容器、视图与可变性

数组长度固定，可保存基本类型或引用；泛型集合保存引用，基本类型需装箱。Collection 是 List、Set、Queue 等接口的共同上层，Map 独立描述键值关系；Collections 则是排序、查找与包装等静态工具类。

### 集合的可变性与类型边界

Arrays.asList 返回由数组支持的定长视图，set 会回写数组，add/remove 则不受支持。new ArrayList<>(view) 复制元素引用并允许结构修改；List.of 与 List.copyOf 提供不可修改列表，但都不是对元素对象做深拷贝。

```java
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;

public class CollectionViewsDemo {
    public static void main(String[] args) {
        String[] source = {"a", "b"};
        List<String> view = Arrays.asList(source);
        List<String> snapshot = List.copyOf(view);
        view.set(0, "x");
        assert source[0].equals("x");
        assert snapshot.equals(List.of("a", "b"));
        try {
            view.add("c");
            throw new AssertionError("定长视图不支持扩容");
        } catch (UnsupportedOperationException expected) {}

        List<String> mutable = new ArrayList<>(view);
        mutable.add("c");
        assert mutable.size() == 3 && source.length == 2;
        List<String> element = new ArrayList<>();
        List<List<String>> shallow = List.copyOf(List.of(element));
        element.add("shared");
        assert shallow.get(0).equals(List.of("shared"));

        int[] numbers = {1, 2};
        assert Arrays.asList(numbers).size() == 1; // 元素是整个 int[]
    }
}
```

不可修改结构不等于元素不可变；数组视图也不等于独立快照。设计返回值时，应明确调用方能否改结构、能否改元素，以及原持有者的修改会不会被观察到。原始类型 List 会绕过泛型检查，应保留元素类型约束。

### 迭代器与遍历

对 ArrayList 按下标遍历通常是 O(n)，对 LinkedList 反复 get(i) 却会变成 O(n²)。增强 for 对集合使用迭代器，对数组则按数组访问规则执行，不能把两者都理解成 Iterator。

遍历时删除使用该迭代器的 remove（前提是实现支持）或容器提供的 removeIf。普通 fail-fast 迭代器会尽力发现非法结构修改，但 ConcurrentModificationException 既不保证每次出现，也不是同步机制。同步包装器的遍历仍需按其约定持有包装对象的锁。

ListIterator 支持前后移动及可选的 set/add/remove。Stream 适合转换和聚合，不能在流水线中随意修改其数据源。并发集合常用弱一致迭代器，CopyOnWriteArrayList 使用创建时的数组快照；后者不会复制每个元素的内部状态。

## List 的位置与访问成本

| 实现 | 保存方式 | 主要成本与边界 |
|---|---|---|
| ArrayList | 动态数组 | 随机访问 O(1)，尾部追加均摊 O(1)，中间插删需移动元素 |
| LinkedList | 双向链表 | 两端操作 O(1)，按下标定位 O(n)，已定位迭代器的局部插删便宜 |
| Vector | 同步动态数组 | 方法级同步的历史实现，复合操作仍需协议 |
| CopyOnWriteArrayList | 写入时复制数组 | 适合小规模、读远多于写的快照读取 |

ArrayList 在 OpenJDK 17 中延迟分配默认数组，扩容通常约为原容量 1.5 倍；这是实现策略，不是 List 接口承诺。已知规模时预估容量可减少复制，但过度预分配也会占用内存。

add 涉及容量判断、元素写入和 size 更新，普通 ArrayList 的并发写不安全。外部锁、同步包装、写时复制或减少共享分别解决不同需求；只把引用声明为 volatile 不能保护内部多步更新。

## Map 的键与查找

### 哈希、有序与插入顺序 Map

| 实现 | 顺序规则 | 相等与并发边界 |
|---|---|---|
| HashMap | 不保证遍历顺序 | hashCode 定位，equals 判等，非线程安全 |
| LinkedHashMap | 插入顺序或访问顺序 | 在哈希索引之外维护访问链，非线程安全 |
| TreeMap | 自然顺序或 Comparator | 比较结果为 0 时视为同键，非线程安全 |
| Hashtable | 不保证顺序 | 方法级同步的历史实现，不接受 null 键和值 |

HashMap 支持 null 键和值，get 返回 null 时需用 containsKey 区分缺失与映射到 null。TreeMap 的自然排序不接受 null 键，明确支持 null 的比较器则可改变这一规则。LinkedHashMap 的访问顺序配合 removeEldestEntry 可形成简单 LRU，访问本身也可能修改链表。

### HashMap 的定位与插入

键先计算哈希，再映射到桶；同桶内还必须用相等规则找键，碰撞不表示相等。新增键才增加 size，已有键只替换值。相等对象必须具有相同 hashCode，入表后不能改变影响 equals/hashCode 的字段。

OpenJDK 17 的容量为 2 的幂，桶位置可用 (capacity−1)&hash。容量翻倍时，每个旧节点只需按新增的那一位拆到原桶或原桶加 oldCapacity，默认负载因子为 0.75。负载因子与扩容是空间、复制和碰撞成本的折中，不是业务数据量上限。

冲突链较长且数组容量至少 64 时可树化，小表则优先扩容；桶收缩后还可能退回链表。树化缓和严重碰撞，但不是对任意键都作统一 O(log n) 查询承诺，也不提供 Map 的有序遍历接口。AVL 与红黑树都维持对数高度，平衡条件与更新策略不同，不能仅据名称断言实际查询一定更快。

旧 JDK 7 的扩容链表问题属于历史实现，不能据此推断当前版本的内部路径；普通 HashMap 在任何情况下都没有并发写安全保证。[HashMap API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/HashMap.html)

### Map 的键、值与条目遍历

同时需要键和值时遍历 entrySet，只有键用 keySet，只有值用 values；这些集合通常是映射的视图，不是独立副本。支持删除的条目迭代器可以在遍历时删除对应映射，具体可变性仍由 Map 实现决定。

## Set 与比较规则

HashSet 通过哈希与 equals 去重，LinkedHashSet 还保留插入顺序，TreeSet 通过自然顺序或比较器去重。比较结果为 0 与 equals 不一致时，树集合和哈希集合可能对同一批对象给出不同大小，BigDecimal 的不同 scale 就是一个例子。

Comparable 定义类型的自然顺序，Comparator 定义外部排序策略。比较必须保持反对称性和传递性；整数比较使用 Integer.compare，避免相减溢出。下面把全部记录字段纳入自然比较，使 compareTo 为 0 与 record 的 equals 保持一致。

```java
import java.util.Comparator;
import java.util.List;
import java.util.TreeSet;

public class StudentOrderingDemo {
    record Student(int id, int score, String name) implements Comparable<Student> {
        private static final Comparator<Student> ORDER =
                Comparator.comparingInt(Student::score).reversed()
                        .thenComparingInt(Student::id)
                        .thenComparing(Student::name);
        public int compareTo(Student other) { return ORDER.compare(this, other); }
    }
    public static void main(String[] args) {
        Student a = new Student(1, 90, "Ada");
        Student b = new Student(2, 90, "Bo");
        Student c = new Student(3, 80, "Cy");
        assert new TreeSet<>(List.of(c, b, a)).first().equals(a);
        assert a.compareTo(new Student(1, 90, "Ada")) == 0;
        assert a.equals(new Student(1, 90, "Ada"));
        assert List.of(a, b).stream().sorted(Comparator.comparing(Student::name))
                .toList().equals(List.of(a, b));
    }
}
```

本例要求 name 非 null。实际业务若按 ID 判断实体相等，则需同时设计 ID 的稳定性和排序目的，不能照搬这套值对象比较规则。

## 并发集合保护到哪一层

ConcurrentHashMap 不接受 null 键和值，提供 putIfAbsent、compute、merge 等单键原子操作。两个独立调用组成的“先查再改”不会自动变成原子事务，跨多个键的不变量也仍需额外协议。

```java
import java.util.concurrent.ConcurrentHashMap;

public class ConcurrentFrequencyDemo {
    public static void main(String[] args) throws InterruptedException {
        var counts = new ConcurrentHashMap<String, Integer>();
        Runnable add = () -> {
            for (int i = 0; i < 10_000; i++) counts.merge("requests", 1, Integer::sum);
        };
        Thread first = new Thread(add);
        Thread second = new Thread(add);
        first.start(); second.start();
        first.join(); second.join();
        assert counts.get("requests") == 20_000;
    }
}
```

OpenJDK 17 中空桶插入使用 CAS，冲突更新结合桶级同步，扩容可以协作迁移；JDK 7 的 Segment 是另一套历史实现。调用方首先依赖原子API的行为约定，而不是把某个版本的内部锁结构当成业务保证。

CopyOnWriteArrayList 的写入复制数组，迭代看到旧快照；ConcurrentSkipListMap/Set 支持并发有序访问。它们各自的迭代规则都不等于对整个业务状态拍一张原子快照，容器线程安全也不替代元素对象的同步。

## Queue、Deque 与优先队列

Queue 规定入队、取队首和查看队首的接口，不统一承诺 FIFO。ArrayDeque 可用于 FIFO 或栈，PriorityQueue 则按优先级决定队首，迭代它并不保证按优先级排序；需要有序取出时反复 poll。

| 操作 | 特殊返回值版本 | 异常版本 | 失败条件 |
|---|---|---|---|
| 入队 | offer 返回 false | add 抛 IllegalStateException | 容量限制使本次无法插入 |
| 取出 | poll 返回 null | remove 抛 NoSuchElementException | 队列为空 |
| 查看 | peek 返回 null | element 抛 NoSuchElementException | 队列为空 |

满队列仍可以正常 poll 或 peek，不能把“满”当成出队失败条件。offer 只把容量不足表达成 false；非法元素、类型或 null 仍可能抛异常。通常不存 null，避免与空队列的返回值混淆。[Queue API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/Queue.html)

```java
import java.util.NoSuchElementException;
import java.util.concurrent.ArrayBlockingQueue;

public class QueueContractDemo {
    public static void main(String[] args) {
        var queue = new ArrayBlockingQueue<String>(1);
        boolean first = queue.offer("A");
        boolean second = queue.offer("B");
        assert first && !second;
        String removed = queue.poll(); // 满队列仍可取出
        assert "A".equals(removed);
        String missing = queue.poll();
        assert missing == null && queue.peek() == null;
        try {
            queue.remove();
            throw new AssertionError("空队列应抛异常");
        } catch (NoSuchElementException expected) {}
        boolean inserted = queue.offer("B");
        assert inserted;
        try {
            queue.add("C");
            throw new AssertionError("满队列应抛异常");
        } catch (IllegalStateException expected) {}
    }
}
```

BlockingQueue 另提供 put/take 的阻塞等待与带超时 offer/poll。ArrayBlockingQueue 有界，LinkedBlockingQueue 未给容量时上限很大，ConcurrentLinkedQueue/Deque 提供非阻塞并发操作。排序、阻塞、容量与并发是不同维度，要分别选择，不能只按“队列”一个名称推断行为。
