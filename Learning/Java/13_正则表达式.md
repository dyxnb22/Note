# 13 正则表达式

正则先定义哪些字符可以出现、出现多少次，以及匹配需要覆盖的范围，再用 Pattern 与 Matcher 执行。表达式、Java 字符串字面量和替换字符串各自有转义规则，混淆这三层会让看似正确的模式产生不同结果。

## 字符、分组、量词与边界

| 写法 | 作用与前提 |
|---|---|
| . | 默认匹配一个非行终止字符，DOTALL 可改变范围 |
| \d、\w、\s | 默认预定义字符类；UNICODE_CHARACTER_CLASS 会改变其 Unicode 语义 |
| [abc]、[^abc] | 指定字符集合或其补集 |
| *、+、?、{m,n} | 控制重复次数 |
| (...)、(?:...) | 捕获分组与非捕获分组 |
| ^、$ | 受 MULTILINE 等规则影响的边界；$ 还可能匹配最终行终止符之前 |
| \A、\z | 整个输入的起点与严格终点 |

选择分支在模式中写为 a 或 b 之间的竖线，例如 Java 表达式 Pattern.compile("cat|dog")。量词默认贪婪，追加问号会改成勉强匹配，但不保证自动消除高成本回溯。前瞻检查条件而不消费字符，反向引用则要求后续内容等于某个已捕获组。

Java 字面量 "\\d+" 运行时才成为模式 \d+。要把用户给定文本当成普通内容查找，用 Pattern.quote；要把它放进替换结果，用 Matcher.quoteReplacement，二者用途不同。

## Pattern、Matcher 与替换

Pattern 保存编译后的规则，可共享复用；Matcher 保存一次输入的匹配位置和捕获状态，不能作为共享可变匹配器供多个线程同时操作。默认 region 是整个输入，也可以显式缩小范围。

matches 检查整个 region，lookingAt 从 region 开始尝试，find 向后查找下一段。只有成功匹配后才读取 group/start/end；再次 find 会推进状态，不能把同一个 Matcher 当成无状态谓词。[Matcher API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/regex/Matcher.html)

下面是可独立运行的 JDK 17 程序，使用 java -ea 验证结果。

```java
import java.util.ArrayList;
import java.util.List;
import java.util.regex.Matcher;
import java.util.regex.Pattern;

public class RegexSemanticsDemo {
    public static void main(String[] args) {
        Pattern digits = Pattern.compile("\\d+");
        assert digits.matcher("123").matches();
        assert !digits.matcher("order-123").matches();
        Matcher matcher = digits.matcher("a12 b34");
        List<String> found = new ArrayList<>();
        while (matcher.find()) found.add(matcher.group());
        assert found.equals(List.of("12", "34"));

        Pattern order = Pattern.compile("order-(\\d+)");
        Matcher capture = order.matcher("prefix order-123 suffix");
        boolean matched = capture.find();
        assert matched && capture.group(1).equals("123");
        assert Pattern.compile(Pattern.quote("a+b")).matcher("a+b").matches();

        String replacement = "$5\\item";
        String output = digits.matcher("order-123")
                .replaceAll(Matcher.quoteReplacement(replacement));
        assert output.equals("order-" + replacement);
        assert !Pattern.compile("\\d").matcher("１").matches();
        assert Pattern.compile("\\d", Pattern.UNICODE_CHARACTER_CLASS)
                .matcher("１").matches();
    }
}
```

## 回溯、输入规模与 ReDoS

嵌套量词与相互重叠的选择可能使失败匹配反复尝试大量路径，如长串末尾不符合规则时的 (a+)+。先减少歧义、限制输入长度与允许的表达式，再评估实际失败路径的成本。

标准 Pattern API 没有通用匹配超时参数。外层 Future 超时或取消只可能结束等待，不保证正则执行立即停止；需要强制资源边界时应选择可隔离执行或符合需求的其他解析方式。正则适合词法提取和校验，嵌套数据结构仍应使用相应解析器。
