# 前端应用工程

本篇在[浏览器原理](../CS/12_浏览器原理与前端工程.md)和[TypeScript 工程基础](TypeScript工程基础.md)之上，建立组件、状态、数据、测试、构建和交付主线。具体框架 API 会变化，课程重点是稳定工程边界。

## 1. 应用分层

```text
路由/页面 → Feature/用例 → 领域状态
→ API Client/Cache → 外部服务
```

通用组件不直接依赖具体业务接口；页面不承担所有请求、状态和规则。

## 2. 组件模型

组件输入使用明确 Props，输出通过事件或回调表达。区分：

- 展示组件与业务组件。
- 本地 UI 状态与服务端状态。
- 派生值与真正需要持久化的状态。
- 组合与过度抽象。

不要把可由 Props/查询结果计算的值重复存储，否则会产生同步问题。

## 3. React 渲染心智模型

React 组件是根据输入计算 UI 的函数。Render 阶段应保持纯净；Effect 用于与外部系统同步，不是普通数据计算工具。

依赖数组应反映 Effect 实际读取的响应值。为躲避重复执行而删除依赖，会制造陈旧闭包。

## 4. 状态管理

状态按作用域放置：

- 单组件交互：本地状态。
- 邻近组件共享：提升或 Context。
- 复杂客户端工作流：Reducer/状态机。
- 服务端数据：Query Cache。
- URL：可分享的筛选、分页和导航状态。

全局 Store 不是默认答案。状态机适合多步骤、可取消和有失败恢复的流程。

## 5. 数据请求与缓存

API Client 统一：

- Base URL、认证和 Trace。
- Schema 校验。
- Timeout/AbortSignal。
- 稳定错误映射。
- 重试和幂等。

服务端状态缓存要定义 Key、过期、失效、乐观更新、并发请求去重和回滚。Mutation 成功后不要机械清空全部缓存。

## 6. SSR、SSG 与 Hydration

- CSR：浏览器获取数据并渲染。
- SSR：服务端按请求生成 HTML。
- SSG：构建时生成静态页面。
- Hydration：客户端为服务端 HTML 绑定交互。

服务端与客户端输出不一致会造成 Hydration 错误。时间、随机数、浏览器 API 和身份状态都要明确边界。

## 7. 路由与权限

前端路由守卫只改善体验，不能承担真正授权。服务端必须对每个资源请求做权限判断。

路由级拆包要与真实访问路径结合，避免碎片过多造成请求瀑布。

## 8. 表单

表单需要处理：

- 客户端即时校验和服务端最终校验。
- 字段级与表单级错误。
- 重复提交和幂等。
- 草稿、离开提示和恢复。
- 无障碍 Label、焦点与错误播报。

不要清空失败后的用户输入。

## 9. 测试

- 单元测试：纯函数和状态转换。
- 组件测试：用户可见交互。
- 合同测试：API Schema。
- E2E：登录、支付等关键路径。
- Visual Regression：稳定组件和布局。

优先通过角色、Label 和可见文本查询，不依赖内部 class 或组件实例。

## 10. 构建与 Monorepo

理解依赖图、Tree Shaking、Code Splitting、Source Map 和缓存指纹。Monorepo 需要明确包边界、公共配置、增量构建和发布版本，不能只把所有项目放进同一仓库。

分析 Bundle 时定位依赖来源和重复版本，再决定拆包或替换。

## 11. 性能

围绕 LCP、INP、CLS 和业务交互：

- 减少阻塞资源和请求瀑布。
- 按路由/功能拆包。
- 图片尺寸、格式和懒加载。
- 避免长任务和无效重复渲染。
- 对大列表虚拟化。
- 使用真实用户监控验证。

Memo 不是默认优化，应先证明重新计算确实昂贵。

## 12. 发布与监控

制品携带版本；Source Map 受控上传；错误、性能和 API 失败能关联版本与 Trace。发布支持灰度、功能开关和回滚。

前端回滚还要考虑 CDN 缓存、Service Worker、后端 Schema 和数据库迁移。

## 项目出现对应复杂度时

当正在开发的应用同时包含登录、列表、编辑或长任务时，再按需加入 Schema、取消、缓存、乐观更新、权限、组件/E2E 测试、性能监控和灰度发布；不为覆盖清单额外新建一个练习应用。

## 项目使用时检查

- UI、本地状态、服务端状态和 URL 状态边界清楚。
- Effect 只同步外部系统。
- API 有运行时校验、取消和稳定错误。
- 关键路径可访问、可测试、可监控和回滚。

## 来源与验证边界

浏览器与平台能力以 Web 标准为准，React 与构建工具行为以项目锁定版本的官方文档为准。性能和交互结论需要真实用户指标、目标设备和可用性测试验证。
