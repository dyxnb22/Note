# 配置、密钥与环境治理

配置改变同一程序在不同环境下的行为，密钥则证明访问身份或权限。非敏感默认值与部署声明可以进入版本库；凭据应由受控存储注入，不能因为都来自环境变量就把两类数据按同一规则管理。

## 解析顺序是一份运行契约

假设约定“默认值低于配置文件，配置文件低于环境变量”，同一个超时值才有确定来源；部署平台若通过环境变量注入，仍沿这条规则解析。优先级不是所有框架通用的事实，应由应用明确规定。

启动时将原始文本解析为有类型的配置，校验范围与关联条件。例如 timeout 必须为正、worker 数不能超过资源上限，启用远程存储时必须同时给出地址与认证来源。错误应在启动阶段暴露，业务代码接收已校验配置，而非到处读取整个环境变量表。

诊断时记录配置版本和非敏感有效值，隐藏 token、密码与私钥。既不能只看提交的文件推断实际配置，也不能为了排错把所有环境变量输出到日志。

## 动态刷新要形成一致快照

并非所有项都适合热更新。日志级别可即时切换，连接池或并发上限可能需要重建资源并等待旧任务退出，数据库地址与协议变化则常需要完整发布流程。

动态配置应先完整解析和校验，再一次切换生效快照。若先更新地址、后更新凭据，中间请求会读到不匹配的组合。多实例还应记录各自使用的版本，才能解释灰度期间行为不同的原因。

## 密钥轮换是消费者迁移

轮换不仅是生成新值，还包括发放、消费者切换、验证使用情况和撤销旧值。例行轮换可按协议短暂接受新旧凭据；发生泄漏时应按风险及时撤销，不能机械保留重叠窗口。

最小权限与审计需要落到调用身份、资源范围和有效期。日志、异常、Trace、前端构建产物与缓存都可能携带凭据，脱敏应在这些边界生效。身份与撤销机制见[秘密生命周期](../Security_and_Governance/02_身份权限与秘密生命周期.md)。

## 功能开关需要退出条件

功能开关用于控制发布人群、实验或紧急关闭。每个开关应有负责人、默认行为、作用范围、到期时间和回退方式；实验结束后应清理失去用途的分支，避免把临时选择变成永久状态组合。

安全相关规则在服务端执行，浏览器里的开关不能成为授权依据。关闭一个开关也不会自动撤销已经写入的数据或发出的消息，回退仍须考虑新旧状态的兼容性。
