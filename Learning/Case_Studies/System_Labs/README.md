# 系统实验路线

这里把理论课程转换成可运行、可故障注入、可复盘的系统实验。实验代码可以后续按子目录加入；本页先定义合同、产物和验收标准。

## 通用实验合同

每个实验记录：

- 目标与非目标。
- 环境、版本和资源。
- 基线输入与预期结果。
- 可观测指标。
- 故障注入。
- 实验结果和原始证据。
- 结论边界。
- 清理和恢复步骤。

禁止在生产或未授权环境执行故障注入。

## Lab 01：小型数据库

### 目标

实现页存储、Slotted Page、B+Tree、WAL 和崩溃恢复的最小链路。

### 阶段

1. 固定大小页和记录编码。
2. Buffer Pool。
3. B+Tree 查找、插入和分裂。
4. WAL 与 LSN。
5. Commit/Abort。
6. Checkpoint 与恢复。

### 故障

- 数据页写一半进程退出。
- 日志已写、数据页未写。
- 未提交事务修改已落页。
- 索引分裂中断。

### 验收

随机操作后不变量成立；任意注入点重启后，只出现已提交事务；恢复结果可与参考模型对照。

## Lab 02：解释器与编译器

### 目标

实现表达式和函数语言，串起 Token、Parser、AST、类型检查、解释执行与字节码。

### 阶段

1. Lexer 与错误位置。
2. 递归下降 Parser。
3. 变量、作用域和闭包。
4. 静态类型检查。
5. Stack VM。
6. 常量折叠和死代码删除。

### 验收

解释器和 VM 对同一程序结果一致；Fuzz 输入不导致未受控崩溃；错误能指向源码位置。

## Lab 03：Raft 故障实验

### 目标

验证选主、日志复制、提交和成员故障下的安全性。

### 故障矩阵

- 延迟、丢包、重复和乱序。
- Leader 与多数派隔离。
- Follower 落后后恢复。
- 节点崩溃并重启。
- 旧 Leader 网络恢复。

### 不变量

- 同一任期最多一个 Leader。
- 已提交日志不会被覆盖。
- 状态机只按提交顺序执行。
- 失去多数派时不确认新写入。

## Lab 04：HNSW 与混合检索

### 目标

比较精确 KNN、HNSW、BM25、混合检索和 Reranker。

### 变量

- `M`、`efConstruction`、`efSearch`。
- 向量维度和数量。
- Metadata Filter 选择率。
- Chunk 策略。
- 候选数和 Rerank 数。

### 产物

召回—延迟—内存曲线；错误查询分类；更新、删除和权限失效测试。

## Lab 05：生产性能与 SLO

### 目标

对一个 API 完成容量估算、压测、Profile、Trace、SLO、告警和事故演练。

### 场景

- 阶梯加压与突发。
- 连接池耗尽。
- 慢 SQL。
- 下游超时和重试风暴。
- 内存泄漏。
- 灰度版本性能退化。

### 验收

找到饱和点和 p99 拐点；告警能在用户影响扩大前触发；Runbook 可由另一人执行恢复。

## Lab 06：模型训练到回滚

### 目标

完成数据版本、训练、注册、推理、Canary、漂移和回滚。

### 阶段

1. 数据 Manifest 和切分。
2. 可恢复训练。
3. 模型质量/性能门禁。
4. Shadow 与 Canary。
5. 输入和预测漂移。
6. 回滚模型、预处理和流量。

### 验收

任一线上预测能追溯模型、代码和数据；漂移告警不直接误触发自动再训练；回滚后指标恢复。

## Lab 07：Python、Go、Java 服务对照

### 目标

以同一 API 和负载比较三种运行模型，而不是评判“哪种语言绝对更快”。

### 统一合同

- 相同接口、数据和外部依赖。
- 相同超时、连接池和返回 Schema。
- 相同 CPU/内存限制。
- 预热后测量 p50/p95/p99、吞吐和资源。

### 观察

- Python asyncio/Worker。
- Go Goroutine/GC。
- Java 线程池/JIT/GC。
- 启动、稳态、过载和优雅退出。

### 验收

结论绑定版本、实现、负载和资源；Profile 解释差异；不使用单个 QPS 数字做语言泛化。

## Lab 08：数据流处理

### 目标

实现 CDC → Kafka → Event-time Window → Lakehouse/Serving。

### 故障

- 重复、乱序、迟到。
- Consumer/Task 崩溃。
- Schema 新增与不兼容变更。
- Checkpoint 恢复。
- Backfill 与在线结果重叠。

### 验收

窗口结果和离线重算对账；重复不产生重复事实；删除和 Schema 演进可追踪。

## 实验推进顺序

```text
编译器/解释器 → 小型数据库 → Raft
→ 服务性能/SLO → 三语言对照
→ 数据流处理 → HNSW → ML 交付
```

顺序不是强制；优先选择能服务当前项目的一项。每个实验完成后，把稳定结论回写主题文档，项目特殊实现保留在本目录。
