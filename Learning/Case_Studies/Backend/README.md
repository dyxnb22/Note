# 后端业务案例

本目录用真实业务约束验证 DDD、状态机、幂等、消息、缓存和补偿。理论定义仍以 `Learning/Backend` 为主；这里记录项目背景、特殊约束、证据层级和可复现实验。

## 阅读顺序

1. [业务项目能力地图](./业务项目能力地图.md)：先识别交易、营销、支付、库存、消息等项目的共同骨架。
2. [拼团交易平台](./拼团交易平台.md)：用订单、拼团、支付和库存四条状态机验证事务、幂等与补偿。
3. [Redis 轻量游戏状态](./Redis轻量游戏状态.md)：验证短生命周期状态、TTL、乱序、重建与跨语言契约。

## 案例完成标准

- 区分“源码存在”“配置可见”“测试已运行”和“外部系统已联调”。
- 至少写出一个业务不变量、一条失败链路和一个可重复实验。
- 通用结论回链到主题文档；项目名、模块名和运行证据留在案例中。
- 无法复现的结论明确标为设计推断，不把学习项目描述为生产就绪。
