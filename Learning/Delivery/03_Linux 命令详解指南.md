# Linux 命令与系统排查

Linux 把文件、进程和网络状态暴露为可查询的对象。先确定要观察哪种资源，再选择命令；命令输出需要结合时间、权限与进程状态解释。

原理见 [操作系统](../CS/OS.md)，协议见 [计算机网络](../CS/Network.md)。本页命令用于 Linux，部分参数在 macOS/BSD 上不同。

## 文件与目录操作

路径定位文件，目录项把名称连接到 inode。查看与复制关注路径和元数据；删除目录项后，文件占用的空间还可能被打开它的进程保留。

| 命令 | 常用参数与行为 | 示例 |
|---|---|---|
| `pwd`、`cd` | 查看与切换工作目录，`cd -` 返回上一目录 | `cd /var/log` |
| `ls` | `-l` 元数据，`-a` 隐藏文件，`-h` 可读大小，`-t` 按修改时间 | `ls -laht` |
| `mkdir` | `-p` 创建缺失父目录 | `mkdir -p data/cache` |
| `cp` | `-r` 递归，`-p` 保留元数据 | `cp -rp source_dir backup_dir` |
| `mv` | 移动或改名，跨文件系统可能涉及复制 | `mv old.log archived.log` |
| `rm` | 删除目录项，`-i` 交互确认 | `rm -i temp.log` |
| `find` | 按类型、名称、时间与路径筛选 | `find /var/log -type f -name '*.log' -mtime +30 -print` |
| `locate` | 查询预先建立的文件名数据库，可能滞后 | `locate app.log` |
| `ln` | 默认硬链接，`-s` 为符号链接 | `ln -s app.log current.log` |

`find -mtime` 按完整 24 小时周期向下取整，`+30` 不是精确的“超过 30 天”。`locate -d` 指定文件名数据库，不表示天数。

硬链接连接同一 inode，通常不能跨文件系统；软链接保存目标路径，目标移动或删除后可能失效。

## 文本查看与处理

| 命令 | 读取与转换方式 |
|---|---|
| `cat` | 输出短文件 |
| `less` | 分页查看；`/` 搜索，`n` 下一处，`q` 退出 |
| `head -n 20`、`tail -n 100` | 读取开头或结尾指定行数 |
| `tail -f` | 持续等待新增内容 |
| `grep` | `-n` 行号，`-i` 忽略大小写，`-v` 排除，`-r` 递归 |
| `awk` | 按字段提取或累计 |
| `sed` | 按规则替换和筛选；`-i` 会修改原文件 |
| `wc` | `-l` 行数，`-w` 单词数，`-c` 字节数 |

管道传递字节，后一条命令从标准输入读取：

```bash
tail -f app.log | grep --line-buffered ERROR
ps aux | awk '{print $2}'
grep ERROR app.log | wc -l
awk '{sum += $5} END {print sum}' data.txt
```

实时过滤时，行缓冲影响结果何时显示。单次 `grep` 命中不能代替时间窗口、错误比例和上下文分析。

## 进程与服务管理

| 命令 | 观察或操作对象 |
|---|---|
| `ps aux`、`ps -ef` | 某一时刻的进程、参数与所属用户 |
| `top`、`htop` | 持续观察 CPU、内存与进程变化 |
| `top -H -p PID` | 查看指定 Linux 进程内的线程 |
| `kill -15 PID` | 发送 SIGTERM，应用可以执行收尾 |
| `kill -9 PID` | 发送 SIGKILL，应用无法捕获并收尾 |
| `systemctl status SERVICE` | 查看 systemd 服务状态 |
| `journalctl -u SERVICE -n 100` | 查看服务近期日志 |
| `nohup` | 调整终端退出相关行为；长期服务通常交由进程管理器托管 |

信号发送成功不等于业务已安全完成。优雅退出还需要应用停止接单、等待在途工作并释放资源。

## 资源使用与性能排查

| 命令 | 主要信息 |
|---|---|
| `free -h` | 内存、缓存与可用内存 |
| `df -h` | 各挂载点空间 |
| `df -i` | inode 使用量 |
| `du -h --max-depth=1 PATH` | 指定目录下的占用分布 |
| `uptime` | 运行时长与负载均值 |
| `vmstat 1` | 运行队列、内存、换页、I/O 与 CPU 时间 |
| `iostat -xz 1` | 设备 I/O 吞吐、等待与利用情况，需要对应工具包 |

CPU 使用率表示 CPU 时间消耗，load average 包含可运行任务和部分不可中断等待，不能直接理解成 CPU 百分比。`free` 中的缓存也不能直接等同于内存泄漏。

## 权限与用户管理

权限按所属用户、所属组和其他用户三组表达，每组的读、写、执行分别对应 4、2、1。`755` 是所有者 `rwx`、其余 `r-x`；`644` 是所有者 `rw-`、其余 `r--`。

| 命令 | 作用 |
|---|---|
| `chmod 755 script.sh` | 设置文件权限 |
| `chmod +x script.sh` | 增加执行位 |
| `chown USER:GROUP PATH` | 改变所属用户与组 |
| `whoami`、`id` | 查看当前身份与组 |
| `sudo` | 按 sudoers 策略执行授权命令 |

目录上的执行位允许进入和按名称访问，读取位允许列出名称；文件执行位表示可以尝试执行，实际仍需格式、解释器和挂载等条件支持。

## 网络排查与远程连接

| 命令 | 观察对象与常见用法 |
|---|---|
| `ip addr`、`ip route` | 接口地址与路由 |
| `ping HOST` | ICMP 可达性；失败不必然表示应用不可达 |
| `curl -I https://example.com` | 响应头 |
| `curl -v https://example.com` | 连接、TLS 与 HTTP 过程 |
| `ss -tulnp` | 监听套接字；查看其他用户进程可能需要权限 |
| `lsof -i :8080` | 与指定端口有关的文件/进程 |
| `ssh -p 22 USER@HOST` | 远程会话 |
| `scp local.txt USER@HOST:/tmp/` | 文件复制，`-r` 递归目录 |

DNS、路由、端口监听、TLS 与应用响应是不同阶段。按阶段检查，可以避免把任意超时都归因于应用代码。

## 管道、重定向与后台执行

| 语法 | 行为 |
|---|---|
| `\|` | 将标准输出连接到下一进程的标准输入 |
| `>` | 覆盖写入标准输出 |
| `>>` | 追加写入标准输出 |
| `2>` | 重定向标准错误 |
| `2>&1` | 将标准错误连接到当前标准输出目的地 |
| `&` | 交给 shell 后台执行 |

重定向按从左到右处理。`command > app.log 2>&1` 把两种输出写到同一文件；后台运行只改变 shell 等待方式，不能替代重启、健康检查与日志管理。

## 常见排障链路

磁盘空间不足时，先用 `df -h` 定位挂载点，用 `df -i` 区分 inode 耗尽，再用 `du` 缩小范围。删除文件后空间未回收时，检查 `lsof` 中仍打开的已删除文件。

端口冲突时，先查监听与 PID，再看进程启动参数和服务归属；CPU 异常时，先定位进程与线程，再结合语言栈或 profiler。日志排查应固定时间窗口，把 request/task ID 与错误和延迟对应起来。
