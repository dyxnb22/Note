# 大模型基础问答

> 归属边界：本页以模型结构、训练、推理和检索基础为主。RAG、Tool Calling、权限、评测和网关题保留为桥接题，便于形成完整回答；Agent 的循环、状态、工具执行和治理以 [Agent 面试题库](../../Agent面试题库/README.md) 为权威，模型原理长文以 [LLM 基础](../LLM基础.md) 和 `DeepLearning/` 为权威。

## 1. Transformer 为什么重要？

Transformer 用自注意力机制建模 token 之间的关系，相比 RNN 更适合并行训练，也更容易扩展到大规模参数和数据。现代大语言模型大多基于 Decoder-only Transformer。

## 2. Attention 的核心公式是什么？

常见表述是 `softmax(QK^T / sqrt(d_k))V`。Q 表示当前 token 查询什么，K 表示每个 token 提供什么索引，V 表示真正聚合的信息。

## 3. 为什么要除以 `sqrt(d_k)`？

点积维度越高，数值方差越大，softmax 容易过度尖锐，导致梯度不稳定。缩放可以让训练更稳定。

## 4. Decoder-only、Encoder-only、Encoder-Decoder 有什么区别？

Encoder-only 适合理解类任务，如分类和匹配。Decoder-only 适合自回归生成，是主流 LLM 架构。Encoder-Decoder 常用于翻译、摘要等输入输出都较长的任务。

## 5. 什么是 Tokenizer？

Tokenizer 把文本转成 token id。模型不直接理解字符，而是处理 token 序列。不同 tokenizer 会影响上下文长度、成本和多语言效果。

## 6. 上下文窗口越长越好吗？

不一定。长上下文会增加成本和延迟，也可能让模型更难关注关键内容。工程上常结合 RAG、摘要和记忆管理。

## 7. 什么是 KV Cache？

**通用补充：** 生成第 N 个 token 时，前面 token 的 key/value 已经算过；KV Cache 保存每一层历史 token 的 K/V，避免解码阶段反复计算完整前缀。它主要提高逐 token decode 吞吐，不能消除长 Prompt 的 prefill 计算，而且会按层数、KV 头数、头维度、序列长度、批量和精度持续占用显存。

工程上要区分 TTFT（首 token 前的排队、网络和 prefill）与 TPOT/生成吞吐；长上下文、大批量并发时 KV Cache 往往先成为容量瓶颈，需要连续批处理、分页式缓存、长度上限或前缀缓存。Prompt Cache 复用共同前缀，不等于把任意相似问题的 KV 安全复用；模型、前缀 token、采样前输入和缓存策略必须匹配。

> 参考：[JavaGuide：LLM 运行机制](https://javaguide.cn/ai/llm-basis/llm-operation-mechanism.html)、[小林 Coding：AI 大模型/Agent 面试题目录](https://www.xiaolincoding.com/project/xiaolinnote.html)

## 8. 什么是 RAG？

RAG 是先从外部知识库检索相关内容，再把内容作为上下文交给模型回答。它适合知识更新快、需要引用来源、需要降低幻觉的场景。

## 9. RAG 常见失败原因？

文档切分不合理、embedding 模型不匹配、召回结果不准、上下文过长、没有重排、Prompt 没约束引用、缺少评测集。

## 10. Embedding 是什么？

Embedding 是把文本映射成向量，语义相近的文本向量距离更近。RAG 常用 embedding 做相似度检索。

## 11. 向量数据库解决什么问题？

它负责高效存储和检索 embedding，支持近似最近邻搜索、过滤条件、元数据管理。常见选择包括 FAISS、Milvus、Qdrant、pgvector。

## 12. Agent 和普通 Chatbot 的区别？

普通 Chatbot 主要生成文本。Agent 会根据目标进行规划、调用工具、观察结果并继续决策。Agent 的关键是工具执行和控制循环。

## 13. Tool Calling 的本质是什么？

模型输出结构化调用意图，例如函数名和参数；程序解析后执行真实函数。模型不应该直接拥有系统权限。

## 14. ReAct 是什么？

ReAct 是 Reasoning + Acting。模型一边推理，一边选择动作，再根据工具观察结果继续推理。

## 15. 为什么 Agent 要做权限控制？

因为模型可能误判、被提示词注入、生成错误参数。删除、支付、发消息、写数据库等动作都应该确认、审计、可回滚。

## 16. Prompt Engineering 重要吗？

重要，但不能只靠 Prompt。生产系统需要工具设计、检索质量、评测、日志、权限和降级策略。

## 17. 什么是 SFT？

SFT 是监督微调，用高质量指令-回答数据训练模型，让模型更符合任务格式和回答风格。

## 18. 什么是 RLHF？

RLHF 用人类偏好训练奖励模型，再优化语言模型输出，使回答更符合人类偏好。但流程复杂、成本较高。

## 19. 什么是 DPO？

DPO 直接使用偏好数据优化模型，不需要显式训练奖励模型，工程实现比传统 RLHF 更简单。

## 20. 什么是 LoRA？

LoRA 冻结原模型权重，只训练低秩矩阵适配任务。它显著减少可训练参数和优化器状态，降低微调成本。

## 21. 什么时候用微调，什么时候用 RAG？

**通用补充：** 先问要改变的是“输入上下文、外部知识、模型行为还是模型体积”。少量指令、格式和当前任务信息先用 Prompt/Structured Output；知识更新快、需要权限过滤和引用时优先 RAG；大量稳定样本证明模型在风格、术语、分类或工具选择行为上系统性不足时再评估 SFT/参数高效微调；需要把大模型能力迁移到更小模型以降低长期成本和延迟时才考虑蒸馏。

RAG 不会自动修复模型不会执行的任务，微调也不适合频繁写入事实，更不能替代数据库权限和实时查询。选型要用同一回归集比较任务成功率、引用/事实性、延迟、Token、训练与运维成本、安全和更新时效；常见组合是 RAG 提供事实、微调稳定行为，但复杂度必须由指标收益证明。

> 参考：[JavaGuide：RAG 基础概念](https://javaguide.cn/ai/rag/rag-basis.html)、[小林 Coding：AI 大模型/Agent 面试题目录](https://www.xiaolincoding.com/project/xiaolinnote.html)

## 22. 什么是量化？

量化把模型权重从 FP16/BF16 降到 INT8、INT4 等更低精度，以减少显存和提升推理速度，但可能损失精度。

## 23. Temperature 是什么？

Temperature 控制采样随机性。低 temperature 更稳定，高 temperature 更多样。严肃问答、代码、抽取任务通常设置较低。

## 24. Top-p 是什么？

Top-p 又叫 nucleus sampling，只从累计概率达到 p 的 token 集合中采样，用于控制生成多样性。

## 25. 幻觉是什么？

模型生成看似合理但事实错误的内容。减少幻觉的方法包括 RAG、引用来源、拒答策略、结构化输出、评测和人工审核。

## 26. LLM 项目如何评测？

先构建代表性测试集，再分别评估正确性、引用依据、格式遵守、工具选择、延迟、成本和安全性。不能只凭主观感觉。

## 27. LLM-as-judge 有什么风险？

评审模型也会偏见和误判。最好配合明确 rubric、少量人工抽检，以及固定测试集回归。

## 28. 生产级 LLM 网关需要什么能力？

统一模型接口、鉴权、限流、重试、超时、缓存、日志、成本统计、trace、降级、安全过滤和审计。

## 29. Prompt Injection 是什么？

用户通过输入诱导模型忽略系统指令、泄露隐私或执行危险动作。防护要靠权限隔离、输入过滤、工具确认和最小权限。

## 30. 面试如何介绍一个 RAG + Agent 项目？

可以按“业务目标 -> 文档处理 -> 检索策略 -> Agent 工具 -> 评测指标 -> 生产保护”讲。重点说明为什么这样设计、失败怎么处理、如何证明效果变好。

## 31. 没有位置编码会怎样？绝对位置、相对位置和 RoPE 怎么理解？

**通用补充：** 自注意力本身只根据 token 内容计算两两关系，不天然知道顺序；没有位置信息时，交换 token 的排列可能得不到模型需要的顺序差异。绝对位置把位置向量加入 token 表示；相对位置直接刻画 token 间距离；RoPE 通过按位置旋转 Q/K，使注意力点积带上相对位置信息，因而常用于 Decoder-only LLM。

RoPE 不是“上下文无限延长”的保证：模型训练长度、旋转频率、外推缩放方法、注意力计算和 KV Cache 容量仍共同限制长上下文效果。回答版本差异时应说明具体模型可能使用 learned position、sin/cos、RoPE、ALiBi 或其变体，不能把一种实现说成 Transformer 规范。

> 参考主题：[小林 Coding：AI 大模型/Agent 面试题目录](https://www.xiaolincoding.com/project/xiaolinnote.html)；更完整原理见 [[../DeepLearning/09_注意力与Transformer/注意力与Transformer|注意力与 Transformer]]。

## 32. 追问：预训练、SFT、RLHF 和 DPO 分别改变什么？

**通用补充：** 预训练主要从大规模语料学习下一个 token 的分布和通用表示；SFT 用“输入—理想输出”示例教模型遵循任务与格式；RLHF 先从人类偏好学习奖励信号，再用强化学习优化策略；DPO 直接用偏好对优化被选答案相对被拒答案的概率，省去显式奖励模型和在线 RL 的一部分复杂度。

它们都可能引入偏差、遗忘、过度拒答或对标注分布过拟合。工程上要把基座、数据版本、模板、训练参数和评测切片固定，分别检查能力、事实性、格式、安全和长尾；“DPO 更简单”不等于效果必然优于 RLHF，也不能用后训练把最新私有事实可靠写进模型。

> 参考主题：[小林 Coding：AI 大模型/Agent 面试题目录](https://www.xiaolincoding.com/project/xiaolinnote.html)。本题的阶段关系为通用补充，未伪称来自未公开课程正文。

## 33. LLM 推理的延迟和成本怎么拆？优化顺序是什么？

**通用补充：** 不要只报总耗时。一次请求至少拆成排队/路由、输入 tokenization、prefill、首 token 延迟 TTFT、逐 token 延迟 TPOT、输出 token 数、工具/RAG 外部耗时和网络传输；成本按输入、缓存命中输入、输出及额外工具/检索调用分别统计。交互产品重点看 TTFT 与 P95/P99，批处理还要看 tokens/s、GPU 利用率和每任务成本。

优化先减少无价值调用与 token，再做模型路由、Prompt/Context 裁剪、RAG TopK、输出上限和缓存；随后才评估连续批处理、量化、更小模型或蒸馏。量化降低权重显存不代表 KV Cache、网络和排队消失，也可能带来质量损失；任何优化都要在固定质量与安全门槛下比较，不能用更短答案制造“延迟改善”。

> 参考：[JavaGuide：LLM 运行机制](https://javaguide.cn/ai/llm-basis/llm-operation-mechanism.html)、[小林 Coding：AI 大模型/Agent 面试题目录](https://www.xiaolincoding.com/project/xiaolinnote.html)

## 34. 什么是 GRPO？与 PPO 有什么区别？

**通用补充：** GRPO 对同一 prompt 采样一组回答，用组内相对奖励（减组均值、除组标准差）作为优势估计，替代 PPO 的价值网络；更新仍用裁剪目标加 KL 约束。省掉 critic 后显存和训练成本明显下降，特别适合奖励可程序化验证的任务；代价是奖励稀疏或组内得分接近时优势方差大，需要加大组大小或改奖励设计。它与 DPO 的区别在于：DPO 是离线偏好优化，GRPO 是在线采样循环。

更完整的 PPO/GRPO 对比和熵坍塌机制见 [[../LLM基础|LLM 基础]] 的 RL 算法族小节。

## 35. 什么是 MoE？路由和负载均衡怎么工作？

**通用补充：** MoE 把 FFN 换成一组专家加路由器，每个 token 只激活 top-k 个专家：显存按总参数付，算力按激活参数付。路由器给 token 打分选专家；专家容量限制单个专家接收的 token 数，超出的丢弃或走旁路；辅助损失做负载均衡，避免路由坍缩到少数专家；部分实现带始终激活的共享专家。工程代价是专家并行的 all-to-all 通信和更复杂的调度，能力要以目标任务评测为准，不按参数量线性换算。

结构细节见 [[../LLM基础|LLM 基础]] 的 MoE 小节。

## 36. GPTQ 和 AWQ 有什么区别？

**通用补充：** GPTQ 逐层量化，用近似二阶信息估计量化误差并补偿到未量化权重，在高压缩率下控制精度损失；AWQ 用激活统计找出对输出敏感的权重通道，量化前缩放保护，不做反向传播。两者都需要校准数据，效果依赖位宽、分组粒度和 kernel 支持，换模型或数据分布后结论不能照搬，要用困惑度、格式遵从和长尾表现验证。

量化收益与风险的完整对照见 [[../LLM基础|LLM 基础]] 的量化小节。

## 37. 什么是投机解码？什么时候收益不明显？

**通用补充：** 小 Draft 模型一次提出 k 个 token，大 Target 模型一次前向并行验证，用修改后的拒绝采样保证最终分布与 Target 单独生成一致，接受率越高一次验证产出的 token 越多。收益不明显的场景：Draft 与 Target 分布差异大（接受率低）、输出很短、请求主要耗在 prefill 或工具等待、大 batch 下验证并行度已被占用。验证要测端到端 P95 和显存，不只看 Decode 吞吐。

机制细节见 [[../LLM基础|LLM 基础]] 的投机解码小节。

## 38. 什么是熵坍塌？如何识别和处理？

**通用补充：** RL 训练后期策略分布过度集中，模型几乎总输出同一模式，探索和泛化下降。诱因包括奖励被钻空子、KL 约束太弱、数据或目标覆盖不足。识别要靠分布层面指标：策略熵曲线、输出多样性（distinct-n、重复率）、pass@k 与 pass@1 差距拉大、长尾成功率退化；只看平均 reward 或 loss 会错过。缓解手段：熵正则、加强 KL 约束、扩数据和任务覆盖、修奖励定义。

完整机制见 [[../LLM基础|LLM 基础]] 的熵坍塌小节。
