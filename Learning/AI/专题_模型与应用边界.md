# 模型与应用边界

在 LLM 基础之后，用本专题把模型能力连接到检索、工具和生产系统。模型结构与训练以 LLM 基础为主，具体执行与治理以 Agent 课程为主。

## 检索、表示与知识更新

RAG 在生成前检索外部内容，把来源和当前问题一起交给模型。Embedding 提供相似度表示，向量索引支持近邻候选检索；知识系统还需要维护文档与版本，执行访问限制，并处理更新和删除。[FAISS](https://github.com/facebookresearch/faiss) 一类检索库与完整数据库承担的职责不同。

切分不当、表示不匹配、过滤错误、召回不足、排序不佳或引用缺失都会导致失败，应分别观测检索结果与最终回答。机制见 [RAG 与检索](../Agent/06_RAG与知识库/RAG与检索.md)，文档更新与来源治理见 [知识摄取与 GraphRAG](../Agent/06_RAG与知识库/知识摄取与GraphRAG.md)。

## Prompt、RAG、微调与蒸馏

先确定需要改变的是输入信息、外部知识、模型行为还是运行成本。指令与格式可以先调整 Prompt/结构化输出；更新频繁且需要引用的事实适合检索；稳定样本证明存在系统性行为缺口时，再评估微调；将能力迁移到更小模型可以评估蒸馏。

RAG 提供信息，微调调整行为，两者可以组合。比较时固定任务集、质量门槛、权限和更新要求，再记录训练、推理、运维成本。模型训练原理见 [LLM 基础](LLM基础.md)。

## 从生成文本到执行动作

Tool Calling 是模型产生结构化调用意图，再由程序校验并执行。Agent 在目标、状态、工具结果之间继续决策；ReAct 是一种交替使用推理与动作观察的组织方式。控制循环、重试、预算和退出由 Runtime 实现，不能靠一段 Prompt 保证。

基础结构见 [Agent 基础与架构](../Agent/01_基础架构/Agent基础与架构.md)，工具合同见 [Tool Calling 与 MCP](../Agent/04_Tool与协议/Tool%20Calling与MCP.md)。

## 权限与提示词注入

不可信指令可以来自用户，也可以藏在检索文档、网页和工具结果里。输入过滤和提示词约束不能单独构成安全边界；程序应独立检查身份、权限、参数、资源和副作用，对需要审批的动作执行既定审批流程，并留下审计与恢复依据。

具体机制见 [可靠性与安全](../Agent/07_可靠性与安全/可靠性与安全.md)。

## 评测与模型裁判

用代表性样本分别检查任务正确性、事实依据、引用、格式、工具选择、延迟、成本和安全。LLM-as-judge 也会偏置、受顺序影响或误判；评分规则、人工抽查与固定回归集应共同约束评估。

从业务目标、数据处理、检索、动作到结果记录一条完整链路，解释每一步失败如何定位。评测体系见 [评测与可观测性](../Agent/08_评测与可观测/评测与可观测性.md)。

## 推理链路与延迟成本

一次调用包含排队与路由、tokenization、prefill、逐 token decode、网络，以及应用自身的检索/工具耗时。TTFT 表示首 token 等待，TPOT 表示输出阶段每 token 的耗时；端到端 P95/P99 和每任务成本更接近用户体验。

先减少无价值调用、输入与输出，再评估路由、缓存、批处理、量化或更小模型。Prompt Cache 需要匹配前缀和具体服务策略；KV Cache 主要减少重复解码计算，仍占用容量。优化时固定质量门槛，避免把减少任务内容当作提速。

## 网关与生产控制

模型网关可集中处理协议适配、鉴权、限流、超时、可重试错误、成本统计、Trace、降级和审计。业务授权、任务状态及幂等仍由应用维持。不同 Provider 的流式事件、错误和 usage 合同需要显式适配。

继续见 [Provider 适配与框架选型](../Agent/10_模型与推理/02_Provider适配与框架选型.md) 与 [生产工程与系统设计](../Agent/09_工程化与系统设计/01_生产工程与系统设计.md)。
