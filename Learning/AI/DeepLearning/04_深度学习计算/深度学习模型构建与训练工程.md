# 深度学习模型构建与训练工程

本章把模型定义、参数管理、持久化、设备和训练循环放在同一个工程边界中理解。目标是从“会调用现成模型”进入“能维护可复现训练程序”。

## 模型层、块与参数管理
`nn.Module` 是 PyTorch 模型的基本单元：在 `__init__` 注册层，在 `forward` 描述数据流。复杂模型应由可复用 Block 组合，而不是把所有逻辑堆在一个 forward 中。

参数通过 `model.parameters()` 交给优化器；命名模块有助于定位参数。共享参数意味着多个位置引用同一个 layer，而非创建两个数值相同的 layer。修改参数前要理解 autograd：推理或手动初始化使用 `torch.no_grad()`，避免把赋值写进计算图。

## 自定义层、模型读写与 GPU
自定义层适用于框架没有的变换；只要继承 `nn.Module` 并实现 `forward`。模型保存优先保存 `state_dict()`，加载时先创建同结构模型再 `load_state_dict()`；同时保存配置、标签映射和预处理方式，权重本身不足以复现服务。

GPU 的规则简单：模型、输入、标签在同一个 device；将数据移动放在训练循环内。显存不足时先减 batch size、图像尺寸或序列长度，再考虑梯度累积与混合精度；不要用不断调用 `empty_cache()` 代替定位泄漏。

## 训练循环的工程化封装
将训练拆成 `train_epoch`、`evaluate`、`fit`、`save_checkpoint` 和 `metrics`。封装的目的是让实验可靠地替换模型、数据和指标，而不是过早抽象成难读框架。

训练函数接收 model、loader、loss、optimizer、device；验证函数必须 `eval/no_grad`；best checkpoint 按验证指标保存；日志至少包括 epoch、train/val loss、主指标、学习率、耗时。配置使用 dataclass 或 YAML，禁止在多个文件复制超参数。

## Checkpoint 与恢复

完整 Checkpoint 至少包含：

- 模型权重。
- 优化器和 Scheduler。
- 混合精度 Scaler。
- Epoch/Global Step。
- 随机数状态。
- 配置、数据与代码版本。

恢复后先用固定 Batch 比较输出和下一步 Loss，确认不是“能加载但语义已漂移”。

## Callback 与训练状态

训练循环扩展可以使用明确事件：`on_train_start`、`on_step_end`、`on_validation_end`。Callback 适合日志、Checkpoint 和 Early Stopping，不应隐藏核心参数更新。

训练状态应是可序列化对象，避免散落全局变量。

## 数据管线与设备重叠

通过多 Worker、Pinned Memory、预取和异步拷贝减少 GPU 等待，但 Worker 过多会增加内存、进程和存储压力。使用 Profiler 证明瓶颈在数据阶段后再调整。

## Checkpoint 最小实现（注释版）

Checkpoint 不只是 `model.state_dict()`；要能恢复优化器、步数和配置，才能解释训练是否真的连续。

```python
import torch


def save_checkpoint(path, *, model, optimizer, epoch, config):
    # 配置和步数与权重一起保存，避免“权重相同但训练语义不同”。
    torch.save(
        {
            "model": model.state_dict(),
            "optimizer": optimizer.state_dict(),
            "epoch": epoch,
            "config": config,
        },
        path,
    )


def load_checkpoint(path, *, model, optimizer, expected_config):
    state = torch.load(path, map_location="cpu", weights_only=False)
    if state["config"] != expected_config:
        # 配置不一致时先显式决定迁移，不要静默继续训练。
        raise ValueError("checkpoint config does not match current run")
    model.load_state_dict(state["model"])
    optimizer.load_state_dict(state["optimizer"])
    return state["epoch"]
```

实际项目还要保存随机数状态、Scaler、数据版本和代码提交；加载后用固定 Batch 比较输出与下一步 Loss，验证恢复的是同一个实验。
