# 优化与训练诊断

本章把优化器、学习率、初始化和训练诊断作为一个闭环：先观察曲线和梯度，再选择干预手段。

## 梯度下降、SGD 与小批量训练
全量梯度下降每次遍历所有数据，稳定但慢；随机梯度下降每次一个样本，更新快但噪声大；小批量 SGD 是实践折中。batch size 受显存、硬件吞吐和泛化共同影响，没有通用最优值。

损失曲线应按样本数或 step 对齐比较，不能仅比较 epoch。梯度噪声有时帮助逃离不良区域，但过大的学习率会直接发散。训练前先让模型在极小数据集过拟合，是验证优化链路的可靠办法。

## 动量、AdaGrad、RMSProp 与 Adam
动量累计梯度的指数滑动平均，减少狭长峡谷中的来回震荡。AdaGrad 为频繁出现的参数降低有效学习率，但长期可能衰减过度；RMSProp 用窗口平均缓解该问题；Adam 结合一阶动量和二阶尺度校正，是常用默认起点。

优化器不是魔法。Adam 仍要调学习率和 weight decay；AdamW 将权重衰减与自适应更新解耦，实践中常更符合正则化意图。比较优化器时固定模型、数据、训练预算和学习率搜索范围。

## 学习率调度、初始化与训练诊断
学习率往往是最重要超参数。warmup 在训练初期从小 lr 平滑升高；step/cosine 调度在后期降低 lr 以收敛。调度必须按 epoch 或 step 正确调用，并写入日志。

初始化应让前向激活和反向梯度的方差大致稳定；不恰当初始化会让网络从第一步就饱和。诊断顺序：先小数据过拟合，再查数据/标签，再查 loss/metric，再调 lr，最后才改架构。

## 学习与验证

- 运行对应最小代码，记录数据、随机种子、模型、优化器和指标。
- 每次只改变一个变量，对比训练曲线、验证指标、吞吐和显存。
- 把失败归因到数据、目标函数、优化、容量或系统资源，而不是只换模型。
- 能用自己的话解释本章各机制之间的因果关系，再进入下一章。

## 更新方程的理解

动量维护梯度的一阶指数平均；Adam 同时维护一阶和二阶矩，并在早期做偏差校正。AdamW 把 Weight Decay 作为独立参数缩放，不与自适应梯度分母混合。

并非所有参数都适合衰减：Bias、LayerNorm 等常单独分组。参数分组必须记录并测试，避免新参数没有进入优化器。

## Scheduler 与有效 Batch

梯度累积使有效 Batch 约为：

```text
micro_batch × accumulation_steps × data_parallel_workers
```

Batch 改变后学习率和 Warmup 可能需要重调。Scheduler 按 Optimizer Step 还是 Epoch 更新必须明确；梯度累积期间不要误按 Micro Step 前进。

## 梯度监控

记录全局梯度范数、参数范数、更新范数和非有限值。若更新量相对参数长期过小，模型可能几乎未学习；长期过大则容易不稳定。

NaN 排查顺序：输入/标签 → Loss 分量 → 前向激活 → 梯度 → 优化器状态 → 混合精度。

## Early Stopping 的边界

Early Stopping 需要预先定义监控指标、方向、耐心和最小改进。反复根据测试集决定停止轮数会污染测试集。

## 梯度与数值稳定性最小检查（注释版）

训练发散时先检查非有限值和梯度规模，再调整模型结构。

```python
def check_gradients(model):
    total_squared = 0.0
    for name, parameter in model.named_parameters():
        if parameter.grad is None:
            continue  # 未参与本轮图的参数不应被误报为零梯度。
        if not torch.isfinite(parameter.grad).all():
            raise FloatingPointError(f"non-finite gradient: {name}")
        total_squared += float(parameter.grad.detach().norm()) ** 2
    return total_squared**0.5
```

该片段假设已导入 PyTorch；生产日志还应记录参数范数、更新范数、Loss 分量和出现异常的 Batch ID，方便回放具体输入。
