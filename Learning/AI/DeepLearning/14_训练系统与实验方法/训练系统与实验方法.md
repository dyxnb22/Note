# 训练系统与实验方法

本篇把数据、训练状态、复现、性能、分布式和失败恢复组织成一套训练系统。模型原理仍按前面章节学习，MLOps 生命周期见[ML 系统与 MLOps](../../ML系统与MLOps.md)。

## 1. 训练系统边界

```text
配置 → 数据清单/切分 → DataLoader
→ 模型/Loss/Optimizer/Scheduler
→ Train/Eval → Checkpoint
→ 指标/制品 → 恢复或发布
```

每一层都有版本和合同。Notebook 适合探索，稳定训练应进入可参数化脚本。

## 2. 配置

配置分为：

- 数据与切分。
- 模型结构。
- 优化与训练预算。
- 运行设备与分布式。
- 日志、评测和 Checkpoint。

运行时把最终解析配置完整保存。默认值、命令行覆盖和环境变量优先级必须固定。

## 3. 数据清单

训练开始前生成 Manifest：样本 ID、路径、标签、切分和内容 Hash。这样可以识别文件变化、重复、交叉切分和缺失。

大数据集使用可恢复迭代器时，需要记录 Shard 和当前位置；否则恢复可能重复或跳过大量数据。

## 4. 训练状态机

```text
INITIALIZING → TRAINING ↔ VALIDATING
→ CHECKPOINTING → COMPLETED
              ↘ FAILED/CANCELLED
```

状态转换记录 Step、时间、原因和制品。收到取消或抢占信号时，在期限内保存可恢复 Checkpoint。

## 5. 梯度累积

累积多个 Micro-batch 后更新一次。Loss 通常按累积步数缩放，避免梯度放大。更新、Scheduler、梯度裁剪和 `zero_grad` 只在 Optimizer Step 边界执行。

BatchNorm 等依赖 Batch 统计的层不会因为累积自动等同于大 Batch。

## 6. 混合精度

前向在 Autocast 中执行，反向使用缩放后的 Loss，更新前先 Unscale 再做梯度裁剪和非有限检查。

比较 FP32 与混合精度：

- 初始若干 Step Loss。
- 最终指标。
- NaN/Overflow。
- 吞吐和显存。

## 7. Checkpoint

采用临时文件写入、同步和原子替换，避免半写制品。分布式分片 Checkpoint 需要记录 World Size、分片格式和转换工具。

定期检查 Checkpoint 可加载，并做一次真正的中断—恢复演练。

## 8. 评测隔离

验证不更新模型、优化器、BatchNorm 统计和随机增强。大型评测可独立进程执行，但必须绑定待评模型版本。

指标聚合区分样本平均、Batch 平均和分布式 Reduce；Batch 大小不同时直接平均 Batch 指标可能有偏。

## 9. 失败分类

| 类别 | 示例 |
| --- | --- |
| 数据 | 损坏样本、漂移、标签错误 |
| 数值 | NaN、Overflow、梯度爆炸 |
| 资源 | OOM、磁盘满、网络慢 |
| 分布式 | Rank 退出、Collective 超时 |
| 逻辑 | 参数未训练、Mask 错、Metric 错 |
| 恢复 | Checkpoint 不完整、版本不兼容 |

失败日志应包含配置、Step、Rank、样本标识和最近指标，但不记录敏感原始数据。

## 10. 性能实验

按层测量 Data、H2D、Forward、Backward、Optimizer、Communication 和 Checkpoint。一次只改变 Batch、Worker、精度或并行策略之一。

寻找最大吞吐时仍要满足数值质量和恢复要求。

## 11. 分布式确定性

每个 Rank 的随机流既要可复现又不能完全相同。数据 Sampler、增强、Dropout 和初始化分别管理种子。

弹性训练改变 World Size 后，样本顺序、有效 Batch 和优化轨迹可能变化，应把它视为新的实验条件。

## 12. 训练测试

- 单 Batch 过拟合。
- 固定输入前向 Golden Test。
- 数值梯度检查。
- 保存—加载输出一致。
- 中断—恢复下一步一致。
- 单卡—多卡短程指标一致。
- OOM/坏样本/Rank 失败处理。

## 现有训练需要生产化时

把一个现有训练 Notebook 改造成：

1. 配置驱动脚本。
2. Manifest 与固定切分。
3. AMP + 梯度累积。
4. 完整 Checkpoint。
5. 指标和 Profile。
6. 可中断恢复的 DDP 训练。
7. 自动生成实验报告。

## 训练系统落地时检查

- 每次运行可追溯配置、代码、数据和环境。
- 训练状态可保存并实际恢复。
- 单卡、多卡和混合精度差异经过数值验证。
- 性能数据能分解到训练阶段。
- 失败能分类、重试或终止，不留下伪成功制品。

## 来源与验证边界

实现语义以项目锁定版本的 PyTorch Distributed、AMP、Profiler 和 Checkpoint 官方文档为准；硬件、驱动和 Collective 行为必须在目标集群验证。
