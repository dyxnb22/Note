# 深度学习实验的基本流程

## 一条可复用的训练链路

`问题定义 → 数据切分 → DataLoader → 模型 → loss → optimizer → 训练 → 验证 → 测试 → 记录与复现`。测试集只在方案冻结后使用；在验证集上反复调参，本质上会对验证集过拟合。

## 训练循环

```python
for epoch in range(num_epochs):
    model.train()
    for X, y in train_loader:
        X, y = X.to(device), y.to(device)
        optimizer.zero_grad()
        loss = criterion(model(X), y)
        loss.backward()
        optimizer.step()
    model.eval()
    with torch.no_grad():
        validate(model, val_loader)
```

`train()` 与 `eval()` 会改变 Dropout、BatchNorm 的行为；`torch.no_grad()` 不构建反向传播图，可节省验证阶段的内存。每个 batch 只能在一次 `backward()` 后再更新参数，否则梯度含义会混乱。

## 指标与基线

回归至少记录 MAE/RMSE；分类至少记录 accuracy，并在类别不平衡时记录 precision、recall、F1 或 PR-AUC。先构造朴素基线（预测均值、最常见类别、线性模型）；模型优于随机不等于模型有业务价值。

## 实验记录

每次实验只改变一个主变量，并记录：代码版本、数据版本、随机种子、模型结构、学习率/批量大小/轮数、训练与验证曲线、耗时、结论。最有价值的记录是“为什么本次失败”。

## 常见误区

- 把数据增强泄漏到验证/测试集；验证集通常只做确定性预处理。
- 只看最后一轮指标，而不看曲线是否震荡或过拟合。
- 不保存 checkpoint；至少保存验证指标最好的模型和配置。

## 最小练习

为任意分类任务输出一张 epoch-loss/accuracy 表，并写一句结论：下一次只改哪个变量、为什么。

## 可复现实验合同

一次实验应生成独立运行目录，包含配置、代码版本、数据版本、随机种子、环境、日志、指标和 Checkpoint。恢复训练时同时恢复模型、优化器、Scheduler、Scaler、当前 Step 和随机数状态。

只固定随机种子不等于完全确定：多进程 DataLoader、非确定性 CUDA 算子、硬件和库版本都可能影响结果。应说明期望是位级一致，还是指标落在可接受区间。

## 训练诊断矩阵

| 症状 | 优先检查 |
| --- | --- |
| Loss 不降 | 标签、Loss 输入、学习率、梯度、参数是否进入优化器 |
| Train/Val 都差 | 数据、容量、特征、优化不足 |
| Train 好、Val 差 | 泄漏、分布差异、过拟合 |
| 突然 NaN | 学习率、混合精度、异常输入、除零/Log |
| GPU 利用率低 | DataLoader、CPU 预处理、小算子、同步 |
| 显存持续增长 | 保留计算图、累计输出、未清理引用 |

先验证模型能过拟合一个极小 Batch，再扩大数据和复杂度。
