# 技术资料证据与复现工作流

本篇负责从论文、RFC、官方文档、源码和二手文章中获得可验证结论，并将其沉淀到主题文档和案例。

## 1. 先定义研究问题

不要从“我要看完这份资料”开始，而要写：

- 要回答的问题。
- 决策或实验用途。
- 所需精度。
- 时间和版本范围。
- 什么证据足够。
- 什么结果会改变判断。

## 2. 来源层级

通常优先：

1. 规范、法律、官方标准。
2. 官方文档和源码。
3. 原始论文、数据和实验。
4. 维护者解释、Issue 和设计记录。
5. 高质量教材与综述。
6. 二手博客、视频和社交媒体。

层级不是绝对质量排序。官方文档也可能过期，论文实验也可能不适合当前环境。

## 3. 证据标签

为结论标记：

- 资料摘要：只读了正文。
- 正文核验：定位到原始段落/规范。
- 源码核验：定位实现和版本。
- 本地复现：运行了实验并保留输出。
- 生产证据：来自受控监控或事故。

不同等级不能混写成“已经验证”。

## 4. 论文阅读

顺序：

```text
问题/贡献 → 假设 → 方法 → 数据
→ Baseline → 指标 → 结果 → 消融
→ 威胁与适用边界
```

记录：

- 研究问题是否重要。
- Baseline 是否公平。
- 数据是否代表目标分布。
- 提升是否稳定且有实际意义。
- 作者没有测什么。

## 5. 论文复现

先复现最小主结论：

1. 固定代码提交和依赖。
2. 获取并校验数据。
3. 复现原始配置。
4. 记录硬件、Seed 和差异。
5. 对齐指标计算。
6. 多次运行。
7. 报告失败与偏差。

复现失败不自动证明论文错误，先区分环境、数据、实现、随机性和未公开细节。

## 6. RFC 与标准

阅读规范时识别：

- 术语与角色。
- 状态机和消息格式。
- MUST/SHOULD/MAY 等规范强度。
- 错误、超时和安全考虑。
- 版本协商与扩展点。
- 非规范性示例。

实现兼容性需要协议测试，不能只阅读摘要。

## 7. 官方文档

记录产品、版本、页面更新时间和适用平台。区分：

- 教程：帮助快速开始。
- How-to：完成具体任务。
- Reference：精确参数和 API。
- Explanation：解释机制。

教程中的默认配置不一定适合生产。

## 8. 源码阅读

```text
README/构建 → 入口 → 核心调用链
→ 状态与数据 → 错误/并发
→ 配置 → 测试 → 发布
```

通过符号搜索和运行时 Trace 验证调用路径，不按目录逐文件漫游。

## 9. Benchmark 审计

检查：

- 硬件、版本和编译参数。
- 数据集与预热。
- 客户端是否成为瓶颈。
- 吞吐和延迟是否同时报告。
- 错误是否被排除。
- 是否选择性展示最好结果。
- 是否能复现。

相对结论也只对同一实验合同成立。

## 10. 易变信息

版本、价格、模型名、协议、监管和命令要记录：

- 核对日期。
- 官方入口。
- 适用区域/版本。
- 失效触发。
- 下一次核验时机。

稳定机制与易变参数分开写，避免整篇文档快速过期。

## 11. 知识沉淀

```text
原始资料 → 研究卡片 → 最小实验
→ 稳定结论 → 主题主文档
→ 项目特殊取舍 → Case Study
```

主题文档不复制项目背景；案例不重复完整理论。

## 12. 反证

每个重要判断至少记录：

- 什么事实会推翻它？
- 有哪些替代解释？
- 反例在哪里？
- 结论对哪些假设敏感？

只收集支持材料会形成确认偏误。

## 13. 引用与摘录

区分原文、翻译、释义和自己的推断。短摘录保留上下文与链接，长内容以总结为主。

记录作者、标题、版本、日期和定位；不要把搜索摘要当作已经阅读原文。

## 14. 版权与许可

源码、数据、图表和文本都有许可边界。使用前检查：

- 是否允许复制、修改和商业使用。
- 是否要求署名或相同许可。
- 数据是否包含个人信息。
- 模型/数据集是否有额外用途限制。

## 15. 研究记录模板

```text
问题：
结论：
证据等级：
来源/版本/日期：
关键原文或源码位置：
实验环境：
结果：
反例与限制：
下一次核验：
进入哪个主题/案例：
```

## 16. 完成标准

- 能追溯每个关键结论。
- 易变事实有版本和核对日期。
- 实验包含环境、输入、输出和失败。
- 推断与来源事实明确分开。
- 新知识进入唯一主文档，不产生重复正文。
