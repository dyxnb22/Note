# 01 语言核心

从程序执行、值与类型开始，依次学习容器、函数、方法、接口、错误和资源释放。先理解一段代码会读写哪些值，再讨论 Runtime 如何执行它。

## 值、变量与执行

Go 用值传递统一解释赋值和函数调用。接下来观察值中保存的究竟是数据本身，还是通往另一块数据的描述信息。

### 程序、变量与控制流

Go 源文件先声明 package。可执行程序使用 `package main` 并提供 `main()`；函数用 `func` 定义，变量可显式声明类型，也可用 `:=` 在函数内推导。整数、布尔值、结构体和数组都有确定的零值，局部变量必须被使用。

`if` 和 `for` 的条件不写圆括号。`for` 可以按计数、按条件或通过 `range` 遍历；多返回值常用于同时返回计算结果和错误。下面是只依赖标准库的完整程序：

```go
package main

import "fmt"

func total(values []int) int {
    result := 0
    for _, value := range values {
        result += value
    }
    return result
}

func main() {
    values := []int{2, 3, 5}
    fmt.Println(total(values)) // 10
}
```

后面的容器、接口和并发都建立在这个执行过程上：函数接收参数，产生结果；是否共享数据，要继续检查参数指向的对象。

### 值传递与共享数据

Go 的函数参数传递是按值复制。数组会复制全部元素；slice、map、channel 的值内部包含指向运行时结构的描述信息，因此复制后可能共享底层数据或状态，但这不等于语言存在“按引用传递”。需要区分复制描述符和共享底层对象。

### 字符串、字节与 Unicode

string 是不可变字节序列，适合文本和只读键；[]byte 适合协议、文件和可变二进制；[]rune 表示 Unicode code point，适合按字符而非字节处理，但转换会分配和占用更多内存。一个“字符”还可能由多个 code point 组成，用户感知字符处理需要更高层规则。

## 容器的共享关系与初始化

slice 的复制保留底层数组关系，map 的复制保留共享状态；零值、容量和显式复制则决定这些容器能怎样使用。

### make 与 new

`new(T)` 分配一个 T 的零值并返回 `*T`；`make` 只用于 slice、map、channel 等引用型运行时结构，返回初始化后的 T。make 的 len/cap、map 的可写状态和 channel 的缓冲容量会影响行为；不要为了“堆分配”机械使用 new，逃逸由编译器决定。

### 数组与 slice

数组长度属于类型，赋值和传参通常复制整个数组；slice 是指向底层数组的指针、长度和容量描述符，适合动态序列。slice 本身按值复制，但多个 slice 可能共享底层数组；API 返回或并发传递 slice 时要明确是否允许调用方修改数据。

### append 与底层数组

当追加后的长度超过容量时，runtime 通常分配新的底层数组并复制元素；未超过容量时可能复用原数组。因此 append 后旧 slice 与新 slice 是否共享不能只看元素内容，要看容量和实际分配。跨边界需要独立所有权时显式复制，性能结论用 benchmark 验证。

### 示例：复制 slice 与复制元素

```go
package main

import "fmt"

func main() {
    source := []int{1, 2, 3}
    shared := source[:2]
    shared[0] = 9
    isolated := append([]int(nil), source...)
    isolated[0] = 7
    fmt.Println(source, shared, isolated) // [9 2 3] [9 2] [7 2 3]
}
```

`shared` 复制的是描述信息，写元素仍会影响 `source`。`isolated` 把元素复制到了独立底层数组。若元素本身是指针、slice 或 map，复制元素仍可能共享下一层数据，这里只演示整数切片。

### map 的读写与遍历

map 将键映射到值，读取时同时返回的 `ok` 表达键是否存在。单独读取所得的零值无法区分“没有这个键”和“保存的值恰好为零”，配置合并、缓存命中和状态判断都可能依赖这个区别。

`delete` 不要求键存在，遍历顺序也不应作为程序依据。普通 map 的并发读写需要同步：可以由一个 goroutine 独占管理，也可以使用锁、分片或适合特定访问模式的 `sync.Map`。

### nil 容器与空容器

nil map 可以读、删和 `len`，但直接写会 panic；空 map 已初始化，可以写入。nil slice 的长度和容量为零，可以 append，append 可能返回新的底层数组；空 slice 可能是非 nil 的零长度值。序列化、接口比较和业务“是否提供”语义要明确区分 nil 与 empty。

很多类型的零值可以直接使用，减少初始化样板并让结构体易组合；但 map、channel、指针、接口和带资源的对象需要区分 nil 的可读/可写/可关闭行为。API 设计要让零值尽可能安全，不能假设所有零值都代表“空但可用”。

## 用方法集表达能力

容器说明数据如何共享，接收者和接口进一步决定调用方能对数据做什么。泛型再把可复用的算法约束提前到编译期。

### 结构体方法与接收者

值接收者复制接收者，适合小型不可变语义；指针接收者可以修改对象、避免大对象复制并统一方法集。选择重点是类型语义和接口满足关系，而不是单纯追求性能；如果部分方法使用指针接收者，通常只有 `*T` 满足包含这些方法的接口。

### 示例：结构体、方法和接口调用

结构体保存状态，方法的接收者决定它能否直接修改该状态。接口只列出调用方需要的能力，满足方法集的类型无需显式声明“实现接口”。

```go
package main

import "fmt"

type Counter struct { value int }
func (c *Counter) Add(delta int) { c.value += delta }
func (c *Counter) Value() int { return c.value }
type Reader interface { Value() int }
func show(r Reader) { fmt.Println(r.Value()) }

func main() {
    counter := Counter{}
    counter.Add(3)
    show(&counter) // 3
}
```

这里 `Add` 使用指针接收者，调用时修改的是同一个 Counter；`show` 只知道 Reader。`Value` 也声明在 `*Counter` 上，所以传入 `&counter`；如果直接把值 `counter` 作为 Reader 传入，就不满足这个方法集。接口约束的是能力，数据是否共享仍由实际值决定。

### 接口值与 nil

接口值包含动态类型和动态值，只有两者都为空时接口才是 nil。把一个 nil 指针放入接口后，接口可能具有动态类型，因此 `iface == nil` 为 false；调用方法还可能在方法内部解引用 panic。解决方式是说明接口怎样处理nil，并在调用入口检查；若类型设计不清楚，反射不能替代这项约定。

### 接口多态与泛型复用

泛型适合对类型参数做算法、容器和数据变换复用，约束可以用 type set 表达允许的类型集合；接口适合表达运行时能力和业务替换边界。先问需要编译期类型复用还是运行时多态，再选择。小接口通常由使用方定义，泛型约束要精确，不能为了消除少量重复制造复杂类型参数。

### 类型集合与泛型约束

type set 限定类型参数可接受的底层类型或联合集合，`~T` 允许底层类型相同但命名不同的类型参与；如果接口还声明方法，类型参数必须同时满足类型集合和方法集合。约束应表达算法真正需要的能力，不能用 `any` 后在运行时反射补救，也不能把复杂 type set 暴露成难以阅读的公共 API。

## 闭包、资源收尾与错误传播

函数返回前还可能运行 defer，闭包也可能让变量继续存活。资源释放与错误处理因此需要结合函数边界和 goroutine 边界理解。

### range 与闭包捕获

闭包引用的是变量，函数真正调用时才读取它的值。需要区分循环中新声明的迭代变量与循环外已经存在、每轮重新赋值的变量。

从 Go 1.22 的语言语义开始，`for _, value := range values` 每轮声明独立的迭代变量；`for _, value = range values` 则继续使用已有变量。模块的 `go` 版本等编译设置决定适用的语言语义，不能只看机器上安装的工具链。跨版本代码可以显式传参，或在循环体创建独立变量，使捕获范围清楚。闭包若仍访问其他共享状态，并发同步问题依然存在。[Go 循环变量规则](https://go.dev/ref/spec#For_statements)

### defer 与资源释放

defer 在函数返回前执行，多个 defer 按后进先出；参数通常在 defer 语句执行时求值，但闭包捕获变量要看变量本身的生命周期和版本语义。它适合释放资源和记录收尾，但在大循环中累积大量 defer 可能延迟释放；要理解命名返回值、panic 和 defer 修改返回结果的交互。

### error、panic 与 recover

可预期的业务失败用 error 返回，panic 用于无法继续的程序不变量、初始化错误或明确的框架边界；recover 只在同一 goroutine 的 defer 中生效。服务边界可以恢复 panic 防止整个进程退出，但必须记录堆栈、终止当前请求并确认共享状态没有被破坏，不能把 panic 当普通流程控制。

### 错误分类与上下文

error 是普通值，调用方必须决定重试、降级、返回还是终止，错误路径更容易被测试和观测。错误应使用 `%w` 保留原因、用 `errors.Is/As` 做分类，避免只比较字符串；错误信息要包含操作上下文，但不泄露密钥和敏感数据。

语义以项目工具链和 [Go 语言规范](https://go.dev/ref/spec) 为准；[Effective Go](https://go.dev/doc/effective_go) 可辅助理解常见写法，泛型和模块需查相应规范。下一章进入 [Runtime 与性能](./02_Runtime与性能.md)。
