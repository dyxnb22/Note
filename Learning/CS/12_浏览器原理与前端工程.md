# 浏览器原理与前端工程

本篇连接网络协议、JavaScript 运行时、渲染管线与前端交付。重点是理解页面为什么慢、为什么不稳定、浏览器安全边界在哪里。

## 1. 浏览器主要进程

现代浏览器通常将浏览器控制、页面渲染、GPU、网络和扩展等职责隔离到不同进程。多进程提高故障和安全隔离，但也带来 IPC 与内存成本。

具体进程模型随浏览器和版本变化，理解职责边界比背固定数量更重要。

## 2. 导航链路

```text
URL → DNS → 连接/TLS → HTTP
→ HTML 解析 → 子资源加载 → 渲染 → 可交互
```

缓存、Service Worker、代理、重定向和预加载会改变实际路径。排障使用 Network、Performance 和 Application 面板提供证据。

## 3. DOM、CSSOM 与渲染

浏览器解析 HTML 构建 DOM，解析 CSS 构建 CSSOM，再生成渲染相关结构，执行布局、绘制和合成。

- Style：计算样式。
- Layout：确定几何位置。
- Paint：生成绘制指令。
- Composite：合成图层。

频繁读取布局信息后立即修改样式可能造成强制同步布局。动画优先使用更容易合成的属性，并通过 Performance Timeline 验证。

## 4. JavaScript 与事件循环

页面脚本、Promise、Timer、网络回调和渲染任务共享事件循环调度。长任务会阻塞输入响应和渲染。

把重计算拆分、使用 Web Worker 或移到服务端；Microtask 过多也可能推迟渲染。

## 5. 资源加载

关键优化问题：

- 哪些资源阻塞解析或渲染？
- 是否正确使用 preload、preconnect、async、defer？
- 图片尺寸、格式和懒加载是否合理？
- 缓存指纹和 CDN 是否正确？
- JavaScript Bundle 是否包含不必要代码？

性能优化必须围绕真实用户指标，而不是只追求更小文件。

## 6. Web 安全模型

同源策略隔离不同源的页面数据。CORS 是服务端授权浏览器读取跨源响应的机制，不是认证。

还要处理：

- XSS 与输出编码/CSP。
- CSRF 与 SameSite/Token。
- 点击劫持。
- 不安全的第三方脚本。
- Cookie 的 Secure、HttpOnly、SameSite。
- 浏览器存储中的敏感数据。

## 7. 状态与离线能力

Cookie、Web Storage、IndexedDB、Cache Storage 和 Service Worker 适合不同场景。需要定义容量、过期、跨标签页一致性、登出清理和数据迁移。

Service Worker 位于网络请求路径，错误缓存策略可能长期发布旧内容，因此必须版本化、可更新、可回退。

## 8. 前端工程

工程链路包括：

```text
类型检查 → lint → 单元/组件测试
→ 构建 → Bundle 分析 → E2E
→ 制品发布 → Source Map/监控 → 灰度与回滚
```

前后端以 OpenAPI/Schema 等稳定契约协作，不能只共享一份会随部署漂移的 TypeScript 类型。

## 9. 用户体验指标

观察加载、交互和视觉稳定性，例如 LCP、INP、CLS，并按设备、网络、地域和版本切片。

实验室数据适合复现和诊断，真实用户监控反映生产分布；两者不能互相替代。

## 最小实践

1. 记录一次页面从导航到可交互的时间线。
2. 制造并定位一次强制同步布局。
3. 比较阻塞脚本、defer 和 async。
4. 配置缓存指纹、CSP 和安全 Cookie。
5. 使用真实用户指标验证一次 Bundle 优化。

## 验收清单

- 能解释导航、解析、布局、绘制和合成链路。
- 能定位长任务、阻塞资源和布局抖动。
- 能区分同源策略、CORS、CSP 和认证。
- 前端制品可监控、灰度和回滚。

## 来源与验证边界

原理参考 HTML、CSS、ECMAScript 和 Fetch 等 Web 标准，以及浏览器官方开发文档。进程模型、性能指标和工具面板会演进，应在目标浏览器版本上验证。
