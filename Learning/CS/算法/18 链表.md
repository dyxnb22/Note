# 链表

链表由节点间引用组织，访问成本来自沿连接移动。修改链接前先保存下一节点，区分节点身份与值；虚拟头节点可统一头部修改的分支。

## 节点身份与指针连接

反转链表时 prev 是已经反转好的前缀，current 是未处理部分的头。先保存 current.next，再修改链接，否则会丢失后续节点。输入前提是有限无环链表。

```python
class Node:
    def __init__(self, value, next_node=None):
        self.value, self.next = value, next_node

def reverse(head):
    previous = None
    current = head
    while current is not None:
        following = current.next
        current.next = previous
        previous, current = current, following
    return previous

first = Node(1, Node(2, Node(3)))
head = reverse(first)
assert (head.value, head.next.value, head.next.next.value) == (3, 2, 1)
assert head.next.next is first and first.next is None
assert reverse(None) is None
```

原节点被重新连接，没有分配替代节点；时间 O(n)，额外空间 O(1)。有环链表需要先明确检测和处理策略，不能直接套用这个终止条件。

## 指针距离怎样表达位置关系

链表缺少随机下标，指针走过的长度可以替代位置计算。相遇、固定间距与总路径长度分别用于不同定位问题。

### 让两条路径的总长度相等

假设两条单链表有限且无环，相交指共享同一个节点对象，此后后缀也共享。两个指针分别沿 A、B 前进，到空后切换到对方头部；都走过两段前缀与公共后缀后，长度差被抵消，便在首个公共节点相遇。

若没有公共节点，最终同时到空。比较必须用节点身份而非值；有环链表还需要分别处理环入口，不能直接套用这个切换终止条件。时间 O(m+n)、额外空间 O(1)。

### 用快慢指针识别环

判断链表中是否有环。快慢指针必须先移动再比较，不能把都从头节点出发的 `while (slow != fast)` 直接作为循环条件，否则循环一次也不会进入。安全边界是先确认 `fast` 和 `fast.next` 非空：

```java
ListNode slow = head, fast = head;
while (fast != null && fast.next != null) {
    slow = slow.next;
    fast = fast.next.next;
    if (slow == fast) return true;
}
return false;
```

时间复杂度 `O(n)`，额外空间 `O(1)`；比较的是节点身份，不是节点值。

### 根据相遇位置定位环入口

返回链表开始入环的第一个节点。 快慢指针先判断是否有环；相遇后，一个从头走，一个从相遇点走，再次相遇的位置就是环入口。

### 用固定间距找到倒数位置

使用 dummy 统一“删除头节点”的边界；让 `fast` 先从 dummy 走 `n + 1` 步，再让 `fast`、`slow` 同时前进，`fast` 到空时 `slow` 正好位于待删节点之前。使用前先确认输入是否满足 `1 <= n <= length`，否则要显式拒绝非法输入。时间复杂度 `O(n)`，额外空间 `O(1)`。

## 修改连接前保留后续路径

反转、合并和复制都会改变节点关系。先保存下一步需要访问的位置，再更新指向，才能避免丢失剩余链表。

### 修改指向前保存后继

pre 初始化为 null，cur 从头节点开始；每次先保存 next=cur.next，再令 cur.next=pre，然后把 pre、cur 推进到原来的当前节点和后继。pre 是已反转前缀的头，不能误建成一个额外结果节点。

```java
ListNode next = cur.next; cur.next = pre; pre = cur; cur = next;
```

循环结束返回 pre。这个实现与开头 Python 程序保持相同的连接不变量，只是使用 Java 的节点类型。

### 逐组维护翻转前后的连接

要求 k>=1；不足 k 个节点的尾段保持原样，k=1 时无需修改。`pre` 站在当前组前面，`end` 往后数 `k` 个节点找组尾；找到后，`start = pre.next` 保存组头，`next = end.next` 保存下一组头；先断开 `end.next`，再反转 `start` 开头的这一组；反转完成后，`pre.next` 接反转后的新头，`start.next` 接回 `next`；因为 `start` 已经从组头变成组尾，所以最后令 `pre = start，end = pre`，进入下一轮。

### 复用已有节点合并有序链表

对两条不共享节点的无环升序链表，选择较小头节点作为当前结果，把它的后继与另一条链表继续合并；任一为空就接上另一条剩余部分。相等时固定选择一侧，可保持合并稳定性。

递归写法清楚但最坏调用栈 O(m+n)；用 dummy 与尾指针迭代连接可把额外空间降到 O(1)。两种写法都复用原节点并修改连接，时间 O(m+n)。

### 把进位作为逐位状态

两条非空链表用逆序十进制数字表示非负整数，个位在头部。每轮把两侧当前位与 carry 相加，缺失位视为 0；新位为 sum%10，进位为 sum//10。

只有两条输入均耗尽且进位为 0 时才结束。最后剩余进位还要创建一位，如 99+1 得到 0→0→1。每个输入节点值须在 0 到 9，结果新建节点，时间 O(max(m,n))。

### 建立原节点到副本的映射

以原节点身份为键，第一遍为每个节点创建唯一副本；第二遍把副本的 next、random 指向对应目标的副本，空指针仍为空。random 按约定只指向本链表节点或空。

两遍使任意向前或向后的 random 都已有映射，不需要按值寻找节点，重复值也不会混淆。副本之间不得残留到原节点的引用，时间 O(n)、辅助映射空间 O(n)，输出节点空间另计。

## 由局部连接构造排序与缓存

合并有序子段、维护多个流的堆顶以及同步更新索引和访问链，都把更大结构的约束落实为少量连接操作。

### 在链表上合并有序子段

归并排序以空链表或单节点为终止。快慢指针找到中点后，必须断开左右两段，再分别排序并合并，保证子问题规模严格缩小。

总时间 O(n log n)。若合并使用迭代，排序递归栈 O(log n)；若合并本身也递归，合并阶段的额外栈可能达到 O(n)，不能只按排序递归层数估算。

### 用堆汇总多个有序流

k 条互不共享节点的有序链表，总节点数 N。把各非空链表的头放入小顶堆，每次取最小节点接到结果，再把它原来的 next 放入堆；堆中始终至多有每条未耗尽链表的一个候选。

时间 O(N log(k+1))，堆空间 O(k)，结果可复用原节点。比较器按节点值比较，Python 用元组时还需序号等次关键字，避免值相等后尝试比较节点对象。

另一种方法把链表数组二分，递归合并两半的结果，同样得到 O(N log k) 的分层合并成本。空数组返回空，只有一条时可直接返回；这里讲的是堆与分治两种汇总方式。

### 用哈希索引和访问链维护 LRU

设计一个满足“最近最少使用”规则的缓存，`get` 和 `put` 都要求平均 `O(1)`。
需要同时维护“按 key 快速定位”和“按使用顺序快速移动、淘汰”两件事，因此使用哈希映射配合双向链表：映射负责找到节点，链表从头到尾表示最近使用到最久未使用。每次访问或更新都把节点移动到头部；插入新节点后如果超容量，就同时从尾部链表和哈希映射删除同一个节点。更新已有 key 时不能新增重复节点，而要先移动原节点并更新值。可用头尾哨兵统一空链与单节点操作；容量为 0 时始终不能保留条目，负容量应拒绝。
