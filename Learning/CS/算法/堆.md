# 堆

什么时候想到堆：需要在动态变化的集合中反复取最大/最小值，且不需要整体有序。只要 Top-K 而不是全排序时，堆 `O(n log k)` 优于排序 `O(n log n)`。

**LeetCode 215. 数组中的第 K 个最大元素**
`PriorityQueue<Integer> pq = new PriorityQueue<>((a, b) -> a - b);`
维护一个大小为 `k` 的小顶堆：堆中保存"当前最大的 k 个数"，堆顶就是第 K 大。新元素大于堆顶才入堆并弹出堆顶——被丢弃的元素不可能进入前 k 名。时间 `O(n log k)`，空间 `O(k)`。
边界：`k == nums.length` 时堆顶是全局最小值，逻辑仍成立；面试可对比 quickselect 平均 `O(n)` 但最坏 `O(n²)`。

**LeetCode 347. 前 K 个高频元素**
用 `HashMap` 统计每个数字出现次数。用一个大小最多为 `k` 的**小顶堆**，按频率排序，保存出现频率最高的 `k` 个数字。
`PriorityQueue<int[]> pq = new PriorityQueue<>((pair1, pair2) -> pair1[1] - pair2[1]);`
丢弃依据同 215：新频率不高于堆顶时，它不可能挤进前 k。时间 `O(n log k)`。
替代解法：桶排序（下标 = 频率，最大频率不超过 n），可做到 `O(n)`，频率范围有限时更优。

**LeetCode 295. 数据流的中位数**
双堆模式：把所有数字分成左右两半。`left`：保存较小的一半，最大堆；`right`：保存较大的一半，最小堆。
不变量：`left` 的所有元素 ≤ `right` 的所有元素，且两堆大小差不超过 1。
数量相同时，新数先进入右边，再把右边最小值转给左边；左边多一个时，新数先进入左边，再把左边最大值转给右边——先进对侧再转移，保证顺序不变量不被破坏。
取中位数：总数为奇时取 `left` 堆顶，为偶时取两堆顶均值。单次插入 `O(log n)`，查询 `O(1)`。
边界：新数必须经过对侧堆"过滤"后再转移，直接按大小插入会破坏两堆的分界。

双堆模式可迁移：滑动窗口中位数（LC 480）、IPO（LC 502，大小堆各管一个约束）。
