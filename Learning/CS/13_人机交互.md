# 人机交互

人机交互关注用户如何理解系统、完成任务、发现错误并恢复。它连接产品设计、界面、可用性、无障碍和人机协同。

## 1. 从任务而不是页面开始

先明确：

- 用户是谁，目标是什么。
- 当前环境、设备和时间压力。
- 任务频率与错误成本。
- 用户掌握哪些概念。
- 成功、失败和中断如何定义。

页面只是任务链路的一个接口。

## 2. 心智模型

用户会根据系统反馈建立解释模型。界面应让对象、动作和结果之间的映射清晰，减少依靠记忆。

一致命名和稳定行为比“每页单独最优”更重要。系统内部术语不应直接暴露给不理解它的用户。

## 3. 反馈与状态可见性

动作后应及时反馈：

- 是否收到请求。
- 当前处于什么状态。
- 是否仍可取消。
- 预计还需要多久。
- 成功后结果在哪里。
- 失败后可以做什么。

长任务适合显示阶段、进度和可恢复标识，不能只用无限转圈隐藏未知状态。

## 4. 错误预防与恢复

优先通过约束、默认值、预览和风险提示预防错误。错误发生后：

- 描述发生了什么。
- 不泄漏内部敏感信息。
- 保留用户已输入内容。
- 给出明确恢复动作。
- 高风险操作支持确认、撤销或版本历史。

确认框过多会形成习惯性点击，不能替代权限和可恢复设计。

## 5. 认知负荷

减少同时需要记忆的信息，使用分组、层级、渐进披露和合理默认值。选项数量、术语和视觉层级应服务当前任务。

快捷键适合高频专家用户，但必须保留可发现的普通路径。

## 6. 可用性评估

常用方法：

- 用户访谈和情境观察。
- 任务分析。
- 纸面/交互原型。
- 可用性测试。
- 启发式评估。
- 日志与漏斗分析。
- A/B 实验。

行为日志能说明发生了什么，不一定解释为什么；定性与定量证据应组合。

## 7. 无障碍

基本要求：

- 键盘可操作和清晰焦点。
- 语义结构和辅助技术可理解的名称。
- 颜色不是唯一信息通道。
- 对比度、字号和点击目标合理。
- 动画可减少。
- 错误与状态变化可被感知。

无障碍不是上线前的补丁，应在组件、内容和测试阶段进入完成标准。

## 8. AI 与 Agent 交互

Agent 产品还要明确：

- 系统准备做什么、为什么。
- 哪些动作需要审批。
- 使用了哪些来源和工具。
- 结果是事实、推断还是建议。
- 用户如何纠正、接管、取消和回滚。
- 自动化程度如何与风险匹配。

“像人一样聊天”不能替代状态可见性和可控性。

## 9. 最小实践

选择一个部署或 Agent 任务：

1. 写出用户、目标、上下文和失败成本。
2. 画任务流和关键状态。
3. 制作低保真原型。
4. 让三名目标用户完成任务并记录阻塞。
5. 修改后复测，并定义线上行为指标。

## 验收清单

- 设计从用户任务和风险开始。
- 系统状态、等待、失败和恢复清晰可见。
- 高风险操作可确认、取消或撤销。
- 可用性结论包含真实用户证据。
- 键盘、语义、对比度和错误提示满足基本无障碍要求。

## 来源与验证边界

课程框架参考 Don Norman《The Design of Everyday Things》、Nielsen 可用性方法和 W3C WCAG。具体设计结论必须通过目标用户与真实任务验证，无障碍验收应核对当前标准版本。
