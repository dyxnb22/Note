# 计算机图形学

本篇建立从几何数据到屏幕像素的基本链路，重点理解坐标变换、光栅化、光照和 GPU 管线。

## 1. 数学基础

图形学反复使用向量、矩阵、点积、叉积、齐次坐标和插值。齐次坐标让平移与旋转、缩放、投影统一表示为矩阵乘法。

变换顺序不可随意交换：先旋转再平移与先平移再旋转通常结果不同。

## 2. 坐标空间

典型链路：

```text
模型空间 → 世界空间 → 观察空间
→ 裁剪空间 → NDC → 屏幕空间
```

模型矩阵放置物体，View 矩阵描述相机，Projection 矩阵完成透视或正交投影。

## 3. 图形管线

现代实时渲染大致包括：

- 顶点处理：Vertex Shader 变换顶点位置和属性。
- 图元组装：把顶点连成三角形、线段等图元。
- 裁剪：丢弃视锥外的图元部分。
- 光栅化：把图元离散成候选像素（片元）。
- 片元着色：Fragment Shader 计算每个片元的颜色与属性。
- 深度、模板与混合：深度测试解决遮挡，混合处理透明度。

## 4. 光栅化与采样

光栅化判断哪些像素被三角形覆盖并插值属性。走样来自连续信号离散采样不足，抗锯齿通过提高采样或过滤减少伪影。

纹理采样需要处理放大、缩小、过滤和 Mipmap。错误的颜色空间会导致光照与混合结果不正确。

## 5. 光照

基础光照模型考虑三个分量：环境光是常数项，近似间接光照的最低保障；漫反射随光线与法线夹角变化，形成表面的立体感；镜面反射在高光方向集中，由粗糙度决定高光大小。物理渲染（PBR）在此基础上引入能量守恒、微表面理论和标准化材质参数，配合环境光照，让材质在不同光照场景下表现一致。

实时光栅化通常用近似换取性能；离线光线追踪通过模拟光线路径获得更真实的全局光照，但计算成本更高。

## 6. 几何与场景

网格由顶点、边、面和属性组成。场景图表达层次变换。包围盒和空间索引用于裁剪、碰撞和加速查询。

## 7. GPU 性能

瓶颈可能在：

- 顶点/三角形数量：几何量太大，顶点处理阶段吃满。
- Fill Rate 和过度绘制：同一像素被反复着色（透明 UI 叠层最典型），着色带宽浪费。
- Shader 复杂度：片元着色器指令太多，单个像素都算得慢。
- 纹理带宽：高分辨率纹理采样超出显存带宽。
- CPU 提交 Draw Call：每次提交有固定开销，几千个小物体能把 CPU 拖满而 GPU 空闲。
- CPU/GPU 同步：CPU 等待 GPU 返回结果（如读回数据），双方互相空转。

使用 GPU Profiler 判断，不只凭帧率猜测。
