# 编程语言与编译原理

本篇建立“源代码如何变成可执行行为”的整体模型，帮助理解类型系统、解释器、编译器、运行时、JIT 和语言互操作。

## 1. 语言实现链路

```text
源代码 → 词法分析 → 语法分析 → AST
→ 名称解析与类型检查 → 中间表示
→ 优化 → 目标代码/字节码 → 链接与运行
```

解释执行、提前编译 AOT 和即时编译 JIT 可以组合存在，不是互斥分类。

## 2. 词法与语法

词法分析把字符流分成 Token；语法分析按文法构建语法树。AST 会丢弃括号、分号等不影响语义的表面结构。

解析器需要处理优先级、结合性、歧义和错误恢复。正则表达式适合词法层的局部模式，不能可靠替代完整嵌套语法解析。

## 3. 名称、作用域与闭包

- 词法作用域根据代码结构绑定名称。
- 动态作用域根据调用栈查找名称。
- 闭包捕获函数定义环境中的变量。

捕获按值还是按引用、变量生命周期和可变性会影响并发安全与内存保留。

## 4. 类型系统

类型系统用于排除某些不合法程序并表达接口：

- 静态与动态类型。
- 名义类型与结构类型。
- 子类型、多态与泛型。
- 类型推断。
- 可空性、代数数据类型和模式匹配。
- Effect/Ownership 等更强约束。

类型安全不等于业务正确，静态类型也不能验证所有外部输入。

## 5. 运行时与内存管理

运行时负责对象布局、调用约定、异常、线程、GC 或引用计数等。

GC 需要在吞吐、暂停、内存占用和实现复杂度间取舍。引用计数回收及时，但循环引用需要额外处理。手工内存管理则要求明确所有权和释放时机。

## 6. 中间表示与优化

IR 将源语言与目标机器解耦。常见优化：

- 常量折叠、死代码删除。
- 内联。
- 公共子表达式消除。
- 循环优化和向量化。
- 逃逸分析。

优化必须保持语言规定的可观察语义；涉及并发、异常和浮点时尤其谨慎。

## 7. 链接、ABI 与 FFI

编译单元通过符号、目标文件和库链接。ABI 规定调用约定、寄存器、栈、对象布局和名称修饰等二进制边界。

FFI 跨语言调用时要管理：

- 数据布局和编码。
- 内存所有权。
- 异常不能随意跨边界传播。
- 线程与运行时初始化。
- 版本和 ABI 兼容。

## 8. JIT

JIT 根据运行时热点把字节码或 IR 编译成本地代码，可利用真实类型和分支信息优化。代价包括预热、编译开销、代码缓存和反优化。

Benchmark 应区分冷启动、预热和稳态，避免把 JIT 尚未稳定的结果当最终性能。
