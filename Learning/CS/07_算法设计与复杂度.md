# 算法设计与复杂度

本篇负责算法的分析、正确性与设计范式；`算法/` 下的文档继续负责具体题型练习。完成标准不是记住模板，而是能说明算法为什么正确、成本在哪里、什么条件下会失效。

## 1. 分析模型

先定义输入规模 n，再选择需要统计的基本操作。时间复杂度和空间复杂度都要区分：

- 最坏、平均和最好情况。
- 额外空间与输入本身占用。
- 单次操作与一组操作的总成本。
- CPU 计算与磁盘、网络 I/O。

`O(n)` 是上界，不代表任何 n 下都更快。对真实程序还要考虑常数、缓存局部性、分支预测、并行度和数据分布。

## 2. 正确性证明

常见证明结构：

1. 写清前置条件和输出合同。
2. 给出关键不变量。
3. 证明算法保持不变量。
4. 证明算法一定终止。
5. 用终止条件和不变量推出结果。

只通过几个样例不能证明算法正确；测试用于发现反例，证明用于覆盖整个输入空间。

## 3. 递归与递推式

递归算法要回答：

- 基础情形是否覆盖并能终止？
- 子问题规模是否严格减小？
- 子问题是否重叠？
- 合并结果需要多少成本？
- 调用栈最深是多少？

常见递推：

```text
T(n) = T(n-1) + O(1)       -> O(n)
T(n) = 2T(n/2) + O(n)      -> O(n log n)
T(n) = T(n/2) + O(1)       -> O(log n)
```

## 4. 摊还分析

摊还分析关注一串操作的平均成本，不依赖输入概率。

动态数组扩容时，某一次复制可能是 O(n)，但按倍数扩容后连续 n 次追加总成本仍是 O(n)，单次摊还 O(1)。常用方法：

- 聚合法：直接计算操作序列总成本。
- 记账法：便宜操作预存信用支付未来昂贵操作。
- 势能法：用数据结构状态的势能变化解释成本。

摊还 O(1) 不等于每次操作延迟都稳定；实时系统仍要关注最坏延迟。

## 5. 排序与选择

理解排序时比较：

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定性 |
| --- | --- | --- | --- | --- |
| 插入排序 | O(n²) | O(n²) | O(1) | 稳定 |
| 归并排序 | O(n log n) | O(n log n) | O(n) | 稳定 |
| 快速排序 | O(n log n) | O(n²) | 依实现 | 通常不稳定 |
| 堆排序 | O(n log n) | O(n log n) | O(1) | 不稳定 |
| 计数排序 | O(n+k) | O(n+k) | O(k) | 可稳定 |

比较排序在一般模型下存在 `Ω(n log n)` 下界；当键的范围或位数受限时，可以用计数、桶或基数排序绕开比较模型。

Top K 不一定要完整排序：

- 数据可全部放入内存：快速选择平均 O(n)。
- 流式数据：维护大小为 k 的堆，O(n log k)。
- 海量分片：局部 Top K 后再归并。

## 6. 分治

分治包含拆分、递归求解和合并。适合子问题结构相同且耦合较弱的场景，如归并排序、快速排序和部分计算几何问题。

判断是否值得分治：

- 子问题能否并行？
- 合并成本是否过高？
- 是否存在大量重叠子问题？
- 拆分是否均衡？

重叠子问题更适合记忆化或动态规划。

## 7. 贪心

贪心每一步做局部最优选择。它成立通常需要：

- 贪心选择性质：存在一个最优解包含当前选择。
- 最优子结构：做出选择后，剩余问题仍是同类最优问题。

常见证明方式是交换论证：把任意最优解中的某个选择替换成贪心选择，且不使答案变差。不能因为“看起来最划算”就认定贪心正确。

## 8. 动态规划

动态规划适合有重叠子问题和最优子结构的问题。设计顺序：

1. 定义状态，说明它代表的完整语义。
2. 写状态转移。
3. 确定初始状态。
4. 确定遍历顺序，保证依赖已计算。
5. 明确答案在哪个状态。
6. 判断是否能压缩空间。

记忆化搜索从目标递归展开；表格 DP 按依赖顺序自底向上计算。空间压缩不能破坏仍需使用的旧状态。

## 9. 图算法

先根据问题选择图模型：

- 无权最短路：BFS。
- 非负权最短路：Dijkstra。
- 允许负权：Bellman-Ford；若存在可达负环则最短路无定义。
- 所有点对最短路：Floyd-Warshall 或多次单源最短路。
- 最小生成树：Kruskal 或 Prim。
- DAG 依赖顺序：拓扑排序。
- 连通性与动态合并：DFS/BFS 或并查集。
- 网络容量：最大流/最小割。

必须明确图是有向还是无向、是否有权、是否允许重边和自环、规模是否允许邻接矩阵。

## 10. 字符串算法

除哈希和普通扫描外，系统学习：

- KMP：利用前缀函数避免重复比较。
- Trie：按字符前缀组织字典。
- Aho-Corasick：多模式匹配。
- Rolling Hash：快速比较子串，但必须考虑碰撞。
- 后缀数组/后缀自动机：复杂子串与重复结构问题，按需学习。

工程中还要考虑 Unicode、规范化、大小写规则和字节/字符边界。

## 11. 随机算法与概率结构

随机化常用于避免恶意或不利输入、降低平均成本：

- 随机选择快速排序枢轴。
- Reservoir Sampling：未知总长度的流式抽样。
- Bloom Filter：允许假阳性、不允许假阴性（前提是实现和删除策略正确）。
- Skip List：用随机层级获得期望 O(log n)。

随机算法的结论要明确是期望复杂度、高概率保证还是确定性上界。

## 12. 复杂性与归约

复杂性理论关注问题本身需要多少资源，而不是某个实现。

- P：存在多项式时间确定性算法的问题。
- NP：给定候选解可在多项式时间验证的问题。
- NP-hard：至少和所有 NP 问题一样难，不要求自身属于 NP。
- NP-complete：既属于 NP 又是 NP-hard。

归约把问题 A 转换为问题 B。如果 A 已知很难且 A 能多项式归约到 B，说明 B 至少同样难。面对 NP-hard 问题时常用：

- 限制输入规模。
- 使用近似算法。
- 使用启发式或搜索剪枝。
- 利用业务数据的特殊结构。

## 13. 外存、缓存与并行算法

数据不能全部放入内存时，I/O 次数可能比比较次数更关键：

- 外部归并排序：分块排序后多路归并。
- 分区：按 Hash 或范围把问题拆到可处理规模。
- 顺序扫描通常比大量随机 I/O 更友好。
- 批量处理减少系统调用和网络往返。

并行算法还要评估串行部分、通信、同步、负载均衡和数据倾斜。Amdahl 定律说明串行部分会限制最大加速比。

## 14. 题型到方法的映射

| 信号 | 优先考虑 |
| --- | --- |
| 有序、单调答案 | 二分 |
| 连续区间、窗口约束 | 双指针、滑动窗口、前缀和 |
| 最近更大/更小 | 单调栈 |
| 动态最值 | 堆、单调队列 |
| 枚举选择组合 | 回溯、剪枝 |
| 重叠子问题 | 记忆化、DP |
| 依赖关系 | 图、拓扑排序 |
| 动态连通 | 并查集 |
| 海量数据 | 分片、外排、Bitmap、Bloom Filter |

映射只用于提出候选方法，最终仍要用约束、正确性和复杂度验证。

## 最小实践

1. 为二分查找写出不变量和终止证明。
2. 实现归并排序并用递推式分析复杂度。
3. 比较 Dijkstra 与 Bellman-Ford 的适用前提。
4. 为一个贪心解法写交换论证；若无法证明，寻找反例。
5. 对同一 Top K 问题实现排序、堆和快速选择并做基准测试。

## 验收清单

- 能从输入约束估算可接受的复杂度。
- 能用不变量或归纳法说明算法正确。
- 能区分最坏、平均、期望和摊还复杂度。
- 能解释分治、贪心、动态规划各自成立的条件。
- 能把内存、I/O、缓存和并行开销纳入工程判断。
