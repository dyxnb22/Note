# 技术沟通速查

本页只做技术输出检查；正文见 [如何写设计文档](./如何写设计文档.md)。

| 输出 | 必须说清 |
|---|---|
| 方案 | 背景、目标、约束、方案、取舍、风险、验证 |
| 架构图 | 边界、组件、数据流、失败路径和责任归属 |
| 接口文档 | 输入、输出、错误、鉴权、幂等、版本 |
| 事故复盘 | 影响、时间线、根因、检测、修复、预防 |
| 决策记录 | 选了什么、没选什么、为什么、何时重审 |

## 快速检查

- 写给谁，读者要据此做什么决定？
- 是否先给结论，再给依据和限制？
- 是否明确 trade-off，而不是只描述方案优点？
- 图、表和文字是否各自承担不同信息？
- 假设、未知、风险和下一步是否可追踪？

复杂流程先画边界和状态，再写文字；事故只描述可验证事实，不把“模型犯错”当根因。
