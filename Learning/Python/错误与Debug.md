# 错误与Debug

Debug 的核心不是背错误，而是建立排查顺序：先看错误类型，再看堆栈，再定位环境、输入、依赖、网络、配置或代码逻辑。

## 1. Debug 基本流程

```text
复现问题
→ 读完整报错
→ 找第一段自己代码位置
→ 看输入和配置
→ 缩小范围
→ 加日志或断点
→ 修复
→ 写测试或记录原因
```

不要只看最后一行，也不要看到红字就重装环境。

## 2. Python 常见错误

| 错误 | 常见原因 | 排查方向 |
| --- | --- | --- |
| `SyntaxError` | 语法错误、括号/引号没闭合 | 看报错行附近 |
| `NameError` | 变量没定义、拼写错 | 检查变量名 |
| `TypeError` | 类型不匹配、函数参数错误 | 打印 type、检查函数签名 |
| `ValueError` | 值格式不对，例如 `int("abc")` | 检查输入值 |
| `KeyError` | dict key 不存在 | 用 `.get()` 或先看 keys |
| `IndexError` | list 下标越界 | 检查 list 长度 |
| `AttributeError` | 对象没有这个属性或方法 | 打印对象类型 |
| `ModuleNotFoundError` | 包没装、环境不对 | 检查 venv / pip |
| `FileNotFoundError` | 文件路径错误 | 打印当前目录和路径 |

`ModuleNotFoundError`/`AttributeError` 还有一个隐蔽来源：自己的文件名遮蔽了标准库或第三方包（例如把脚本命名为 `json.py`、`token.py`），import 会先解析到本地文件。

## 3. 读懂 Traceback

- 从下往上读：最后一行是异常类型和消息，往上是调用链，越靠下越接近出错现场。
- 在调用链中找到**最深的一层自己写的代码**，那里通常才是要检查的位置；框架和库的帧只说明路径。
- 出现两段堆栈时区分异常链：
  - `The above exception was the direct cause ...`：来自 `raise NewError(...) from e`，是刻意转换的异常，先看上面那段原始异常。
  - `During handling of the above exception, another exception occurred`：错误处理代码本身又出错了，两个问题都要修，但根因是第一段。
- 重新抛出异常用裸 `raise`（保留原始堆栈），不要 `raise e`（在部分写法下会截断或改写回溯信息）。

## 4. 工具选择

| 工具 | 适用场景 |
| --- | --- |
| `print()` | 一次性、本地、快速确认某个值 |
| `logging` | 需要级别、时间戳和上下文；生产环境唯一选择，事后可查 |
| `breakpoint()` | Python 3.7+ 内置，进入 pdb 交互式检查现场 |
| `traceback.print_exc()` | 在 `except` 块里打印完整堆栈而不中断程序 |
| IDE 断点调试 | 复杂状态、多层调用，需要单步和变量面板 |

pdb 最常用的命令：`p 表达式`（打印）、`n`（下一行）、`s`（进入函数）、`c`（继续运行）、`l`（看上下文）、`w`（看当前调用栈）、`q`（退出）。

## 5. 缩小范围的策略

- **最小复现**：把问题剥离成十几行能独立运行的脚本。剥离过程中问题消失，说明根因在被剥掉的那部分。
- **二分定位**：注释一半代码/数据看问题是否还在；跨版本的回归用 `git bisect`。
- **固定随机性**：涉及随机、并发或时间的 bug，先固定 seed、串行化或冻结时间，让问题稳定复现再排查。
- **环境对照**：`pip freeze` 对比可疑环境与干净 venv 的差异；“本机好的、线上坏的”优先查版本、配置和数据差异，而不是代码。

## 6. 常见误区

**误区 1：裸 `except:` 或 `except Exception: pass`**
吞掉异常等于把报错现场销毁。至少要记录日志再决定是否继续；裸 `except:` 还会拦截 `KeyboardInterrupt` 这类本不该拦截的退出信号。

**误区 2：一报错就重装环境或重启**
重启可能暂时清除现象，但没有回答“为什么发生”。先保留现场（日志、堆栈、输入），再考虑恢复手段。

**误区 3：只在出错行找问题**
异常抛出的位置经常不是引入错误的位置。`KeyError` 的根因可能在几层之外构造 dict 的地方；要沿数据流向上追。

**误区 4：修完不留证据**
修复后补一个能复现原 bug 的测试或至少一条记录。同类问题第二次出现时，排查成本应该趋近于零。
