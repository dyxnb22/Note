# 06 Agent 开发

> 前提同 01。这里只讲**实现视角**:Python 里怎么把 Agent 搭起来。概念、治理和评测方法论不在这里重复。

## LLM 调用

- 显式设置超时(连接 / 首字节 / 总)和最大输出长度。
- **超时只表示这次等待结束,不代表模型没执行。** 有计费或副作用的调用要按幂等键 + Provider request ID 查询对账。
- 重试要区分:可重试(429、5xx、网络抖动)和不可重试(400、内容策略拒绝)。
- 流式输出:首事件超时、总超时、响应大小上限要分别设。
- 记录 token 用量和成本,便于预算和异常检测。

## 消息与 Prompt 结构

- 角色:`system`(行为约束)、`user`、`assistant`、`tool`(工具结果)。
- 输入分区要清晰并标注来源:系统指令 / 用户输入 / 检索上下文 / 工具输出。
- 上下文有窗口上限,超了要裁剪或摘要,裁剪策略要可解释。
- **提示注入**:外部内容(网页、文档、工具结果)一律当不可信输入,不能让它覆盖系统约束。

## 结构化输出

- 优先用模型的结构化输出 / JSON schema 能力,别靠正则解析自然语言。
- 解析失败要有明确失败路径和重试上限,不要静默兜底成默认值。
- 校验通过 ≠ 业务合法,业务规则在代码里再校一次。

## Tool Calling

- 工具 schema 要精确:类型、必填、枚举、描述。描述是**给模型看的**,要写清什么时候用。
- 流式返回时工具参数是**增量分片**的:按 index 组装完整 JSON 再解析。
- 执行前校验:参数合法、调用方有权限、资源存在、幂等键。
- 工具执行是**真实副作用**,要有超时、白名单、沙箱、审计日志。
- 工具结果要能区分"成功"、"业务失败"、"执行异常",不能都当成功。

## Agent 循环与分层

- 分层:`Provider`(模型客户端)/ `Tool`(工具注册与执行)/ `State`(会话与中间状态)/ `Loop`(编排与控制)。
- Loop 必须有终止条件:**最大轮次、总超时、预算上限、明确完成信号**,至少满足两个。
- 状态持久化:每轮可中断可恢复(Checkpoint),不要整个会话只放内存。
- 幂等:同一轮重放不应重复产生副作用。
- 观测:每轮记录输入摘要、工具调用、token、耗时、结束原因。

## RAG

- 流程:切分 → 嵌入 → 检索 → (重排) → 拼进上下文。
- 切分按语义边界,保留来源元数据(路径、标题、位置)。
- 检索质量优先于提示词调优:先看召回,再看精排。
- 向量检索可与关键词检索混合,再重排。
- 引用要能回到原文位置,便于核对。

## 评测

- 没有标准答案的任务要建评测集:输入 + 期望特征 + 判据(规则 / 模型裁判 / 人工)。
- 区分离线评测和线上指标;线上看任务成功率、失败类型、成本、延迟。
- 改 Prompt、换模型都要跑同一套评测,不要凭感觉。
- 记录版本:Prompt 版本、模型版本、检索索引版本。

## 安全与执行边界

- 工具权限最小化:只给必要的工具,只给必要的资源范围。
- 高风险动作(写文件、发请求、花钱)要能审批或限额。
- 沙箱执行代码 / shell,限制网络和文件系统访问。
- 审计:谁在什么时候让 Agent 做了什么,可追溯。
