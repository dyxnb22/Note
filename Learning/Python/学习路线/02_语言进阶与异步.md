# 02 语言进阶与异步

> 前提同 01。这一章是往后端和 Agent 走的必经路。

## 迭代协议

- 可迭代对象实现 `__iter__`(返回迭代器);迭代器实现 `__next__`,耗尽时抛 `StopIteration`。
- `for`、`in`、解包、`list()` 都走这套协议。
- 类型注解里区分 `Iterable`(可迭代)和 `Iterator`(迭代器本身)。

## 生成器

```python
def gen(n):
    for i in range(n):
        yield i

g = gen(3)     # 惰性,调用时不执行
next(g)        # 0
list(g)        # [1, 2]
```

- `yield` 暂停并保存函数状态;`yield from` 委托给子生成器。
- **只能消费一次**;要重复用就重新生成或缓存成 list。
- `send()` 回传值,`close()` / `throw()` 控制结束与异常。
- 生成器表达式 `(x for x in xs)` 等价但更省代码。

## 装饰器

```python
import functools

def log(fn):
    @functools.wraps(fn)          # 保留 __name__ / __doc__
    def wrapper(*a, **kw):
        print(fn.__name__)
        return fn(*a, **kw)
    return wrapper

@log
def run(): ...
```

- 装饰器是"接收函数、返回函数"的可调用对象;`@log` 等价于 `run = log(run)`。
- 带参数的装饰器外面再包一层。
- 异步函数要用异步装饰器(`async def wrapper` + `await`)。
- 常用:`functools.lru_cache` / `functools.cache`、`staticmethod` / `classmethod` / `property`。

## 上下文管理器

```python
with open("f.txt", encoding="utf-8") as f:
    data = f.read()
```

- 协议是 `__enter__` / `__exit__(exc_type, exc, tb)`;`__exit__` 返回真值会吞掉异常。
- `contextlib.contextmanager` 可以把一个生成器写成上下文管理器。
- `contextlib.ExitStack` 管理数量不定的资源。

## 描述符

- 实现 `__get__` / `__set__` / `__delete__` 的类属性,决定实例属性的读写行为。
- `property`、`classmethod`、`staticmethod`、普通函数本身就是描述符。
- 只在需要复用属性逻辑时才自己写;大多数场景 `property` 够用。

## dataclass

```python
from dataclasses import dataclass, field

@dataclass(frozen=True, slots=True)
class User:
    id: int
    tags: list[str] = field(default_factory=list)
```

- 自动生成 `__init__` / `__repr__` / `__eq__`。
- 可变默认值必须用 `field(default_factory=...)`,直接写 `[]` 会报错。
- `frozen=True` 近似不可变并生成 `__hash__`;`slots=True` 省内存。
- 需要额外校验用 `__post_init__`,或直接上 `pydantic`。

## 类型注解

```python
def f(x: int, items: list[str]) -> dict[str, int]: ...
```

- 注解**运行时不做校验**,只是元数据(存在 `__annotations__`)。
- 3.9+ 用内置泛型 `list[int]`;3.10+ 用 `X | Y`;3.12+ 有 `type` 别名语句。
- `typing.Optional[X]` 就是 `X | None` 的旧写法,两者等价(`Optional[TreeNode] == TreeNode | None` 为 `True`),但 `Optional` 要 `from typing import Optional`,在只写现代语法的代码库里看到它按 `X | None` 读即可。
- 常用:`X | None`、`Literal`、`TypedDict`、`Protocol`、`Callable`、`Iterable` / `AsyncIterator`、`Annotated`、`TypeVar`、`Generic`。
- `Protocol` 是**静态**的结构化子类型,不要求继承,适合依赖反转。
- `abc.ABC` + `@abstractmethod` 是**运行时**接口约束:不能实例化,漏实现会报错。要强制约束就用它。
- `NewType("UserId", int)` 只做静态标记,运行时还是 `int`,用于区分同底层类型的不同语义。
- 运行时校验要另找工具:`pydantic`、`typeguard`。静态检查用 `mypy` 或 `pyright`。

## 序列化

- 事件、缓存键、签名要**稳定序列化**:键顺序固定、浮点表示固定、时间格式固定。
- 常用写法:`json.dumps(obj, sort_keys=True, separators=(",", ":"))`。
- 内容摘要用 `hashlib`,**不要用 `hash()`**(有随机化,进程间不稳定)。
- `pickle` 反序列化会执行任意代码,**不能用于不可信数据**;跨信任边界一律用 JSON 这类数据格式。

## 同步并发原语

- `threading.Lock` / `RLock`:保护共享可变状态,用 `with lock:`。`Lock` 是基础互斥;`RLock` 记录持有线程和递归计数,适合递归或回调会重入同一段代码的场景。
- `queue.Queue`:线程安全队列,实现生产者—消费者。
- `threading.Event` / `Condition` / `Semaphore`:事件通知、条件等待、限流。`Semaphore` 适合连接池和并发上限;`Event` 是一次性广播开关,适合优雅停止。
- `concurrent.futures`:线程池 / 进程池,统一 `submit` / `map` 接口。
- `multiprocessing`:跨进程共享用 `Value` / `Array` / `Queue`,或干脆传消息。
- 读-改-写**不是**原子操作,别指望 GIL 保证正确性。

## 竞态、死锁与饥饿

- 竞态:缩小临界区,或把共享可变状态换成 `queue.Queue` 消息传递 / 不可变数据来消除。
- 死锁:固定加锁顺序、用 `acquire(timeout=...)` 或非阻塞获取留退路、避免持锁状态下调用未知回调。
- 饥饿:限制单次持锁时间和任务粒度。
- 更推荐的结构:用队列把写操作收敛到单线程/单消费者,线程只承担阻塞 I/O,CPU 密集交给多进程。
- 锁的正确性要用并发压测和竞争检测工具验证,不能只靠单测。

## CPython 执行模型与 GIL

- 源码 → 字节码 → 解释执行;`dis` 可看字节码。
- 引用计数即时回收;循环引用由分代 GC 处理(`gc` 模块)。
- **GIL**:同一时刻只有一个线程执行 Python 字节码。
  - 纯 Python 的 CPU 并行拿不到;I/O 等待和释放 GIL 的扩展(如 `numpy`)仍能并行。
  - 3.13+ 有实验性的自由线程构建,生产仍需评估。
- GIL ≠ 线程安全。

## 线程 / 进程 / 协程怎么选

| 场景 | 选择 |
|---|---|
| I/O 密集、连接多 | `asyncio` |
| I/O 密集、只能用同步库 | 线程池 `ThreadPoolExecutor` |
| CPU 密集 | 多进程 `ProcessPoolExecutor` |

- 进程内存独立,通信要序列化(pickle),开销大。
- 线程适合"包住阻塞调用",不适合绕过 GIL 做计算。

## asyncio 核心

```python
import asyncio

async def fetch(u):
    async with client.get(u) as r:
        return await r.json()

async def main():
    return await asyncio.gather(*(fetch(u) for u in urls))

asyncio.run(main())
```

- `async def` 定义协程;调用它只得到协程对象,`await` 才真正执行。
- 事件循环单线程调度,`await` 处让出控制权。
- **不能在协程里跑阻塞调用**(`time.sleep`、同步 `requests`),会卡住整个循环;用异步库,或 `await asyncio.to_thread(...)`。
- 并发控制:`gather`(全部一起)、`as_completed`(谁先完先处理)、`wait`(按条件等)、`TaskGroup`(3.11+,异常聚合)、`Semaphore`(限流)。
- 选 `gather` / `wait` / `as_completed` 时要提前规定:异常是否立即传播、兄弟任务是否取消、超时后如何清理,不能只看 API 名称。
- 超时:`asyncio.timeout(5)`(3.11+)或 `wait_for`;超时要包住真实的外部操作,而不是只包一层等待。
- 取消:`Task.cancel()` 通过 `CancelledError` 传播;**取消点只在 `await` 处**。取消要沿调用链传播并在 `finally` 中释放连接、文件、锁等资源;捕获 `CancelledError` 后清理完继续传播,不要静默吞掉。
- 超时只说明当前等待没有得到结果,不一定说明外部操作没完成;带副作用的请求需要查询状态或对账。
- 别裸用 `gather`:一个失败会影响其他,要显式处理异常和取消。

## 异步资源与生命周期

- 异步上下文管理器:`async with` + `__aenter__` / `__aexit__`。
- 异步迭代:`async for` + `__aiter__` / `__anext__`;异步生成器用 `async def` + `yield`。
- 关闭流程:取消未完成 Task、关闭连接池、用 `gather(..., return_exceptions=True)` 收尾。
- 关键清理用 `asyncio.shield` 保护,避免被取消掉。

## 上下文传递

- `contextvars.ContextVar`:在异步任务链条里传 `request_id`、租户、trace 上下文的标准做法。
- `asyncio` 的每个 Task 会复制当前 context,所以不会串到别的请求;`asyncio.to_thread()` 也传播当前 Context。
- 自建线程池、进程、消息队列或独立后台任务不能一概假设自动继承,应按 API 和版本显式传递需要的字段。
- 用法:请求入口 `set()`、`finally` 中用 token `reset()`;不要用模块级全局变量保存请求上下文,`threading.local()` 也不能正确表达同一线程中交错的多个协程。
- 权限不能只存在 `ContextVar` 或日志 MDC 里:工具执行器仍要接收显式身份/租户参数并重新授权;测试要并发运行不同租户请求验证日志不串号。

## 性能与内存排查

- 先固定负载和基线,再区分 CPU / I/O / 序列化 / 下游。
- CPU:`cProfile` + `pstats`,线上用 `py-spy`。
- 内存:`tracemalloc`、`objgraph`。
- 对象内存还给分配器 ≠ RSS 立即下降。
- 优化后复测 P95 和错误率,不只看平均值。
