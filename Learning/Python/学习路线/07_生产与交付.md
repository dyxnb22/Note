# 07 生产与交付

> 前提同 01。这章解决"能跑"到"上线还能跑"之间的差距。

## 容器与部署

- 多阶段构建:运行时只带依赖,不带编译工具链。
- 固定基础镜像版本;`pip install --no-cache-dir`;先装依赖再 copy 源码,利用层缓存。
- 非 root 运行;可行时只读根文件系统;显式暴露端口。
- 健康检查区分 liveness(要不要重启)和 readiness(能不能接流量)。

## 配置与环境

- 配置来自环境变量或配置中心,不写死在镜像里。
- 启动即校验配置,缺项快速失败。
- 密钥由密钥管理服务注入,不落盘、不进镜像层。

## 可观测性

- 日志:结构化,带 trace_id,可检索。
- 指标:请求侧看速率 / 错误率 / 延迟,资源侧看利用率 / 饱和度 / 错误;关注 P95 / P99 而不是均值。
- Trace:跨服务、跨模型调用串起来,标出下游耗时。
- 三者用同一套 ID 关联起来。

## 容量与可靠性

- 每个依赖设超时、重试上限、熔断和并发上限。
- 有界队列 + 背压:队列满了要快速失败,不要无限堆积。
- 限流既保护自己,也保护下游。
- 用 SLO + 错误预算决定发版节奏,别把"零故障"当目标。

## 优雅退出

- 收到 SIGTERM 后:停止接新请求 → 等在途请求完成 → 关闭连接池 / 取消任务 → 退出。
- 设退出上限时间,超时强制退出。
- 长任务要能被取消,或标记为可恢复。

## 灰度与回滚

- 发布用滚动 / 蓝绿 / 金丝雀;先小流量看指标,再放量。
- 数据库变更加迁移脚本,且要向后兼容:先加后用,最后清理。
- 回滚路径要提前演练,不能只写在文档里。

## 事故响应

- 先止损(回滚 / 限流 / 降级),再定位。
- 保留现场:日志、Trace、指标、堆栈。
- 复盘关注机制和检测手段,不只写"某人操作失误"。

## 依赖与供应链

- 锁文件进仓库,构建可复现。
- 定期扫已知漏洞;升级要有测试覆盖。
- 慎用不活跃依赖,评估许可证。
