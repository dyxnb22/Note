# 04 工程基础

> 前提同 01。这一章解决"代码怎么组织、怎么跑得起来、怎么交付"。

## 虚拟环境与依赖

- 开发依赖应装在项目隔离环境里,例如 `python -m venv .venv`;不要依赖全局环境。
- 项目元数据和直接依赖写在 `pyproject.toml`;requirements 文件仍适用于 pip 安装清单、部署输入或简单脚本,不是废弃格式。
- 锁文件记录依赖解析结果,用于在不同机器上重建一致环境;应按所用工具提交对应锁文件。
- `uv`、`poetry`、`pip-tools` 等会覆盖不同的项目、解析、锁定和安装工作流,不只是“更快的 pip”。
- 具体区别、常见命令与选型见[Python 环境与依赖管理专题](./专题_环境与依赖管理.md)。

## 项目结构

```text
src/app/
  main.py        # 组合根:装配依赖、启动
  api/           # 协议层:路由、DTO、错误映射
  domain/        # 领域层:纯逻辑,不 import 框架
  infra/         # 基础设施:数据库、HTTP 客户端、外部适配
tests/
```

- 依赖方向指向内层:`api → domain ← infra`。
- 领域层不要 import FastAPI / SQLAlchemy。
- 组合根(composition root)放启动层,不要散落到业务代码里。
- Service 编排用例、Client 封装外部 API、Repository 隔离数据读写;是否抽象取决于真实替换边界、测试需求和状态复杂度,不是类越多越工程化。

## 配置与密钥

- 配置从环境变量读;用 `pydantic-settings` 做校验和默认值。
- 密钥不进仓库、不进日志、不进镜像;`.env` 只用于本地并写进 `.gitignore`。
- 启动时校验一次配置,缺项直接失败,别拖到运行中才炸。

## 日志

- 用标准库 `logging`;库代码只 `getLogger(__name__)`,不在库里调 `basicConfig`。
- 结构化日志(JSON)便于检索,至少带 `request_id` / `trace_id`。
- 级别语义:DEBUG 调试、INFO 关键业务事件、WARNING 可恢复异常、ERROR 需介入。
- 不要用 `print`;不要把密钥和整段敏感数据打进日志;完整 token、Prompt 和用户内容也不无边界写入日志,先脱敏。

## 测试

- pytest:`test_*` 函数 + `assert`;`conftest.py` 放共享 fixture。
- fixture 管理资源生命周期,`yield` fixture 做前后清理。
- 分层:单元(纯逻辑)→ 集成(数据库、HTTP 用测试容器 / 响应桩)→ 契约(对外接口)→ 端到端。
- 替身:Stub(固定返回)、Fake(简化可用实现,如内存仓库)、Mock(验证调用);只验证"调用过某方法"不能证明结果正确。
- 时间、随机、并发要可控:注入时钟 / `freezegun`、固定随机种子;必要时用事件屏障、虚拟时钟和故障注入让竞态可重复,测不变量而不是脆弱的 `sleep`。
- 异步测试用 `pytest-asyncio`;HTTP 用 `httpx.MockTransport` / `respx`。Mock 适合精确控制状态码、断连、超时和响应顺序;TLS、连接池和真实协议仍需要少量真实集成测试,Mock 不能证明线上 Provider 的所有语义。
- 别用 `sleep` 等异步结果,等事件或轮询条件。
- 断言要覆盖:调用次数、退避上限、超时/取消后任务结束与资源释放、异常没有被吞;对已发出副作用的调用,还要测响应丢失、重复投递和对账路径。
- 不要把所有内部实现细节固定成测试,也不要用 Mock 掩盖真实协议、权限和超时问题。

进阶三种测试:

- **契约测试**:验证对外接口的约定(请求 / 响应形状、错误码)不漂移,不测具体实现。
- **金测试(golden)**:把已知正确的输出冻结成基线做比对。风险是容易被无脑"更新基线",从而失去判别力,基线变更必须有人审。
- **属性测试**(`hypothesis`):声明不变量让工具生成用例,适合边界和往返性质,例如"解码(编码(x)) 等于 x"。

## 代码质量

- `ruff`:格式 + lint(替代 flake8 / isort / black)。
- `mypy` 或 `pyright`:静态类型检查;Python 版本、依赖、`mypy` 配置和检查命令写进 `pyproject.toml`,CI 在干净环境执行 `python -m mypy src`,有意忽略的边界逐条说明。
- `import-linter`:约束模块依赖方向(比如领域层不许 import 基础设施)。
- 三者写进 CI;本地用 pre-commit 提前跑。三者互不替代:类型正确不代表依赖方向正确,格式正确不代表运行时输入合法。
- 依赖方向和组合根约束也进自动化门禁,提交时阻止反向导入,把"哪些层可以知道什么"变成可执行合同。

## 打包与入口

- `python -m build` 产出 wheel / sdist;`[project.scripts]` 声明 CLI 入口。
- CLI 退出码也是契约:0 成功,非 0 表示具体失败类型。
