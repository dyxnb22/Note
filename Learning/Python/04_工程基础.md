# 04 Python 工程组织与质量

同一条业务规则，可能同时被命令行、HTTP 和后台任务调用。把规则放在哪里、怎样传入依赖、在哪里转换错误，决定了这些入口能否共用代码。

[订单查询脚本](案例_订单查询脚本.md#文件怎样配合)展示命令行入口与业务模块的实际分工；同一业务模块还由 Agent 入口复用。

## 从脚本到工程

一个脚本可以混写配置、查询、业务判断和输出。入口多了之后，容易在 CLI、HTTP 和后台任务里各复制一份规则；改了一处，其他地方就可能漏改。

以订单查询为例，能否取消订单属于业务规则，从数据库读取订单属于存储操作，把错误转成 HTTP 状态码则由接口层处理。业务规则只接收判断所需的数据，CLI、HTTP 和后台任务可以复用同一份实现。

取消规则拆出来后，只需修改一份业务代码。几行能讲清、也只有一种实现的逻辑，直接写函数即可，不必逐层包装成 Service、Repository 和 Manager。

## 模块、包与 src 布局

一个模块可以放一组相关的函数和类，包则把模块组织起来。调用方使用公开接口，模块内部的实现可以独立调整。

src 布局把要安装的代码放在源码子目录中。在项目根目录测试时，Python 可能直接导入本地源码，掩盖安装包缺文件的问题。检查安装结果时，结合解释器、工作目录、安装方式和 sys.path，确认实际导入位置。

两个模块互相导入时，可以把共用的数据定义移到第三个模块，让两边都导入它，或调整模块之间的调用关系。这通常比在每个函数里延迟导入更容易理解。

## 用参数传入依赖

依赖注入最简单的写法，就是由调用方创建查询对象，再通过参数传给业务函数。环境变量读取和数据库连接创建留在应用入口。

```python
from typing import Protocol

class OrderReader(Protocol):
    def status(self, order_id: str) -> str: ...

def cancellation_allowed(reader: OrderReader, order_id: str) -> bool:
    return reader.status(order_id) == "pending"
```

业务函数只调用 status，所以连接真实数据库的查询对象和测试用的内存对象，都只需提供这个方法。类型检查器通过 Protocol 判断两者的方法是否符合要求，数据校验和超时由运行时代码处理。接口先包含当前用到的方法，有新需求再扩展。

## 依赖声明与运行环境

pyproject.toml 可以声明项目元数据、直接依赖和允许的版本范围；锁文件记录解析器选定的版本及来源等信息。范围说明“允许哪些版本”，锁定结果说明“解析器实际选定了哪些版本”。

同一依赖版本在不同平台上可能选中不同 wheel，因此还要记录 Python 版本、操作系统、架构和原生库条件。目标机器按声明与锁文件重建环境，具体工具见[环境与依赖管理](专题_环境与依赖管理.md)。

## 测试、类型检查与输入校验

| 方式 | 主要回答的问题 | 不能单独证明什么 |
|---|---|---|
| 单元测试 | 某段行为在给定条件下是否符合预期 | 完整系统在所有环境都正确 |
| 集成测试 | 数据库、接口或组件之间能否配合工作 | 没有测到的业务场景是否正确 |
| 静态类型检查 | 类型与接口关系是否一致 | 外部输入一定合法 |
| Lint 与格式检查 | 是否存在常见错误、格式是否一致 | 业务规则是否正确 |
| 运行时校验 | 当前输入是否符合明确约束 | 数据来源真实、调用已授权 |

测试尽量检查用户关心的行为。例如取消订单后重新读取，确认状态已变更；只检查 update 函数被调用过，会漏掉提交失败等问题。单元测试可以使用替身隔离依赖，事务提交和跨连接读取则需要接入真实存储验证。

验证异步行为时，可以用 Event 等待任务到达指定阶段。固定休眠容易受机器负载影响：时间到了，任务却未必已经执行到那里。

## 配置、日志与异常的处理位置

入口读取环境变量、命令行参数和配置文件，校验后传给业务对象。必需项缺失时直接启动失败，避免收到请求后才发现配置问题。

命令行程序通常将业务输出写到 stdout，诊断日志通过 logging 写到 stderr 或日志系统。库模块取得日志对象，日志级别和处理器由应用入口配置。

请求 ID 与任务 ID 用于关联记录，密钥与完整敏感输入不应直接写入普通日志。

存储层报告写入冲突后，业务层可以把它解释成业务冲突，HTTP 层再映射成状态码。每一层只转换自己能解释的错误，并保留异常原因链，方便回查底层问题。

## 分发格式与安装验证

wheel 是已经构建好的 Python 安装包，源码分发包保存构建所需的源码，容器镜像还包含运行环境和系统依赖。

安装后检查模块和资源是否齐全，再到目标环境验证权限、依赖服务和业务行为。步骤见[生产与交付](07_生产与交付.md)。
