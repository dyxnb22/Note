# 06 Python 中的 Agent 运行时

模型提出动作后，Python 程序接收响应、校验参数、执行工具并保存结果。这一篇看接口怎样写，控制策略和检索原理见 [[Learning/Agent/00_01_Agent系统全景|Agent 系统全景]]。

可运行实现见[订单查询 Agent 案例](../Agent/案例_订单查询Agent.md)。案例采用同步标准库；下面另外展示异步接口和 Pydantic 参数模型，供后续扩展时参考。

## 用适配层接入模型

不同服务的消息、工具参数、内容块、停止原因和用量格式不同。业务代码如果直接依赖某个 SDK 的返回对象，更换接口时，就得一起修改依赖这个对象的代码。

适配层把外部响应转成应用自己的类型。如果接口要求下一轮带回调用 ID、原始内容块或签名，适配层就要保存这些数据。不支持的内容按约定处理或报错，不能直接丢弃。具体协议检查见[Provider 适配](../Agent/10_模型与推理/02_Provider适配与框架选型.md)。

## 用 Protocol 描述模型接口

Protocol 描述调用方需要的方法和属性。类型检查器判断对象有没有提供符合要求的方法和属性，不要求它们继承同一个基类。

```python
from typing import Protocol

class ModelClient(Protocol):
    async def decide(self, messages: list[dict], tools: list[dict]) -> dict: ...
```

这个 Protocol 让类型检查器检查调用方式：需要 await 调用，参数是上下文和工具定义，返回值是 dict。dict 里的响应字段、服务异常和工具选择，仍由运行时代码处理。

## 在运行时校验工具参数

收到工具参数后，用 Pydantic 校验字段类型、长度和未知字段。同一个参数模型生成 JSON Schema，让工具说明与执行校验共用一份规则。

```python
from pydantic import BaseModel, ConfigDict, Field

class LookupOrder(BaseModel):
    model_config = ConfigDict(strict=True, extra="forbid")
    order_id: str = Field(min_length=1, max_length=32)
```

参数模型只接收订单号，租户由运行时从可信身份取得。字段校验通过后，执行器再检查目标订单是否属于当前访问范围。别名和序列化见 [Pydantic 专题](专题_Pydantic.md)。

## 异步等待、超时与取消

在 async def 函数中，await 用来等待模型或异步工具完成。同步数据库调用仍可能阻塞事件循环，可以改用异步驱动，或交给有并发上限的线程池。

每次模型等待可以有超时，整个任务还应有统一期限。重试时重新分配完整超时，会让总耗时不断增长。取消通常通过 CancelledError 传播，清理放在 finally；已经提交的外部动作不会因此撤销。

并发请求怎样共享预算、处理未知用量，见[运行时状态流转](../Agent/01_基础架构/运行时机制与状态流转.md#调用前预留额度，调用后保存结果)。

## 按调用 ID 配对工具结果

执行器按工具名从注册表取出函数，校验参数和权限后调用它，再把返回结果配回原调用 ID。工具名选择函数，调用 ID 配对消息，业务操作 ID 追踪业务意图。

一次返回可能含多个调用，结果按 ID 配对，回填时遵循 Provider 对内容块与消息顺序的要求。流式参数先完整组装，再解析和校验，最后交给执行器。

## 保存任务状态与模型请求

State 保存任务 ID、当前阶段、剩余预算、版本、待处理动作和结果。版本要注明对象，例如任务状态版本或订单资源版本；用户及租户身份也要与任务 ID 分开记录。

若要还原模型调用，还要保存完整请求，包括 system 指令、工具 Schema、模型标识和生成参数。单独的消息历史未必包含这些内容。

中断恢复还要核对剩余额度、未知写操作和当前授权，并检查保存的 Prompt、工具版本是否兼容。迁移和停止恢复的处理见[持久化执行](../Agent/09_工程化与系统设计/02_Durable与生产运维.md)。

## 按业务要求判断任务完成

运行时按任务要求验收：查询要取得所需事实，引用要支持结论，写操作要确认外部状态。模型服务的停止原因如何处理，见[Loop 控制](../Agent/01_基础架构/Loop控制与Harness.md#区分工具结果、任务状态与停止原因)。
