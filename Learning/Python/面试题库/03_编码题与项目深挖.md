# Python 编码题与项目深挖

> 递进路径：先写正确的基础算法，再补复杂度、并发边界和项目验收。

## Level 1｜基础编码题

### 1. 两数之和如何实现？

答：遍历数组，用 dict 记录已经出现的值和下标；当前值为 `x` 时先查 `target - x`，存在就返回两个下标，再记录 `x`。时间 O(n)，空间 O(n)。要先查后存，避免同一个元素被使用两次，并说明没有答案和重复值的处理。

### 2. 如何合并区间？

答：按左端点排序，维护当前合并区间；下一个区间与当前重叠就扩展右端点，否则输出当前区间并开始新区间。排序 O(n log n)，扫描 O(n)。要先澄清端点是否闭区间、是否允许相邻区间合并以及空输入。

### 3. 如何实现最长无重复子串？

答：用滑动窗口和 dict 记录字符最近位置；右指针扩展，遇到窗口内重复字符就把左指针跳到上次位置加一，并更新最大长度。每个字符位置最多被处理常数次，时间 O(n)，空间 O(k)。

### 4. 如何设计 LRU Cache？

答：dict O(1) 定位节点，双向链表维护最近使用顺序；get/put 命中后移到表头，超容量删除表尾。要说明容量为零、更新已有键、并发访问、过期时间和统计指标；并发服务需要锁或分片，不能因为底层 dict 单次操作看似原子就宣称整体线程安全。

### 5. 如何做 Top K 高频元素？

答：先用 dict 计数，再用大小为 K 的最小堆维持当前 K 个元素，时间 O(n log k)、空间 O(n)；如果值域有限可用桶排序，平均更快但需要额外条件。要问清楚是否只返回频次、是否要求稳定顺序和 K 是否大于元素种类数。

### 6. 如何验证括号是否匹配？

答：用栈保存左括号，遇到右括号检查栈顶是否对应，最后栈为空才有效，时间 O(n)、空间 O(n)。如果输入包含字符串、转义或注释，先明确是否只处理三种括号，不能把简单题直接扩展成错误的语言解析器。

## Level 2｜并发与工具编码题

### 7. 实现一个带并发上限的异步抓取器，关键状态有哪些？

答：至少有输入 URL、并发信号量、每项 deadline、重试次数、结果状态、错误类型和取消信号；每项请求使用独立超时，成功/失败/取消都释放信号量。父任务取消时停止提交新任务并等待已启动任务清理，聚合结果时区分部分成功和真正完成。

```python
import asyncio


async def fetch_all(urls, fetch, *, limit=10, timeout_s=5):
    semaphore = asyncio.Semaphore(limit)

    async def one(url):
        async with semaphore:
            try:
                async with asyncio.timeout(timeout_s):
                    return url, "ok", await fetch(url)
            except asyncio.CancelledError:
                raise
            except Exception as exc:
                return url, "error", exc

    return await asyncio.gather(*(one(url) for url in urls))
```

这段代码只展示控制流；生产实现还要限制输入规模、复用 HTTP 客户端、区分可重试错误并处理结果未知的副作用。

### 8. 如何写一个带指数退避和抖动的重试装饰器？

答：只对明确的瞬时错误重试，等待时间使用 `min(cap, base * 2**attempt)` 加随机 jitter，限制次数和总时间；每次调用带 trace 和幂等键。未知是否已执行成功的副作用请求不能直接重试，应先查状态或进入对账。

### 9. 如何实现一个带背压的生产者—消费者模型？

答：使用有界 `asyncio.Queue`，生产者在队列满时等待或拒绝，消费者固定数量取任务并在完成后 `task_done`；关闭时先停止生产，再等待队列清空或取消剩余任务。队列容量、任务超时、错误传播和消费者退出必须写进协议，不能用无界队列掩盖下游过慢。

### 10. 如何流式处理 JSON Lines 文件？

答：按行读取而不是一次性读入，逐行解析、校验和处理，记录行号和错误；输出采用临时文件后原子替换，避免进程中断留下半成品。大文件要限制单行大小，必要时把失败记录写入隔离文件并保证可重放。

### 11. 如何实现一个令牌桶限流器？

答：保存容量、补充速率、当前令牌数和最近更新时间；每次请求先按经过时间补充令牌，再原子地检查并扣减。单进程可以用锁保护状态，分布式要用支持原子更新和过期的存储；时钟、突发容量、拒绝/排队语义和租户 Scope 都要明确。

## Level 3｜系统设计与项目深挖

### 12. 设计一个 Python 任务执行服务，如何保证任务不丢、不重复和可恢复？

答：任务表保存 task ID、输入摘要、状态、版本、租约、重试次数和结果引用；提交用唯一幂等键，Worker 通过租约领取并定期心跳，完成时用条件更新提交状态。进程崩溃后租约过期可重试，外部副作用需要业务幂等和状态查询；Checkpoint 只能保存可验证的阶段状态，不能把内存对象直接当恢复依据。

### 13. 设计一个 FastAPI + MySQL + Redis 的订单/任务 API，如何划分边界？

答：API 层做协议和鉴权，服务层做状态机和幂等，Repository 层处理事务，Redis 只做缓存/短状态，后台队列处理慢任务；数据库唯一约束是最终一致性底线。创建请求先落库并记录幂等结果，再通过 Outbox 或可靠事件发布任务；查询缓存要定义失效、版本和回源策略。

### 14. 项目中一次最值得讲的性能优化怎么回答？

答：按“现象—基线—定位—改动—结果—副作用”回答：先说 P95、吞吐、CPU/内存或下游等待的具体问题，再说明使用了什么 profile/trace/执行计划定位；改动后报告相同负载下的指标变化，以及连接数、成本、复杂度和失败率是否受影响。不要只说“用了异步所以快”。

### 15. 项目中一次线上故障怎么回答？

答：先说明用户影响和时间线，再讲监控如何发现、如何缩小范围、临时止血、根因、修复和验证；如果是超时/重试/重复副作用，要说明状态是否未知和如何对账。最后补自动化改进：超时、告警、限流、幂等、回放测试、灰度或 Runbook。

### 16. 面试官让你把同步脚本改成可扩展服务，你会先问什么？

答：先问任务是否有副作用、输入规模、并发/QPS、延迟目标、失败重试、结果持久化、权限和取消语义；再判断是同步 API、异步队列还是批处理。架构从最小可运行版本开始，逐步补连接池、背压、状态机、观测和部署，不直接把脚本包装成无边界的后台线程。

### 17. Python 遇到线上异常时，如何从 traceback 快速定位？

答：先看最后一行的异常类型和消息，再沿调用链找到最深的一层自己代码，结合输入、配置和依赖响应判断根因；异常链中用 `raise ... from ...` 区分包装错误，处理后重新抛出通常用裸 `raise` 保留原始堆栈。还要排查本地文件遮蔽标准库、虚拟环境不一致和错误处理代码二次失败。

### 18. 一个难以复现的 Python bug 应该如何缩小范围？

答：先保存完整 traceback、输入、版本和配置，做最小复现；涉及随机、时间或并发时固定 seed、冻结时钟或降低并发，跨版本回归可用二分定位。修复后补一个能稳定复现原问题的测试，避免只靠重启、重装环境或增加日志掩盖根因。

### 19. 如何设计一个带事件 ID、断线重连和最终状态的 SSE/LLM 流式代理？

答：服务端把任务状态和事件序列分开保存，事件至少包含 task ID、递增序号、类型、版本和是否终止；客户端收到事件后按 ID 去重，断线通过 Last-Event-ID 或任务查询继续，而不是重新执行副作用。Provider 断连时记录未知结果并按策略查询/对账，最终答案需经过 schema、敏感内容和业务验收后再标记 succeeded。

### 20. 如何用测试验证第三方重试不会造成重复扣费或重复写入？

答：Fake Provider 按预设序列返回连接断开、超时、明确 5xx、重复响应和状态查询结果，固定时钟验证退避和总 deadline；断言所有尝试携带同一幂等键，未知结果先查询，明确不可重试错误不再调用，成功只提交一次业务状态。把最小失败序列沉淀为回归测试，并保留一条真实协议/账单沙箱集成测试。
