# Python 工程与后端

> 递进路径：从项目组织和 API 边界，讲到数据库、缓存、任务队列、测试和上线；现代 AI 服务额外关注结构化输出、流式传输、Provider 失败和费用边界。

## Level 1｜工程基础

### 1. 一个可维护的 Python 服务如何组织目录？

答：入口层负责组装配置和依赖，接口层负责协议适配，业务层负责用例和不变量，基础设施层负责数据库、HTTP、队列和外部服务；模块之间通过稳定接口依赖，避免导入时执行副作用。目录名不是重点，重点是把业务逻辑从框架、网络和存储中隔离，方便单测和替换。

### 2. 如何管理虚拟环境、依赖和配置？

答：用项目级依赖声明和锁定文件记录直接/间接依赖，构建时使用可复现环境；配置从环境或受控配置中心注入，密钥不写进仓库和日志。启动时校验必填配置、类型、范围和版本，运行中不要随意修改连接池、超时等关键配置。

### 3. API 输入校验和业务校验有什么区别？

答：输入校验检查类型、格式、长度、枚举和结构，业务校验检查权限、状态机、库存、幂等和跨字段约束。Pydantic/FastAPI 等工具能完成第一层，但不能替代数据库约束和领域规则；错误响应要有稳定结构、可观测 request ID 和不泄露内部信息的消息。

### 4. Python HTTP 客户端必须设置哪些边界？

答：至少设置连接/读取/总超时、连接池上限、响应大小、状态码处理、取消、重试条件和幂等键；复用客户端并在服务关闭时释放连接。超时后的结果可能未知，POST 等副作用请求不能按网络错误盲目重试，必要时先查询状态。

### 5. 同步接口和异步接口如何选择？

答：端点内部主要调用支持异步的网络/数据库库且需要高并发 I/O 时选 async；已有同步库、CPU 计算或简单低并发服务可用同步。不能在事件循环中直接执行长时间阻塞调用；如果必须调用同步代码，要隔离到线程/进程并设置上限。

### 6. FastAPI 的依赖注入解决什么问题？

答：它把认证、配置、数据库会话、客户端和公共校验作为可替换依赖注入到端点，减少全局单例并方便测试。依赖生命周期要明确：请求级资源在请求结束释放，应用级客户端在启动/关闭管理；注入不是授权本身，权限仍要由业务层和数据层校验。

## Level 2｜数据、缓存与任务

### 7. 数据库连接池如何设计？

答：连接池大小由并发请求、数据库上限、查询耗时和实例数共同决定；借用连接要有超时，请求结束归还，异常时回滚/关闭游标。连接池不是吞吐越大越好，过大可能把应用排队转移成数据库过载；要观察活跃连接、等待时间、慢查询和错误率。

### 8. Python 服务中的事务边界如何划分？

答：把一个需要原子提交的数据库状态变化放在明确的事务函数内，事务中避免不可控网络调用和长时间等待；提交后再发布事件，或用 Outbox 保证数据库状态与事件可靠衔接。跨服务调用不能假设共享一个事务，必须用幂等、状态机、补偿或对账。

### 9. Redis 适合做什么，不适合做什么？

答：适合缓存、短期状态、计数、限流、去重和排行榜等低延迟场景；关键事实、复杂事务和必须长期可靠保存的任务状态不应只放 Redis。需要说明过期、淘汰、穿透/击穿/雪崩、持久化、热 key 和故障降级。

### 10. 如何实现缓存更新，避免脏读和击穿？

答：先定义数据新鲜度和一致性要求，再选择 Cache Aside、写穿或失效通知；热点 key 可用单飞/互斥重建、随机过期和预热，空值短缓存可防穿透。更新失败不能让缓存和数据库永久分叉，关键数据应有版本、重试、对账或直接回源。

### 11. 后台任务和消息队列如何保证可恢复？

答：任务要有稳定 ID、持久化状态、租约/心跳、超时、重试预算和幂等键；Worker 崩溃后可从可验证的 Checkpoint 或任务状态恢复，未知副作用先查询再重试。队列至少一次投递是常见现实，业务层仍要做去重和副作用幂等。

### 12. 如何实现一个有界的异步 Worker Pool？

答：用有界队列限制内存和等待，用固定数量 worker 处理任务；提交方在队列满时阻塞、拒绝或降级，任务带 deadline，worker 传播第一个关键错误并停止接收新任务，关闭时等待已接收任务安全结束。必须测试消费者失败、超时、取消和生产速度超过消费速度。

## Level 3｜测试、观测与可靠性

### 13. Python 服务测试如何分层？

答：纯函数、状态机和错误分类用单元测试；HTTP、数据库、队列协议用集成测试；关键业务流程用端到端或回放测试；性能和并发问题用 Benchmark/压测。fixture/conftest 管理资源和作用域，Mock/Fake 替换外部边界并验证合同；不能把所有内部实现细节固定成测试，也不能用 Mock 掩盖真实协议、权限和超时问题。

### 14. 如何测试异步代码的取消和超时？

答：使用确定性事件、Barrier、可控 Future 或测试服务器，不依赖随机 `sleep`；验证任务在 timeout/cancel 后结束、连接和文件释放、队列状态可解释、异常没有被吞掉。对于已经发出副作用的调用，还要测试响应丢失、重复投递和对账路径。

### 15. 日志、指标和 Trace 应该记录什么？

答：日志记录结构化事件、错误类型、任务/请求 ID 和必要上下文；指标记录请求量、成功率、P50/P95、超时、重试、队列、连接池和资源使用；Trace 贯穿 API、数据库、缓存、外部 HTTP 和后台任务。敏感数据要脱敏，不能把完整 token、Prompt 或用户内容无边界写入日志。

### 16. Python 服务如何优雅退出？

答：先停止接收新请求/任务，再通知后台 worker 和下游客户端取消，等待有界时间完成可安全收尾，最后关闭连接池、文件和事件循环；超时后要记录未完成任务并让进程退出，而不是无限等待。多实例部署还要配合负载均衡摘除、租约和消息重新投递。

### 17. 如何给 Python API 做性能分析？

答：先定义真实负载和目标，再区分应用 CPU、事件循环阻塞、序列化、锁、连接池、数据库和外部 HTTP；使用采样 profiler、火焰图、事件循环延迟、连接池指标和数据库执行计划定位。优化后要用相同数据、并发和版本复测 P95、错误率、CPU、内存和下游压力。

### 18. 如何处理不可信输入和供应链风险？

答：限制请求大小、字段深度、文件类型、正则复杂度和解析时间；禁止对不可信输入使用 `eval`/不安全反序列化，外部命令使用参数数组和沙箱；依赖要锁定版本、扫描漏洞、最小权限和可复现构建。Prompt 或文档内容也应视为数据，不能绕过系统权限。

## Level 4｜场景追问

### 19. 设计一个 Python 文件处理 API，如何避免大文件拖垮服务？

答：请求层限制大小和类型，把上传流写入受控临时存储，再用持久化任务队列异步处理；处理器按块读取、设置 CPU/内存/时间预算，产物写入带版本的对象存储，状态表记录进度和失败原因。下载使用鉴权的短期 URL，取消和清理要覆盖临时文件及半成品。

### 20. 设计一个外部模型/HTTP 聚合服务，如何处理并发和失败？

答：为每个下游设置连接池、并发上限、超时和熔断/降级；独立请求可 fan-out，但总预算和取消必须由父请求控制，聚合时保留部分失败而不是填假数据。副作用请求使用幂等键，响应按 schema 校验，指标区分自身耗时、下游耗时、重试和限流。

### 21. 什么时候该用 Celery、RQ、进程池或 asyncio Task？

答：短生命周期、进程内且可丢弃的 I/O 任务可以用受控 asyncio Task；需要跨进程、持久化、重试和恢复时用任务队列；CPU 密集任务考虑进程池或独立计算服务。选择要看任务是否必须可靠执行、是否有副作用、队列规模和运维成本，而不是只看 API 好不好用。

### 22. Python 项目如何把“能跑”变成“能交付”？

答：补齐锁定依赖、配置校验、类型/格式检查、单测和集成测试、结构化日志、健康检查、超时/取消、容器化构建、灰度和回滚。最终验收应包含一次正常请求、一次依赖超时、一次进程重启和一次重复投递，证明状态、资源和副作用都可解释。

## 进阶追问：HTTP、FastAPI 与代码组织

### 23. `requests` 和 `httpx` 在服务代码中如何选择？

答：脚本或同步流程可以使用 requests；需要异步 I/O、统一超时和清晰连接复用边界时通常使用 httpx。无论选择什么，都应复用长生命周期 Client/Transport，设置连接/读取/总超时，及时关闭响应，调用 `raise_for_status()` 或统一映射状态码，并区分网络错误、非 2xx 和 JSON 解析失败。

### 24. FastAPI 的 path、query、body、header 参数如何区分？

答：路径参数标识资源，query 参数用于过滤/分页，body 承载结构化提交，header 承载认证、Trace ID 等元数据；Pydantic 模型负责形状、类型和范围校验，响应模型负责输出合同。422 只说明请求没有通过输入校验，不代表业务授权、资源存在或状态迁移成功。

### 25. FastAPI 的依赖注入和生命周期怎么设计？

答：`Depends` 适合复用认证、配置、数据库会话和服务对象；请求级资源在请求结束释放，应用级 HTTP 客户端/连接池在 lifespan 启动时创建、关闭时释放。不要在每个 handler 里创建连接池，也不要把依赖注入当成权限本身；业务授权仍由服务层检查。

### 26. Service、Client、Repository、Registry 和 Pipeline 分别解决什么问题？

答：Service 编排业务用例，Client 封装外部 API，Repository 隔离数据读写，Registry 管理一组可发现/可授权的能力，Pipeline 表达稳定的多步骤流程。路由层只做协议适配；是否抽象取决于真实替换边界、测试需求和状态复杂度，不是类越多越工程化。

### 27. 如何把模型/工具输出放进 Python 的可靠执行边界？

答：先用 JSON/Pydantic 解析结构，再做长度、枚举、权限、资源存在性和副作用校验，最后转换成领域命令交给执行器；执行结果带稳定状态、错误码和调用 ID。Schema 合法不等于事实正确，也不等于用户有权限；高风险动作需要幂等、审批、审计和程序化成功证据。

### 28. Python 项目如何保证依赖和检查命令可复现？

答：用 `pyproject.toml` 记录项目元数据和工具配置，用锁文件固定解析结果，区分运行时与开发依赖，并在干净虚拟环境中执行格式、lint、类型检查和测试。`venv`/uv 只是环境工具，真正的合同是 Python 版本、依赖版本、启动命令、配置样例和测试入口一致。

## 面经补充｜现代 Web、AI 服务与测试工程

### 29. Pydantic v2 在 API 请求和结构化模型输出中应该负责什么？

答：它适合把 JSON/字典解析成带类型的 DTO，并用字段约束、嵌套模型和自定义校验拒绝形状错误；`model_validate`、`model_dump` 等版本 API 要以项目锁定版本为准。校验通过后仍要转换成领域命令，继续做权限、资源状态、幂等和副作用检查；模型输出也必须限制枚举、长度、未知字段和 schema 版本，不能把“能解析”当成“可执行”。

### 30. FastAPI 的 SSE 和 WebSocket 如何选择？流式输出怎样保证可恢复？

答：SSE 是服务端到客户端的单向文本事件流，适合进度、日志和 Token 增量；WebSocket 支持双向交互，适合需要客户端持续发送控制事件的会话。事件要带稳定 ID/序号、任务 ID 和版本，客户端断线后从任务状态或 Last-Event-ID 续接并去重；流结束前不能把半截文本当最终成功，最终结果应持久化并经过 schema/业务校验。

### 31. 调用 LLM 或第三方 API 超时后，如何处理“可能已经扣费/执行”的未知结果？

答：先区分连接未建立、服务端明确拒绝、响应丢失和客户端 deadline；请求带 provider request ID、业务幂等键和预算，重试只针对明确可重试的错误。响应未知时优先查询任务/账单/调用状态，或进入对账队列；记录每次尝试、Token/费用、模型版本和最终状态，不能因为客户端没收到响应就盲目重发。

### 32. pytest 如何测试异步下游、重试、取消和重复副作用？

答：用 fixture 管理应用、数据库、测试服务器和临时目录，用 Fake/MockTransport 控制响应序列和断连，用可控事件或时钟替代随机 `sleep`；断言调用次数、退避上限、取消后的资源释放、幂等键和未知结果处理。关键 HTTP/数据库/序列化合同还要保留少量集成测试，避免 Mock 让错误协议“通过”。

### 33. 如何排查 Python API 在面试中出现的“偶发慢请求”？

答：先用 request/trace ID 把慢请求拆成排队、事件循环延迟、序列化、连接池、数据库、外部 HTTP 和重试，按 P95/P99 找样本；数据库用执行计划和锁等待，HTTP 用连接/读取/总超时，Python 用采样 profiler 或事件循环监控。修复后用同版本、同数据和同并发复测尾延迟、错误率、资源和下游压力，不能只把 handler 改成 `async`。

### 34. 如何设计一个“模型输出 → 执行器”的安全边界？

答：模型只产生受限的意图或命令草案，先做 JSON/schema 解析，再做 allowlist、权限、资源状态、额度、幂等和人工审批判断，最后由确定性执行器调用外部系统。执行结果必须返回稳定状态、调用 ID 和程序化成功证据；未知字段、低置信度、越权和高风险副作用进入拒绝/澄清/人工分支，不能让模型直接拼接 SQL、Shell 或任意 URL。

### 35. 类型标注、`Protocol` 和 `mypy` 如何协作？

答：类型标注描述函数、数据结构和依赖边界，`Protocol` 可以按行为定义可替换的客户端/仓储合同，`mypy` 在运行前检查这些合同是否被一致使用。它们不能替代运行时输入校验、权限、状态机和数据库约束；外部 JSON 仍要用 Pydantic 等工具解析。工程上应把 Python 版本、依赖、`mypy` 配置和检查命令写进 `pyproject.toml`，在干净环境执行 `python -m mypy src`，并把有意忽略的边界逐条说明。

### 36. Python Agent 项目如何划分 Provider、Tool、State 和 Loop？

答：Provider 只负责模型协议与响应适配，Tool 负责参数校验、权限、超时和实际副作用，State 记录目标、事实、预算、步骤和恢复点，Loop 负责在有限步数内选择继续、调用工具或结束。模型输出先解析为受限命令，再交给确定性执行器；测试用固定 Provider/Tool Fixture 验证成功、拒绝、超时、取消和恢复，不能把模型直接放进业务状态或让它拼接 Shell/SQL。
