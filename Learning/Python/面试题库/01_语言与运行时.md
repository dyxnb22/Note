# Python 语言与运行时

> 递进路径：先回答对象和容器，再讲执行模型、并发和性能；实现细节以项目锁定的 Python 版本为准。

## Level 1｜语言基础：对象、容器与函数

### 1. Python 中 list、tuple、set、dict 有什么区别？

答：list 有序、可变、允许重复，适合通用序列；tuple 有序、不可变，适合固定结构或作为可哈希组合的一部分；set 关注去重和成员判断；dict 是键到值的映射。面试时还要补复杂度和语义：平均情况下 dict/set 查找接近 O(1)，但哈希冲突、键的可哈希性和数据规模会影响实际表现。

### 2. `is` 和 `==` 有什么区别？为什么判断 `None` 要用 `is`？

答：`is` 比较对象身份，`==` 调用相等性比较协议比较值。`None` 是解释器中的单例，`value is None` 表达的是“它就是空值对象”；`== None` 可能被自定义的 `__eq__` 改写，也不够准确。小整数和字符串的驻留可能让错误的 `is` 比较偶尔通过，不能依赖。

### 3. Python 的可变对象和不可变对象有什么影响？

答：变量是名称到对象的绑定，不是固定类型的盒子。list、dict、set 可以原地修改，str、int、tuple 通常通过创建新对象改变“值”；多个名称绑定同一可变对象时，一个地方的原地修改会被其他引用看到。函数接口要明确是否会修改传入对象，避免隐藏共享状态。

### 4. 浅拷贝和深拷贝有什么区别？

答：浅拷贝只复制最外层容器，内部嵌套对象仍共享；深拷贝递归复制可达对象，但可能成本高，也可能无法正确处理锁、文件句柄、循环引用或有意共享的对象。工程上优先使用明确的构造、不可变数据或按字段复制，不要把 `deepcopy` 当成通用并发安全方案。

### 5. 为什么不建议使用可变对象作为默认参数？

答：默认参数在函数定义时求值，而不是每次调用时重新创建。下面的 list 会在多次调用之间共享：

```python
def add_item(item, items=[]):
    items.append(item)
    return items
```

通常改成 `items=None`，进入函数后创建新 list。这个问题本质是对象生命周期和共享语义，不是 Python 随机缓存了参数。

### 6. 可迭代对象、迭代器和生成器有什么区别？

答：可迭代对象能通过 `iter()` 取得迭代器；迭代器实现 `__next__()`，每次取一个元素并在结束时抛出 `StopIteration`；生成器是用 `yield` 或生成器表达式创建的迭代器，能惰性地产生值并保存暂停位置。生成器降低峰值内存，但通常只能消费一次。

### 7. 列表推导式和生成器表达式如何选择？

答：如果需要立即得到完整结果、多次遍历或按索引访问，使用列表；如果数据量大、只需顺序消费或要把多个阶段串成流水线，使用生成器。生成器不等于自动更快：如果最终仍要把所有结果收集成 list，主要收益可能只是中间阶段的峰值内存降低。

### 8. 闭包是什么？Python 闭包有什么常见陷阱？

答：闭包是函数携带其定义作用域中的自由变量，即使外层函数已经返回，仍可访问这些变量。循环中创建闭包时常遇到晚绑定：函数执行时才读取变量的最终值；可用默认参数或工厂函数固定当轮值。闭包还可能无意中持有大对象，造成任务或缓存无法释放。

### 9. 装饰器的原理和使用场景是什么？

答：装饰器接收一个函数并返回包装函数，在不修改原函数主体的情况下增加行为。常用于日志、计时、权限、重试、缓存和统一错误处理；实现时应使用 `functools.wraps` 保留元数据，并明确参数、异常、同步/异步函数和副作用语义。装饰器适合横切逻辑，不应隐藏核心业务流程。

### 10. `*args` 和 `**kwargs` 分别是什么？

答：`*args` 接收额外位置参数，`**kwargs` 接收额外关键字参数；调用时也可用它们展开序列和映射。它们能做适配层和装饰器，但会降低函数合同的可发现性；公共接口应优先使用明确的参数、关键字参数和类型注解。

### 11. `with` 语句和上下文管理器解决什么问题？

答：上下文管理器通过 `__enter__`/`__exit__` 或 `contextlib` 统一管理资源的获取和释放，即使代码块抛出异常也能执行清理。文件、锁、数据库事务和临时目录都适合使用；`__exit__` 是否吞掉异常必须有明确语义，不能为了“让程序继续”而静默隐藏失败。

### 12. Python 异常应该如何设计和处理？

答：只捕获当前层能够处理的异常，区分参数错误、依赖失败、权限拒绝、超时和未知结果；对外暴露稳定的错误类型/错误码，对内保留原始异常和上下文。避免裸 `except:`、空处理和把所有错误都转换成“系统异常”。重试前还要判断操作是否幂等。

### 13. `__new__` 和 `__init__` 有什么区别？

答：`__new__` 负责创建并返回实例，`__init__` 在实例已经创建后初始化状态。不可变类型、元类或需要控制实例创建时才会重点使用 `__new__`；普通业务对象通常只需要 `__init__` 或 `dataclass`。重写 `__new__` 时必须正确处理父类和返回值，否则对象可能未创建或类型不匹配。

### 14. 模块、包、导入和 `if __name__ == "__main__"` 的作用是什么？

答：模块是可导入的 Python 文件，包是组织模块的目录；导入会执行模块顶层代码并缓存模块对象，因此顶层不应发起网络请求或写入业务数据。`__name__ == "__main__"` 让文件作为脚本运行时执行入口，而被导入时不执行入口逻辑。循环导入通常说明模块边界或依赖方向需要调整。

## Level 2｜运行时与并发：怎么执行、怎么停止

### 15. CPython 大致如何执行 Python 代码？

答：CPython 通常先把源码编译为字节码，再由解释器执行；函数调用、属性查找、对象分配和异常处理都会产生运行时成本。回答时要区分 Python 语言语义、CPython 实现、C 扩展行为和操作系统/外部服务等待，不能把某个解释器的实现细节说成所有 Python 实现的规则。

### 16. CPython 的引用计数和循环垃圾回收如何配合？

答：引用计数在对象引用数降为零时通常能快速回收对象；互相引用的对象即使外部已经不可达，引用数也可能不为零，所以还需要循环垃圾收集器处理部分引用环。内存释放给 Python 分配器也不等于 RSS 立即归还操作系统，因此排查内存问题要看对象增长、分配器、C 扩展和进程指标。

### 17. GIL 是什么？它是否意味着 Python 没有并发？

答：CPython 的 GIL 让同一解释器中通常只有一个线程执行 Python 字节码。它限制纯 Python CPU 密集任务通过线程获得真正并行，但 I/O 等待、释放 GIL 的 C 扩展、多个进程和异步 I/O 仍可以并发。GIL 不代表所有复合操作天然线程安全，也不代表线程对阻塞 I/O 没有价值。

### 18. 线程、进程和协程分别适合什么场景？

答：线程适合大量阻塞 I/O 或复用同步库，但要处理 GIL、锁和线程生命周期；进程适合 CPU 密集任务和故障隔离，但有启动、内存和序列化成本；协程适合大量可异步 I/O，需要异步库、超时、取消和背压。先测量计算/等待比例，再选模型，不要用“协程一定更快”作结论。

### 19. `async`、`await`、Task 和事件循环分别是什么？

答：`async def` 定义协程函数，调用后得到协程对象；Task 把协程交给事件循环调度，`await` 等待另一个可等待对象并在必要时让出执行权。事件循环负责调度 I/O、定时器和任务；`async` 不会自动把 CPU 计算变成并行。任务必须被等待、取消或记录异常，不能无界创建后台 Task。

### 20. asyncio 中如何正确处理超时和取消？

答：超时要包住真实的外部操作，取消要沿调用链传播并在 `finally` 中释放连接、文件、锁和临时资源；捕获 `CancelledError` 后通常应清理后继续传播，而不是静默吞掉。超时只说明当前等待没有得到结果，不一定说明外部操作没有完成；带副作用的请求需要查询状态或对账。

### 21. `asyncio.gather`、`wait` 和 `as_completed` 的选择有什么差异？

答：`gather` 适合等待一组已知任务并按输入顺序收集结果；`wait` 适合按完成/超时条件得到 done 与 pending 集合；`as_completed` 适合谁先完成就先处理的流式场景。要提前规定异常是否立即传播、兄弟任务是否取消、超时后如何清理，不能只看 API 名称。

### 22. Python 中如何定位内存泄漏或内存持续上涨？

答：先固定负载和版本，区分真实对象增长、缓存无上限、Task/闭包持有、循环引用、C 扩展堆外内存和分配器保留；再用 `tracemalloc`、对象统计、Heap Profile、GC 和 RSS 指标定位。`sys.getsizeof` 只反映浅层大小，单看 RSS 下降或不下降都不足以下结论。

### 23. Python 性能问题应如何排查？

答：先建立可复现基线，拆分 CPU、等待、序列化、锁、连接池和下游耗时，再用采样 Profiler、Benchmark、火焰图和内存工具定位热点。常见优化是批处理、减少不必要复制、使用合适容器、把计算下沉到高效库或调整并发；每次修改后必须在相同工作负载下复测。

### 24. 描述符、`property` 和 `__getattribute__` 有什么关系？

答：属性访问会综合实例字典、类属性、继承和描述符协议；`property`、绑定方法和许多 ORM 字段都依赖描述符。`__getattr__` 只在普通查找失败后调用，`__getattribute__` 拦截所有查找，错误实现容易递归。它们适合框架基础设施，普通业务不应为了炫技引入动态属性。

## Level 3｜边界与验证

### 25. 类型注解是否等于运行时类型校验？

答：不等于。类型注解主要服务于阅读、IDE 和静态检查，Python 默认不会自动在运行时验证参数；外部输入、HTTP 请求和 JSON 仍需要显式解析/校验，或使用 Pydantic 等运行时工具。类型检查器发现的问题也不能替代业务规则、权限和数据库约束。

### 26. Pickle 适合做跨信任边界的数据格式吗？

答：不适合。反序列化不可信 Pickle 可能执行任意代码，也不适合作为长期稳定的跨语言合同。服务边界优先使用带版本和大小限制的 JSON、MessagePack、Protobuf 等格式，并明确编码、兼容、失败和大对象策略。

### 27. Python 版本或实现变化会影响哪些面试结论？

答：字节码、对象布局、GIL 演进、asyncio API、垃圾回收细节和第三方库行为都可能随版本/实现变化；语言级语义和标准库合同应参考对应版本文档，实现级性能必须在项目解释器、依赖和工作负载上实验。回答时要主动标注“语言保证”还是“CPython 当前实现”。

### 28. `str`、`bytes` 和文件/网络边界应该如何处理？

答：`str` 表示文本，`bytes` 表示原始字节；编码和解码必须发生在明确的 I/O 边界，不能把未知字节直接当 Unicode 文本。文件、HTTP body 和子进程输出都要明确编码、非法字节策略、大小上限和是否流式处理，避免隐式转换造成乱码或内存峰值。

### 29. Python 的 `for`/`while`、推导式和生成器如何按场景选择？

答：已知集合上的简单转换适合推导式，复杂分支、需要调试或多个状态变量时用普通循环；`while` 必须有可证明的停止条件；生成器适合惰性流水线和大数据量，但只能消费一次且错误会延迟到迭代时出现。面试时同时说可读性、内存和异常发生位置。
