# 软件工程与演进式架构

软件工程解决的不是“如何写出一段能运行的代码”，而是多人长期修改系统时，如何保持需求、设计、实现、验证和交付之间的可追踪关系。

## 1. 从问题到可验证目标

开始前写清：

- 用户与业务目标。
- 当前行为和痛点证据。
- 成功指标。
- 范围内/范围外。
- 约束和风险。
- 验收场景。

技术任务也应说明可观察结果，例如“p99 从多少降到多少”，而不是只写“优化性能”。

## 2. 需求分解

使用用户场景、业务规则、状态机和非功能需求分解。每项需求尽量小到可以独立验证，但不要把一个完整不变量拆成互相不知道的零散任务。

非功能需求包括可靠性、性能、安全、兼容性、可维护性和可观测性，不能在开发结束后再补。

## 3. 模块化

模块通过明确接口隐藏实现。好边界通常具有：

- 高内聚：相关规则和数据放在一起。
- 低耦合：依赖稳定抽象。
- 单向依赖。
- 可独立测试和替换。
- 数据所有权明确。

按技术层拆目录不自动得到业务模块。关键是变化是否被限制在少数位置。

## 4. 依赖管理

依赖方向应指向更稳定的策略。业务核心不直接依赖 Web 框架、数据库实体或第三方 SDK。

引入依赖前评估：

- 解决的问题和替代方案。
- API/维护/许可证。
- 传递依赖和供应链风险。
- 运行时资源与故障。
- 升级和退出成本。

## 5. 重构

重构保持外部行为不变，先建立测试与观测基线，再小步修改。

常见顺序：

1. Characterization Test 锁定现状。
2. 提取命名和重复逻辑。
3. 建立接口/适配层。
4. 移动职责。
5. 删除临时兼容层。

不要把大规模重写包装成重构。重写需要迁移、双跑、数据和回滚方案。

## 6. Code Review

Review 关注：

- 行为和边界条件。
- 数据、状态与并发不变量。
- 安全和权限。
- 失败、恢复和观测。
- 测试是否真的能发现错误。
- 兼容、迁移和回滚。

格式和机械规则交给工具。评论说明风险与依据，区分阻塞问题、建议和个人偏好。

## 7. ADR

Architecture Decision Record 记录：

```text
背景 → 决策 → 候选方案 → 取舍
→ 影响 → 验证方式 → 复审条件
```

ADR 不是永久真理。环境变化后新增决策覆盖旧决策，并保留历史原因。

## 8. 技术债

技术债要登记：

- 具体症状和影响。
- 产生原因。
- 利息：每次修改增加多少成本或风险。
- 偿还方案和触发条件。
- 负责人。

“代码不好看”不足以排序。优先处理妨碍业务、可靠性、安全和交付速度的债务。

## 9. 遗留系统理解

先建立：

- 运行入口和部署拓扑。
- 核心请求/事件链路。
- 数据源与所有者。
- 外部依赖。
- 测试和观测现状。
- 高频变更与故障区域。

用日志、Trace、数据库和生产流量验证理解，不只依赖过期文档。

## 10. 渐进式迁移

Strangler 模式让新旧路径长期可比较。迁移策略：

- 先读兼容，再切写入。
- Shadow/Dual Read 对比。
- 双写需处理部分失败和事实源。
- Backfill 可暂停、重试和校验。
- 按租户、地域或流量灰度。
- 明确回滚数据边界。

## 11. API 与数据演进

使用 Expand/Contract：

1. 增加新字段/表/API，保持旧消费者可用。
2. 发布兼容读写。
3. 回填并核验。
4. 切换消费者。
5. 观察旧路径归零。
6. 删除旧结构。

破坏性变更必须有消费者清单和时间表。

## 12. 质量内建

Definition of Done 包含：

- 测试和静态检查。
- 安全与依赖检查。
- 日志、指标和 Trace。
- 文档/ADR。
- 迁移、发布和回滚。
- 运行手册和负责人。

质量门禁应与风险匹配，不让低风险修改承担与高风险资金系统相同流程。

## 13. 版本与发布

制品不可变并可追溯到提交、依赖和构建。Feature Flag 分离部署与功能开放，但 Flag 需要所有者、到期和清理。

Rollback 不是唯一恢复方式；数据库、消息和外部副作用可能要求 Roll-forward、补偿或人工修复。

## 14. 团队反馈闭环

观察：

- Lead Time 与部署频率。
- 变更失败率和恢复时间。
- Review 等待与返工。
- 缺陷逃逸。
- 认知负担和所有权。

指标用于定位系统问题，不用于机械考核个人提交数或代码行。

## 最小实践

选择一个遗留模块：

1. 画上下文、请求和数据图。
2. 写 Characterization Test。
3. 记录一条 ADR。
4. 通过适配层迁移一个用例。
5. Shadow 对比并灰度。
6. 演练回滚并清理临时路径。

## 验收清单

- 需求能追踪到设计、实现和验收。
- 模块边界与数据所有权清楚。
- 重构有行为基线，迁移有双跑与回滚。
- 技术债按影响和利息管理。
- 制品、决策和生产行为可追溯。
