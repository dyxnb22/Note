# Go 网络服务工程

本篇覆盖 HTTP/RPC 服务、客户端、数据库、配置、可观测性和优雅退出。

## 服务分层

```text
Transport/Handler → Application Service
→ Domain → Repository/Client Adapter
```

Handler 负责协议解析、认证上下文、校验和错误映射；业务规则不应依赖具体 HTTP 框架。

## HTTP Server

必须配置读取 Header、读取 Body、写响应和空闲连接等超时。默认无限超时可能被慢客户端长期占用资源。

限制请求体大小，校验 Content-Type，区分参数错误、认证失败、冲突、限流和内部错误。响应开始写出后通常无法再改变状态码。

## HTTP Client

复用长生命周期 Client 和 Transport，避免每次请求创建新连接池。设置：

- 连接、TLS、响应头和整体 Deadline。
- 每主机连接上限和空闲连接。
- 最大响应体。
- 重试条件和幂等保护。
- Context 取消。

收到响应后及时关闭 Body，并按需读完以便连接复用。

## Middleware

中间件适合认证、Trace、日志、恢复、限流和统一错误，但顺序影响语义。Panic Recover 应位于足够外层；Trace/Request ID 要在日志之前注入。

## gRPC

IDL 负责稳定契约。服务端和客户端传播 Deadline、身份和 Trace；流式 RPC 还要处理背压、半关闭和客户端中断。

只对幂等且明确可重试的状态码启用重试，避免 RPC 框架把重复写入隐藏起来。

## 数据库

`sql.DB` 是并发安全的连接池句柄，不是单连接。配置最大打开、最大空闲、连接寿命，并观察等待数和等待时间。

事务中所有语句使用同一 `Tx`；不要在事务中执行长时间外部网络调用。用唯一约束和条件更新保护并发不变量。

## 配置和依赖

启动时解析并校验配置，依赖初始化失败应快速失败。业务代码依赖小接口，具体数据库或客户端在组合根装配。

配置热更新只用于语义清晰且可回滚的项；连接、线程和安全策略变化可能需要重建资源。

## 可观测性

统一记录：

- 请求率、错误率和延迟。
- 路由模板而非原始高基数路径。
- 下游调用和数据库等待。
- Build Version、实例和环境。
- Trace 与业务 ID。

日志字段要稳定，避免记录 Token、密码和完整敏感请求体。

## 优雅退出

收到终止信号后：

1. 标记不再就绪。
2. 停止接收新请求。
3. 在 Deadline 内等待在途请求。
4. 停止后台任务和消费者。
5. Flush 遥测并关闭资源。
6. 超时后强制退出。

## 最小项目

实现一个订单 API：HTTP + PostgreSQL + 外部库存客户端，加入超时、幂等、迁移、Trace、指标、集成测试、负载测试和优雅退出。

## 验收清单

- Server 与 Client 超时完整。
- Handler、领域和适配器边界清楚。
- 数据库池和事务有指标与测试。
- 重试只用于安全操作。
- 发布和 SIGTERM 不丢在途请求或后台任务。

## 来源与验证边界

接口行为参考 Go `net/http`、`database/sql`、Context 与 gRPC 官方文档。默认超时、连接复用和框架中间件语义必须使用实际 Go/库版本做集成测试。
