# 任务、消息与补偿

任务解决“以后还要做什么”，消息解决“把事实通知给谁”。两者可以共用可靠投递和重试机制，但语义不能混为一谈。

## 本地任务消息模型

```text
事务内产生业务事实
        ↓
写入任务/事件记录
        ↓
HTTP 或 MQ 通知
        ↓
成功确认 / 失败重试 / 超限转人工
```

适合支付回调后的发券、库存释放、积分返利、订单关闭和跨系统同步。核心业务提交成功后，外部通知可以异步完成，但任务记录必须和业务事实处在可恢复的边界内。

## 任务状态

建议至少包含：`WAITING`、`PROCESSING`、`SUCCESS`、`RETRY`、`DEAD`。记录业务类型、业务号、目标、payload 版本、重试次数、下次执行时间、错误原因和锁定时间。

- 抢占任务要有租约或超时释放，避免 worker 崩溃后永久卡住。
- 重试按指数退避和上限执行；不可恢复错误直接进入死信。
- 失败任务可由定时扫描兜底，但扫描必须分页并限制并发。
- 人工重放前先检查最新业务状态，避免补偿已经成功的副作用。

## 消息策略

| 策略 | 用途 | 注意事项 |
|---|---|---|
| Spring Event | 同进程解耦 | 进程崩溃或跨服务时不可靠 |
| HTTP 通知 | 简单跨服务调用 | 超时、签名、重试和幂等必须明确 |
| MQ | 削峰、解耦、异步 | 消费幂等、顺序、堆积和死信 |
| 延迟消息/定时扫描 | 超时关单、过期释放 | 不能只依赖一次触发 |

## 切面与入口

可以用 AOP 统一记录任务、拦截需要通知的业务动作，但切面只负责捕获和持久化，不应隐藏关键领域规则。任务来源、状态迁移和副作用仍要在应用/领域层可见。

## 租约抢占与状态迁移（伪代码）

Worker 不能只按 `status = WAITING` 查询再更新，否则多个 Worker 会同时执行同一任务。抢占必须是带条件的原子更新，并用租约时间处理 Worker 崩溃。

```python
def claim_task(now, worker_id: str, lease_seconds: int):
    # 条件应覆盖“待执行”以及“租约已过期”的任务；排序和批量大小要有限制。
    task = select_one(
        """
        SELECT * FROM task
        WHERE (status IN ('WAITING', 'RETRY') AND next_run_at <= :now)
           OR (status = 'PROCESSING' AND lease_until < :now)
        ORDER BY next_run_at, id
        LIMIT 1
        FOR UPDATE SKIP LOCKED
        """,
        now=now,
    )
    if task is None:
        return None

    # 在同一事务内写入 Worker 和租约；提交后其他 Worker 才能看到新状态。
    update_task(
        task.id,
        status="PROCESSING",
        worker_id=worker_id,
        lease_until=now + lease_seconds,
    )
    return task


def finish_task(task_id: str, worker_id: str, result: dict) -> bool:
    # 只有当前租约持有者可以完成任务，避免旧 Worker 覆盖新 Worker 的结果。
    return conditional_update(
        task_id,
        where={"status": "PROCESSING", "worker_id": worker_id},
        set_values={"status": "SUCCESS", "result": result, "lease_until": None},
    )
```

这里的 SQL/函数是伪代码，数据库方言和任务表结构需要按项目替换。租约时长应大于正常处理时间但小于业务可接受延迟；长任务可续租，续租也必须校验 `worker_id`，否则旧实例可能在新实例开始后继续执行副作用。

## 设计检查

- 任务记录是否与业务事实建立唯一业务号？
- 重复投递和乱序消费是否可预测？
- 消费成功但 ACK 丢失时会发生什么？
- 任务处理超时后谁释放租约？
- 队列堆积、死信和对账差异谁负责？
- 是否支持暂停、重试、重放和人工终止？
