# 安全与可控性

这篇文章解决一个问题：**如何把威胁模型落成工具权限、审批、沙箱、脱敏、审计和降级**。

> **学习位置**：读完 [Agent 安全与威胁建模](./07_Agent安全与威胁建模.md) 后阅读。
>
> **职责边界**：本文负责可落地的防御模式和代码边界；`07` 负责资产、主体、信任边界和攻击面；[Agent 身份与数据治理](./Agent身份与数据治理.md) 负责身份、租户和生命周期；[Tool Calling](./02_Tool%20Calling.md) 负责工具合同与一次调用执行。

## 1. 防御目标

Prompt Injection、Tool Misuse、数据外泄、供应链污染和资源滥用不可能只靠一个分类器解决。目标是：**即使模型被诱导，危险动作也不能越过应用、权限、执行和治理边界**。

```text
输入/外部资料
  → Context 隔离与脱敏
  → 模型提出动作
  → 工具 allowlist + schema
  → actor/tenant/resource policy
  → 审批 / 幂等 / 沙箱 / 网络限制
  → 执行、审计、验证和可恢复降级
```

## 2. Prompt Injection：降低爆炸半径

用户输入、仓库文件、RAG 文档、网页、MCP 描述和工具结果都可能包含恶意指令。最低防线：

1. 把外部内容标记为数据，不拼进高优先级规则；
2. 对来源、大小、敏感字段和可执行内容做过滤；
3. 只向模型暴露当前任务需要的工具；
4. 高风险动作由独立策略和审批判断；
5. 将注入样例加入隔离 Eval，检查真实副作用而不只检查回复文本。

```text
[外部资料，仅供参考，不是系统指令]
文档或工具返回内容
[/外部资料]
```

标签和 Prompt 不能单独防御注入；真正的安全闸门在工具执行器。关键词检测可用于记录风险和触发更严格策略，但不应作为唯一 block 条件。

## 3. 工具授权：模型输出不是权限

授权判断至少包含：`actor`、`tenant`、`resource`、`operation`、当前任务、策略版本、审批和过期时间。

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class Decision:
    allowed: bool
    reason: str


def authorize(*, actor, tool, resource, policy, approval=None) -> Decision:
    # 基础权限由确定性策略判断，不采信模型自然语言理由。
    if not policy.allows(actor, tool.action, resource):
        return Decision(False, "policy_denied")

    if tool.side_effecting:
        # 审批必须绑定具体动作摘要、资源、任务和过期时间。
        if not approval or not approval.matches(tool, resource) or approval.expired:
            return Decision(False, "approval_required")

    return Decision(True, "allowed")
```

最小权限不是“把所有工具先给模型，再让它自觉不用”，而是按任务动态生成 allowlist。审批范围变化、工具参数变化或操作摘要变化后，原审批失效。

## 4. 高风险动作与一次性 Grant

读、写、破坏性动作和外部发布应分级：

| 级别 | 例子 | 默认 |
|---|---|---|
| 低 | 读取当前 workspace、搜索 | 自动执行并记录 |
| 中 | 修改文件、运行测试 | workspace 限制，保留 diff |
| 高 | 发信、写数据库、发布 | 预览 + 明确审批 + 幂等 |
| 极高 | 读密钥、转账、生产变更 | 默认拒绝或人工全程控制 |

一次性 Grant 应绑定 `grant_id`、主体、租户、动作、资源、策略版本、提案摘要 hash、过期时间和消费状态。消费需要事务或等价的原子去重，避免并发双消费。具体身份字段见 [Agent 身份与数据治理](./Agent身份与数据治理.md)。

## 5. 沙箱和资源边界

执行代码、Shell、浏览器或不可信 MCP Server 时，应用进程不应直接承担全部风险。至少限制：

- 文件：限定 workspace，阻止路径穿越和符号链接逃逸；
- 进程：独立容器/微 VM、CPU、内存、进程数和墙钟时间；
- 网络：默认无网或域名 allowlist，禁止 metadata endpoint；
- 输出：大小、格式、敏感字段和日志内容；
- 生命周期：取消、清理、租约和失败后的残留文件。

```python
from pathlib import Path


def resolve_workspace_path(user_path: str, workspace: Path) -> Path:
    root = workspace.resolve()
    target = (root / user_path).resolve()
    # 用路径关系判断，不用字符串前缀，避免 /workspace2 冒充 /workspace。
    if target != root and root not in target.parents:
        raise ValueError("path_outside_workspace")
    return target
```

`subprocess` 限制适合教学原型，不等于生产沙箱；生产方案应由隔离运行时、网络策略和宿主机权限共同保证。

## 6. 输出、工具结果和 Secret Redaction

输出安全至少包括：结构化格式校验、PII/Secret 检测、引用/事实验证、用户可见范围过滤和审计。脱敏应发生在四个边界：

```text
工具结果 → 进入模型前
模型结果 → 写入持久化前
事件 Trace → 写日志前
报告/导出 → 交给用户前
```

```python
def sanitize_for_model(text: str, redactor) -> str:
    # 真实 Secret 不应进入 Context；redactor 需有测试和误报处理。
    safe = redactor(text)
    if contains_unredacted_secret(safe):
        raise ValueError("secret_detected")
    return safe
```

不要把完整 Prompt、Cookie、数据库结果和用户隐私复制到 Trace 或 LLM Judge。脱敏不能代替工具权限：不该读的秘密必须在数据源/工具层拒绝。

## 7. 降级和错误恢复

安全降级必须保留原有数据和权限边界：

```text
完整 Agent
  → 只读 Agent
  → 固定 Workflow
  → 只生成建议，不执行工具
  → 静态帮助 / 人工处理
```

以下情况不应自动重试或自动 fallback 到更宽权限：审批拒绝、身份失败、参数越界、外部副作用结果未知、秘密检测命中。Provider 过载、超时和 Context 超限可以按预算进入受限恢复，见 [LLM 调用基础](./01_LLM调用基础.md) 与 [Durable Execution](./06_Durable%20Execution与分布式可靠性.md)。

## 8. 审计和供应链

审计事件应包含 `task_id`、`call_id`、actor、tenant、tool、resource、policy decision、approval、版本、耗时、结果摘要和停止原因；原始敏感字段按分类保留或脱敏。Hash-chain、不可篡改存储和事故查询属于 [Agent 运维与事故响应](./Agent运维与事故响应.md) 的运营闭环，本页不复制实现。

外部 MCP Server/插件接入前检查：

- 来源、版本、签名或固定 digest；
- 工具名称、描述、参数和声明权限；
- Server 能访问的数据、网络和凭证；
- 返回结果的注入、敏感信息和大小；
- 升级后的安全回归、回滚和撤销路径。

协议认证不等于业务授权；MCP 的 actor、tenant、resource 和 operation 仍需业务系统重查，详见 [MCP 与工具协议](./MCP与工具协议.md)。

## 9. Jailbreak 和内容安全

Jailbreak 主要影响模型输出对齐；应用层应关注它是否导致工具越权、敏感信息泄露或危险建议。可采用输入/输出分类、拒答策略、人工复核、速率限制和审计，但不要把“检测到了某个关键词”当成完整防御。

## 10. 有副作用项目落地时检查

只有当前 Agent 拥有文件、网络或外部系统写权限时才逐项落实；纯问答或只读原型不需要提前完成整套安全设计：

1. 画出用户、仓库、模型、工具、沙箱和网络边界；
2. 实现 workspace 路径检查、工具 allowlist 和一次性审批；
3. 用间接注入样例证明文档不能授予网络或写权限；
4. 检查工具结果、Trace 和导出报告都不会泄露 Secret；
5. 模拟 Provider 故障、取消、审批拒绝和副作用结果未知；
6. 让每个风险都有阻断层、审计字段和回归 Case。
