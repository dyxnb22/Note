# GraphRAG 与关系检索

本文回答：**什么时候需要在向量/词法检索之外引入实体与关系图，以及它如何与普通 RAG 分工**。摄取与解析见 [文档摄取与解析](文档摄取与解析.md)；通用 RAG 链路见 [RAG](RAG.md)。

## 1. 解决什么问题

纯向量检索擅长「意思相近的段落」，弱于：

- 多跳事实：「A 的供应商的合规负责人是谁」；
- 实体消歧：同名产品、同名人跨文档；
- 全局汇总：「本季度所有涉及供应商违约的条款变更」；
- 关系约束下的证据链，而不只是相似片段拼接。

GraphRAG 类方法把文档中的实体、关系或社区摘要建成图（或图+向量混合），检索时先定位子图或社区，再生成。它增加构建成本、更新复杂度和评测难度，**不是默认升级路径**。

## 2. 最小对象模型

```text
DocumentVersion
  → Entity（稳定 ID、类型、别名）
  → Relation（主谓宾、证据 span、置信度）
  → Community / Cluster（可选：主题团、摘要）
  → 回链 Chunk / page
```

实体与关系必须带**证据定位**。没有回链的三元组不能单独作为可引用事实。

## 3. 与普通 RAG 的组合

常见模式：

1. **先图后文**：实体链接 → 扩展一跳/二跳邻居 → 取关联 Chunk → 生成。
2. **先召回后图**：混合检索拿候选段 → 在候选内抽实体关系做消歧与冲突展示。
3. **社区摘要**：离线对图做社区发现与摘要；查询先匹配社区摘要，再下钻原文（适合宽泛调研，不适合精确条款）。

权限过滤仍在检索前：图扩展不得跨过用户无权的 DocumentVersion。

## 4. 何时值得引入

值得考虑：

- 任务明确需要多跳关系或组织/产品拓扑；
- 已有较干净的实体源（主数据、组织架构、物料主数据），不全靠 LLM 抽；
- 能评测多跳与实体消歧，而不只测单段 QA。

不应引入：

- 单跳手册问答已足够；
- 语料噪声大、实体抽取不稳定且无人校正；
- 更新极频繁却无法增量维护图；
- 无法证明相对基线 RAG 有召回或任务收益。

## 5. 构建与更新风险

- LLM 抽三元组会幻觉关系；需置信度、规则校验或人工抽检。
- 文档更新必须使旧关系失效或版本化，避免过期边继续被遍历。
- 同义实体未合并会导致图断裂；过度合并会导致错误连通。
- 图全量重建成本高；要有按文档版本的增量删除/重抽策略。

## 5.1 受权限约束的图扩展（伪代码）

图检索最容易犯的错误是先沿边扩展，再在最后过滤权限；这样无权实体已经影响了答案。权限应作为扩展条件的一部分。

```python
def expand(seed_ids, *, graph, actor, max_hops):
    visited = set(seed_ids)
    frontier = list(seed_ids)
    for _ in range(max_hops):
        next_frontier = []
        for node_id in frontier:
            for edge in graph.out_edges(node_id):
                # 每条边和目标节点都要经过同一主体/租户授权检查。
                if not graph.authorized(actor, edge.target):
                    continue
                if edge.target not in visited:
                    visited.add(edge.target)
                    next_frontier.append(edge.target)
        frontier = next_frontier
    return visited
```

图扩展结果还要保留来源 Chunk、版本和路径，便于回答中解释“为什么这个实体被加入上下文”。

## 6. 评测要点

在通用 RAG 指标之外增加：

- 多跳问题的答案正确率与证据链完整率；
- 实体链接准确率 / 消歧错误率；
- 无权扩展导致的泄露（必须为零容忍）；
- 相对纯混合检索的延迟与成本增量。

先用固定多跳集做消融：无图基线 vs 图增强。没有收益就回退。

## 验收清单

- 能否说明图边如何回到原文版本与位置？
- 权限是否在图扩展前生效？
- 是否有「不用图」的退出条件与基线对比？
