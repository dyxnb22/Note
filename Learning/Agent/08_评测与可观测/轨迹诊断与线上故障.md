# 08.3 轨迹诊断与线上故障

本页从运行轨迹和指标入手，讲离线/线上及单轮/多轮评测，再把线上 Badcase 接入可复现的修复闭环。

## 轨迹与指标

### 1. 离线评测与在线评测的目标、数据和反馈速度有什么区别？

答：离线评测用冻结任务和环境比较方案，反馈快且可重复；在线评测在真实流量中用 A/B、抽样和延迟业务结果判断用户价值；生产监控持续发现可用性、成本、安全和质量信号异常。调用真实模型不等于在线评测，监控代理指标也不等于有标签的质量评分。线上 Badcase 需经抽样、标注和归因后再进入稳定回归集。

### 2. 单轮任务和多轮任务应该如何分别评测？

答：单轮重点看输入到输出的正确性、证据、格式、工具选择和一次调用延迟；多轮还要看状态是否正确演化、上下文压缩、记忆污染、用户插入/中断、恢复、重复动作和长程成功率。多轮评测的样本必须包含不同长度、失败恢复和人工接管路径，不能把每一轮拆开平均后假装等价于一次任务。

### 3. 任务成功率、步骤成功率、工具选择准确率和最终答案质量有什么关系？

答：步骤成功是过程信号，工具选择/参数正确是局部能力，最终答案质量是用户可见结果，任务成功还应包含业务副作用和验收条件。步骤都正确不保证目标完成，最终答案看似正确也可能没有真实执行；应同时记录分层指标并建立“哪个步骤失败导致任务失败”的映射。

## 评测设计

### 4. 新模型上线前，如何设计模型替换评测？

答：冻结同一任务集、工具/知识环境、权限、Prompt、预算和评分器，只替换模型，比较任务成功、关键安全门、工具调用、长尾、P95、Token 和成本。然后做按任务类型的分桶、影子流量和小比例灰度；如果新模型在平均分提升但高风险或某类工具调用退化，应阻止全量发布或只做路由。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#15. 如何设计 benchmark，保证不同方案在相同环境下公平比较？|主线题15]]

### 5. 新增一个 Tool、Skill 或 Middleware 后，如何证明它真的带来收益？

答：做消融实验：固定模型、输入和其他工具，只改变新增能力，并同时保留没有触发该能力的对照样本。除了目标成功率，还要看误触发、选择错误、上下文 Token、延迟、权限拒绝、卸载残留和长尾回归；如果收益来自额外信息而不是设计本身，要把新增信息量纳入对照。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#34. 如何证明一个新增 Agent 能力值得构建？|主线题34]]

### 6. 评测集应该怎样按简单、长尾、对抗、不可回答和高风险样本分层？

答：按任务复杂度、工具依赖、数据新鲜度、权限边界、失败模式和业务风险建立标签，保证每层都有可验证的期望结果。简单集看基本能力，长尾集看覆盖，对抗集看注入/越权，不可回答集看拒答与澄清，高风险集看审批和副作用门禁；汇总分之外必须查看各层和硬性安全指标。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#12. 如何构建离线数据集、沙箱、回放集和回归集？|主线题12]]

### 7. 采集 Rollout 时，如何处理隐私、敏感数据、用户授权和可删除性？

答：采集前说明用途并按最小化原则只保留调试所需字段，敏感内容做脱敏、哈希、分离加密和访问控制；用户撤回授权或要求删除时能定位并清理相关轨迹及派生索引。训练/评测使用前还要去标识化、审查跨租户泄露和保留期限，不能因为“只是日志”就绕过数据治理。

## 线上观测与故障闭环

### 8. 线上任务没有即时人工标签时，如何监控 Agent 质量？

答：结合可观测代理指标和延迟标签：工具参数校验失败、无进展率、重复调用、验证通过率、转人工、用户重问/撤销、任务耗时、成本、权限拒绝和抽样人工审查。对关键任务建立延迟回传的业务结果，并按用户、版本、任务类型和租户分桶，避免只看全局平均。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#28. 如何监控延迟、Token、成本、吞吐、错误率、超时和任务成功率？|主线题28]]

### 9. 一次 Agent 事故复盘应该包含哪些环节？

答：先保留现场和影响范围，整理按时间排序的 Trace 与配置变更记录；再定位触发条件、首次偏离、故障传播、检测/拦截失效的原因和用户影响。行动项要有负责人、优先级、回归用例、监控/告警和发布门禁，并区分临时止损与根治，不能只写“加强 Prompt”。

### 10. 如何判断问题来自模型、Prompt、Context、RAG、Tool、网络还是 Harness？

答：沿第一处偏离逐层做对照：先构造提供正确且精简 Context 的基线，再替换为固定工具结果、绕过或替换检索、模拟网络与权限条件，并检查 State/StopReason，观察错误是否消失。若输入、证据、工具合同和执行状态都正确，任务仍稳定失败，才更可能是模型能力问题；若替换某一层后恢复，就优先修复该层并补充对应回归。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#19. 如何给 Badcase 分类：路由、上下文、检索、工具、规划、模型、执行还是展示？|主线题19]]

### 11. Agent 连续得到相同工具结果却不停止，如何从 Trace 定位并修复？

答：检查工具结果是否写回了正确的 State 版本、模型是否看到结果、解析器是否丢失成功字段，以及任务验收条件是否可判定；随后用参数/结果指纹做重复检测，加入无进展 StopReason 和最大重试。若工具本身缓存或数据未更新，应增加新鲜度和版本信息；若是模型策略问题，再调整 Prompt、路由或更换模型，而不是只提高轮数上限。

### 12. RAG 的召回、工具调用和最终回答各自正常，但整体任务仍失败，如何分析？

答：检查三者之间的接口语义：召回证据是否被正确注入、工具返回字段是否和后续节点 Schema 对齐、时间/权限是否一致、最终验收是否要求了召回和工具没有提供的事实。还要看 State 聚合、引用映射、排序和停止条件；这类问题通常是跨模块契约或目标定义错误，不能只重新调 Embedding 或模型温度。

## 发布与场景题

### 13. 离线评测明显提升，但线上成功率下降，你会如何排查？

答：先核对离线集是否泄漏、线上流量分布是否变化，以及线上版本、权限、工具和路由是否与评测一致。然后按用户、任务和模型版本查看 Trace，重点检查 Token/延迟是否引发超时、缓存是否污染、工具依赖是否受限，以及离线评分是否代表真实用户目标。若确认是新版本导致回退，就缩小灰度或回滚，并把真实失败样本补入隐藏评测。

关联：[[Learning/Agent/08_评测与可观测/评测与可观测性#17. 如何做线上离线一致性评测？|主线题17]]

### 14. 如何为一个可运行数十分钟、允许人工介入的长程 Agent 设计完整评测体系？

答：评测分为离线和线上两部分。离线准备多阶段任务、故障注入和人工介入样本，检查目标推进、State/Checkpoint、取消恢复、权限、证据与最终结果，并统计阶段成功率、重复/无进展、Token、延迟和人工介入质量。线上用任务级 Trace、延迟业务标签和抽样审查监测真实效果，把中断恢复、版本迁移和副作用对账纳入发布回归与安全门禁。
