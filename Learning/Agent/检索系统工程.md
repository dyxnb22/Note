# 检索系统工程

本文负责 RAG 的检索基础设施：索引、ANN、混合检索、更新、容量和评测。[RAG](./RAG.md) 负责应用链路，[知识系统](./知识系统.md) 负责来源、权限、版本与删除治理。先读 RAG，再按项目需要深入本文。

## 1. 先定义检索合同

明确文档/Chunk 唯一 ID、可检索字段、权限过滤层、更新/删除生效时间、延迟/吞吐/召回目标，以及无结果、冲突和过期资料的处理。检索只返回候选证据，不保证最终答案正确。

## 2. 召回方式与索引

| 方式 | 擅长 | 代价/边界 |
|---|---|---|
| BM25/倒排 | 编号、代码、专有名词、精确术语 | 受分词、同义词、语言分析器影响 |
| 向量 | 同义表达、语义相似 | 相近不等于事实一致或有权限 |
| 混合 | 同时覆盖词法与语义 | 需要融合、去重和额外延迟 |

Embedding 的相似度、归一化和索引配置必须一致；更换 Embedding 意味着新索引与版本切换，不能混用空间。向量库按数据驻留和权限 → 过滤/多租户 → 规模/延迟 → 运维 → 价格选择：本地 FAISS/Chroma 适合原型，已有 Postgres 可评估 pgvector，大规模或托管场景再比较 Qdrant、Milvus、云服务等，不要只背产品名。

精确 KNN 扫描全部向量；ANN 用近似换延迟和内存。常见结构：

- HNSW：多层近邻图；`M` 影响内存/连接数，`efConstruction` 影响建索引，`efSearch` 影响召回/延迟；
- IVF：先聚类再搜索部分桶；
- PQ：压缩向量省内存，但会损失精度；
- Disk-based ANN：用磁盘承载更大索引。

参数必须用真实查询集调优；删除、更新和并发构建还要观察 Tombstone、重建和版本切换。

## 3. Chunk、Metadata 与权限

Chunk 过小会丢失主语和上下文，过大会稀释主题并浪费 Context。优先按标题、段落、代码块、表格等结构切分；必要时用 Parent-child、Sentence Window、多向量和标题/路径/实体 Metadata。切分是否有效由召回与引用测试决定，不由固定字符数决定。

Metadata 字段要类型稳定并建立索引。权限必须在候选进入模型上下文前生效：

- Pre-filter：先限定允许集合再搜，安全直观但可能降低 ANN 效率；
- Post-filter：先搜再过滤，可能不足 K 条，且未授权内容不能进入任何后续步骤。

可用租户分区、允许列表 Bitmap 或迭代扩大候选平衡安全与召回；正文、向量和权限记录共享稳定 ID。

## 4. 混合检索与精排

```text
词项召回 + 向量召回 → 各自 TopN → 按 ID 去重/保留证据 → RRF → Reranker → TopK
```

不要直接相加 BM25 与向量原始分数，它们量纲和分布不同。RRF 按名次融合：

\[
\mathrm{RRF}(d)=\sum_{r\in R}\frac{1}{k+\mathrm{rank}_r(d)}
\]

`k` 只是平滑参数，要用固定评测集调；RRF 不能找回任何一路都没召回的正确答案。对比实验至少包含 BM25、向量、RRF、RRF+Rerank，并按精确标识符/口语改写等查询类型切片。

查询前可做拼写/术语规范化、实体与过滤条件抽取、多查询扩展、HyDE 或对话改写，但必须保留原查询、限制次数并单独评测，因为改写可能丢约束或引入事实。

Reranker 只在候选集内重排，需确定候选数、保留数、长文截断和延迟预算。默认叙事是 BM25+向量 → RRF → Cross-Encoder；Bi-Encoder 负责快召回，Cross-Encoder 负责小集合精排，Late Interaction 是更重的折中方案。

## 5. 更新、容量与性能

```text
采集 → 解析 → Chunk → Embedding → 写索引 → 验证 → 激活版本
                         ↘ 更新/删除/重建/回滚
```

必须处理：内容 Hash 与幂等摄取、旧 Chunk 删除、Embedding 升级时双索引/全量重建、部分成功重试、删除传播延迟和上一版本回滚。估算向量数为文档数 × 平均 Chunk 数；内存约为数量 × 维度 × 每维字节，再加图边、Metadata、倒排和缓存。压测要使用真实租户、过滤选择率、更新比例和并发，均匀随机数据会高估生产性能。

## 6. 评测与诊断

离线数据至少包含查询、相关 Chunk、相关等级和无答案标记。核心指标：Recall@K、Precision@K、MRR、NDCG、Zero-result Rate、权限泄漏率和过期资料命中率。标注有主观性时，记录指南、多人一致性和争议处理。

线上观察点击、引用展开、复制、用户纠正、人工接管、任务成功、延迟、成本、零结果和超时，并按查询类型、租户、索引版本切片。点击受位置偏差影响，不能直接当真值；发布前后都要固定版本和流量。

## 7. 最小实验

1. 建立含编号、同义表达和无答案查询的测试集。
2. 比较 BM25、向量和混合的 Recall@K。
3. 调整 HNSW `efSearch`，画召回—延迟曲线。
4. 加入 Reranker，验证它只能改善候选内排序。
5. 更新/删除文档，验证旧 Chunk、权限和引用失效。

### RRF 与 Recall@K

```python
from collections import defaultdict


def reciprocal_rank_fusion(
    ranked_lists: list[list[str]], *, k: int = 60
) -> list[tuple[str, float]]:
    scores: defaultdict[str, float] = defaultdict(float)
    for ranked in ranked_lists:
        seen: set[str] = set()
        for rank, chunk_id in enumerate(ranked, start=1):
            if chunk_id in seen:
                continue
            seen.add(chunk_id)
            scores[chunk_id] += 1.0 / (k + rank)
    return sorted(scores.items(), key=lambda item: item[1], reverse=True)


def recall_at_k(
    gold: dict[str, set[str]], results: dict[str, list[str]], *, k: int
) -> float:
    labelled = [ids for ids in gold.values() if ids]
    if not labelled:
        return 0.0
    hits = sum(
        bool(set(results.get(query_id, [])[:k]) & relevant_ids)
        for query_id, relevant_ids in gold.items()
        if relevant_ids
    )
    return hits / len(labelled)
```

实验记录同时保存查询类型、各路 TopN、融合 TopK、耗时和权限过滤前后候选数；一个总 Recall@K 不能定位是哪一路漏召回。

## 验收清单

- 能按查询类型选择词项、向量或混合检索；
- 能解释 HNSW 参数对召回、延迟和内存的影响；
- 权限在模型上下文前生效；
- 更新、删除、模型升级和回滚可验证；
- 指标能按召回、融合、精排和权限阶段定位失败。
