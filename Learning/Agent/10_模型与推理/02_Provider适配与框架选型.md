# 10.2 Provider 适配与框架选择

## 转换为应用内部类型

Provider 使用各自的消息、工具调用、流式事件、用量和错误格式。Adapter 统一转换为内部类型，任务代码只依赖自己的接口。

应用定义 ModelResult、ToolCall 等类型，适配器负责与 Provider 字段互转，并声明是否支持结构化输出、取消和各类内容块。不支持的能力返回具体说明。

## 工具调用与内容块

一次返回可能包含文字、多个工具调用或其他类型内容。调用 ID、名称、完整参数与返回结果需要保持关联；同一轮多个工具是否并行，由依赖、资源和授权决定。

有些服务要求下一轮原样带回特定内容块、签名等数据，用来继续会话，后文称为连续性数据。这些内容不能用摘要替代。

多个工具的发出顺序、完成顺序和协议回填顺序可能不同，适配器要按调用 ID 保存对应关系，不能指望字典顺序或调度碰巧排对。应用的任务状态和服务的会话状态分别管理。

## 明确适配器支持的协议子集

例如，适配器可以只支持非流式文本与客户端工具调用，并逐项检查顶层 JSON 类型、内容块、调用 ID 和参数。若要增加推理内容块、流式事件或托管工具，还要处理对应协议要求的连续性数据。

收到 HTTP 200 后继续检查响应结构，分别识别根节点类型错误、缺失工具 ID、输出截断与正常结束，再按应用策略继续或终止。

字段转换后，下一轮仍须保留协议要求的旧消息、签名和工具配对信息。

## 增量参数先组装再解析

例如调用 c1 的参数先后到达两段文本：`{"order_` 和 `id":"A"}`。只有在确认该调用完成、片段完整拼接成 `{"order_id":"A"}` 后，才能解析并校验字段。

多个调用交错到达时，需要按调用 ID 分别缓冲；完成顺序不同，不应把 c1 的第一段与 c2 的第二段拼到一起。

增量事件字段按 Provider 协议解析。适配器限制缓冲区，处理多调用交错、重复和断流，确认完成后再解析 JSON、校验字段与权限，最后交给执行器。

## 错误、停止与用量

Adapter 将网络故障、限流、非法输入、不支持的能力、安全拒绝和输出截断转成稳定的结果类别，运行时据此继续、修正或停止。对外错误说明避免暴露敏感信息。服务停止字段和任务终态的区别见[Loop 控制](../01_基础架构/Loop控制与Harness.md#区分工具结果、任务状态与停止原因)。

分别记录接口返回的用量、程序估算的用量和最终报告值，并注明来源；没有拿到的数值记为未知。预留与结算见[运行时状态流转](../01_基础架构/运行时机制与状态流转.md#调用前预留额度，调用后保存结果)。价格和计费规则放在服务配置中。

## 托管服务与私有部署的职责变化

托管服务承担部分模型运维，应用负责数据选择、身份授权、任务预算、适配和结果验证。选型时核对实际账户与部署配置：数据怎样使用和保留、哪些地区可用、怎样联网、支持哪些能力。同一品牌的不同部署也可能不同。

私有部署由自己的团队负责模型进程、硬件容量、权重版本、Tokenizer、推理引擎、扩缩容和故障恢复。加载权重后，在所选组合上逐项验证工具调用、结构化输出、流式协议、长输入与取消行为。

显存需求除了权重，还包括 KV Cache、临时计算和并发开销。量化可以减少部分显存占用，但是否影响任务表现，还要重新测试；更大的批次也可能增加等待。容量规划要按真实输入长度、输出长度和任务轮次测量，再计算可支持的业务负载。模型放不进单个设备时，还需评估跨设备并行带来的通信和运行成本。[vLLM 并行与扩展说明](https://docs.vllm.ai/en/latest/serving/parallelism_scaling/)

私有部署的选择取决于数据要求、稳定负载、延迟、模型能力和维护投入。推理留在自有网络时，检索、日志、重排和遥测仍可能访问外部服务，需要逐项核对权限与数据去向。

## 按状态与控制需求选择框架

状态少、流程清楚时，普通代码就够。缺少模型、检索和工具连接时，可以用组件库；需要管理节点、分支和持久状态时，再考虑图运行时。选择 LangChain、LangGraph 或其他框架，从当前缺口和维护成本出发。

Reducer 定义并行更新怎样合并，Checkpoint 保存图状态，interrupt/resume 用于暂停执行、之后继续。这些接口在不同框架中的签名和行为可能不同，要固定版本验证。例如 LangGraph 从中断恢复时，可能再次进入原节点，因此节点中的副作用要按幂等要求处理，避免重复生效。

## 兼容验证与替身模型

Scripted/Fake Provider 返回固定决策序列，用于验证调用配对、状态转移和错误路径。接入真实模型后，再测试工具选择、流式事件、用量报告、拒绝、取消，以及多轮交互的连续性数据。

升级适配器时，保留旧样本与版本组合，先回归检查消息、状态和结果转换，再比较完整任务效果。

参考：[LangGraph 中断与恢复](https://docs.langchain.com/oss/python/langgraph/interrupts)。
