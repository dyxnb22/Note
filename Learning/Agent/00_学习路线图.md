# AI Agent 工程学习路线图

> 这是一张执行路线，不是知识正文。主题边界与完整目录见 [README](README.md)，跨领域顺序见 [AI / Python / Agent 学习地图](../00_Navigation/AI-Python-Agent学习地图.md)。

## 使用方法

1. 先完成“核心主线”，不要一开始同时学习 RAG、MCP、多 Agent 和 GUI 自动化。
2. 每阶段以可运行产物和测试作为完成证据，不以“读完文章”作为完成标准。
3. 选一个 Python 实践仓库建立 Agent 行为主线；其他路线只做机制或语言对照，不重复抄写相同示例。
4. 遇到具体问题再进入专题文档，完成后回到主线。
5. Rust 是阶段 1 之后的实现分支：先证明 Agent Loop 和 Tool 合同，再承担语言与 Runtime 的额外复杂度。

## 阅读层级

不要把全部笔记按文件名从头读到尾。按下面的层级选择一条主线：

1. **核心机制**：`01 → 02 → 03 → 04`，建立调用、工具、循环、状态和 Context 的共同模型。
2. **一个工程分支**：Coding Agent 读 `05`；长任务读 `06`；知识型 Agent 读 `文档摄取与解析 → RAG → 检索系统工程 → 知识系统`。
3. **生产门槛**：安全先读 `07` 再读 `08`，评测先读 `09` 再读 `10`，最后接 `11 → 12`。
4. **按需专题**：Workflow、Memory、MCP、Skills、多 Agent、GUI、语音和框架选型只在需求出现时进入。

每个层级只选一个实现主线。`learn-claude-code` 用来拆解 Harness 机制，`ai-agent-learning` 用来完成 SDK-first 应用，`rust-agent-runtime` 用来做 Runtime 对照；不要把三套实践当成三遍必修课。

面试准备不另起一条技术主线：先按 [学习范围与面试题型](面试/学习范围与面试题型.md) 完成 P0，再选择一个与项目匹配的 P1 场景；公司题目只作为题型练习，不作为第二份正文。

## 阶段 0：建立可靠的 API 程序

### 学习重点

- Python 项目结构、类型、测试、日志和异常处理。
- HTTP 的认证、超时、重试、限流与幂等。
- LLM 请求中的消息、采样、结构化输出、流式响应和用量统计。
- 配置与密钥通过环境或密钥系统注入，不写入代码和笔记。

### 完成标准

- [ ] CLI 能读取配置并调用模型。
- [ ] 超时、限流和无效响应有明确错误路径。
- [ ] 日志不泄露密钥或完整敏感输入。
- [ ] 至少有成功、超时和格式错误三个测试。

## 阶段 1：打通最小 Agent 循环

最小循环只有四步：模型决策、工具调用、结果回填、判断终止。先做窄任务，再增加框架。

### 学习重点

- 工具描述、参数 schema、返回值和错误语义。
- 最大步数、超时、预算与重复调用检测。
- 工具注册表与执行器分离；模型不能直接获得任意系统权限。
- 对有副作用的工具加入确认、作用域和幂等键。

### 建议练习

从 [ai-agent-learning](实践/ai-agent-learning/README.md) 的项目 03–05 任选一条连续完成；再阅读 [learn-claude-code](实践/learn-claude-code/README.md) 的最小循环与工具章节作对照。

### 完成标准

- [ ] 至少三个工具使用统一协议注册。
- [ ] 错误结果能回到循环并被模型处理。
- [ ] 循环达到步数、时间或成本上限时确定终止。
- [ ] 重放同一输入可解释每一步为何发生。

## 阶段 2：构建稳定的 Agent Harness

Harness 是包围模型的确定性系统：它管理上下文、权限、状态、执行环境和生命周期。模型能力提升不能替代这层工程。

### 学习重点

- 上下文选择、压缩、缓存与污染控制。
- 文件、Shell、浏览器等工具的隔离和变更验证。
- checkpoint、幂等、重试、取消与人工接管。
- trace、事件日志和 session journal，使失败可以定位和恢复。

### 建议练习

完成 [ai-agent-learning](实践/ai-agent-learning/README.md) 的服务化与工作流项目，或按 [learn-claude-code](实践/learn-claude-code/README.md) 实现权限、Hook、任务状态和会话恢复。不要同时维护两套同功能代码。

### 完成标准

- [ ] 进程中断后能从最近 checkpoint 恢复。
- [ ] 写操作有变更预览、权限边界和写后验证。
- [ ] 上下文超限时按策略压缩，而不是静默截断。
- [ ] 用户可以取消、暂停或接管任务。

## 阶段 3：生产安全、评测与上线

生产门槛不是“多数演示成功”，而是风险可控、质量可测、故障可恢复。

### 学习顺序

1. 用 [07_Agent安全与威胁建模](07_Agent安全与威胁建模.md) 识别资产、信任边界和攻击面。
2. 用 [08_安全与可控性](08_安全与可控性.md) 落实最小权限、审批、沙箱和审计。
3. 用 [09_Agent Eval实验方法](09_Agent%20Eval实验方法.md) 设计可证伪实验，再用 [10_Eval与测试体系](10_Eval与测试体系.md) 建立持续回归。
4. 用 [11_可观测性与调试](11_可观测性与调试.md) 连接 trace、指标、成本和用户反馈。
5. 依照 [12_部署与生产化](12_部署与生产化.md) 设置灰度、SLO、回滚和事故流程。

### 完成标准

- [ ] 高风险动作默认拒绝或要求明确审批。
- [ ] 检索权限在检索前过滤，间接提示注入有隔离与测试。
- [ ] 离线回归集包含成功、拒绝、边界与历史事故样本。
- [ ] 线上质量、延迟、成本和安全指标均有阈值。
- [ ] 完成一次取消、降级和回滚演练。

## 实践仓库的分工

### ai-agent-learning：产品工程主线

适合从 API 客户端逐步走向 Tool Calling、服务化、工作流、记忆、RAG、MCP 和评测。以其 [README](实践/ai-agent-learning/README.md) 为唯一项目顺序来源，本路线不复制项目清单。

### learn-claude-code：Harness 机制解剖

适合通过小步实现理解循环、权限、Hook、子 Agent、任务状态、压缩、隔离与会话机制。尽管目录名源于一个具体产品，学习目标是可迁移的架构机制；模型和 SDK 应由运行环境配置，不把示例中的版本号当作推荐。

### rust-agent-runtime：Runtime 实现分支

适合在已经理解 Agent Loop 后，用 Rust 验证 Tool Registry、有限状态、预算、取消、受限执行、Checkpoint 和 Eval。它不承担 Prompt 或框架入门，而是把已有行为合同迁移到新的语言运行模型。

### 选择原则

- 想做一个可部署服务：以前者为主。
- 想理解代码 Agent 内部机制：以后者为主。
- 两者都学：只选一个实现主项目，另一个用于代码阅读和设计对照。
- 想用 Rust 做 Runtime/Harness：先任选一个 Python 项目建立行为基线，再用 `rust-agent-runtime`实现相同合同；比较正确性、复杂度、延迟和资源，而不是只比较代码行数。

## 最终验收清单

- [ ] 能解释 Agent 与普通工作流的边界。
- [ ] 能从一次 trace 定位模型、工具、上下文或基础设施故障。
- [ ] 所有副作用动作都有权限、审计、幂等或补偿设计。
- [ ] 质量结论来自固定数据集和可复现实验，而非少量演示。
- [ ] 成本、延迟和成功率可以按任务、模型与工具拆分。
- [ ] 模型、SDK 或协议升级经过回归测试和灰度，而非直接替换。
- [ ] 用户知道系统能做什么、何时会确认、如何停止及如何纠错。

## 一次综合验收

用一个小型 Coding Agent 把整条主线串起来，不追求功能多，追求边界完整：

1. 输入一个明确任务，Agent 通过 `read/search → patch → test` 完成修改，并用程序化测试证明结果。
2. 工具执行经过 schema、权限、超时、幂等/重复检测和审计；写操作可预览，危险动作可审批。
3. Context、State、Checkpoint、Trace、取消、恢复和预算都能在一次失败演练中被观察到。
4. 准备成功、工具失败、越权、Prompt Injection、进程中断和模型升级六类 Case，跑完 Eval 并能解释结果。

最终交付物应包括：架构图、工具合同、状态图、威胁模型、回归集、一次 Trace/Replay、成本与延迟账本，以及灰度/回滚方案。能完成这组交付，才算把 Agent 从“会调用模型”学到“能可靠交付系统”。

完成这些条件后，再把学习重点从“增加能力”转向“缩小失败面、提升可解释性和运营效率”。
