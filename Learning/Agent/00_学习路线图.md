# AI Agent 工程学习路线图

本页是 `Learning/Agent` 唯一学习入口。README 只做目录；正文负责一个主题；实践负责运行代码。第一次学习直接从核心主线开始，概念会在需要它的章节中逐步出现。

## 怎么读

1. 先完成核心机制，再进入一个实践主线；不要同时重做三套实践。
2. 每阶段以“产物 + 测试 + 一次失败复盘”验收，不以读完文件为完成标准。
3. RAG、Memory、Workflow、MCP、多 Agent、GUI 和语音是场景分支；完整通读时按下方顺序，实际项目按需跳转。
4. 面试资料只做复习，不另建一条技术主线。

## 一次完整学习顺序

1. **核心循环**：`01 LLM 调用 → 02 Tool Calling → 03 Agent 架构 → 04 Context`。实践 00 是可选的无 API 预热，不是额外理论前置。
2. **执行与状态**：`05 代码 Agent → 06 Durable Execution`；需要跨请求/跨会话记忆时再读 `Memory`。
3. **安全与治理**：`07 威胁建模 → 08 安全与可控性 → 身份与数据治理`。
4. **质量与上线**：`09 Eval 实验 → 10 Eval 测试 → 11 可观测性 → 成本性能 → 12 部署 → 运维 → 版本来源`。
5. **编排实现**：`Workflow → LangGraph`。
6. **知识分支**：`文档摄取 → RAG → 检索系统 → 知识系统 → GraphRAG`。
7. **工具生态**：`MCP → Skills → 多 Agent → 跨 Agent/A2A`。
8. **产品扩展**：`产品与人机协同 → 项目表达`，再按岗位学习 Computer Use、语音、推理服务、推理模型、模型行为训练、框架选型。
9. **面试补充**：`面试/学习范围与面试题型 → Agent主题速答 → 大厂真题汇总`。

正文链接和文章职责见 [README](./README.md)；同一行的文章按箭头阅读。

## 先分清必修、进阶和分支

不要把目录中的每一篇都当成第一遍的前置：

| 层级 | 第一次学习做什么 | 目的 |
|---|---|---|
| **核心必修** | `01 → 02 → 03 → 04 → 实践 01–05`（00 可选） | 在对应章节中建立调用、工具、循环和 Context 的共同模型 |
| **可靠交付必修** | `05 → 06 → 07 → 08 → 09 → 10 → 11 → 成本性能 → 12 → 运维` | 让 Agent 能被权限控制、测试、观测、恢复和上线 |
| **场景分支** | RAG、Memory、Workflow、MCP、GUI、语音、多 Agent、A2A | 按项目需求选择，不是核心 Loop 的前置 |
| **面试/研究补充** | 框架选型、推理服务、Thinking、模型行为训练、项目表达 | 在能运行一个 Agent 后再学习 |

如果当前只是想先理解 Agent，不要从 `MCP`、`LangGraph`、`RAG` 或多 Agent 开始；先完成核心必修并能画出一次工具循环。遇到概念阻塞时，回到它首次出现的章节：Provider/Adapter 看 `01`，ToolCall/ToolResult 看 `02`，State/Loop/Trace 看 `03`，Context/Memory 看 `04`。

## 阶段验收

| 阶段 | 必须产物 | 验收问题 |
|---|---|---|
| 1. 调用与循环 | 一张端到端消息/状态轨迹；一个有配置、超时、错误处理的 CLI；三个统一 Tool；有限 Agent Loop | 模型提出什么，执行器负责什么，Provider 差异在哪层适配，循环如何成功/失败/停止？ |
| 2. Harness | 文件/命令工具、Context 预算、Trace、Checkpoint、取消/恢复 | 写操作如何预览、验证、审计？进程中断后如何避免重复副作用？ |
| 3. 安全与质量 | 威胁模型、权限/沙箱、回归集、Eval Harness、Replay | Prompt Injection、越权、工具失败和质量退化如何被发现并阻止？ |
| 4. 生产交付 | 版本矩阵、成本账本、SLO、灰度、降级、回滚演练 | 能否按任务拆成功率、延迟、成本和风险，并解释一次事故？ |

## 实践只选一条主线

- [ai-agent-learning](./实践/ai-agent-learning/README.md)：理论主线从 `01–04` 开始；可先或稍后运行无 API 的 00 号最小循环练习，再从 Python/HTTP/API 到 Tool、Loop、FastAPI、LangGraph、Memory、RAG、MCP；适合从头做应用。
- [learn-claude-code](./实践/learn-claude-code/README.md)：用 s01–s20 拆解 Loop、权限、Context、任务、恢复、团队和 MCP；按问题挑实验，不必全做。
- [rust-agent-runtime](./实践/rust-agent-runtime/README.md)：在理解 Loop 后，用 Rust 重做 Tool、预算、取消、Trace、Checkpoint 和受限执行。

## 最终验收

用一个小型 Coding Agent 串起 `read/search → patch → test`：

- 工具经过 schema、权限、超时、幂等/重复检测和审计；危险动作可审批。
- Context、State、Checkpoint、Trace、预算、取消和恢复都能在一次失败演练中观察到。
- 回归集覆盖成功、工具失败、越权、注入、中断恢复和模型升级。
- 能提交架构图、工具合同、状态图、威胁模型、Eval/Replay、成本账本和灰度回滚方案。

完成这组交付，才算从“会调用模型”学到“能可靠交付 Agent 系统”。不要单独背术语：沿着一次任务的轨迹回看 `01` 的调用、`02` 的动作、`03` 的状态转移和 `04` 的输入装配即可。
