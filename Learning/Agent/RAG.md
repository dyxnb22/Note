# RAG

RAG（Retrieval-Augmented Generation）是在生成前检索外部证据，让模型基于可追溯资料回答。它解决知识更新、私有资料接入和引用问题，不保证模型一定正确。

> **学习位置**：按 `文档摄取与解析 → RAG → 检索系统工程 → 知识系统` 阅读。需要多跳实体关系时再读 [GraphRAG](./GraphRAG与关系检索.md)。
>
> **职责边界**：本文负责 RAG 应用链路、Context 装配、Grounding、Agentic RAG 和端到端排障；解析细节在 [文档摄取与解析](./文档摄取与解析.md)，检索基础设施在 [检索系统工程](./检索系统工程.md)，来源/权限/版本/删除在 [知识系统](./知识系统.md)。

## 1. 完整链路

```text
数据源
 → 分类/解析/质量门禁
 → DocumentVersion / Chunk / Metadata
 → 权限过滤
 → Query 理解与检索
 → 候选排序
 → Context Assembly
 → 生成、引用和拒答
 → Eval、反馈、更新或删除
```

回答错误时要区分：资料不存在、解析丢失、切分错误、召回失败、排序错误、权限过滤错误、Context 截断、模型误读和引用验证失败。

## 2. RAG 的最小检索合同

检索器应返回结构化证据，而不是只返回一串文本：

```json
{
  "chunk_id": "chunk-17",
  "document_id": "doc-3",
  "text": "...",
  "source": {"title": "policy.pdf", "page": 4},
  "version": "v8",
  "tenant_id": "tenant-a",
  "permission_checked": true,
  "score": 0.82
}
```

权限必须在证据进入模型前检查。Chunk ID、文档版本和引用位置要稳定；检索器的 BM25、向量、混合、RRF、ANN、Rerank、更新和容量细节见 [检索系统工程](./检索系统工程.md)。

## 3. Context Assembly 与 Grounding

Context 组装至少处理：

- 候选去重和相邻 Chunk 合并；
- 同一来源占比、时间和权威性；
- Token 预算和无关内容裁剪；
- 冲突证据并列展示；
- 来源标签，防止文档指令被当作系统指令；
- 每个关键结论与真实 Chunk ID 的引用绑定。

生成合同应要求模型区分证据事实、推断和未知；证据不足时拒答或请求更多信息。引用由系统根据 Chunk ID 生成并校验，不能让模型凭空编造 URL 或页码。

## 4. 什么时候使用 Agentic RAG

固定的“改写 → 召回 → 排序 → 生成”管线优先用于单跳问答、严格 P99 或答案已稳定在 TopK 的场景。Agentic RAG 让模型决定是否继续检索、改写查询、调用搜索或比较证据，适合开放式多步研究，但会增加延迟、成本和空转风险。

使用 Agentic RAG 前先定义：最大检索次数、每次候选数、总预算、可访问数据源、停止条件、无答案行为和轨迹指标。先跑固定管线 Baseline，再用消融证明动态循环有净收益。

## 5. 端到端评测

至少分层评估：

| 层 | 关注 |
|---|---|
| 摄取 | 正文完整、表格可读、版本及时 |
| 权限 | 无权资料不进入候选或 Context |
| 召回/排序 | Recall@K、MRR/NDCG、关键证据位置 |
| 生成 | Faithfulness、相关性、拒答正确性 |
| 引用 | 引用存在且真正支持结论 |
| 系统 | 延迟、成本、零结果、更新/删除传播 |

测试集必须包含无答案、冲突答案、过期资料、精确标识符、权限隔离和多跳问题。RAG 评测与 Agent 轨迹评测的边界见 [Agent Eval 实验方法](./09_Agent%20Eval实验方法.md)。

## 6. 排障顺序

1. 文档是否存在、版本是否正确？
2. 解析后正文和表格是否完整？
3. Chunk、Metadata 和权限索引是否正确？
4. 权限过滤是否误删或放行？
5. 正确证据是否进入候选？
6. 排序是否把证据排低？
7. Context 是否截断、重复或混入注入？
8. 模型是否超出证据生成，引用是否支持结论？

先拿掉生成模型，单独验证检索和证据；再逐步接回 Reranker、Context 和生成，避免把所有问题都叫作“幻觉”。

## 7. 构建 RAG 项目时检查

只有进入知识型 Agent 分支时才使用本清单。先完成普通检索基线，再按项目风险增加无答案、权限、过期和冲突查询：

- 能分别定位摄取、过滤、召回、排序、Context 和生成错误；
- 能说明固定 RAG 与 Agentic RAG 的边界；
- 每条回答的引用都能追溯到有权限的 Chunk；
- 更新和删除后旧版本、缓存和引用不会继续返回；
- 能用 Baseline/消融实验证明每个新增组件的收益。
