# 01.2 Loop 控制与 Harness

## 一轮运行包含什么

一轮通常从读取状态开始，经过上下文组装、模型调用，到处理返回结束。工具执行是否算在这一轮里，要看应用的计数方式。Session、Run、Turn 在不同框架中也可能指不同范围。

消息历史记录对话和工具返回，任务状态保存当前阶段、版本、剩余预算、待执行动作与错误。只存对话时，恢复任务还得重新从文字里提取这些值。

## 控制事件改变后续运行

用户补充条件时，程序先把它记为事件，等当前请求返回后用于下一轮，或取消当前请求后重新发送。steer 通常用于调整方向，followup 用于追加工作，interrupt 用于暂停当前工作；名称和处理时点以宿主实现为准。

模型请求已经发出后，修改内存中的 Prompt 不会改变服务端已收到的输入。即使请求取消，也要核对工具是否已经执行。

Hooks 或 Middleware 用于在调用前后插入逻辑，例如检查预算、记录用量，可通过回调或包装函数实现。

## 区分工具结果、任务状态与停止原因

查到订单后，模型可能还要查物流，也可能已经能回答。下表用一组应用自定义字段，区分工具结果、停止原因和任务状态。

| 层次 | 示例中的记录方式 | 一种结果 | 接下来由谁判断 |
|---|---|---|---|
| 模型提案 | 动作类型、工具名、调用 ID | 查询工具、答案候选 | 运行时决定执行或验收 |
| 工具执行 | tool_result 中的 status | ok、not_found、denied | 运行时回填观察并决定下一步 |
| 任务结束或最近一次等待的原因 | State.reason | verified、provider_timeout、budget_exhausted | 调度器按产品规则决定后续处理 |
| 任务状态 | State.status | running、succeeded、failed、cancelled | 运行时检查转换条件后更新状态 |

物流查询返回 ok，只说明查到了数据，任务仍为 running。答案验证通过后，任务才变成 succeeded，停止原因记为 verified。

如果查询已成功，但预算耗尽时还没有可交付答案，本例把任务记为 failed、停止原因记为 budget_exhausted，已取得的观察仍然保留。

界面可据此显示“因预算停止，已查到订单状态”。评测也能分开统计主动取消、证据不足和正常完成；需要继续任务的产品，可以另设等待或可恢复阶段。

模型服务的 stop_reason 描述本次生成如何结束，例如 tool_use。适配器解析它，运行时根据执行结果更新 task_status 与 task_reason；后两个名称由应用定义。

## 继续与停止的状态转换

| 当前状态 | 事件或条件 | 后续状态 | 运行时处理 |
|---|---|---|---|
| running | 有额度，开始下一轮 | running | 已开始调用数增加 |
| running | 答案通过完成验证 | succeeded | 原因是已验证完成 |
| running | 用户取消 | cancelled | 保留已取得的事实和已执行操作的记录 |
| running | 没有新增工作额度且未完成 | failed 或部分完成状态 | 原因是预算不足 |
| 已结束 | 迟到的旧提案 | 保持终态 | 不因旧提案自动重新执行；修订需要新的有效请求 |

产品如果允许修订，可以由仍有权限的用户发起新请求。运行时重新核对目标、授权和资源版本后，再进入修订流程。

两轮上限按已启动轮数计数。第二轮答案通过完成验证，就以 verified 结束；若只有部分观察，则保留结果并说明缺口。费用预留和并发扣减见[运行时状态流转](运行时机制与状态流转.md#调用前预留额度，调用后保存结果)。

## Harness 提供的运行支持

Harness 为模型循环提供运行支持，通常负责上下文、工具执行、预算、验证和记录，也可以集中处理工具错误与停止控制。

控制面决定任务采用什么策略、何时运行，执行面负责读写文件、操作浏览器、使用 Shell 和访问网络。将两者分开后，同一套运行逻辑可以连接不同执行环境。真正执行动作的入口必须检查权限，不能只靠隐藏工具说明。

## 切换模型与阶段交接

切换模型或执行者时，要把当前目标、已完成阶段、待确认动作、证据来源和剩余预算交给接收方。新运行实例负责核对权限与资源版本，再查操作账本，确认尚无结果的动作是否已经生效；模型接收本轮决策所需的信息。

## 执行环境与恢复范围

冷启动创建新环境，恢复从已有状态继续，快照保存某个时间点的环境内容。快照是否包含内存、进程或网络连接，取决于沙箱产品；恢复后分别核对文件、进程、远端请求和凭证状态。

空闲环境仍可能持有文件、进程和敏感配置，需要设置过期时间并清理。恢复后的业务操作核对见[持久化执行与恢复](../09_工程化与系统设计/02_Durable与生产运维.md)。
