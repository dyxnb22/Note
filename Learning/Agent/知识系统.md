# 知识系统

知识系统负责资料的进入、版本、授权、检索、引用、更新和退出。RAG 是它的一个消费方式；检索算法见 [RAG](./RAG.md) 与 [检索系统工程](./检索系统工程.md)，PDF/OCR/表格解析见 [文档摄取与解析](./文档摄取与解析.md)，关系增强见 [GraphRAG](./GraphRAG与关系检索.md)。

> **学习位置**：完成 [RAG](./RAG.md) 和 [检索系统工程](./检索系统工程.md) 后阅读。它负责把“能检索”提升为“有来源、版本、权限、删除和引用生命周期的知识系统”。
>
> **职责边界**：本文负责来源、版本、权限、质量、引用、更新和退出；解析、检索算法和生成链路分别由 [文档摄取与解析](./文档摄取与解析.md)、[检索系统工程](./检索系统工程.md) 和 [RAG](./RAG.md) 负责。

## 1. 对象与生命周期

```text
Source → Document → DocumentVersion → Chunk → IndexRecord
                                      ↘ Citation
```

原文、版本、权限和删除状态是事实源；向量/倒排记录是可重建的派生物，不能把向量库当唯一真相。

```text
发现变化 → 拉取与安全检查 → 解析/标准化 → 质量校验
→ 版本落库 → Chunk/Metadata → 建索引 → 验证 → 原子发布
```

每一步应幂等、可重试、可观测；失败文档隔离出主索引，新版本完全验证前不能和旧版本半更新混用。解析需按数字件、扫描件、Office、表格分流，并保留原文定位与置信度。

## 2. 来源、版本与新鲜度

来源记录至少包括：URI、所有者、采集时间、作者/发布时间/有效期、权威等级、内容 Hash、解析器版本，以及是否允许用于回答、训练或外发。官方规范、内部批准文档、个人笔记和自动摘要不能拥有相同权重。

`DocumentVersion` 不可变；更新创建新版本，索引记录绑定确切版本，引用保留 `version_id` 以便历史回答重放。系统还要定义同步频率、删除/重命名/权限变化发现方式、冲突优先级、过期处理和索引落后时的回答策略。

## 3. 权限与引用

权限决策至少包含主体、租户、资源、动作和当前上下文。正确顺序是：

```text
身份验证 → 计算允许范围 → 检索过滤 → 重排 → 组装 Context
→ 生成 → 引用再次鉴权
```

不能等生成后再隐藏无权内容；缓存键也必须包含租户和权限上下文。`Citation` 至少保存 `document_id`、`version_id`、`chunk_id`、标题/URI、定位、支持片段、检索/回答时间和权限结果；展示链接变化时仍以稳定 ID 和版本为准。

## 4. 删除、质量与冲突

删除要覆盖原文、所有版本、向量/倒排、缓存、备份、已生成回答和审计记录，并处理法律保留与用户删除的冲突。先写 Tombstone 让查询立即过滤，再异步清理派生物；每个清理任务要幂等且可证明完成。

摄取阶段检查空文档、乱码、OCR 置信度、重复内容、标题/表格/代码结构、原文定位、敏感信息和恶意指令。低质量资料应隔离、降权或人工复核。

多来源冲突不能只选相似度最高者，应结合权威性、生效时间、区域和版本；无法自动裁决时展示冲突。业务规则可保存生效区间和替代版本，避免旧政策继续被召回。

## 5. 观测与恢复

观察同步成功率/延迟、解析失败和重复率、原文与索引版本差、零结果/低置信/过期命中、权限过滤前后候选数、引用纠错和删除传播时间。每次回答都应能反查知识版本、检索参数和权限范围。

可恢复事实至少包括：原始文档或受控引用、版本元数据、权限映射、Chunk/解析器/Embedding 配置、发布状态和审计日志。只备份向量库无法恢复来源、引用和权限语义。

```python
def publish_version(document_id: str, version_id: str) -> None:
    assert index_is_ready(version_id)
    mark_current_version(document_id, version_id)
    enqueue("activate_index_alias", document_id=document_id, version_id=version_id)


def request_delete(document_id: str, reason: str) -> str:
    tombstone_id = create_tombstone(document_id, reason=reason)
    enqueue("purge_derived_data", document_id=document_id, tombstone_id=tombstone_id)
    return tombstone_id
```

这是流程示意：实际实现要用条件更新、权限检查和审计记录，防止旧清理任务误删新版本。删除验收至少记录 Tombstone、各派生存储的 checkpoint、重试次数、最后校验时间和仍可查询记录数。

## 维护长期知识服务时检查

只有知识需要持续更新、删除、审计和重建时才落实完整生命周期；一次性本地 RAG 实验不需要提前完成：

- 任一 Chunk 能回到确切原文版本和位置；
- 权限变化能在规定时间内影响检索和缓存；
- 删除覆盖索引、缓存、备份和回答保留策略；
- 索引可从事实源和版本化处理配置重建；
- 冲突、过期、低质量和无答案都有明确规则；
- 历史回答能按当时的知识版本、引用和检索参数复现。
