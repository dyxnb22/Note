# 成本与性能工程

这篇文章解决一个问题：**如何把 Token、延迟、并发、缓存和预算变成可观测、可约束的工程指标**。

> **学习位置**：在 `09–11` 之后阅读，再把预算和运行 Profile 接入 [部署与生产化](./12_部署与生产化.md)。
>
> **职责边界**：本文负责费用账本、延迟拆解、缓存、模型路由、并发和 Agent 预算。`01` 只讲调用层 usage；`04` 负责 Context 裁剪；`11` 负责把指标接入 Trace；`12` 负责部署配置。

## 1. 成本账本

基础模型成本近似为：

```text
总成本 = 输入 token × 输入单价
       + 输出 token × 输出单价
       + 缓存/工具/检索/存储/等待等附加成本
```

单价、折扣、缓存和 Batch 条件会变化，不在本文写固定价格。账本至少按 `request_id`、任务、租户、模型、工具和版本记录实际 usage：

```python
from dataclasses import dataclass, field


@dataclass
class UsageLedger:
    input_tokens: int = 0
    output_tokens: int = 0
    calls: int = 0
    by_model: dict[str, dict[str, int]] = field(default_factory=dict)

    def record(self, model: str, *, input_tokens: int, output_tokens: int) -> None:
        self.input_tokens += input_tokens
        self.output_tokens += output_tokens
        self.calls += 1
        bucket = self.by_model.setdefault(model, {"input": 0, "output": 0, "calls": 0})
        bucket["input"] += input_tokens
        bucket["output"] += output_tokens
        bucket["calls"] += 1


def cost_from_versioned_prices(ledger: UsageLedger, prices: dict[str, dict]) -> float:
    # 价格必须和模型 ID、Provider、币种及生效日期绑定，不能使用隐含默认值。
    total = 0.0
    for model, usage in ledger.by_model.items():
        price = prices[model]
        total += usage["input"] / 1_000_000 * price["input_per_m"]
        total += usage["output"] / 1_000_000 * price["output_per_m"]
    return total
```

## 2. 延迟拆解

```text
端到端延迟
 = 网络/排队
 + TTFT（首 token）
 + 生成时间（输出 token × TPOT）
 + 工具/检索/数据库等待
 + 重试、审批和人工等待
```

先区分：

- TTFT 高：Context 太长、Provider 排队或首轮调用慢；
- TPOT 高：输出太长、模型/并发不合适；
- 工具等待高：外部依赖、串行调用或超时策略问题；
- 任务完成慢：长任务应异步化，不要只优化一次 HTTP 连接。

优化要和用户目标绑定：streaming 改善首字节体验，不能证明任务已经成功；并行只适用于无冲突操作；缩短 Context 同时影响质量，需要 Eval 验证。

## 3. 缓存分层

| 缓存 | 缓存什么 | 关键失效条件 |
|---|---|---|
| Prompt Cache | 稳定前缀的 Provider 计算 | Prompt/工具/模型版本、保留时间 |
| Semantic Cache | 相似请求的只读结果 | 租户、权限、知识版本、意图误命中 |
| Result Cache | 幂等工具/检索结果 | 参数、资源版本、权限和 TTL |

带副作用的 Agent 轨迹不能直接把最终文字缓存成事实；最多缓存只读证据或已验证的查询结果。缓存键至少考虑 `tenant`、`actor scope`、Prompt/工具/模型/知识版本和数据分类。

命中率、误命中率、节省 token、过期结果和权限串用都要观测。缓存不能绕过最新授权。

## 4. Model Routing 与 fallback

先定义任务复杂度、质量下限和数据边界，再路由：

```text
简单提取/分类 → 快速模型
常规生成/代码 → 平衡模型
复杂推理/长任务 → 强模型
```

路由器本身会增加一次调用和失败点；先用规则/元数据做基线，再用小模型分类，并通过分片 Eval 证明节省没有造成安全或质量退化。Fallback 不仅检查过载，还要检查数据区域、工具调用能力、Prompt/Context 兼容性和预算。

## 5. 并发、队列和背压

- 无依赖的只读模型/工具调用可以并行；写操作按资源冲突串行或加锁；
- 每个租户、模型、工具和 Worker 都要有并发上限；
- 入口限流不够，因为一次请求可能 fan-out 多次调用；
- 队列过长时要拒绝、降级、延后或转人工，不能无限堆积；
- 长任务返回 `task_id`，由 Queue/Lease/Worker 执行，见 [Durable Execution](./06_Durable%20Execution与分布式可靠性.md)。

## 6. Agent 预算和 stuck loop

每个任务至少同时限制步数、Token、费用、墙钟时间、工具并发和重复意图：

```python
from dataclasses import dataclass


@dataclass
class LoopBudget:
    max_steps: int = 20
    max_tokens: int = 100_000
    max_cost_usd: float = 2.0
    steps: int = 0
    tokens: int = 0
    cost_usd: float = 0.0

    def record(self, *, tokens: int, cost_usd: float) -> None:
        self.steps += 1
        self.tokens += tokens
        self.cost_usd += cost_usd

    def stop_reason(self) -> str | None:
        if self.steps >= self.max_steps:
            return "step_budget_exhausted"
        if self.tokens >= self.max_tokens:
            return "token_budget_exhausted"
        if self.cost_usd >= self.max_cost_usd:
            return "cost_budget_exhausted"
        return None
```

预算值由任务类型和部署配置注入；Trace 记录每次扣除和最终停止原因。stuck detection 应比较工具名、规范化参数、State 版本和最近结果，而不是只比较自然语言。

## 7. Batch 与离线任务

不要求即时响应的 Eval、批量抽取、翻译和报告可以使用 Provider 的 Batch 能力或自建队列。采用前先比较：实时/批量单价、等待时间、失败重试、结果持久化、取消和隐私边界。不要把某个 Provider 的固定折扣或请求上限写成长期规则。

## 8. 优化顺序

1. 先建立按任务/模型/工具的 usage、延迟和成功率账本；
2. 删除无关 Context，修复重复工具和无效重试；
3. 对只读结果做权限感知缓存；
4. 用固定 Eval 比较模型路由和并发；
5. 为长任务引入队列、取消和预算；
6. 最后再做 Batch、Prompt Cache 或更复杂的推理优化。

## 9. 练习与验收

为一个知识型 Agent 建立成本/性能报告：

- 记录 20 个任务的 token、模型、工具等待、TTFT、E2E、费用和成功率；
- 找出最贵的一个组件和最慢的一条路径；
- 比较一次 Context 压缩、缓存或模型路由前后的质量/成本；
- 让预算耗尽、stuck loop、Provider 过载和队列过长都进入明确降级；
- 在 Trace 中能解释每个优化节省了什么，又增加了什么风险。
