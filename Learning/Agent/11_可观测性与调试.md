# 可观测性与调试

这篇文章解决一个问题：**Agent 失败时，如何定位到底是模型、Context、工具、权限、外部依赖还是运行时造成的**。

> **学习位置**：在 [Agent Eval 实验方法](./09_Agent%20Eval实验方法.md)、[Eval 与测试体系](./10_Eval与测试体系.md) 后阅读。
>
> **职责边界**：本文负责 Trace、事件、日志、Replay 和故障定位。质量/发布门槛由 `09/10` 负责，SLO/告警/事故 runbook 由 [Agent 运维与事故响应](./Agent运维与事故响应.md) 负责，成本账本由 [成本与性能工程](./成本与性能工程.md) 负责。

## 1. Agent 可观测性多了什么

传统服务看可用性、延迟和错误率；Agent 还要回答：

- 模型看到了哪些 Context 和工具？
- 为什么选择这个工具和参数？
- 哪些工具成功、失败、重试或被拒绝？
- 是否发生越权、泄露、重复副作用或空转？
- 任务最终成功的证据是什么，成本和等待时间是多少？

最终答案正确不代表轨迹安全；最终答案失败也不一定是模型失败。

## 2. Trace 合同

一次任务一个 `trace_id`，每次模型、工具、检索、审批、状态迁移和验证都是 Span/Event。公共字段保持稳定，原始 Provider payload 只作为受控调试附件。

```python
from dataclasses import dataclass, field
from time import time
from typing import Any
import uuid


@dataclass
class Event:
    trace_id: str
    event_id: str = field(default_factory=lambda: str(uuid.uuid4()))
    kind: str = ""
    task_id: str | None = None
    parent_id: str | None = None
    started_at: float = field(default_factory=time)
    ended_at: float | None = None
    status: str = "running"
    attributes: dict[str, Any] = field(default_factory=dict)


def finish(event: Event, *, status: str, safe_attributes: dict[str, Any]) -> None:
    event.status = status
    event.ended_at = time()
    # 只写脱敏后的摘要；Secret、完整 Prompt 和私有源码不要默认进入 Trace。
    event.attributes.update(safe_attributes)
```

LLM Event 至少记录模型/Provider、Prompt/工具/策略版本、输入输出 token、结束原因和请求 ID；Tool Event 记录工具、参数摘要、授权决策、审批、耗时、错误码和副作用状态；Context Event 记录来源 ID、预算和压缩原因。

## 3. 事件类型和指标

建议使用稳定的事件集合：

```text
task_started / task_succeeded / task_failed / task_cancelled
model_requested / model_completed
tool_requested / tool_completed / tool_denied
approval_required / approval_granted / approval_rejected
context_compacted / checkpoint_saved / task_resumed
validation_started / validation_failed / validation_passed
```

从事件计算：任务成功率、每步延迟、TTFT、工具错误率、重试次数、拒权率、stuck loop、人工接管、恢复成功率、Token/费用和外部等待时间。指标按任务类型、模型、工具、租户和版本分片。

成本详细计算见 [成本与性能工程](./成本与性能工程.md)，安全门槛见 [安全与可控性](./08_安全与可控性.md)。

## 4. 日志与隐私

结构化日志至少关联 `trace_id`、`task_id`、`tenant_id`、`agent_version`、`model_version` 和 `policy_version`。默认记录摘要、hash、长度和错误码，不记录完整消息。

写日志前执行：

1. Secret/PII 脱敏；
2. 租户和数据分类检查；
3. Payload 大小限制；
4. 采样和保留期判断；
5. 访问审计。

用户可见的进度事件与服务端调试 Trace 分离；产品层只推送安全摘要，见 [Agent 产品与人机协同](./Agent产品与人机协同.md)。

## 5. 失败分类

| 层 | 常见信号 | 优先检查 |
|---|---|---|
| Provider | 超时、限流、空响应、格式错误 | 模型版本、请求大小、适配器和重试 |
| Context | 丢约束、信息过时、注入、超限 | 来源、预算、压缩和边界标记 |
| Tool | 参数错、超时、未知结果、重复副作用 | schema、权限、幂等、外部状态 |
| RAG | 零召回、错误排序、权限泄露 | 解析、过滤、索引版本、引用 |
| Runtime | 卡死、重复投递、恢复失败 | State、Lease、Checkpoint、取消 |
| Product | 用户目标误解、审批不清、无法接管 | 任务合同、澄清、状态和 UX |

“模型幻觉”不是最终根因，必须落到一个可修复的层和 Case。

## 6. 调试流程和 Replay

```text
1. 用 task_id/trace_id 找到完整链路
2. 先看停止原因、State 迁移和预算
3. 检查 Context 版本、来源和压缩记录
4. 检查模型请求/响应和工具选择
5. 核对授权、外部副作用和验证结果
6. 在隔离环境 Replay，固定模型/工具/数据
7. 修改一个变量，比较 Trace 和 Eval
8. 把修复后的失败样例加入回归集
```

Replay 必须冻结输入、Context、Provider 响应、工具和环境；实时外部依赖要替换为 Fixture。Replay 不是“把原 Prompt 再发一次”，否则结果不可比较。

## 7. 与第三方 Tracing 的边界

LangSmith、Langfuse、OpenTelemetry 或自建事件系统都可以承载 Trace。选型时先确认：

- 能否关联模型、工具、状态和人工事件；
- 能否脱敏、采样、设置保留期和租户隔离；
- 能否导出为 Eval/Replay Case；
- 是否记录真实 Provider/工具版本，而不只是框架节点名。

框架自动追踪不能替代应用级成功证据、权限决策和副作用断言。

## 8. 告警和事故衔接

本文不维护告警阈值，但 Trace 必须提供事故响应所需字段：任务/租户范围、版本矩阵、风险事件、未完成副作用、Checkpoint、Kill Switch 影响和恢复结果。具体告警、降级、回滚和复盘见 [Agent 运维与事故响应](./Agent运维与事故响应.md)。

## 9. 练习与验收

为一个 Tool Agent 实现最小 Trace：

1. 记录一次模型决策、一次工具成功、一次工具拒绝和一次验证失败；
2. Trace 能按 `trace_id` 还原事件顺序和停止原因；
3. 日志不含 Secret、完整私有输入或无权租户数据；
4. 能在隔离环境 Replay 一次失败；
5. 从 Trace 导出一个 Eval Case，并说明修复后哪项指标改善。
