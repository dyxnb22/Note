# 09.3 架构取舍与组合设计

## 先判断任务需要什么结果

固定标签任务可以比较规则、分类器和受限生成。标签清楚、数据充足时，分类器通常更容易优化；判断标准常变，或答案需要结合外部证据解释时，再评估生成模型的效果和输出约束。

重复问题可以用缓存、固定模板或直接工具调用。复用缓存时，权限、参数和实时状态须满足原结果的适用条件。

## 按时效选择信息源

当前交易结果优先查业务 API，频繁变化的内容使用可更新索引，相对稳定的制度进入长期知识库。缓存记录原来源、适用范围、数据版本与时间，便于判断何时可以复用。

| 信息需求 | 优先连接的事实来源 |
|---|---|
| 当前订单状态 | 业务 API |
| 频繁变化的信息 | 可更新搜索入口 |
| 某个版本的制度条文 | 可追溯知识文档 |

路由可以由分类器或模型提出，运行时校验访问范围，取得结果后再检查事实与版本。

## 结构化数据与 Text-to-SQL

“本月取消了多少采购订单”需要聚合计算，“哪些情形允许取消”需要制度依据，“现在取消这一单”需要执行写操作。一句话可能包含这三类需求，分别由受控查询、文档检索和业务命令处理。

结构化查询先说清指标怎么算：订单数量按订单还是明细计数，退款是否影响收入，统计哪些状态，月份边界按哪个时区计算。确定时间范围和去重单位后，再核对结果。稳定的高频问题，可以使用审核过的指标层或参数化模板。

一个受控聚合可以采用固定 SQL 结构，把租户和时间作为参数：

```sql
SELECT COUNT(*) FROM purchase_orders
WHERE tenant = ? AND status = 'cancelled'
  AND cancelled_on >= ? AND cancelled_on < ?;
```

这里以规范化日期字段为例，时间范围左闭右开。使用时间戳时，还要明确时区和边界换算。查询中的租户等访问范围，从可信认证结果取得。

固定 SQL 限定了指标、表和条件，模型只需提出查询请求。执行器检查指标是否开放、范围是否允许；租户取自认证结果，不能由模型指定。按日期文本比较时，库中字段须使用同一规范格式。

语句以 SELECT 开头，或带有 LIMIT，都不足以证明安全：只读查询仍可能暴露数据、调用不适当函数或消耗大量资源。

若确实开放 Text-to-SQL，生成语句仍是候选。执行服务需要解析 SQL 结构，限制语句、表、列、函数与可调用能力，结合数据库角色、行列权限、只读设置、超时和资源限制执行。

以 PostgreSQL 为例，行级安全由数据库策略执行，但超级用户、带 BYPASSRLS 的角色，以及通常情况下的表所有者会绕过它。要用受限的数据库账号执行实际查询，检查行级安全是否生效；只看到配置里写了 RLS 还不够。statement_timeout 等限制也由执行层控制。[行级安全](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)、[语句执行时限](https://www.postgresql.org/docs/current/runtime-config-client.html)

查询结果进入模型前，限制行数和字段，处理敏感信息。最终回答注明指标口径、数据时间和来源，不能把当前可见范围说成全企业总量。若专用查询工具已能覆盖需求，就不必开放任意 SQL。

## 固定检索与 Agentic RAG 的取舍

简单问答可能一次召回就够。需要拆解问题、发现缺口再补查时，可以让 Agent 根据已有结果调整查询或数据源，这是 Agentic RAG 的一种实现。每增加一轮，都应补一个具体缺口。

数据源、权限或排序目标差异明显时，可以使用多个专用检索器；检索器本身不必各自成为 Agent。

例如，要说明“华东与华南的差旅政策差异”，一次检索只取得华东制度。下一步应补齐华南的适用版本，再比较住宿标准、交通规则和例外条件。若两地制度涉及不同日期，还要先对齐比较时点；继续重复搜索“差旅政策”未必能补齐这些条件。

| 当前观察 | 合理的后续动作 | 保持不变的约束 |
|---|---|---|
| 缺少另一地区材料 | 在允许数据源中检索该地区制度 | 当前用户权限与比较范围 |
| 同名制度版本不明 | 查询版本元数据或适用日期 | 原始来源可追溯 |
| 文档无法回答实时状态 | 调用已授权的业务查询工具 | 查询能力与任务预算 |
| 已覆盖全部关键维度 | 组织对比并检查引用 | 不把材料未提及解释成禁止 |
| 达到预算仍存在缺口 | 交付已确认部分并说明不足 | 不降低证据与授权要求 |

运行时保存已覆盖主题、证据和未确认条件，据此更新进度。每次改写查询、扩大范围或切换工具，都注明要补哪个缺口，方便检查这次查询是否有效。

达到完成标准时结束，持续无进展或预算耗尽时停止。重复片段和不适用的条款不算进展，此时应改查法、澄清或结束。比较动态检索与固定 RAG 时，用同一任务集，计入额外延迟和故障路径。[固定 RAG 与 Agentic RAG](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-solution-design-and-evaluation-guide)

## 长报告的证据与产物链

长报告可以按“确认范围 → 收集证据 → 整理事实 → 分章写作和审校”推进，各阶段保存产物与来源。写作时按需回查原文，摘要也留下引用和未解决的冲突。

独立章节可并行，术语、结论与交叉引用仍需统一检查。失败时保留可复用证据包，重新执行失败阶段，不必每次从最初搜索开始。

## 带界面的媒体处理系统

视频剪辑场景中，Agent 将用户需求转换为编辑计划，媒体工具执行受限命令，任务服务管理进度与产物。界面展示时间线、预览和状态，不直接让模型拼接任意 Shell 命令。

输出视频后，检查时长、轨道、编码和保存位置等业务要求。关闭界面、取消任务和清理临时产物分别处理；原文件与最终结果分别记录版本，恢复时先核对，避免覆盖用户的新修改。
