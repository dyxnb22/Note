# 09.3 系统设计场景与取舍

> 本页保留需要跨专题组合判断的设计场景；单项机制回到相应主专题。

## 模型与架构取舍

### 1. 固定标签、数据充足的任务，为什么常常应先用分类器而不是生成式推理？

答：分类器输出空间受约束、目标函数直接对应 Accuracy/F1、推理快、容易校准和监控；固定标签、样本覆盖充分且不依赖外部知识时通常更稳定。生成式推理只有在标签边界依赖动态规则、长尾语义、外部证据或需要统一承载多种标准时才有优势，并应限制输出标签、证据和置信度。

### 2. 多业务标准不统一时，单模型如何避免任务冲突和旧任务退化？

答：把任务 ID、标签定义、规则、输出 Schema 和边界样例显式作为条件，区分共享表示与任务私有头/Adapter/能力；按任务分桶训练、评测和路由，监控新任务加入后的旧任务回归。若梯度、标签或数据分布长期冲突，应拆专家或模型，并用分任务结果而非一个总分判断退化。

### 3. 高频核心路径为什么适合缓存、固定模板或直接调工具？

答：高频问题的意图、参数和结果验收稳定时，固定模板、分类路由或直接工具调用能减少模型轮次、Token、延迟和随机性；模型只处理真正需要澄清或组合推理的长尾。缓存必须绑定参数、权限、数据版本和新鲜度，固定路径仍要做结果校验和异常回退。

## 知识与系统设计

### 4. 知识更新很快时，Agent 如何选择实时 API、搜索索引、缓存或长期知识库？

答：按事实的时效要求、权威性、查询成本和权限路由：当前状态/交易结果优先实时 API，频繁变化的公开内容用带版本和时间的搜索索引，短时间重复读用有 TTL 的缓存，稳定制度和历史知识进长期库。缓存键包含租户、权限 Scope、数据版本和时间条件；更新事件负责失效或版本切换。新鲜度无法确认时实时查询或明确标注待核实，高风险动作不能只依赖过期缓存。

### 5. 设计一个需要输出长报告的 Agent，如何处理权限、目标读者、证据覆盖、审校和成本？

答：先澄清数据范围、读者、格式、截止时间和证据标准，按权限过滤来源；检索阶段覆盖主题和关键子问题，分析阶段保存带引用的中间事实，写作阶段只读取已验证证据，最后由引用/事实/格式审校器检查。长任务采用分段并行、阶段摘要和预算控制；失败时保留证据包和部分结果，避免全量重跑。

### 6. 如何判断应该采用单次 RAG、Agentic RAG 还是多个专用检索器？

答：单次 RAG 适合问题边界清楚、一次召回即可覆盖的事实问答；Agentic RAG 适合需要拆解、补检索、跨文档或根据工具结果调整路线的任务；多个专用检索器适合数据源、权限、排序目标明显不同且可独立评测的场景。先做混合检索/重排基线，只有多步检索对长尾、多跳或覆盖率有稳定收益时才增加延迟和错误传播风险。

## 综合场景

### 7. 如何设计一个带 TUI 的交互式视频剪辑工具？

答：系统由 TUI、任务 State、媒体分析/编辑服务、任务队列和文件存储组成。Agent 把用户要求转成受限编辑计划，FFmpeg 和文件操作由执行器校验后在隔离工作区运行。剪辑任务异步执行，界面通过事件展示进度和取消状态；交付前验证输出文件，并保留输入与结果版本供恢复。
