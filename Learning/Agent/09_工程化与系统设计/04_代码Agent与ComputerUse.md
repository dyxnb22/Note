# 09.4 代码 Agent 与 Computer Use

## 读取代码并确定修改范围

代码 Agent 通常先搜索和读代码，再修改文件并运行检查。查找时可以按问题选择工具：

- 文本搜索：查找具体名称或文本。
- 符号查询与 LSP（语言服务协议）：查找定义和引用。
- AST（抽象语法树）：分析语法结构。

代码库地图用于定位模块，实际行为再看源码和运行结果。

动手前看清目标、接口约束和已有改动。应用模型生成的 patch 时，核对路径和基线，避免覆盖用户同时进行的修改。

## 让修改与基线绑定

生成修改提案时，保存原文件的哈希值。应用补丁前重新计算并比较：文件已经变化，就重新合并或拒绝旧提案；没有变化，再写入补丁并检查结果。

## 验证需要对应实际产物

检查围绕实际改动选择：语法、格式、类型，以及相关测试或运行行为。保存真实退出码和产物，写明已经验证的行为。

检查命令同样经过执行层的权限校验。提交、发布与本地编辑分别记录授权和结果，验证通过后也按相应授权决定能否提交或发布。

## 用业务场景检查修改行为

假设目标是“只有 pending 订单允许取消”。将函数改成始终返回 True，可以通过语法检查，却不符合已发货订单不可取消的业务要求。

核对哈希后、写入补丁前，源码仍可能被其他人修改。最终交付的代码必须与检查时读取的代码一致，不能沿用旧版本的验证结果。

锁、版本化提交或补丁冲突检测，可以用来处理这个并发窗口。最后再由独立进程读取并检查实际产物，确认最终交付的代码满足要求。

## API、DOM 和视觉操作

Computer Use 观察界面、执行动作，再看预期变化是否出现。稳定 API 适合精确数据操作，DOM（文档对象模型）用于定位页面元素，图像或缺少结构的界面依靠视觉观察。几种方式可以配合；坐标点击后尤其要重新看页面。

点击前的截图可能已经过时。每个动作后应观察预期状态是否出现，避免反复点击导致重复提交。页面响应超时也不能证明按钮没有生效。

## 浏览器状态与副作用

登录状态、Cookie、下载、剪贴板和窗口，可能在一次动作结束后继续保留。执行任务时，要决定哪些可以复用、哪些需要隔离或清理。浏览器和页面提供的内容也可能包含注入指令，这些内容不能授予新的执行权限。

表单预览、提交和外部确认分别记录。提交后，用订单号或任务状态查询实际结果，界面动画和提示只用来反馈进度。

## 成本与终止条件

视觉观察、页面等待和重复探索都会增加延迟。记录观察次数、动作次数、等待和失败原因，比较直接接口与 GUI 路径的成本。

无法稳定定位、目标状态不清或出现冲突时，保留现场并停止，或请求补充信息。结束前确认用户要求是否已经完成，例如文件是否已保存、指定订单的状态是否已变更。
