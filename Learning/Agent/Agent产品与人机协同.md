# Agent 产品与人机协同

本文负责任务定义、用户澄清、进度、审批、失败接管和产品指标；模型、工具授权和 Eval 实现分别见 [Agent 架构](./03_Agent架构与设计.md)、[安全与可控性](./08_安全与可控性.md) 和 [Eval](./10_Eval与测试体系.md)。

## 1. 先判断任务与边界

输入开放、规则难穷举、结果允许概率性且可验证/可反馈的任务适合 AI。规则明确、错误代价极高或必须严格确定时，优先普通程序或固定 Workflow；AI 可以只负责提取、排序、草稿或解释，不直接获得最终执行权。

任务规格至少写清：用户、触发场景、输入、目标、允许改变的资源、禁止副作用、成功证据、失败代价、询问条件和停止条件。

```json
{
  "goal": "修复仓库中的缺失 import",
  "scope": ["src/", "tests/"],
  "allowed_side_effects": ["修改源码", "运行测试"],
  "forbidden_side_effects": ["删除文件", "联网发布"],
  "success_evidence": ["相关测试通过", "git diff 可审查"]
}
```

“帮我处理一下”不是可验收的任务规格；“像人”“更智能”也不是指标。

## 2. 自主性与澄清

| 模式 | Agent 能做什么 | 适合 |
|---|---|---|
| 建议 | 只读、分析、草稿 | 高风险或早期产品 |
| 确认后执行 | 准备动作，用户批准后执行 | 改代码、发消息 |
| 范围内自动 | 在 workspace、预算和工具范围内执行 | 测试、重构、批量读取 |
| 后台自治 | 定时/异步完成低风险任务 | 可回滚流程 |

自主性要和影响范围、可撤销性、用户预期匹配；高自主性不是目标，可靠完成才是。

只有在“不澄清会改变目标、产生不可逆副作用，或存在多个同样合理方案”时提问，并给出最小选择：

```text
我发现两个范围：A 只改 src/payment.py；B 同时更新测试和文档。
这会影响 3 个文件，你选哪一种？
```

审批要绑定具体动作摘要。至少展示目标资源、参数、副作用、证据、影响范围和允许范围（一次/本任务/拒绝）；参数或目标变化后原审批失效。

## 3. 进度、失败与接管

长任务对用户展示稳定状态事件，而不是模型内部思维：

```text
task_started → context_loaded → tool_requested → tool_completed
             → approval_required / validation_failed
             → waiting_user → task_succeeded / task_failed
```

进度至少包含目标/范围、已完成、等待项、下一步、时间/预算，以及暂停、取消和接管方式。答案 token 通道与步骤事件分开；密钥、完整私有检索内容和调试噪声只进受控 Trace。

失败消息说明：发生了什么、已完成什么、未完成什么、是否产生副作用、用户能选择什么。接管可以是修改参数后继续、补充文件/权限、人工完成当前步骤、回滚或导出证据。

## 4. 反馈、指标与发布

把反馈归因到可修复的层：

| 反馈 | 优先排查 |
|---|---|
| 目标理解错 | 澄清、任务模型、Router |
| 找错资料 | Context、检索、权限 |
| 调错工具 | Schema、工具集合、模型 |
| 结果不正确 | 实现、验证器、推理 |
| 太慢/太贵 | Context、路由、并发、缓存 |
| 不敢使用 | 透明度、审批、可撤销性、隐私 |

反馈关联 `task_id`、Agent/Model 版本、工具 Trace 和最终结果，再脱敏进入 Eval。至少观察任务完成率、首次成功率、人工接管/恢复率、澄清接受率、审批拒绝/撤销率、P95 完成时间、每任务成本、越权率和重复使用率，并按任务类型分片。

上线前确认：任务边界明确、成功可验证、副作用可预览/撤销、可暂停/取消/接管、失败状态可解释、有审计与质量回归集，且能快速关闭高风险能力。

## 5. 练习与验收

为一个代码修改 Agent 设计“建议、确认后执行、范围内自动”三种模式，分别写出：

1. 工具、资源范围和副作用；
2. 用户看到的事件和审批字段；
3. 失败、取消、恢复和回滚状态；
4. 任务质量、体验和安全指标。

安全边界和审批实现见 [安全与可控性](./08_安全与可控性.md)。
