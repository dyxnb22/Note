# 12.2 实践路线与项目表达

把实验验证、工程取舍和个人贡献连成一条证据链。阅读本页时选一个真实案例，如实区分源码分析、可运行原型、可重复测试、压测和生产数据。

## 面试表达与自测

本页收录口头表达结构、系统设计答题顺序和项目复盘方法；模块阅读顺序与岗位优先级见 [[Learning/Agent/README|Agent 总目录]]。专题问答用于练习取舍，不必逐题背诵。

**60 秒回答结构：**问题与边界 → 主流程 → 一个失败或风险 → 验收证据。

**系统设计题可按以下顺序展开：**

1. 明确用户、成功标准、数据范围、时延/成本和失败代价。
2. 先判断普通程序或固定 Workflow 是否足够，再说明哪些环节需要模型决策。
3. 讲清入口、Context、Provider、工具、State 和验收组成的主链路。
4. 覆盖参数错误、超时、未知结果、部分成功、取消与恢复。
5. 交代身份、最小权限、不可信输入、审批和审计边界。
6. 说明评测集、成功证据、线上指标、灰度、回滚和降级。
7. 用质量、延迟、成本、复杂度和维护责任比较方案。

**每读完一个专题，检查自己能否：**解释核心概念及边界；描述输入、状态、输出和关键转移；说明设计取舍；讲清异常、权限、成本、观测与恢复；指出支撑结论的测试或真实证据。

## 实践路线与项目追问


### 1. 一个 Agent 项目应该如何从一次调用逐步演进到服务化、图编排、Memory、RAG 和 MCP？

答：先验证 Provider/Adapter 和消息输入输出，再加入 Tool Schema/执行器和有限 Loop；需要外部接口时做服务化，再用显式 State/Node/Edge 表达分支，确有跨轮需求才加 Memory/Checkpoint；知识问题进入 RAG，跨宿主工具复用时再引入 MCP。每一步都应说明新增能力、约束、验证和成本。

### 2. 为什么实践项目中的 Mock Provider、内存 Checkpointer 和关键词检索不能直接当生产方案？

答：它们是为了隔离变量和观察机制，缺少真实 Provider 波动、持久化、并发、权限、数据规模和更新语义。面试时应说明它们验证了什么、未验证什么，以及生产升级需要补的适配、存储、Eval 和安全边界。

关联：[[Learning/Agent/08_评测与可观测/评测实验与发布门禁#7. Mock Provider 的价值和边界是什么？|题7]]

### 3. DevPilot 这类 Coding Agent MVP 为什么先生成建议级 diff？

答：建议级 diff 能先验证 Router、Analyzer、Fixer、Approval、Reviewer、PR Creator 的状态和责任边界，避免模型未经授权直接改文件。后续再加入真实 patch、`apply --check`、测试、回滚和 PR，能把风险逐步引入并评测。

### 4. 如何把一个练习项目讲成“自己解决了什么工程问题”？

答：按“业务目标与约束 → 用户、输入输出和成功标准 → Loop/State/Tool/RAG 如何组成关键链路 → 个人负责范围 → 最难的工程问题及取舍 → 一个失败与修复 → 指标、测试和失败证据 → 后续边界”表达。不要只报 RAG、Agent、MCP 等组件名或 API；要说明为什么采用这些组件、如何控制权限和风险，以及结果如何验证。

## 证据与项目复盘

### 5. 面试官问“你的 Agent 线上效果怎么样”，在没有完整线上数据时如何准确回答？

答：如实区分已观测、离线测量和估算：说明任务集规模、成功定义、关键指标、样本/环境、限制和未观测项；没有数据就说没有记录，不编造线上百分比。可以进一步说明如何建立 Baseline、Replay、灰度和 SLO。

### 6. 如何把一次失败的实践实验转化成项目亮点，而不是只说“代码跑通了”？

答：描述失败现象和影响，定位到具体层（如工具结果未配对、State 被覆盖、检索召回为空或重复副作用），说明改动、验证和新增回归 Case。失败能体现边界意识和工程闭环，但要明确实验代码与生产级实现的差距。
