# 06.1 RAG 与知识库

本页负责在线证据链：召回、融合、重排、Context、引用和检索评测。解析/OCR、文档版本、更新删除与图索引的深入设计见 [知识摄取与 GraphRAG](./知识摄取与GraphRAG.md)。

## 基础认知：知识如何进入系统

### 1. RAG 的完整流程是什么？

答：离线侧解析、清洗、切分、生成索引；在线侧理解查询、按权限召回候选、重排、组装 Context，模型基于证据生成并返回引用。真正的 RAG 还要处理文档更新、删除、权限、评测和失败，而不是只接一个向量库。

### 2. 固定长度切分、按段落切分、语义切分和父子块有什么区别？

答：固定长度简单但**可能切断语义**，段落切分保留结构**但长度不稳定**，语义切分按主题边界更自然但成本和稳定性更高；父子块用小块召回、较大的父块提供上下文。选择取决于文档结构、召回粒度和上下文预算，应通过检索评测验证。

**面经变体：Markdown 没有标题时**，优先沿段落、列表和代码块等结构边界切分；结构不足时再按 Token 长度切分，并保留文档、页码或段落等元数据。简短查询可能缺少语义线索，可在评测证明有收益时结合上下文改写或多路召回；长 chunk 保留上下文较完整，但可能稀释主题并增加噪声。按文档类型和问题集验证，不凭单一长度经验定参数。

来源：[美团 AI Agent 开发一面](https://www.nowcoder.com/discuss/927332803098808320)。

### 3. Chunk Size 和 Overlap 如何确定？

答：以一个问题所需的最小完整语义单元为起点，**观察召回是否缺上下文、重复率和 Token 成本**；**Overlap 只补跨边界信息，过大会制造重复**。不同文档类型可用不同策略，并用 Recall、MRR、答案正确率和延迟联合调参。

### 4. OCR 准确率和端到端问答准确率如何评估？

答：OCR 层看**字符/词错误率、表格单元格准确率、布局和关键字段召回**；**端到端看检索命中、引用正确、答案正确和拒答质量**。两层要分开定位，否则答案错时不知道是识别、检索还是生成的问题。

关联：[[Learning/Agent/06_RAG与知识库/知识摄取与GraphRAG#9. OCR 质量应该如何评估？为什么不能只给一个总体准确率？|知识摄取与 GraphRAG题9]]

### 5. 如何让 RAG 支持结构化数据库和非结构化文档？

答：结构化问题优先**生成受限 SQL/API 并由权限和结果校验控制**，非结构化问题**走文档检索**；需要联合时**由 Workflow 规划数据源，再用统一证据 Schema 合并**。不要把业务数据库全量转成文本来规避权限和一致性问题。

## 原理机制：如何召回和排序

### 6. BM25、向量检索和混合检索各自适合什么场景？

答：BM25 擅长**专有名词、编号、精确词面和稀有关键词**，向量检索擅长**语义相近、表达不同的查询**；混合检索适合企业知识中两类需求并存的场景。权重和召回数不能凭经验固定，要按题型分桶评测。

### 7. 多阶段 RAG 中 BM25 和向量结果如何合并？

答：各路召回保留文档/Chunk ID、路内名次与原始分数；清理同一路的重复项后，按稳定 ID 聚合多路贡献，再用 RRF、分数归一化或学习排序融合，交给 Reranker。不能先丢掉重复文档的一路记录，导致 RRF 失去“被多路召回”的信号。

Recall TopK、融合候选数、Rerank 输入量和最终 Context TopK 是不同截断点。每阶段保留来源与权限信息，按题型比较召回、排序、答案、延迟和 Token。

**面经追问：RRF 的 `k` 怎么选？**标准形式可写作 `score(d) = Σ 1 / (k + rank(d))`（具体名次从 0 还是 1 开始要保持实现一致）。`k` 是名次平滑常数，不是候选数量；增大它会缩小相邻名次的贡献差异。固定候选集和评测集，对多个 `k` 比较排序指标、下游答案质量、延迟和权限过滤结果，没有跨数据集通用的最佳值。

来源：[美团 AI Agent 开发一面](https://www.nowcoder.com/discuss/927332803098808320)。

### 8. 混合检索的比例如何确定？实际收益如何验证？

答：按数据集中的**精确词面题、语义题、长查询和实体题分桶**，网格或离线实验比较 Recall、MRR/NDCG、答案正确率、延迟和成本。比例不是越平均越好，线上还要观察文档类型变化和查询分布漂移。

### 9. Rerank 为什么有效？放在什么位置？

答：初检索追求高召回，候选排序可能只使用词面或向量相似度；**Reranker 用查询和候选的联合语义关系重新排序，适合放在混合召回之后、Context 组装之前**。候选太多会增加延迟和成本，需要限制 TopK 并做缓存/分级。

**追问：BM25 召回了关键词正确但语义不相关的文档，向量检索和 Rerank 如何配合修复？**

保留 BM25 的精确词优势，增加向量候选扩大语义覆盖，合并去重后由 Reranker 用 query–document 联合关系排序，再按题型调权和 K。用相关性标注比较候选覆盖、排序和最终答案，不能只看单个查询。

### 10. Rerank TopK 截断怎么做？为什么？还有哪些替代方案？

答：在标注集上测 Recall 随 K 的变化，并联合答案/引用质量、延迟和 Token 预算选 K；不同查询类型可动态设置。截断时保留高相关且互补的证据，结合相似度阈值、MMR 去重和单文档上限。多跳问题按子问题分别召回后合并去重；也可按问题类型路由、分层检索或让模型从候选中选取，但要用评测验证收益。

### 11. 如何避免召回重复内容？

答：在索引和在线阶段都**保留文档/段落 ID，先精确去重，再按相似度或 MMR 去掉高度重叠块，并限制同一来源数量**。摘要只能减少展示重复，不能掩盖底层切分和索引重复问题。

### 12. 如何处理查询改写、Multi-Query 和 HyDE？

答：查询改写**扩展实体、约束和缺省上下文**，Multi-Query 用**多个视角提高召回**，HyDE 用假设答案的语义表示帮助召回；它们会增加调用和噪声。Reranker 是召回后的精排步骤，位置和收益见题9；组合前按切片验证收益是否抵得上延迟与成本，不默认叠加。只在原查询 Recall 明显不足的题型启用，并保留原查询、改写和证据链用于评估。

关联：[[Learning/Agent/02_Prompt与上下文/Prompt与Context Engineering#19. 什么是查询改写？什么时候需要做查询改写？|Prompt 与 Context Engineering题19]]与[[Learning/Agent/02_Prompt与上下文/Prompt与Context Engineering#20. 多维度查询改写如何做？|题20]]

### 13. 如何区分检索失败、阅读失败、推理失败和表达失败？

答：检查金标准证据**是否进入候选和最终 Context**，若没有是检索/权限问题；有证据但模型未使用是 Context/阅读问题；证据足够仍推断错误是推理问题；内容正确但格式/引用不对是表达/校验问题。**Trace 要记录每层输入输出，不能统称“RAG 不准”**。

**追问：检索结果正确但最终回答仍然幻觉，如何区分上下文组织、模型推理和输出校验问题？**

先确认正确证据是否真的进入模型 Context，以及是否被摘要或截断破坏；证据完整但结论错属于模型推理/Prompt，结论正确但格式或引用错属于输出校验。用固定证据回放和分层评测分别验证，不要重新调整整个 RAG。

## 工程设计：如何更新、隔离和评测

### 14. 文档更新、删除和权限变更如何同步到索引？

答：完整同步机制见 [[Learning/Agent/06_RAG与知识库/知识摄取与GraphRAG|知识摄取与 GraphRAG]]：检测变化，建立文档版本，更新派生索引并验证可见版本。普通内容更新期间，只有业务允许旧版本且权限仍有效时，才可带时间/版本标记返回旧内容。

删除和撤权要立即在查询授权边界拒绝，不能以“索引还在更新”为由继续返回旧文档。缓存和输出前的来源校验也要使用当前有效权限。

### 15. 如何做分租户、分用户、分文档的权限过滤？

答：权限元数据随文档和索引存储，查询时使用真实身份构造强制过滤条件，不能让模型在结果返回后自行筛掉；应用层和存储层双重校验，缓存键也包含权限 Scope。权限变更需要及时失效索引和缓存。

### 16. 如何单独评估 Retriever、Reranker 和 Generator？

答：Retriever 看**金标准证据 Recall/候选覆盖**，Reranker 看相关文档排序和 NDCG/MRR，Generator 看有证据时答案正确、引用和拒答质量。分层评估能避免生成模型偶然猜对掩盖召回问题。

### 17. 如何评估 Recall、Precision、MRR、NDCG 和上下文利用率？

答：先建立查询—金标准文档/段落标注；Recall 衡量找全，Precision 衡量噪声少，MRR 关注首个正确结果，NDCG 兼顾多级相关性，上下文利用率看模型是否使用了召回证据。指标要按查询类型分桶，不要只报一个平均数。

关联：[[Learning/Agent/06_RAG与知识库/知识摄取与GraphRAG#20. 如何评估检索质量、权限安全和时效性？|知识摄取与 GraphRAG题20]]

### 18. 如何让 Agent 在需要时自主决定是否检索？

答：先用任务类型、是否需要实时/外部事实、置信度和知识缺口做路由，模型可以提出检索，但执行器限制可用数据源、次数和预算。检索后还要验证证据是否真的覆盖问题，不能把“调用过搜索”当成回答有依据。

### 19. 如何把检索结果、引用和最终回答建立可追溯关系？

答：每个 Chunk 带稳定文档/版本/页码/段落/表格区域 ID，Context 和生成结果记录引用映射；输出只允许引用已进入 Context、权限有效且能回源到原文坐标的证据，不能引用无来源的向量块或未使用链接。评测检查每条引用是否支持具体结论，存储侧 citation ID 的字段设计见 [[Learning/Agent/06_RAG与知识库/知识摄取与GraphRAG#5. 引用如何回指到具体版本、页码和区域？|知识摄取与 GraphRAG题5]]。

关联：[[Learning/Agent/06_RAG与知识库/知识摄取与GraphRAG#5. 引用如何回指到具体版本、页码和区域？|知识摄取与 GraphRAG题5]]

### 20. 文档库很大时如何控制延迟和成本？

答：离线做分层索引和增量更新，在线先用轻量过滤/关键词/向量召回，再对小候选集 Rerank；缓存 Embedding、热门查询和稳定上下文，按复杂度路由模型。优化前先测解析、检索、Rerank、模型和网络各段耗时，避免盲目压缩 K 伤害质量。

## 场景追问：复杂文档和企业知识

### 21. 设计一个支持扫描 PDF、表格、权限和增量更新的企业知识 Agent。

答：系统可分为摄取、检索和更新三段。摄取时区分原生文本与 OCR，保留页码、坐标、表格结构和权限元数据；检索时按租户和文档版本过滤，再做混合召回、Rerank，并用带引用的 Context 生成答案；更新或删除通过版本事件切换索引。最后分别评测解析、召回、引用、答案和越权率。

### 22. 知识系统处理更新、删除和权限变化时，在线检索侧需要额外做什么？

答：索引同步和撤权的主流程见 [[#14. 文档更新、删除和权限变更如何同步到索引？|题14]]。在线侧还要在输出前复核来源权限；删除传播期间可降级为只查权威存储，并用“已删除/无权文档”对抗集验证缓存和引用已失效。
