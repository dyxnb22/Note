# 06.2 知识摄取、版本与 GraphRAG

## 原文、文档版本与派生索引

一次文件更新，可以按下面这些对象记录：

| 对象 | 记录什么、何时产生 |
|---|---|
| Source | 来自哪个文件库、知识平台或业务系统 |
| Document | 来源中的哪份文档，保留稳定 ID |
| DocumentVersion | 文档的一个内容版本；内容变化时新增 |
| Chunk | 从某个文档版本解析、切分出的片段 |
| IndexRecord | 建索引时生成的检索记录 |
| Citation | 回答中指向原文位置的引用 |

文档内容不变，解析器或嵌入模型等配置变化，也可能需要重新分块、建索引。

原文版本和解析位置单独保留，方便回查检索内容、重建索引、纠正引用和执行删除。文档重命名后继续使用原来的文档 ID，历史引用仍能找到它。

## 摄取流水线与文档结构

发现新文件或内容更新后，先获取文件，核对类型、大小和权限，再解析和规范化内容。质量检查通过后，才生成分块与索引。数字 PDF、扫描 PDF 和混合页面可能需要不同处理；多栏、页脚、旋转文字和跨页表格都可能打乱提取后的阅读顺序。

Word 的标题和表格、PPT 的备注和图形、Excel 的表头、单位、公式与缓存值，都可能影响事实解释。处理表格时保留行列关系，使单元格中的值能对应到具体指标和条件。

OCR 置信度不能直接当作准确率。用标注样本核对字符或字段，尤其注意数字、专名、金额和低质量页面。坏文件单独处理，避免拖住整批任务。

## 表格、图像与跨页材料的证据位置

查询“华东区第三季度收入”时，只找到一个数字还不够，还要知道它对应的地区、时间、币种，以及指标按什么方式计算。因此，表格检索需要保留行列标题、合并单元格、单位、注释和跨页关系，让数字能对上这些条件。

图像或流程图可以同时保留原始页面、OCR 文本和文字描述。原页面用于展示，OCR 用于查原字词，文字描述帮助检索相关图片或流程图。使用多模态编码模型时，也要检查坐标、箭头、图例和小字是否被准确识别。文字描述单独保存，重要结论仍要回到原图核查。

定位证据时，可以记录文档版本、页码、表格与单元格标识，以及页面区域坐标。检索片段与用户打开的页面使用同一版本和坐标约定，引用才不会错位。扫描件中的金额、日期或型号若置信度低或相互冲突，就标记为尚未确认，保留页面位置和冲突字段供核查。[按材料结构设计分块](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-chunking-phase)

## 从企业数据源持续取得变化

连接器访问文件库、知识平台或业务系统，把变化写成处理记录。每条记录注明来自哪个系统，并保存对象的稳定 ID、内容版本、权限和删除标记。路径与标题用于展示；移动、重命名或更新内容后，仍通过稳定 ID 找到原对象。

第一次接入，先列出来源中的全部对象，例如全部文件；以后再通过变化游标、事件或增量接口读取新增、修改和删除。数据库中的 CDC 指变化数据捕获，文件平台也可能有自己的增量协议。来源不支持可靠增量时，需要定期核对全部对象，不能只查“更新时间大于上次运行时间”的记录。

变化通知可能重复，也可能只含部分信息。连接器要按来源协议取得完整变化，并处理分页。这一轮变化全部收到、可靠保存后，再记下下次读取的位置。

例如 Microsoft Graph 用 nextLink 继续读取本轮后续页面，用 deltaLink 保存下一轮增量查询的入口。[增量查询说明](https://learn.microsoft.com/en-us/graph/delta-query-overview)

若游标失效，应重新枚举并核对本地状态。完整枚举尚未结束时，不能把“当前页没有返回”解释成对象已删除；来源的权限丢失、连接器配置改变与真实删除也应分别记录。否则一次扫描故障就可能误删整批知识。

## 接收进度与可搜索进度分别提交

收到变化后，内容还要经过解析、分块、Embedding、暂存和发布，才能被搜索到。各步保存输入版本、结果引用和失败状态，中断后从已完成的位置继续。

| 进度 | 说明什么 | 何时可以推进 |
|---|---|---|
| 来源接收进度 | 已可靠接收哪些变化 | 变化记录与续传位置都已持久化 |
| 加工进度 | 哪个输入版本已完成解析和索引准备 | 对应产物与状态已保存 |
| 发布进度 | 哪个版本允许对外检索 | 完整版本通过检查并切换可见入口 |

先保存游标、后保存变化，中途崩溃可能永久跳过内容。可以先把收到的变化写入待处理表（收件箱），与游标放在同一事务中提交，再由后台进程加工。处理失败的记录保留原因和重试入口。

没有收件箱时，也要保证提交方式能安全地重新取得当前批次。

重复加工时，用稳定的对象标识和版本标识覆盖对应记录或去重，旧版本加工完成后，也不能覆盖已经发布的新版本。需要跳过坏文件才能继续同步时，应先可靠登记失败记录，而不是把它从任务集合中静默删掉。

## 分别处理内容、权限与删除事件

正文没变，用户组权限仍可能变化；文件删除后，旧加工任务也可能迟到。因此，正文哈希只用于比较正文，权限与可见性按各自事件更新。

假设一个来源为同一对象提供连续修订号，完整快照包含正文与权限，局部事件只包含某种变化。不同事件需要不同处理：

| 已知状态 | 新事件 | 含义 |
|---|---|---|
| 修订 1 的正文与权限 | 修订 2 撤权 | 正文可不变，但访问范围必须收紧 |
| 修订 3 已删除 | 修订 1 的旧正文迟到 | 保持删除，不能复活旧内容 |
| 修订 1，缺少修订 2 | 修订 3 仅更新权限 | 存在变化缺口，应补齐或回查 |
| 修订 1 | 修订 3 的完整快照 | 确认快照包含当前全部字段后，再据此更新本地状态 |
| 已删除对象 | 更新版本的来源确认快照 | 确认来源是否明确表示恢复该对象，再决定是否解除本地删除标记 |

删除记录保留修订信息，通常称为墓碑，用于阻止迟到旧任务重新发布内容。局部更新不能机械地用最大修订号覆盖，否则可能遗漏其他字段变化；同号而内容不同也需要核对。

出现缺口时，旧授权不能继续被当成当前授权。来源的 ETag 与游标未必是连续整数，更不能直接按字符串大小判断新旧；事件顺序和快照语义应遵循来源协议。

## 一次查询固定一个可见版本

文档的新版本可能拆成多个片段。若写入一段就开放一段，查询可能拿到新第一段和旧第二段，拼出原文中从未存在过的内容。

常见做法是先准备完整版本，再切换对外可见的版本。查询开始时读取当前可见版本号，本次查询的所有片段都按这个版本取。

| 加工状态 | 对外可见版本 |
|---|---|
| 新版本尚未准备完整 | 完整旧版本 |
| 新版本已准备，尚未发布 | 完整旧版本 |
| 发布指针原子切换完成 | 完整新版本 |

存储层用原子操作切换可见版本指针，查询仍按开始时选定的版本读片段。每个版本保存内容哈希、解析与分块配置、嵌入配置、来源位置和权限。更换嵌入模型时，新旧向量空间分开管理。

## 用业务时间衡量知识新鲜度

记录来源变更、连接器发现和新版本可搜索的时间，就能分清延迟发生在发现还是加工阶段。再逐份查看版本进度，找出长期没有更新的文档。

例如制度在 09:00 生效，09:05 被发现，09:20 才发布，用户在 09:10 提问时，回答要说明当时依据的版本。业务不允许使用旧制度时，可以暂停回答该范围，等待新版发布。

普通内容更新是否允许暂用旧版，由业务规定；撤权和删除则先阻止访问，不能等索引更新完再处理。

内容负责人维护适用范围、生效与失效日期、替代关系和复核周期，供系统判断制度效力；同步管道负责传递这些信息。

## 删除、撤权与派生数据

撤权时，访问入口先按当前授权拒绝读取，再清理索引、缓存、摘要和其他派生产物。异步清理未完成时，查询仍不能继续暴露旧内容。权限元数据随索引存储有利于过滤，但不能替代当前授权判断。

删除还要考虑引用、轨迹、回放数据和备份；保留范围与可访问性按适用政策管理。系统应能追踪数据从哪里派生，避免只删原文件却留下可检索摘要。

## 从文本证据到关系证据

分块检索通常返回与问题相近的文本。若问题是“哪个团队负责维护 A 服务依赖的 B 组件”，答案需要把“服务 A 依赖 B”与“团队 C 维护 B”接起来。将这类关系记录为图中的边后，检索时可以沿连接查找依据。

| 关系记录 | 来源 | 可用于解释的内容 |
|---|---|---|
| 服务 A 依赖组件 B | 架构文档版本 2 的片段 8 | 依赖关系 |
| 团队 C 维护组件 B | 维护表版本 5 的第 3 行 | 维护职责 |

这两条关系可以组合出“团队 C 维护 A 所依赖的 B 组件”，回答时同时保留两份依据。连接前要确认两条记录中的 B 是同一个组件，否则就会把无关事实接在一起。

## 图检索增加关系信息

图增强检索利用实体和关系寻找证据。graph-first 先定位实体或路径，再取原文；retrieve-first 从文本候选做局部关系扩展。社区摘要则适合对大量材料作主题级总结。Microsoft GraphRAG 是其中一种具体方案，不代表所有图增强检索都必须采用同一流水线。

实体需要消歧，关系需要来源、版本和有效时间。两个同名公司被错误合并，会把各自事实接到一起；错误边或过期摘要也会传播成看似完整的推理链。图边与摘要都应能回到原始证据。

## 图检索的权限与成本

有权读取一个实体，不代表有权沿关系读取所有节点、边或社区摘要。扩展与聚合前需要过滤，图结构本身也可能暴露敏感对象的存在。

图检索可能更适合关系、多跳或全局主题问题。与混合检索比较时，保持任务和权限一致，查看是否补齐了证据链，以及质量、延迟、建索引和更新成本的变化。

## 让检索、引用与验证使用同一版本

检索读了新制度，验证器却还用旧常量，回答和验证就用了两套规则。检索结果、引用和验证输入都携带可见版本，程序才能核对它们是否使用同一份材料。

版本发布和旧任务回写沿用前文的规则；撤权、删除仍先阻止访问，再异步清理。

图扩展可以复用来源和引用结构。验证器还要核对两条关系中的 B 是不是同一个组件、来源在哪里、时间是否适用，以及能不能据此得出结论。
