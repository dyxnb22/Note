# 语音与实时对话 Agent

本文回答：**语音/实时交互给 Agent 带来哪些额外约束**，以及和文本 Agent 的边界。通用 Loop、工具与安全仍以核心主线文档为准；本文不重复 Tool Schema 与威胁建模全文。

> **学习位置**：文本 Agent 和取消/审批边界稳定后再阅读；本文只补实时音频、打断、端点检测和可听反馈。

## 1. 实时链路长什么样

```text
音频入 → ASR（流式识别）
  → 端点检测 / 打断（VAD、barge-in）
  → Agent（理解、工具、策略）
  → TTS 或文本回传
  → 播放与可取消
```

延迟是乘积：识别尾延迟 + 模型首 token + 工具往返 + 合成首包。用户可感知的「卡顿」往往出在端点检测过晚或工具同步阻塞，而不只是模型慢。

## 2. 与文本 Agent 的关键差异

| 维度 | 文本 | 语音实时 |
|---|---|---|
| 输入完整性 | 整句提交 | 部分假设不断修正 |
| 打断 | 少见 | 用户随时打断播放与推理 |
| 输出 | 可长文 | 宜短句、可分段播报 |
| 错误表现 | 错别字 | 听错人名/数字/同音词 |
| 工具 | 可显示进度 | 必须有可听/可见等待策略 |
| 安全 | 文本注入 | 另有环境噪音、旁人指令、回声 |

## 3. 工程不变量

1. **部分结果不可直接当最终意图**：ASR 中间假说会变；工具调用应等稳定 endpoint 或置信阈值，除非明确「边听边搜」且可撤销。
2. **打断可取消**：用户 barge-in 时取消 TTS、取消未开始的危险工具；已发出的副作用仍靠幂等与补偿。
3. **数字与专有名词**：订单号、金额、地址用复述确认或屏显确认，不单靠一次识别。
4. **会话状态**：电话/语音通道的 session 与文本 session 统一 `thread_id`/用户身份，避免多通道记忆分裂。
5. **隐私**：原始音频保留策略、转写脱敏、第三方 ASR/TTS 的数据边界要单独声明。

## 4. Agent 策略调整

- 缩短单轮工具链；长任务改为「先口头确认，后台执行，完成后回调」。
- 进度用极短状态语（「正在查订单」），避免朗读思维链。
- 高风险动作默认要求明确口头确认词或切到可视审批。
- 识别低置信时主动澄清，不猜着调用写操作。

## 5. 何时不该上语音 Agent

- 任务以长表格、长代码、精确编辑为主；
- 法规要求全量可检索书面证据且语音难留痕；
- 网络或工具 P99 延迟无法满足对话节奏，又没有异步化设计。

此时保留文本/可视化主通道，语音只做唤醒或摘要播报。

## 6. 评测要点

- 端到端延迟分位（含打断恢复时间）；
- 关键槽位（人名、金额、ID）准确率；
- 误触发工具率、打断后的错误副作用率；
- 嘈杂环境与口音分桶；
- 与文本同一任务集的成功率对比。
