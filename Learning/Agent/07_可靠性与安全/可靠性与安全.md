# 07.1 可靠性与执行安全

## 分开检查信息、决策与执行

错误可能出在不同位置：模型理解错目标，检索漏掉证据，工具返回过期数据，或回答编造结论。排查时沿执行顺序回看，找到最早偏离预期的一步。

外部状态、金额、权限和执行结果，不能只凭模型文字确认。重要业务除了检查工具回执，还要到负责该状态的业务系统核实。

## 外部文本与提示注入

网页、文档、仓库说明和工具返回值可能包含改变目标或索要密钥的指令。程序应记录来源，把它们作为待分析数据，限制可访问能力，并在实际工具入口检查权限。

攻击可能藏在引用、代码注释、图片文字或多轮结果中，关键词过滤和模型指令难以覆盖这些情况。防御还应限制访问范围、约束输出，并用对抗样本检验效果。

## 将审批绑定到具体动作

审批记录要写明谁可以执行、使用哪个工具版本、操作哪个资源，以及获准的参数、资源版本和有效期。单个 approved 布尔值无法说明这些条件。

例如批准的是：“user-1 使用 v1 工具，将版本 3 的 file-A 重命名为 B，在期限内有效。”

| 后续变化 | 原审批是否仍覆盖 |
|---|---|
| 参数改成重命名为 C | 不覆盖 |
| 工具版本改变 | 需要按版本与能力变化重新判断 |
| 资源已更新为版本 4 | 原版本前置条件失效 |
| 超过有效期限 | 不覆盖 |

审批记录分别保存执行者、审批人和适用策略。参数按支持的数据类型统一格式，便于核对实际提交是否与获批内容一致。执行器要能确认记录真实有效，并检查是否已撤销、能否重复使用。提交时，把资源版本等条件检查和写入放在同一次操作中；条件变了就拒绝执行。

## 区分能力、参数与资源越界

系统只允许查订单，模型却提出 shell，是能力越界；查询参数额外增加 tenant，是输入契约越界；用合法工具读取另一租户订单，是资源授权问题。即使最终都被拒绝，记录中仍要分清原因。

提示注入测试分两步看：模型有没有受材料诱导，执行器有没有挡住越界提案。同时保留正常请求，检查防御是否误拒合法任务。

## 沙箱与最小能力

模型提出动作后，只能通过宿主暴露的工具执行；加载 Skill、修改 Prompt 或调用子 Agent，都不能扩大实际权限。限制也要覆盖工具启动的子进程和间接动作，防止从其他入口绕过。

对受保护资源，在执行层限制写入，必要时比较运行前后的状态。检测到越界修改即判为不合格，即使主程序退出码为零。恢复与清理沿用同一权限约束。

## 失败、部分成功与未知结果

参数错误反馈给模型修正，权限不足则停止或进入授权流程。暂时性故障只有在操作可安全重复时才限次重试；超时且结果未知的操作，先查询原操作再决定下一步。

多个动作部分成功时，逐项保存状态和证据。例如支付已经完成，要退款就得再发起一笔业务操作，退款也可能失败，需要单独记录和处理。这类补偿与回滚尚未提交的事务不同。无法确认操作结果时，查询原操作、对账或转人工处理。

## 联网工具也有执行边界

“读取网址”看似只是查询，也可能被诱导访问内网服务或云环境的元数据入口，这类攻击称为服务端请求伪造（SSRF）。无论 URL 来自用户、检索材料还是模型，执行器都要检查实际访问的地址。

业务只需要访问固定系统时，优先提供“查询工单”“下载指定知识文档”等限定能力，由服务端确定目标地址。

确实需要开放网页访问时，应限制协议、目标网络、重定向、下载大小、耗时和返回类型。检查范围还包括域名解析及重定向后的地址，并配合网络出口限制；单纯查找 URL 字符串中的 localhost，不能形成可靠防护。[SSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

浏览网页、解析文档和运行下载的脚本，要分别设置允许的操作和访问范围。下载成功不代表允许执行，文件扩展名也不能证明内容安全。需要运行代码时，另外检查来源、权限和隔离环境。

## 工具、Skill 与知识源的变更治理

更新工具时检查能力和副作用，更新 Skill 时检查说明和脚本行为，更新知识源时检查质量和权限。三者都记录来源与版本，才能解释运行结果为什么变化。

例如，工具原本只读取工单，升级后增加“关闭工单”的行为，即使名称没变，也应重新核对权限、审批和回归样本。Skill 更新脚本或依赖时，要检查实际差异；运行记录保存本次使用的内容版本，避免只记录一个会被覆盖的名称。

材料自称“来自管理员”，也不能取得更高权限。新来源先限定读取范围，确认内容和访问控制后再发布。污染资料未必触发异常，却可能诱导错误结论，因此来源链和关键业务验证仍要保留。

## 证据、日志与完成判断

运行记录将模型提案、工具执行和最终业务状态关联起来，保存状态版本、验证退出码与产物引用。验证没通过，就按原标准修复；只能交付部分结果时，写清已确认内容和证据缺口。

日志与 Trace 设置访问权限和保留期限，输入原文、工具参数及私人资料按需脱敏，密钥避免进入日志。轨迹记录的具体内容见[评测与可观测性](../08_评测与可观测/评测与可观测性.md#还原一次模型决策需要的轨迹)。
