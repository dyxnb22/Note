# Rust 所有权与类型系统

> 递进路径：先回答值由谁拥有，再讲借用、生命周期、trait、错误和智能指针；编译器约束不等于业务逻辑已经正确。

## Level 1｜所有权、借用与生命周期

### 1. Rust 的所有权规则是什么？

答：每个值有一个所有者，所有者离开作用域时值被 drop；同一时间可以有多个不可变借用，或一个可变借用；引用必须始终有效。move 把非 Copy 值的所有权转移给新绑定，防止多个所有者在释放时造成 double free。所有权是编译期约束，不是运行时垃圾回收。

### 2. Copy 和 Move 有什么区别？

答：实现 Copy 的简单值在赋值/传参时按位复制，原绑定仍可用；非 Copy 值默认 move，原绑定不能再使用。Copy 适合小且语义上复制安全的类型，包含 String、Vec 等资源所有权的类型通常不实现 Copy。`clone()` 是显式复制，可能深拷贝和产生明显成本，不能作为借用设计错误的默认修复。

### 3. 不可变借用和可变借用为什么不能同时存在？

答：规则防止一边读取旧数据、一边通过别名修改同一数据；可以有多个 `&T`，也可以有一个 `&mut T`，但两类不能在重叠生命周期内同时存在。借用检查器关注引用的有效范围和别名关系，不会替你保证业务状态机、锁顺序或外部系统一致性。

### 4. 生命周期是什么？它会延长对象寿命吗？

答：生命周期是编译器用来描述引用有效范围关系的参数，不会把被引用的对象活得更久。多个输入引用和一个返回引用有关联时，生命周期标注表达返回值不能超过相关输入的最短有效期。大多数局部函数可由省略规则推断，结构体持有引用或多个输入关系不明显时才需要显式标注。

### 5. 为什么函数不能返回局部变量的引用？

答：局部变量在函数返回时被释放，返回引用会指向无效内存；Rust 在编译期拒绝这种代码。解决方式是返回拥有值（如 `String`/`Vec<T>`）、借用调用方传入的数据并正确标注生命周期，或把数据放进拥有更长生命周期的容器。不要用 `'static` 强行绕过真实所有权关系。

### 6. `String`、`&str`、`Vec<u8>` 和 `&[u8]` 如何选择？

答：`String` 拥有 UTF-8 文本，`&str` 是借用的 UTF-8 字符串切片；`Vec<u8>` 拥有二进制字节，`&[u8]` 是借用的字节视图。函数只读时优先接收借用，跨线程/任务或需要独立保存时接收/返回拥有值。UTF-8 字节、Unicode scalar value 和用户感知字符不是同一层概念。

### 7. 如何解决借用检查器报错？

答：先缩短借用范围，把读取和修改阶段分开；再检查函数签名是否应该转移所有权、返回拥有值或只借用；小而廉价的数据可以复制，真正需要共享所有权时再考虑 `Rc`/`Arc`。不要一看到错误就加 `clone()`、`RefCell` 或 `'static`，先解释数据的所有权和生命周期。

### 8. 结构体持有引用时为什么要写生命周期参数？

答：结构体中的引用必须不能比其指向的数据活得更久，`struct Parser<'a> { input: &'a str }` 表达这种关系。业务对象常更适合拥有 `String`、`PathBuf` 或 `Arc<T>`，牺牲一次复制换取独立生命周期；借用结构体适合临时视图、解析器和明确受限的作用域。

### 9. `'static` 到底表示什么？

答：对引用来说，`'static` 表示引用指向的数据在整个程序运行期间有效，例如字符串字面量；拥有的数据也可能满足 `'static`，因为它不借用外部数据。它不是“让所有东西永久存在”的开关，滥用通常说明任务边界、线程所有权或 API 签名没有设计清楚。

## Level 2｜类型、trait 与错误

### 10. trait 和泛型解决什么问题？

答：trait 描述一组能力或行为边界，泛型让同一算法在满足约束的不同类型上复用；静态分发通常在编译期单态化，trait object 则通过动态分发支持运行时替换。选型看调用方需要编译期类型安全、运行时多态还是简单接口，不要为了泛型复用少量代码制造复杂约束。

### 11. 静态分发和动态分发有什么取舍？

答：泛型 `T: Trait`/`impl Trait` 通常允许编译器单态化和内联，类型信息保留更充分但可能增加编译时间和二进制体积；`dyn Trait` 使用 trait object 和虚表，运行时可替换但有对象安全、生命周期和动态调用成本。业务边界若需要插件/异构集合可用 dyn，否则优先保持简单泛型或具体类型。

### 12. `Fn`、`FnMut` 和 `FnOnce` 有什么区别？

答：`FnOnce` 允许闭包消费捕获值，最多调用一次；`FnMut` 允许通过可变借用修改捕获环境；`Fn` 只通过共享借用访问捕获环境，可重复调用。约束从宽到窄不是简单的继承替换，闭包是否移动、修改或只读取环境决定它满足哪些 trait。

### 13. `Option<T>` 和 `Result<T, E>` 为什么适合表达错误？

答：`Option` 明确表示有值或缺值，`Result` 表示成功或带错误失败，调用方必须通过 `match`、组合器或 `?` 处理分支。它们把错误路径放进类型和控制流，不等于业务上每个错误都被正确恢复；错误还需要分类、上下文、日志和对外映射。

### 14. `?` 运算符做了什么？

答：`?` 在成功时取出内部值，在失败时提前返回并进行必要的错误转换，因此要求当前函数的返回类型能承接该错误。它简化错误传播但不会自动添加上下文、重试或日志；边界层应使用带上下文的错误类型，避免把低层实现细节直接暴露给用户。

### 15. 模式匹配为什么是 Rust 的重要能力？

答：`match` 要求覆盖枚举和结构的可能分支，能把状态机、错误和可选值的处理写成显式控制流；编译器在很多遗漏场景给出提示。不要用 `_` 过早吞掉未来分支，关键状态应保留明确错误或不可达说明。

### 16. `Box<T>`、`Rc<T>`、`Arc<T>`、`RefCell<T>` 和 `Mutex<T>` 如何区分？

答：Box 提供单一所有权并把值放在堆上；Rc 提供单线程引用计数共享；Arc 提供线程安全的引用计数共享；RefCell 在单线程运行时检查借用规则；Mutex 用锁保护共享可变数据，跨线程通常和 Arc 组合。智能指针解决的是内存/所有权边界，不自动解决业务竞态、锁顺序、取消或数据一致性。

### 17. `Rc<RefCell<T>>` 为什么可能在运行时出问题？

答：它允许单线程共享所有权和内部可变性，借用规则从编译期部分推迟到运行时；同一时刻违反借用规则会 panic，引用计数环还会造成内存无法回收。它适合树、图或需要单线程共享状态的明确场景，不是绕过所有权的万能方案。

## Level 3｜高级类型与资源管理

### 18. Drop/RAII 在 Rust 中解决什么问题？

答：值离开作用域时自动调用 Drop，能把文件、锁、连接和临时资源的释放绑定到所有权生命周期，减少异常/提前返回路径的泄漏。Drop 只保证资源释放动作被安排，不保证外部事务已经提交或网络副作用可以撤销；提交/回滚仍需显式状态设计。

### 19. `mem::replace` 或 `mem::take` 什么时候有用？

答：当结构体字段被借用或不能直接移动出来时，用一个新值替换旧字段，可以安全地取得旧值并维持结构体有效。它常用于状态机更新、从字段中取出拥有值和避免部分移动；替换本身不代表业务状态迁移已经成功，失败路径仍要设计。

### 20. `PhantomData` 解决什么问题？

答：它在运行时不存储数据，但让类型在编译期“表现得像”持有某种类型、生命周期或所有权关系，从而影响 variance、auto trait 和 drop check。它常用于 FFI 句柄、类型标记和生命周期关联；使用前要能说清虚拟关系是什么，不能只为消除编译错误随便添加。

### 21. Rust 的 `Send` 和 `Sync` 是什么？

答：`Send` 表示值可以安全移动到另一个线程，`Sync` 表示对值的共享引用可以安全地在线程间共享，等价于 `&T: Send`。`Rc` 通常不满足这些 trait，`Arc<T>` 也只有在 T 具备相应条件时才安全；编译器能检查类型级安全，但不能证明业务锁顺序和状态机没有错误。

### 22. 如何判断应该借用、移动还是 clone？

答：只读且调用期间有效就借用；需要把数据交给异步任务、线程或长期状态就移动/拥有；数据小、复制成本低且能让边界更清晰时才 clone。回答要同时考虑生命周期、跨线程、数据大小、共享语义和失败路径，而不是把“零拷贝”当作绝对目标。

### 23. Rust 中 `mut`、遮蔽、`const` 和 `static` 有什么区别？

答：`mut` 允许修改同一个绑定指向的值；遮蔽会创建一个新绑定，可以改变类型并结束旧绑定的直接使用；`const` 是编译期常量，不保证固定运行时地址；`static` 是整个程序生命周期存在的全局值，涉及共享可变状态时需要额外同步和 unsafe 边界。面试时不要把遮蔽说成原地修改。

### 24. 为什么 `match` 和 enum 适合建模状态？

答：enum 可以把有限状态及其携带数据表达成一个类型，`match` 要求穷尽分支，新增状态时编译器会提示需要更新的代码。`_` 虽然方便，但可能把未来状态静默吞掉；状态迁移应通过方法限制非法组合，而不是多个互相矛盾的 bool。

### 25. Rust 为什么不能直接用字符串整数下标？

答：String 是 UTF-8 字节序列，一个 Unicode 标量值可能占多个字节，任意 byte index 可能落在字符中间，所以 Rust 不提供 `s[0]` 这种可能非法的操作。按字节用 `as_bytes`，按标量值用 `chars`，按用户感知字素簇则需要专门 Unicode 处理；切片边界也必须在合法 UTF-8 边界。

### 26. Debug 和 release 构建会影响哪些 Rust 结论？

答：优化级别、溢出检查、断言和内联策略会影响性能以及部分错误行为；性能必须在接近生产的 release 配置、固定数据和工具链上测量。整数运算不能依赖“当前模式刚好如何处理溢出”，应显式使用 checked/saturating/wrapping 等语义。

### 27. Rust 如何编译成可被 C/Go/Python 调用的动态库？

答：先把库 crate 配置成目标平台需要的 `cdylib`，导出使用明确 C ABI 的窄函数，并固定整数、指针和结构体布局；`#[no_mangle]` 等属性的写法要以目标 Edition/工具链为准。导出的接口不能直接暴露 Rust 泛型、trait object 或含 Rust 私有布局的类型，所有返回码、错误信息和句柄都要有跨语言合同。

### 28. FFI 中的字符串、句柄和内存释放如何设计？

答：优先传指针+长度或明确 NUL 终止的 UTF-8/字节合同，拒绝空指针、非法长度和不满足对齐的输入；句柄由 Rust 创建并以 opaque pointer 暴露，必须提供配对的 destroy/free 函数并规定释放方。不能让 C 侧 free Rust 分配器的内存，也不能让 panic、线程或异常跨越 C ABI；边界测试要覆盖空值、重复释放、错误和版本不兼容。

## Level 4｜集合、字符串与迭代器

### 29. `Vec<T>`、数组和切片应该如何选择？

答：数组长度属于类型且通常按值复制，适合长度固定的小数据；`Vec<T>` 拥有堆上的可增长序列；`&[T]` 是不拥有数据的连续切片，函数只读时通常优先接收它。API 要先说清楚调用期间借用是否有效、结果是否需要跨越输入生命周期，以及扩容是否可能让元素地址失效。

### 30. `HashMap` 和 `HashSet` 的使用边界是什么？

答：`HashMap<K, V>` 用于键到值的映射，`entry` API 适合“存在则更新、不存在则插入”；`HashSet<T>` 用于去重和成员判断。键放入集合后不能以影响 `Eq`/`Hash` 的方式改变；哈希集合不承诺稳定遍历顺序，序列化、测试和分页不能依赖它的当前顺序。

### 31. 什么时候应该使用 `BTreeMap` 和 `BTreeSet`？

答：需要按键排序、范围查询、稳定遍历或希望把有序性写进数据结构合同时，用 `BTreeMap`/`BTreeSet`；只需要平均常数时间的成员查询且不关心顺序时，通常用 `HashMap`/`HashSet`。选择还要结合键的比较成本、范围访问模式和数据规模，不能把“有序”当成无条件更好。

### 32. `iter`、`iter_mut`、`into_iter` 和 `collect` 分别表达什么？

答：`iter()` 产生 `&T`，`iter_mut()` 产生 `&mut T`，`into_iter()` 消费集合并产生拥有的 `T`；它们分别表达只读借用、原地修改和转移所有权。迭代器是惰性的，`map`/`filter` 要到 `collect`、`sum` 或 `for` 等消费操作才执行；`collect` 的目标类型决定结果是 `Vec<T>`、`HashSet<T>` 还是 `Result<Vec<T>, E>`。

### 33. Rust 中字符串、字节和“字符”不是一回事，如何处理文本？

答：`String`/`&str` 是 UTF-8 文本，`Vec<u8>`/`&[u8]` 是字节序列，`char` 是 Unicode scalar value，都不等同于用户感知的字素簇。协议和文件边界先按字节处理，文本逻辑再按合法 UTF-8、`chars()` 或专门的 Unicode crate 处理；不能用任意 byte index 截取字符串。

### 34. 如何在集合 API 中避免借用冲突和无谓 `clone`？

答：先明确操作是读取、原地修改还是消费集合，再缩短借用范围，把查询和更新拆成两个阶段；需要长期保存或跨线程/任务传递时再移动或拥有数据。小值的显式复制可以换取清晰边界，但不应为了绕过借用检查器，随意堆叠 `clone`、`RefCell` 或 `'static`。

## 验证边界

- 所有权和 trait 结论要用 `cargo check/test` 与目标 Rust Edition 验证，不能把某个编译器报错的修复方式当成通用设计。
