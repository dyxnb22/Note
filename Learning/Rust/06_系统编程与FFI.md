# 06 系统编程与 FFI

跨语言接口把 Rust 内部的安全边界暴露给不受借用检查器约束的调用方。先定义调用约定、拥有关系和错误，再把 unsafe 限制在可以审查的小范围。

## 从安全 Rust 跨越到外部接口

FFI 让 Rust 调用方和外部语言共同维护一组约定。unsafe 标记需要额外证明的操作，ABI 再约定符号、参数与返回值怎样传递。

### Unsafe 的额外不变量

unsafe 不是“关闭所有检查”，而是允许执行者承担额外不变量，如裸指针、外部函数、未验证别名或初始化；安全封装应把 unsafe 缩小到最小块，并在安全 API 边界证明前置条件。FFI 还需处理 ABI、布局、所有权、线程、panic 跨边界和资源释放，不能只说性能更高。

### 动态库与 C ABI

先把库 crate 配置成目标平台需要的 `cdylib`，导出使用明确 C ABI 的窄函数，并固定整数、指针和结构体布局；`#[no_mangle]` 等属性的写法要以目标 Edition/工具链为准。导出的接口不能直接暴露 Rust 泛型、trait object 或含 Rust 私有布局的类型，所有返回码、错误信息和句柄都要有跨语言调用约定。

### 示例：固定宽度数值的 C ABI

先从没有裸指针的窄接口理解导出。将下面完整库代码保存为 `bridge.rs`，用 `rustc --edition=2024 --crate-type=cdylib bridge.rs` 构建动态库。不同平台会生成不同后缀。

```rust
// SAFETY: 部署的程序中为该课程符号保留唯一名称。
#[unsafe(no_mangle)]
pub extern "C" fn course_saturating_add(left: u32, right: u32) -> u32 {
    left.saturating_add(right)
}
```

接口只接收和返回固定宽度整数，溢出采用饱和语义，调用方无需理解 Rust 的枚举或字符串布局。`extern "C"` 指定 ABI，`no_mangle` 保留导出符号名；Rust 2024 要求这类属性显式标记 unsafe，相关约束见 [Edition Guide](https://doc.rust-lang.org/edition-guide/rust-2024/unsafe-attributes.html)。

当接口增加缓冲区或句柄时，需要新增的约定包括：

| 资源 | 必须明确的关系 |
|---|---|
| 输入指针与长度 | 数据有效范围、对齐、别名和调用期间是否可写 |
| 返回缓冲区 | 分配方、释放函数、长度及编码 |
| Opaque handle | 创建、可调用状态、线程约束与唯一销毁 |
| 错误结果 | 错误码、错误对象寿命与是否发生了副作用 |

一个非空地址仍可能已经失效。安全 Rust 包装类型应隐藏这些裸接口，把可检查的条件放在边界，其余要求写入调用约定并在受控调用路径上保证。

## 资源的创建、借用与释放

数值参数可以按值传递，字符串和句柄还携带资源有效期。创建方、释放方以及失败后的资源状态需要通过接口明确表达。

### 跨语言字符串、句柄和释放

优先传指针+长度或明确 NUL 终止的 UTF-8或字节编码约定，拒绝空指针、非法长度和不满足对齐的输入；句柄由 Rust 创建并以 opaque pointer 暴露，必须提供配对的 destroy/free 函数并规定释放方。不能让 C 侧 free Rust 分配器的内存，也不能让 panic 或外部异常不受控地穿过未约定展开的 C ABI；句柄是否允许不同线程调用，应由接口与同步规则明确规定。边界测试要覆盖空值、重复释放、错误和版本不兼容。

### FFI 文件处理库的合同

导出窄的 `extern "C"` 接口和 opaque handle，输入采用指针+长度并校验空指针、溢出、UTF-8/字节和资源上限；创建与释放由同一侧配对，错误通过状态码/错误对象返回，不能让 panic 穿过 ABI。内部把 unsafe 集中在小模块，外围用拥有类型和测试证明别名、生命周期、线程和 double-free 边界。

### 宏、代码生成与安全封装

宏在编译期生成代码，不是运行时反射；能用函数、trait 或泛型解决时不要用复杂宏。unsafe 要缩小范围并写 SAFETY 不变量，FFI 要明确 ABI、布局、NUL 字符串、谁分配/释放、空指针、线程和 panic 边界；不能把 unsafe 当性能开关。

### 安全封装的检查顺序

先写清谁创建、谁释放、是否允许跨线程、失败如何返回，再确定布局和 ABI。空指针检查只能检查空值，无法证明一个非空地址有效；地址范围、对齐、初始化、唯一释放和生命周期仍属于调用约定。不能用“做了空值检查”声称任意 C 指针都安全。

具体属性写法、目标平台和 panic 策略必须按锁定 Edition 与工具链验证；这里描述接口机制，不提供可以直接接收任意裸指针的通用实现。
