# 01 所有权与类型系统

先掌握绑定、表达式与函数，再从数据由谁释放理解 move、borrow 和 lifetime。类型与 trait 负责表达可用能力，资源释放则跟随所有权。

标准库示例使用 Rust 2021 Edition；异步与 FFI 章节分别标明外部依赖和 Edition。所有权规则决定资源何时有效，具体运行时再决定任务如何执行。

## 绑定、值与所有权

绑定让名字关联一个值，所有权则决定值由谁负责释放。Copy 和 Move 的区别会继续影响函数调用、集合操作和跨任务传递。

### 绑定、表达式与函数

Rust 用 `let` 创建默认不可变的绑定，用 `mut` 允许修改绑定中的值。函数参数和返回值写明类型；代码块末尾不带分号的表达式可以成为返回值。`struct` 描述一组字段，`enum` 描述互斥的几种情况，`impl` 为类型提供方法。

```rust
fn add_one(value: i32) -> i32 {
    value + 1
}

fn main() {
    let mut count = 2;
    count = add_one(count);
    assert_eq!(count, 3);
}
```

接下来要区分绑定与其拥有的数据：一个整数值可以复制，拥有堆缓冲区的 `String` 默认会转移所有权。

### 可变绑定、遮蔽与常量

`mut` 允许修改同一个绑定指向的值；遮蔽会创建一个新绑定，可以改变类型并结束旧绑定的直接使用；`const` 是编译期常量，不保证固定运行时地址；`static` 是整个程序生命周期存在的全局值，涉及共享可变状态时需要额外同步和 unsafe 边界。不要把遮蔽说成原地修改。

### 所有权与作用域

每个值有一个所有者，所有者离开作用域时值被 drop；同一时间可以有多个不可变借用，或一个可变借用；引用必须始终有效。move 把非 Copy 值的所有权转移给新绑定，防止多个所有者在释放时造成 double free。所有权是编译期约束，不是运行时垃圾回收。

### Copy 与 Move

实现 Copy 的简单值在赋值/传参时按位复制，原绑定仍可用；非 Copy 值默认 move，原绑定不能再使用。Copy 适合小且语义上复制安全的类型，包含 String、Vec 等资源所有权的类型通常不实现 Copy。`clone()` 是显式复制，可能深拷贝和产生明显成本，不能作为借用设计错误的默认修复。

## 借用表达访问范围

借用暂时取得访问权，生命周期标注描述引用之间的关系。返回值、结构体字段和闭包跨越不同作用域时，都需要把被引用对象的存活范围说明白。

### 共享借用与独占借用

规则防止一边读取旧数据、一边通过别名修改同一数据；可以有多个 `&T`，也可以有一个 `&mut T`，但两类不能在重叠生命周期内同时存在。借用检查器关注引用的有效范围和别名关系，不会替你保证业务状态机、锁顺序或外部系统一致性。

### 生命周期关系

生命周期标注描述引用有效范围之间的约束，不延长被引用数据的存活时间。例如函数让两个输入与返回值共享同一参数 a，表示返回引用只能在两份输入都有效的范围内使用。

若返回值只借用第一个输入，就不必把第二个输入也绑到相同参数。实际关系由签名表达，不能笼统地把所有输入都缩成最短生命周期；局部情形常可由省略规则推断。

### 返回引用与拥有值

局部变量在函数返回时被释放，返回引用会指向无效内存；Rust 在编译期拒绝这种代码。解决方式是返回拥有值（如 `String`/`Vec<T>`）、借用调用方传入的数据并正确标注生命周期，或把数据放进拥有更长生命周期的容器。不要用 `'static` 强行绕过真实所有权关系。

### 结构体中的引用

结构体中的引用必须不能比其指向的数据活得更久，`struct Parser<'a> { input: &'a str }` 表达这种关系。业务对象常更适合拥有 `String`、`PathBuf` 或 `Arc<T>`，牺牲一次复制换取独立生命周期；借用结构体适合临时视图、解析器和明确受限的作用域。

### 静态借用与 'static 约束

对引用来说，`'static` 表示引用指向的数据在整个程序运行期间有效，例如字符串字面量；拥有的数据也可能满足 `'static`，因为它不借用外部数据。它不是“让所有东西永久存在”的开关，滥用通常说明任务边界、线程所有权或 API 签名没有设计清楚。

### 根据借用检查错误调整设计

先缩短借用范围，把读取和修改阶段分开；再检查函数签名是否应该转移所有权、返回拥有值或只借用；小而廉价的数据可以复制，真正需要共享所有权时再考虑 `Rc`/`Arc`。不要一看到错误就加 `clone()`、`RefCell` 或 `'static`，先解释数据的所有权和生命周期。

### 示例：借用结束后继续修改

```rust
fn main() {
    let mut name = String::from("Rust");
    let length = name.len();
    let borrowed = &name;
    assert_eq!(borrowed, "Rust"); // borrowed 最后一次使用
    name.push('!');
    let owned = name;           // 所有权移交给 owned
    assert_eq!(length, 4);
    assert_eq!(owned, "Rust!");
    // 此后不能继续使用 name。
}
```

借用有效期由使用关系约束，不必延续到变量所在代码块的最后一行。`owned` 离开作用域时负责释放这块字符串缓冲区；移动没有复制字符串内容。

### 借用、移动与 clone 的选择

只读且调用期间有效就借用；需要把数据交给异步任务、线程或长期状态就移动/拥有；数据小、复制成本低且能让边界更清晰时才 clone。需要同时考虑生命周期、跨线程、数据大小、共享语义和失败路径，而不是把“零拷贝”当作绝对目标。

## 类型组织状态与能力

Enum 和模式匹配表达有限状态，Trait 表达类型提供的能力。泛型与 trait object 决定能力在编译期还是运行时被选择，闭包也遵循这套访问与调用约束。

### 模式匹配与分支覆盖

`match` 要求覆盖枚举和结构的可能分支，能把状态机、错误和可选值的处理写成显式控制流；编译器在很多遗漏场景给出提示。不要用 `_` 过早吞掉未来分支，关键状态应保留明确错误或不可达说明。

### Enum 与状态建模

enum 的每个变体可以携带不同字段，使状态与所需数据一起成立。例如 Succeeded 携带结果引用，Running 携带租约，就能在类型层面避免“成功却缺少结果”这类组合。

match 处理各状态的行为，迁移方法再限制哪些状态可以转入下一状态。类型减少非法组合，但数据库并发修改与外部副作用仍需独立保护。

### Trait 与泛型

trait 描述一组能力或行为边界，泛型让同一算法在满足约束的不同类型上复用；静态分发通常在编译期单态化，trait object 则通过动态分发支持运行时替换。选型看调用方需要编译期类型安全、运行时多态还是简单接口，不要为了泛型复用少量代码制造复杂约束。

### 静态分发与动态分发

泛型 `T: Trait`/`impl Trait` 通常允许编译器单态化和内联，类型信息保留更充分但可能增加编译时间和二进制体积；`dyn Trait` 使用 trait object 和虚表，运行时可替换但有对象安全、生命周期和动态调用成本。业务边界若需要插件/异构集合可用 dyn，否则优先保持简单泛型或具体类型。

### 示例：同一种能力的静态与动态调用

结构体持有数据，`impl` 定义操作，trait 描述调用方需要的能力。泛型调用保留具体类型，trait object 允许同一容器在运行时装入不同实现。

```rust
trait Describe {
    fn describe(&self) -> String;
}
struct User { name: String }
impl Describe for User {
    fn describe(&self) -> String { format!("user:{}", self.name) }
}
fn render(item: &impl Describe) -> String { item.describe() }

fn main() {
    let user = User { name: String::from("Ada") };
    assert_eq!(render(&user), "user:Ada");
    let objects: Vec<Box<dyn Describe>> = vec![Box::new(user)];
    assert_eq!(objects[0].describe(), "user:Ada");
}
```

`render` 借用 User，不消费它；把 User 放进 Box 时才转移拥有关系。`dyn Describe` 通过虚表调用，要求 trait 满足动态兼容条件。这里没有把引用延长为静态生命周期，也不需要为共享借用复制整个 User。

### 闭包与 Fn 系列 trait

所有闭包都实现 FnOnce，允许通过取得闭包所有权调用一次；这不表示它们都只能调用一次。不把捕获值移出闭包体的闭包可实现 FnMut，通过可变访问重复调用；不需要通过可变借用访问捕获环境的闭包还可实现 Fn。Fn 同时满足 FnMut 与 FnOnce 的约束。

move 决定如何捕获变量，调用 trait 由闭包体怎样使用捕获值决定。例如 move 闭包只读取自己拥有的 String，仍可能实现 Fn；把 String 直接返回、移出闭包环境时，才只能按 FnOnce 调用。[The Rust Book：闭包与调用 trait](https://doc.rust-lang.org/book/ch13-01-closures.html)

## 资源共享、内部可变性与析构

需要共享所有权或延后借用检查时，智能指针把新的约束放进类型。Drop、引用计数和 Send/Sync 继续限定资源怎样释放与跨线程使用。

### 智能指针与内部可变性

Box 提供单一所有权并把值放在堆上；Rc 提供单线程引用计数共享；Arc 提供线程安全的引用计数共享；RefCell 在单线程运行时检查借用规则；Mutex 用锁保护共享可变数据，跨线程通常和 Arc 组合。智能指针解决的是内存/所有权边界，不自动解决业务竞态、锁顺序、取消或数据一致性。

### 引用计数环与运行时借用

`Rc<RefCell<T>>` 允许单线程共享所有权和内部可变性，借用规则从编译期部分推迟到运行时；同一时刻违反借用规则会 panic，引用计数环还会造成内存无法回收。它适合树、图或需要单线程共享状态的明确场景，不是绕过所有权的万能方案。

### Drop 与 RAII

正常离开作用域或发生栈展开时，值的析构把文件、锁等资源释放绑定到所有权生命周期，提前返回也能沿相同规则清理。RAII 减少遗漏，但进程中止或显式遗忘值等情况不会保证执行 Drop。

析构也不等于提交业务事务，不能依靠进程退出时的清理来保证远端状态或持久化结果正确；提交、回滚、取消和恢复仍要显式设计。

### 替换字段与取得所有权

当结构体字段被借用或不能直接移动出来时，用一个新值替换旧字段，可以安全地取得旧值并维持结构体有效。它常用于状态机更新、从字段中取出拥有值和避免部分移动；替换本身不代表业务状态迁移已经成功，失败路径仍要设计。

### PhantomData 与类型关系

它在运行时不存储数据，但让类型在编译期“表现得像”持有某种类型、生命周期或所有权关系，从而影响 variance、auto trait 和 drop check。它常用于 FFI 句柄、类型标记和生命周期关联；使用前要能说清虚拟关系是什么，不能只为消除编译错误随便添加。

### Send 与 Sync

`Send` 表示值可以安全移动到另一个线程，`Sync` 表示对值的共享引用可以安全地在线程间共享，等价于 `&T: Send`。`Rc` 通常不满足这些 trait，`Arc<T>` 也只有在 T 具备相应条件时才安全；编译器能检查类型级安全，但不能证明业务锁顺序和状态机没有错误。

[The Rust Book：所有权](https://doc.rust-lang.org/book/ch04-01-what-is-ownership.html) 可配合编译器错误阅读。集合和错误处理继续见 [下一章](./02_集合与错误处理.md)。
