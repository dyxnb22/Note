# 02 集合与错误处理

容器选择同时影响所有权、迭代顺序和更新方式。先区分拥有值、借用视图与文本编码，再把缺失、失败和错误传播写进返回类型。

## 集合和文本的拥有关系

拥有容器负责保存与释放数据，切片和文本引用只取得一段访问范围。字符串还受 UTF-8 边界约束，因此字节位置与用户看到的字符数量不能混用。

### 数组、Vec 与切片

数组 `[T; N]` 的长度属于类型；赋值或传参时，只有元素类型 `T: Copy` 的数组才能隐式复制（见 [数组类型文档](https://doc.rust-lang.org/std/primitive.array.html)），其他数组会移动。`Vec<T>` 拥有堆上的可增长序列；`&[T]` 是借用连续数据的切片，只读参数通常优先接收它。扩容可能使元素地址失效，跨越输入生命周期保存结果时需要拥有数据。

### 拥有字符串与借用文本

`String` 拥有 UTF-8 文本，`&str` 是借用的 UTF-8 字符串切片；`Vec<u8>` 拥有二进制字节，`&[u8]` 是借用的字节视图。函数只读时优先接收借用，跨线程/任务或需要独立保存时接收/返回拥有值。UTF-8 字节、Unicode scalar value 和用户感知字符不是同一层概念。

### UTF-8 边界与索引

String 是 UTF-8 字节序列，一个 Unicode 标量值可能占多个字节，任意 byte index 可能落在字符中间，所以 Rust 不提供 `s[0]` 这种可能非法的操作。按字节用 `as_bytes`，按标量值用 `chars`，按用户感知字素簇则需要专门 Unicode 处理；切片边界也必须在合法 UTF-8 边界。

组合音标等情况会让一个可见字符包含多个标量值。因此协议长度、字符遍历和光标移动需要选择不同单位，不能用同一个“字符数”替代。

### HashMap、HashSet 与 entry

`HashMap<K, V>` 用于键到值的映射，`entry` API 适合“存在则更新、不存在则插入”；`HashSet<T>` 用于去重和成员判断。键放入集合后不能以影响 `Eq`/`Hash` 的方式改变；哈希集合不承诺稳定遍历顺序，序列化、测试和分页不能依赖它的当前顺序。

### BTreeMap 与有序访问

需要按键排序、范围查询、稳定遍历或需要让调用方可以依赖有序遍历时，用 `BTreeMap`/`BTreeSet`；只需要平均常数时间的成员查询且不关心顺序时，通常用 `HashMap`/`HashSet`。选择还要结合键的比较成本、范围访问模式和数据规模，不能把“有序”当成无条件更好。

## 迭代过程中的借用与移动

迭代器把逐步访问包装为组合操作，但元素被借用、修改还是移动，仍由迭代方式决定。统计词频可以直接观察借用数据的存活要求。

### 迭代器与收集类型

对拥有的 `Vec<T>`，`iter()` 产生 `&T`，`iter_mut()` 产生 `&mut T`，`into_iter()` 消费 Vec 并产生 `T`；对引用调用 `into_iter()` 则由对应的 `IntoIterator` 实现决定元素类型。适配器如 `map`、`filter` 通常惰性执行，`collect`、`sum` 或 `for` 推动迭代；目标类型决定收集为 Vec、集合或 Result。

### 集合更新中的借用范围

先明确操作是读取、原地修改还是消费集合，再缩短借用范围，把查询和更新拆成两个阶段；需要长期保存或跨线程/任务传递时再移动或拥有数据。小值的显式复制可以换取清晰边界，但不应为了绕过借用检查器，随意堆叠 `clone`、`RefCell` 或 `'static`。

### 示例：借用文本并统计词频

```rust
use std::collections::HashMap;

fn main() {
    let text = String::from("rust go rust");
    let mut counts: HashMap<&str, usize> = HashMap::new();
    for word in text.split_whitespace() {
        *counts.entry(word).or_insert(0) += 1;
    }
    assert_eq!(counts.get("rust"), Some(&2));
    let doubled: Vec<i32> = [1, 2, 3].iter().map(|n| n * 2).collect();
    assert_eq!(doubled, vec![2, 4, 6]);
}
```

`counts` 中的键借用 `text`，不分配每个单词的副本。若结果需要在函数返回后独立存活，可改为拥有 `String`。这里用空白切词，未做大小写归一、标点和字素规范化。

### 迭代器流水线

流水线的适配器保存计算步骤，不会在创建时立即处理整个输入。消费端逐个请求元素时，filter、map 等依次执行；take 等操作还可能提前结束，因此闭包内的副作用不保证对所有输入发生。

collect 成拥有集合会分配结果，收集为 Result 则可在首个错误处短路。借用输入并不意味着输出也借用；是否复制、分配或转移，取决于闭包返回类型和收集目标，热点仍需测量。

### 统计规则也是数据契约

示例的 split_whitespace 按空白切分，不会自动移除标点、统一大小写或完成中文分词。即使代码和生命周期都正确，切词规则不同仍会得到不同统计结果。

应先确定“同一个词”的语义，再选择规范化与切分规则，并限制输入大小。二进制输入先处理 UTF-8 解码失败，借用键的结果则必须保持原缓冲有效。

## 把缺失和失败写进返回类型

Option 表达可能没有值，Result 表达成功或失败。调用链继续传播错误时，还需要保留失败所属的操作与层次。

### Option 与 Result

`Option` 明确表示有值或缺值，`Result` 表示成功或带错误失败，调用方必须通过 `match`、组合器或 `?` 处理分支。它们把错误路径放进类型和控制流，不等于业务上每个错误都被正确恢复；错误还需要分类、上下文、日志和对外映射。

### 问号运算符与错误传播

`?` 在成功时取出内部值，在失败时提前返回并进行必要的错误转换，因此要求当前函数的返回类型能接受转换后的错误。它简化错误传播但不会自动添加上下文、重试或日志；边界层应使用带上下文的错误类型，避免把低层实现细节直接暴露给用户。

### 示例：用 Result 保留解析错误

```rust
use std::num::ParseIntError;

fn parse_total(lines: &str) -> Result<i64, ParseIntError> {
    let mut total = 0;
    for line in lines.lines() {
        let value: i32 = line.trim().parse()?;
        total += i64::from(value);
    }
    Ok(total)
}

fn main() {
    assert_eq!(parse_total("12\n3").unwrap(), 15);
    assert!(parse_total("12\noops").is_err());
}
```

`?` 在解析失败时提前返回错误；示例只表达解析路径。真实大输入还需要总字节/行数上限、求和溢出策略和错误行号，调用方再决定拒绝、修复还是重试。

### 文件解析中的错误分层

边界函数把 IO、UTF-8、格式和业务校验错误分层，返回带上下文的 `Result<T, E>`；调用方用 `?` 传播可处理错误，在 API 边界映射成稳定错误码。按行读取可控制内存，错误中携带文件路径和行号但避免泄露敏感内容；测试正常、空文件、非法行、超大行和半成品输出。

## 把所有权规则应用到算法

查找、区间更新和缓存操作的目标不同，但都要明确哪个结构拥有数据、修改时哪些引用仍然存在。

### HashMap 求两数之和

用 `HashMap` 保存已访问值到下标，遍历时查找 `target - value`，找到后返回；时间 O(n)，空间 O(n)。需要注意整数溢出策略、重复值和借用 map 时的可变/不可变借用冲突；可以先查找，再插入，减少借用范围。

### Vec 排序与区间合并

按起点排序，维护当前区间；若下一个区间与当前重叠则更新右端点，否则把当前结果推入 Vec 并开始新区间。时间 O(n log n)，空间取决于排序和输出。Rust 中可以先让数据拥有 `Vec<(i32, i32)>`，避免为了借用排序而让生命周期复杂化。

### LRU 的所有权模型

核心难点不是 HashMap，而是 map、节点链表和 key/value 所有权如何同时安全维护。一种实现是 `HashMap<K, Entry>` 加有序结构，更新访问顺序时要避免悬挂引用；生产中可以使用成熟 crate 或索引/句柄而不是手写自引用链表。还要补容量、过期、并发和缓存一致性。

迭代协议见 [The Rust Book：迭代器](https://doc.rust-lang.org/book/ch13-02-iterators.html)。共享数据进入多线程后，还需 [并发与异步](./03_并发与异步.md) 中的同步关系。
