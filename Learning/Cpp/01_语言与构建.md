# 01 语言与构建

先理解变量、作用域、指针与引用，再看编译、链接和跨文件声明。语法规则、对象生命周期与二进制实现需要分开理解。

完整示例使用 C++17 标准库。对象布局、ABI 和诊断选项还取决于编译器与目标平台，语言语义和某次编译结果需要分开理解。

## 一个最小程序

C++ 程序从 `main` 开始，声明给值指定类型；`#include` 引入标准库声明。自动存储期对象通常在作用域结束时析构，这为后面的 RAII 资源管理提供基础。

```cpp
#include <cassert>
#include <vector>

int main() {
    std::vector<int> values{1, 2, 3};
    int total = 0;
    for (int value : values) {
        total += value;
    }
    assert(total == 6);
}
```

把示例保存为 main.cpp，可在独立目录用 `clang++ -std=c++17 main.cpp -o app` 编译。


## 指针、引用与悬空访问

指针是保存地址的对象，可以为空、改指向并参与有限的地址运算；引用是已有对象的别名，初始化后不能改绑，语义上应始终引用有效对象。未初始化或值不确定的指针常称野指针；对象生命周期结束后仍指向其原地址的是悬空指针，解引用都会产生未定义行为。

工程上优先用值、引用和 RAII 表达所有权；裸指针更适合表达非拥有观察关系。返回局部变量地址、容器扩容后继续使用旧迭代器/指针、删除后未清理别名，都是常见悬空来源。把一个别名置空不能修复其他别名。

`const int*` 表示不能通过该指针修改整数，`int* const` 表示指针本身不能改指向；两者可以组合。函数指针是“指向函数的指针”，返回指针的函数则是另一种声明，阅读复杂声明时从标识符向外分析。

## 参数传递与生命周期

小且可复制的值优先值传递；只读且复制昂贵的对象用 `const T&`；需要修改调用方对象但不允许为空时用 `T&`；“可为空、可改指向”用 `T*`。所有权转移应使用值、`std::unique_ptr` 或明确的移动语义，而不是靠注释解释裸指针。

引用和指针在 ABI 层可能都通过地址实现，但语言语义不同。分析不能只说“引用更安全”，还要说明生命周期：被引用对象必须活得足够久，异步任务捕获引用尤其容易悬空。

## Const、Static、Volatile 与 Inline

`const` 表达不可通过当前接口修改；`static` 的含义取决于作用域，可控制静态存储期、内部链接或类级共享成员；`inline` 主要解决跨翻译单元的定义规则并允许编译器自行决定是否内联；宏是预处理文本替换，没有类型和作用域保护。

`volatile` 只限制编译器对特定对象访问的优化，常用于内存映射 I/O 等低层场景；它不是原子类型，也不能建立线程间 happens-before。并发同步应使用 `std::atomic`、锁或标准同步原语。

头文件里直接定义普通非 `inline` 全局变量可能造成多重定义；优先使用声明、`inline` 变量（C++17）或合适的模块边界。类型常量优先 `constexpr`/`const`，函数式宏优先模板、`constexpr` 函数或 `inline` 函数。

## 编译、链接与符号

典型链路是预处理、编译、汇编、链接。每个源文件连同其头文件形成翻译单元；链接器解析符号、合并目标文件并完成重定位。静态库把需要的代码放入最终构件，部署直接但体积和升级成本较高；动态库在装载/运行时解析，便于共享和独立升级，但引入 ABI、搜索路径和版本兼容问题。

排查 `undefined reference` 要区分声明缺失、实现未参与链接、库顺序/搜索路径、名字改编和 ABI 不兼容。与 C 接口交互时 `extern "C"` 控制语言链接，主要避免 C++ 名字改编，不会把 C++ 代码自动变成 C 语义。
