# 02 对象模型与泛型

类把数据和操作放在一起；继承、虚函数和模板提供不同的复用方式。理解资源归属后，才能正确设计复制、移动和析构。

## 重载、重写、隐藏与动态多态

重载发生在同一作用域、函数名相同但参数列表不同；重写是派生类覆盖基类虚函数；派生类声明同名函数还可能隐藏基类的其他重载。运行时多态通常通过虚函数、对象中的虚表指针和动态派发实现，但具体对象布局属于 ABI 实现细节。

如果对象可能经基类指针删除，基类析构必须为虚函数，否则行为未定义、派生资源可能无法释放。构造函数不能是虚函数，因为构造前完整动态类型尚未建立；构造/析构期间调用虚函数也只按当前构造层级派发。

接口类通常提供虚析构；不允许多态删除的基类可以使用受保护的非虚析构明确边界。不要把“所有类析构都必须 virtual”当成通用规则。

## 特殊成员函数与 Rule of Zero

编译器可能隐式声明默认构造、析构、拷贝构造、拷贝赋值、移动构造和移动赋值，但能否生成、是否被删除以及是否 `noexcept` 受成员和已声明特殊成员影响。资源所有权优先交给标准容器和智能指针，让类遵循 Rule of Zero；必须手工管理资源时，成组考虑析构、拷贝和移动语义。

深拷贝要复制独立资源，浅拷贝只复制句柄可能造成双重释放或共享修改。资源管理类的移动操作通常应在正确时声明 `noexcept`，这样容器扩容更可能采用移动；但不能为了性能错误承诺不抛异常。

## 值类别、移动与完美转发

值类别描述表达式的身份和可移动性；右值引用允许绑定到可被复用资源的对象。`std::move` 本身不移动任何数据，只把表达式转换成可触发移动重载的值类别；真正的资源转移发生在移动构造或移动赋值中。

被移动对象仍必须可析构、可赋值，但其具体值通常只保证“有效但未指定”，除非类型约定另有说明。模板中的转发引用配合 `std::forward` 保留实参值类别；无条件使用 `std::move` 可能破坏调用方仍要使用的对象。

## 模板与编译期实例化

模板在编译期按类型或值生成代码，实现泛型算法和容器。函数模板可由实参推导部分参数，类模板通常需要显式参数或依赖类模板实参推导。模板实例化会增加编译时间和构件体积，错误也常在实例化点暴露。

现代 C++ 可用 Concepts/约束表达模板要求，使错误更接近接口；不要把所有多态都改成模板，运行时插件、稳定 ABI 和动态集合仍可能更适合虚函数或类型擦除。

## 示例：虚函数与模板的两条复用路径

虚函数允许经同一基类接口调用不同对象；模板则在编译期为满足表达式要求的具体类型生成实现。一个程序可以同时使用两种机制。

```cpp
#include <cassert>
#include <memory>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};
class Rectangle final : public Shape {
    double width_;
    double height_;
public:
    Rectangle(double width, double height) : width_(width), height_(height) {}
    double area() const override { return width_ * height_; }
};
template <typename T>
T total(const std::vector<T>& values) {
    T result{};
    for (const T& value : values) { result += value; }
    return result;
}
int main() {
    std::unique_ptr<Shape> shape = std::make_unique<Rectangle>(3.0, 4.0);
    assert(shape->area() == 12.0);
    assert(total(std::vector<int>{1, 2, 3}) == 6);
}
```

经 `Shape*` 销毁对象时，虚析构保证派生对象正确析构；`override` 让编译器检查签名。`total<int>` 要求 T 可默认构造并支持累加，这些要求在实例化时检查。基类多态不自动提供值拷贝语义，模板也不自动保证所有类型的数值运算都满足预期。

## 构造、复制、移动与析构的时间线

对象创建先建立基类与成员，再执行构造函数体；析构时按相反方向释放成员和基类。拥有动态资源的类若默认复制裸地址，两个对象就可能错误地认为自己都应释放同一资源。

使用 `std::vector`、`std::string` 和 `std::unique_ptr` 保存资源，通常能依靠成员自身的正确语义遵循 Rule of Zero。只有确实需要自定义资源操作时，再同步考虑复制构造、复制赋值、移动构造、移动赋值与析构之间的约定。

## 从对象语义选择接口

只观察对象时可以传 `const T&`；需要独立持有结果时返回拥有值；转移独占资源时使用能表达移动的拥有类型。`std::move` 本身只进行值类别转换，资源是否被转移取决于实际调用的构造或赋值操作。不要把 moved-from 对象一律理解成空值，其有效状态由类型约定规定。
