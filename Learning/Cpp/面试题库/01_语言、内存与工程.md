# C++ 语言、内存与工程面试问答

> 相似问题合并为题簇；回答顺序是结论、机制、边界和追问。通用 OS/网络算法不在本页重复。

## 1. 指针和引用有什么区别？什么是野指针、悬空指针？

核心回答：指针是保存地址的对象，可以为空、改指向并参与有限的地址运算；引用是已有对象的别名，初始化后不能改绑，语义上应始终引用有效对象。未初始化或值不确定的指针常称野指针；对象生命周期结束后仍指向其原地址的是悬空指针，解引用都会产生未定义行为。

工程上优先用值、引用和 RAII 表达所有权；裸指针更适合表达非拥有观察关系。返回局部变量地址、容器扩容后继续使用旧迭代器/指针、删除后未清理别名，都是常见悬空来源。把一个别名置空不能修复其他别名。

常见追问：`const int*` 表示不能通过该指针修改整数，`int* const` 表示指针本身不能改指向；两者可以组合。函数指针是“指向函数的指针”，返回指针的函数则是另一种声明，阅读复杂声明时从标识符向外分析。

## 2. 值传递、指针传递和引用传递如何选择？

核心回答：小且可复制的值优先值传递；只读且复制昂贵的对象用 `const T&`；需要修改调用方对象但不允许为空时用 `T&`；“可为空、可改指向”用 `T*`。所有权转移应使用值、`std::unique_ptr` 或明确的移动语义，而不是靠注释解释裸指针。

引用和指针在 ABI 层可能都通过地址实现，但语言语义不同。面试不能只说“引用更安全”，还要说明生命周期：被引用对象必须活得足够久，异步任务捕获引用尤其容易悬空。

## 3. `const`、`static`、`volatile`、宏和 `inline` 分别解决什么？

核心回答：`const` 表达不可通过当前接口修改；`static` 的含义取决于作用域，可控制静态存储期、内部链接或类级共享成员；`inline` 主要解决跨翻译单元的定义规则并允许编译器自行决定是否内联；宏是预处理文本替换，没有类型和作用域保护。

`volatile` 只限制编译器对特定对象访问的优化，常用于内存映射 I/O 等低层场景；它不是原子类型，也不能建立线程间 happens-before。并发同步应使用 `std::atomic`、锁或标准同步原语。

常见追问：头文件里直接定义普通非 `inline` 全局变量可能造成多重定义；优先使用声明、`inline` 变量（C++17）或合适的模块边界。类型常量优先 `constexpr`/`const`，函数式宏优先模板、`constexpr` 函数或 `inline` 函数。

## 4. C++ 从源文件到可执行文件经历什么？静态链接和动态链接如何取舍？

核心回答：典型链路是预处理、编译、汇编、链接。每个源文件连同其头文件形成翻译单元；链接器解析符号、合并目标文件并完成重定位。静态库把需要的代码放入最终构件，部署直接但体积和升级成本较高；动态库在装载/运行时解析，便于共享和独立升级，但引入 ABI、搜索路径和版本兼容问题。

排查 `undefined reference` 要区分声明缺失、实现未参与链接、库顺序/搜索路径、名字改编和 ABI 不兼容。与 C 接口交互时 `extern "C"` 控制语言链接，主要避免 C++ 名字改编，不会把 C++ 代码自动变成 C 语义。

## 5. 重载、重写、隐藏和多态有什么区别？为什么基类析构通常要虚拟？

核心回答：重载发生在同一作用域、函数名相同但参数列表不同；重写是派生类覆盖基类虚函数；派生类声明同名函数还可能隐藏基类的其他重载。运行时多态通常通过虚函数、对象中的虚表指针和动态派发实现，但具体对象布局属于 ABI 实现细节。

如果对象可能经基类指针删除，基类析构必须为虚函数，否则行为未定义、派生资源可能无法释放。构造函数不能是虚函数，因为构造前完整动态类型尚未建立；构造/析构期间调用虚函数也只按当前构造层级派发。

常见追问：接口类通常提供虚析构；不允许多态删除的基类可以使用受保护的非虚析构明确边界。不要把“所有类析构都必须 virtual”当成通用规则。

## 6. 类会隐式生成哪些特殊成员？什么是 Rule of Zero/Three/Five？

核心回答：编译器可能隐式声明默认构造、析构、拷贝构造、拷贝赋值、移动构造和移动赋值，但能否生成、是否被删除以及是否 `noexcept` 受成员和已声明特殊成员影响。资源所有权优先交给标准容器和智能指针，让类遵循 Rule of Zero；必须手工管理资源时，成组考虑析构、拷贝和移动语义。

深拷贝要复制独立资源，浅拷贝只复制句柄可能造成双重释放或共享修改。资源管理类的移动操作通常应在正确时声明 `noexcept`，这样容器扩容更可能采用移动；但不能为了性能错误承诺不抛异常。

## 7. 左值、右值、移动语义和完美转发怎么理解？

核心回答：值类别描述表达式的身份和可移动性；右值引用允许绑定到可被复用资源的对象。`std::move` 本身不移动任何数据，只把表达式转换成可触发移动重载的值类别；真正的资源转移发生在移动构造或移动赋值中。

被移动对象仍必须可析构、可赋值，但其具体值通常只保证“有效但未指定”，除非类型合同另有说明。模板中的转发引用配合 `std::forward` 保留实参值类别；无条件使用 `std::move` 可能破坏调用方仍要使用的对象。

## 8. 模板解决什么问题？模板错误为什么难排查？

核心回答：模板在编译期按类型或值生成代码，实现泛型算法和容器。函数模板可由实参推导部分参数，类模板通常需要显式参数或依赖类模板实参推导。模板实例化会增加编译时间和构件体积，错误也常在实例化点暴露。

现代 C++ 可用 Concepts/约束表达模板要求，使错误更接近接口；不要把所有多态都改成模板，运行时插件、稳定 ABI 和动态集合仍可能更适合虚函数或类型擦除。

## 9. `vector`、`deque`、`list`、`map`、`unordered_map` 怎么选？

核心回答：默认从 `vector` 开始，它连续、局部性好且随机访问快；两端频繁操作可考虑 `deque`；只有在确实需要稳定节点地址和中间频繁插删时才考虑链表。`map` 提供有序和对数复杂度，`unordered_map` 平均常数查找但受哈希质量、装载因子和攻击输入影响。

容器修改必须考虑迭代器失效：`vector` 扩容会使全部指针/引用/迭代器失效，中间插删还会影响位置之后元素；节点式容器通常只使被删节点失效，但标准规则要按具体容器和操作核对。遍历删除使用容器返回的下一个迭代器，不能在失效后继续自增。

常见追问：`push_back` 接收现有对象，`emplace_back` 在容器位置构造对象，但不保证在所有写法中更快；先以清晰和正确为主。标准容器对同一实例的并发写通常不安全，外部同步或分片设计不可省略。

## 10. 智能指针如何表达所有权？为什么仍会泄漏？

核心回答：`unique_ptr` 表达唯一所有权，可移动不可复制；`shared_ptr` 用共享控制块管理引用计数；`weak_ptr` 是不增加强引用计数的观察者，用于打破环和尝试获取临时共享所有权。优先 `make_unique`/`make_shared`，并让所有权关系在接口类型中可见。

`shared_ptr` 不能自动解决循环引用；两个对象互相持有强引用会让计数永不归零。它也不等于对象线程安全：不同 `shared_ptr` 实例的控制块操作可安全协作，不代表被指向对象的成员可以并发读写。

常见追问：不能用两个独立控制块管理同一裸指针，否则会双重删除；从对象内部生成共享指针应使用 `enable_shared_from_this` 且对象已经由兼容的 `shared_ptr` 管理。

## 11. C++ 内存区域、对齐和 `new/delete` 应怎样回答？

核心回答：进程通常包含代码、只读数据、静态存储、堆、栈和映射区，但精确布局由 OS、ABI 和装载器决定。对齐让对象地址满足硬件和 ABI 要求，也会引入 padding；结构体不能用 `memcmp` 一般性判断值相等，因为 padding、浮点表示和对象表示都可能不同。

`new` 表达式通常先取得存储再构造对象，`delete` 先析构再释放；`malloc/free` 只管理原始字节。两组不能混用，数组形式也必须配对。现代业务代码应优先 RAII 容器和智能指针，手工分配集中在清晰的底层边界。

## 12. 如何排查崩溃、内存泄漏和性能问题？

核心回答：先保存可复现输入、构建标识、编译参数、日志和 Core Dump，再用符号化栈确认首次异常位置；随后检查生命周期、越界、数据竞争、未定义行为和资源增长。不要只在最后崩溃行猜原因，内存破坏可能早已发生。

建议组合：编译器警告与静态分析；Address/Undefined/Thread/Leak Sanitizer；调试器和 Core；堆分析与采样 Profiling。优化前先用基准和采样证明 CPU、缓存、锁、分配或 I/O 瓶颈，避免凭感觉微优化。

常见追问：Release 才出现的问题常与未定义行为、竞态、优化改变时序或缺失符号有关；“加日志后不复现”可能是 Heisenbug，不能当作修复。
