# 03 容器与资源管理

容器管理元素，智能指针表达拥有关系。先分析访问模式和生命周期，再判断迭代器失效、共享引用和诊断工具的使用。

## 顺序容器、关联容器与迭代器

默认从 `vector` 开始，它连续、局部性好且随机访问快；两端频繁操作可考虑 `deque`；只有在确实需要稳定节点地址和中间频繁插删时才考虑链表。`map` 提供有序和对数复杂度，`unordered_map` 平均常数查找但受哈希质量、装载因子和攻击输入影响。

容器修改必须考虑迭代器失效：`vector` 扩容会使全部指针/引用/迭代器失效，中间插删还会影响位置之后元素；节点式容器通常只使被删节点失效，但标准规则要按具体容器和操作核对。遍历删除使用容器返回的下一个迭代器，不能在失效后继续自增。

`push_back` 接收现有对象，`emplace_back` 在容器位置构造对象，但不保证在所有写法中更快；先以清晰和正确为主。标准容器对同一实例的并发写通常不安全，外部同步或分片设计不可省略。

## Unique、Shared 与 Weak 所有权

`unique_ptr` 表达唯一所有权，可移动不可复制；`shared_ptr` 用共享控制块管理引用计数；`weak_ptr` 是不增加强引用计数的观察者，用于打破环和尝试获取临时共享所有权。优先 `make_unique`/`make_shared`，并让所有权关系在接口类型中可见。

`shared_ptr` 不能自动解决循环引用；两个对象互相持有强引用会让计数永不归零。它也不等于对象线程安全：不同 `shared_ptr` 实例的控制块操作可安全协作，不代表被指向对象的成员可以并发读写。

不能用两个独立控制块管理同一裸指针，否则会双重删除；从对象内部生成共享指针应使用 `enable_shared_from_this` 且对象已经由兼容的 `shared_ptr` 管理。

## 存储期、对齐与动态分配

进程通常包含代码、只读数据、静态存储、堆、栈和映射区，但精确布局由 OS、ABI 和装载器决定。对齐让对象地址满足硬件和 ABI 要求，也会引入 padding；结构体不能用 `memcmp` 一般性判断值相等，因为 padding、浮点表示和对象表示都可能不同。

`new` 表达式通常先取得存储再构造对象，`delete` 先析构再释放；`malloc/free` 只管理原始字节。两组不能混用，数组形式也必须配对。现代业务代码应优先 RAII 容器和智能指针，手工分配集中在清晰的底层边界。

## 示例：独占所有权与容器

```cpp
#include <cassert>
#include <memory>
#include <utility>
#include <vector>

int main() {
    auto owner = std::make_unique<int>(42);
    std::vector<std::unique_ptr<int>> values;
    values.push_back(std::move(owner));
    assert(owner == nullptr);
    assert(*values.front() == 42);
}
```

移动后，`unique_ptr` 的拥有关系转移给容器中的元素；这里原指针变空是 `unique_ptr` 的约定。容器离开作用域时逐个析构元素，元素释放所拥有的整数，异常或提前返回也遵守同样的作用域释放规则。


## 崩溃、泄漏与性能诊断

先保存可复现输入、构建标识、编译参数、日志和 Core Dump，再用符号化栈确认首次异常位置；随后检查生命周期、越界、数据竞争、未定义行为和资源增长。不要只在最后崩溃行猜原因，内存破坏可能早已发生。

建议组合：编译器警告与静态分析；Address/Undefined/Thread/Leak Sanitizer；调试器和 Core；堆分析与采样 Profiling。优化前先用基准和采样证明 CPU、缓存、锁、分配或 I/O 瓶颈，避免凭感觉微优化。

Release 才出现的问题常与未定义行为、竞态、优化改变时序或缺失符号有关；“加日志后不复现”可能是 Heisenbug，不能当作修复。

## 版本与来源
